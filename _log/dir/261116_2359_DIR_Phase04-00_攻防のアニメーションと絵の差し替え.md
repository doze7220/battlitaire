## 1. 大ゴール
コアループ（段取り → 攻防 → 次のフェーズ、3体の敵、タイトルと結果の画面）は Phase 3 までにひととおりできた。アウトゲーム成長（Phase 6）の前に1回のプレイの質を上げる。その最初として、いちばん単純な攻防の段を作り変える。戦闘の段をクオータービュー（斜め上から見下ろす形）にし、兵を1人＝1体で描いて群れとして戦わせる。放った札が光の玉になって兵に変わる流れと、敵ごとの攻防の見せ方も作る。あわせて、仮の図形を、発注者が OZ Vector Editor で作ったスプライトに差し替える。ルールは変えない。
* **完了の目安**: ゴール型。タイトルからクリアまたは負けまで通しで遊んだとき、次の状態になっている。
  * 戦闘の段がスプライトで描かれたクオータービューになっている。
  * 放った札が光の玉になって兵に変わる。
  * 兵が1人＝1体で、敵ごとの見せ方で戦う。
  * 相打ちとダメージは「1対1でぶつかり、ぽこんと跳ねて画面の下へ落ちる」形にそろっている。
  * 発注者の試遊で「見ていてちょっと面白い」と判断される。

## 2. やらないこと（Non-goals）
* ルールの変更 → しない。演出と絵だけを変える。演出の途中・早送り・スキップのどれでも、ルールの結果は変わらない（憲法 3章）
* デバッグモード（タイトル画面の入口、理論上の最大の兵を出すボタンなど）→ Phase 5（`_doc/PROJECT_MILESTONE.md` の「演出と UI の磨き込み」）
* カードのデザイン全体と札の動きの演出、フェイズ開始・バトル開始の演出、タイトル画面、BGM・SE → Phase 5。カードについては、P4 ではスートの絵をスプライトに差し替えるだけにする
* 兵の手足（丸い体に手と足が浮いた形）と、敵に同じ作りを使う案 → Phase 5 以降。P4 の兵は丸い体と武器だけ
* ゲージの行（攻撃・防御・修理・金貨の数字）の作り替え → しない。ゲージの行はそのまま残し、名前だけ変える。戦闘の段の上端の人数と二重に見えるかは試遊で確かめる。整理は Phase 5 で扱う
* 城の上のオブジェ（金貨を表すもの）→ 作らない。金貨は数字の表示だけ
* スプライトの Canvas キャッシュ → P4 ではエンジンに頼まない。JS のスプライトのまま動かし、要望は後でまとめる（`_doc/PROJECT_MILESTONE.md` の「エンジンへの要望」）
* 兵が理論上の最大（ゲージ1つあたり 128 体）を超えたときの描き方 → Phase 6
* アウトゲーム成長、スキル、保存 → Phase 6

### Phase 04-01: クオータービューとスプライトの差し替え
* **目的**: 戦闘の段をクオータービューの見た目にし、仮の図形を発注者のスプライトに差し替える。
* **実装要件**:
  * 戦闘の段に背景のスプライトが描かれ、斜め上から見下ろした見た目になっている。地面は回さず、左が自軍・右が敵のまま。
  * 城は戦闘の段の左端から少し内側に置かれている。城の後ろ（左側）に、04-02 で剣と修理の兵が並ぶ場所が空いている。
  * 城・ゴブリン・巨人・ドラゴン・自軍の兵が、`assets/sprites/` のスプライトで描かれている。仮の図形（城の四角、巨人の緑の玉、ドラゴンの赤い玉など）は画面に残らない。
  * スートの絵が変わっている。効果は変わらない。
    * 剣と盾はそのまま。
    * 薬はハンマーになる。回復の兵は城を直す大工にあたる。
    * 力こぶは金貨の袋になる。
  * 盤面のカードの絵（いまは絵文字）が、スートのスプライト（剣・盾・ハンマー・金貨）になっている。
  * ゲージの行の名前は「回復」が「修理」に、「力こぶ」が「金貨」になっている。画面のほかの文字（攻防の案内など）も同じ名前にそろっている。
  * 攻防の流れと兵の動きはいまのままでよい。描く絵が変わるだけで、通しで遊べる。
  * `PROJECT_ARCHITECTURE.md` の戦闘の段の記述（Phase 2 の「サイドビュー」）を、クオータービューに直してある。
* **持ち越し事項**:
  * 兵の当たる位置（`armorHitX`・`enemyHitX`）は、敵の種類によらず同じになっている。スプライトの大きさに合わせて、敵ごとに見直す（`_doc/COWORK_STATUS.md` 2章 A。04-04 で作り直すなら、ここでは仮でよい）。
  * `_doc/PROJECT_MILESTONE.md` の「演出と手触り」にある「兵の絵は図形の仮」。
* **メモ**:

    * スート: 100×100（`suit_sword.js`・`suit_shield.js`・`suit_hammer.js`・`suit_gold.js`）
    * 小さいユニット: 100×100（`unit_solder.js`・`unit_goblin.js`）
    * 大きいユニット: 200×200（`unit_castle.js`・`unit_giant.js`・`unit_dragon.js`）

  * REQ 作成時に確認すること。
    * スプライトの基準点（中心か足元か）と前方の向きは、実際のファイルで確かめる。前方の向きは開発資料に書く（ENGINE_API 23章）。

### Phase 04-02: 兵の群れ
* **目的**: 自軍の兵を1人＝1体で、陣地に分けて描き、相打ちとダメージの後に跳ねて落ちる消え方にする。
* **実装要件**:
  * 兵の数は、ゲージの量と同じになっている。「大きな1体で10人分」のようなまとめ方はしない。端数が減ったときに、大きな兵が割れて小さな兵に変わって見えないようにするため。
  * 兵は丸い体に、役割のスートの武器を縮小して持っている。攻撃の兵は剣、防御の兵は盾、修理の兵はハンマーだけを持つ。
  * 陣地は、右（敵の側）から順に「盾 → 城 → 剣 → 修理」と並んでいる。
    * 防御の兵は城の前にいて、敵の攻撃を受ける。
    * 攻撃の兵は城の後ろにいて、突撃のときに城の後ろから敵へ向かって出ていく。
    * 修理の兵は、攻撃の兵のさらに後ろにいる。
  * 兵どうしは重なってよい。奥の兵から先に描かれていて、手前の兵が奥の兵の上に見える。
  * 兵の位置は、何番目の兵かで決まる。毎フレームちらつかない。1体が消えても、ほかの兵は並び替わらない。
  * 兵は歩く動きを持たず、揺れながら、または弾みながら移動する。どちらにするかは試遊で決める。
  * 戦闘の段の上端に、攻撃・防御・修理の兵の人数がまとめて表示されている。
    * 攻防の間、兵が消えるたびに数がその場で減る。
    * スキップすると最後の値になる。
    * 数は、ルールが出した結果を演出の時間に合わせて見せるもので、ルールの値は変わらない。
  * 兵は、相打ちになったときと、相手にダメージを与えた後に、ぽこんと跳ねてから画面の下へ落ちて消える。
  * 落ちていく兵は戦闘の段の中だけに描かれる。下のソリティアの段には描かれない。
  * ゲージ1つあたり 128 体（3種類で 384 体）を出しても、遊べる速さで動く。エンジンの FPS 表示で確かめる。
  * 早送り・スキップは今と同じく使え、結果は変わらない。
* **持ち越し事項**:
  * 攻防の当たり・修理の時刻の式が `js/anim/battleCues.js` と `js/anim/battleTimeline.js` の2か所にある（`_doc/COWORK_STATUS.md` 2章 A。常時防御力の段・敵の回復の段も同じ）。攻防の演出を作り変えるので、1か所にまとめるかを REQ 作成時に決める。
  * 片付けの Interrupt の4件（`_doc/COWORK_STATUS.md` 2章 A）。対象のファイルを触るなら、いっしょに直してよい。
    * `drawHud` の使っていない引数 `outOfActions`
    * `DEFEAT_HINT_TEXT` の置き場所
    * `battleShowView.js` と `battleStageView.js` の責務定義のずれ
  * （04-01 から）城の中心を約 110 → 240 に動かしたので、城と敵の間の兵が動く場が約 364 → 約 250px に縮んだ。陣地の広さを決めるときに見る（城の位置 `CASTLE_CX`・大きさ `CASTLE_H` は `js/view/layout.js` の定数）。
  * （04-01 から）いまの兵の丸は、兵の矩形（`smallW` 約 21 × `smallH` 約 38）の幅に収めているので直径約 21px（大きなユニットは約 38px）。兵の大きさを決めるときに見直す。
  * （04-01 から）`_doc/PROJECT_MILESTONE.md` の「演出と手触り」の「兵の絵は図形の仮」。丸のスプライトにはしたので、武器を持たせたところで片付ける。
* **メモ**:
  * 04-03 ができるまでは、兵がいまと同じ時点（「行動終了」の後）に戦闘の段に現れてよい。
  * REQ 作成時に確認・決定すること。
    * 兵の理論上の最大（ゲージ1つあたり 128）を、ルールの設定の値から確かめる。
    * 兵の大きさと陣地の広さは REQ 作成時に決め、試遊で調整する。
    * デバッグモードは Phase 5 なので、兵の数を一時的に増やして重さを確かめる方法を REQ で決める。確かめた後に、その仕掛けを残すかどうかも決める。
    * 修理の兵の見せ方（城へ向かって消えるなど）と、使われずに残った兵がフェーズの終わりにどう消えるか（ルールでは、余った攻撃・防御はフェーズの終わりに消える）は REQ 作成時に決める。消え方は「跳ねて落ちる」にそろえてよい。

### Phase 04-03: 放つ → 光の玉 → 兵
* **目的**: 放った札が光の玉になって戦闘の段まで飛び、兵に変わる流れを作る。兵は段取りの間に城のまわりで待ち、放つたびに増える。
* **実装要件**:
  * 放つと、列の札が下から順に光の玉になり、戦闘の段まで飛ぶ。着いたところで兵に変わり、04-02 の陣地に並ぶ。
  * 同じスートの束（倍率がかかる区切り）は、1つにまとまってから兵になる。そのとき「12 ×2 = 24」のように倍率が見える。
  * 連鎖の音（1枚ごとに高くなる）は、玉が飛ぶのに合わせて鳴る。
  * 金貨の玉は兵にならず、金貨の数字の表示へ飛ぶ。着くと数字が増える。
  * 段取りの間、兵は陣地で待っている。放つたびに軍勢が増える。攻防が始まると、待っていた兵がそのまま戦う。
  * 玉が飛んでいる間も、次の操作（めくる・置く・放つなど）ができる。
  * 「行動終了」を押したときに飛んでいる玉があれば、全部が着いてから攻防が始まる。
  * ゲージの数字と兵の数は、玉が着いた後に一致する。
* **持ち越し事項**:
  * （04-02 から）兵の名簿は、攻防の始めに時間割から1回だけ作っている（`js/anim/troopRoster.js`。家の位置は `js/anim/campSlots.js` で番号から決まり、兵が消えても並び替わらない）。段取りの間に放つたびに兵を足すには、名簿を途中から伸ばす形か、段取り用の別の入れ物を作って攻防の始めに引き継ぐ形が要る。
  * （04-02 から）人数の表示（戦闘の段の左上）は、ゲージの行と二重にならないよう攻防の演出の間だけ出している。段取りの間に兵が並ぶなら、出すかどうかを決める。
* **メモ**:
  * 玉がまとまる見せ方（合体してから弾けるか、など）、玉の速さ、飛ぶ道筋は REQ 作成時に決め、試遊で調整する。
  * ルール層は、放った時点で結果（ゲージの量）を確定している。玉は、その結果を時間をかけて見せるだけにする。
  * REQ 作成時の決定（2026-11-17、発注者）: 札は下から順に玉になって列の真上へ上り、区切りごとに1つの大きな玉に合体して「12 ×3 = 36」を出す。大きな玉が陣地へ飛んで弾け、兵が弾けた所から家へ跳んで並ぶ。ゲージの数字は兵が着くのに合わせて増える。人数の表示は今と同じく攻防の間だけ。玉が着いたときの新しい効果音は足さない。REQ `_log/req/261117_0929_Phase04-03_放つと光の玉.md`。

### Phase 04-04: 敵ごとの攻防の見せ方
* **目的**: 敵の種類ごとに攻防の見せ方を変え、相打ちをすべて「1対1でぶつかり、ぽこんと落ちる」形にそろえる。
* **実装要件**:
  * **ゴブリン**
    * 並んでいるゴブリンの群れの数が、ゴブリンの HP と同じになっている。
    * 自軍の兵がゴブリンに当たると、当たった分だけゴブリンが倒れて群れが減る。
    * 攻撃と防御のスタンスのゴブリンは、HP の群れとは別に、画面の外（右）から跳ねながら現れる。HP の群れはその場に残るので、群れの数はいつも HP と同じになる。
    * 攻撃: 攻撃力の数だけゴブリンが現れ、群れになって城へ向かう。
      * 防御の兵と1対1で相打ちになり、跳ねて落ちる。
      * 防御の兵を越えたゴブリンが城に当たる。その数が城へのダメージになる。
    * 防御のスタンス: スタンスの量の数だけゴブリンが現れ、HP の群れの前に立つ。
      * 自軍の攻撃の兵は、まず防御のゴブリンと1対1で相打ちになる。
      * 越えた兵が HP の群れに当たり、ゴブリンを減らす。
  * **巨人とドラゴンの防御**
    * 防御（常時防御力と防御のスタンスの合計）の数だけ、体の上にシールドが並んでいる。
    * 自軍の攻撃の兵は次々に巨人・ドラゴンに当たり、跳ねて落ちる。
    * 兵が1体当たるごとに、シールドが1つ剥がれて落ちる。
    * シールドがなくなった後に当たった兵の数が、敵へのダメージになる。
  * **巨人の攻撃とドラゴンの爪攻撃**
    * 飛んでいくもの（エフェクト）は描かない。
    * 防御の兵のところにヒットマークが出て、防御の兵が攻撃力の分だけ1体ずつ跳ねて落ちる。
    * 防御の兵で受けきれなかった分が、城へのダメージになる。
  * **ドラゴンのブレス**
    * 攻撃力の数だけ炎（`effect_fire.js`）がドラゴンから出て、城へ向かって進む。
    * 炎は防御の兵と1対1で相打ちになる。
    * 防御の兵を越えた炎が城に当たる。その数が城へのダメージになる。
    * ブレスの攻撃と同時に、燃やす札が1枚ずつ炎を出して燃え、捨て札へ移る。いまはブレスの後に順に燃えているので、それより短くなる。
    * ルール（ダメージの量、燃える札、燃える順番）は変わらず、見せる時刻だけが変わる。
  * **倒したとき**: 巨人とドラゴンは、倒されると、ぽこんと跳ねてから画面の下へ落ちていく。ゴブリンは、群れが全部倒れて消える。
  * 落ちていくもの（兵・ゴブリン・シールド・巨人・ドラゴン）は、すべて戦闘の段の中だけに描かれる。
* **持ち越し事項**:
  * 兵の当たる位置が、敵の種類によらず同じになっている（`_doc/COWORK_STATUS.md` 2章 A）。ここで敵ごとに作り直す。04-01 では今と同じ値（`armorHitX` 560・`enemyHitX` 620）のままで、巨人・ドラゴンの絵の中に入ることだけ確かめた。
  * （04-01 から）シールドマークは盾のスプライトにしたが、並べる先の体の上の矩形は仮の割合（`js/view/enemyView.js` の `ENEMY_FIGURES` の `shield`）で、マークは約 15px（前は約 26px）。光るときは同じ絵を `lighter` で重ねている。シールドを体の上に並べ直すときに作り直す。
  * 札が燃える段の長さ（1枚 0.65 秒で、6枚で約4秒。`_doc/PROJECT_MILESTONE.md` の「演出と手触り」）。攻撃と同時に燃やすことで扱う。
  * （04-02 から）敵の側の余った兵（敵の守り・敵兵）は今の流れのまま、それぞれの段の始めから薄れて消える。自軍の使われなかった兵は終わりに城へ走って帰って消えるので、消える時刻と見せ方がそろっていない。敵の側の見せ方を作り直すときにそろえる。
  * （04-02 から）城に当たる位置 `castleHitX` は城の矩形の右端 − 10（`js/view/layout.js` の `CASTLE_HIT_INSET`）にした。敵の当たる位置と合わせて見直す。
  * 燃える段の時刻の式は `js/anim/burnTrack.js` の `burnCardOffsets` の1か所にあり、時間割と音のきっかけの両方から呼ばれている（`_doc/COWORK_STATUS.md` 2章 A）。
  * 攻防の演出中は、列と捨て札を燃える前の写しから描いている。盤面の UI は燃えた後の状態から作るので、両者がずれうる（`_doc/COWORK_STATUS.md` 2章 A）。燃える時刻を変えるときに確かめる。
* **メモ**:
  * ゴブリンの HP の群れの数がとても大きくなるときの描き方は、REQ 作成時に設定の値から確かめる。
  * シールドの並べ方と大きさ（常時防御力 15 にスタンスが足されたときなど）は、REQ 作成時に決める。
  * 巨人の振りかぶりとドラゴンの吸い込みは、行動しないフェーズである。見せ方の作り込みは 04-05（ための動き）で扱う。

### Phase 04-05: 攻防のエフェクト
* **目的**: 当たりの手応えと、大きな一撃の重さが見て分かるように、攻防にエフェクトを足す。
* **実装要件**:
  * 当たった瞬間に、短いヒットストップと白い光が出る。
  * 城と敵にダメージが入ると、ダメージの数字が出て、粒が散る。修理のときは、修理の粒が出る。
  * 大きな一撃（巨人の攻撃、ドラゴンのブレスなど）で、戦闘の段が揺れる。
  * 待っている兵が、呼吸するように体を伸び縮みさせている。
  * 突撃するとき、兵が加速して踏み込む。
  * 巨人の振りかぶりとドラゴンの吸い込みでは、ためる動きが見え、画面が暗くなる。撃つ瞬間に光る。
  * 早送り・スキップでも、エフェクトのせいで結果や進行が変わらない。ヒットストップが早送り・スキップを妨げない。
* **持ち越し事項**: `_doc/PROJECT_MILESTONE.md` の「演出と手触り」の「相殺で当たった印（光・揺れなど）がない」。ここで扱う。
* **メモ**:
  * 「大きな一撃」とみなす基準（行動の種類か、ダメージの量か）は REQ 作成時に決める。
  * エフェクトの強さと長さは、試遊で調整できる設定の値にする。

### Phase 04-06: 試遊と調整
* **目的**: 通しで遊び、演出の速さ・大きさ・並び・エフェクトの強さを調整する。
* **実装要件**:
  * 発注者の試遊を受けて、演出の設定の値を調整する。対象は、兵の大きさと陣地、移動の速さ、揺れと弾み、玉の速さ、エフェクトの強さと長さなど。
  * 調整後の値で、タイトルからクリア・負けまで通しで遊べる。
  * 兵の移動の見せ方（揺れるか、弾むか）が決まっている。
* **持ち越し事項**: 04-01〜04-05 の申し送りのうち、試遊で確かめるもの。
  * （04-01 から）城の HP・敵の HP・予告・数え下ろし・フェーズの枠を、今の位置のまま背景の上に描いている。重なり方を見る。
  * （04-01 から）敵の回復の量（「+20」）は巨人の絵の上端から高さの 15% の位置に重ねて描く。読みにくければ `ENEMY_HEAL_TEXT_RATIO` で動かす。
  * （04-02 から）兵の動きの値は `js/anim/battleAnimConfig.js` の `BATTLE_ANIM`（`moveStyle`（初期値 `'hop'`）・弾み／揺れ・跳ねて落ちる・ずらし・`healMoveMs`・`returnMs`）、兵の大きさと陣地は `js/view/layout.js`（`TROOP_SIZE` 24・`TROOP_CAMPS_X` など）。揺れるか弾むかをここで決める。
  * （04-02 から）攻撃の兵が突撃した後に待つ位置（約 x 350〜440）と防御の陣地（x 300〜400）が重なる。見え方を見る。
  * （04-02 から）城と敵の HP の表示は、最初の兵が当たる時刻から最後の兵の時刻まで直線で変わる（1体ごとの段差ではない）。ずれが目立つか見る。
  * （04-02 から）相打ち・当たり・修理の音は、段の最初の瞬間に1回だけ鳴る（1体ごとには鳴らさない）。
  * （04-02 から）ゴブリンの軍勢の絵の兵が約 21px → 24px になり、少し大きくなった。
  * （04-02 から）兵が数百体のときの描画の重さは、デバッグモード（Phase 5、`_doc/PROJECT_MILESTONE.md`）ができてから確かめる。ここでは扱わない。
* **メモ**:
  * ルールの数値（敵の HP・攻撃・防御など）は変えない。
  * 試遊で出た要望は、小さいものはここで扱う。大きいもの、または Phase 5 の範囲のもの（ゲージの行の整理など）は `_doc/PROJECT_MILESTONE.md` に送る。
