## 1. 大ゴール
P7 でエンドレスの進行と★の抽選ができたが、★2の敵は巨人の1種だけで、強敵のステージはいつも巨人になる。P8 では★2の敵を4種（毒キノコ・ネクロマンサー・ゴーレム・侵略軍）足し、★2の中の出し分けをくじ袋の決まりにする。新しい敵は、それぞれ違う段取りをプレイヤーに迫る（下の表）。★3の敵の追加は P9 で行う。

| 敵 | 迫ること |
|---|---|
| 毒キノコ | 予告された束を、出撃の前に組み直せ |
| ネクロマンサー | 死なせるな。予告を見て、剣を出すか・寝かせるか・盾を出すかを選べ（基本は盾を出さず、城と修理で耐える） |
| ゴーレム | 溜めさせるな、削り続けろ |
| 侵略軍 | 守りながら、剣で壊せ |

P8 で確かめるのは、「強敵のステージごとに違う段取りを考えるのが楽しいか」である。

* **完了の目安**: ゴール型。次の状態になっている。
  * ★2の敵が5種（巨人・毒キノコ・ネクロマンサー・ゴーレム・侵略軍）になり、★2のステージにくじ袋の決まりで出る。
  * 新しい4種は、それぞれ上の表の「迫ること」を、予告を読んで対処できる形で迫る。

### 資料との関係
企画の資料は `_doc/バトリティア_アイデアメモ_敵.md`（1章）である。この DIR と食い違うところは、この DIR を正とする（主な違い: 侵略軍の攻城兵器に属性を付けない。毒キノコの「決めていないこと」を、この DIR の 08-01 で決めた）。資料の「案」のうち、この DIR に「案」と書いたものは、REQ 作成時に発注者と確かめてから決める。

## 4. サブフェイズごとの実装要件

### 敵を足すサブフェイズに共通の要件（08-01・08-03・08-04・08-05）
* 足した敵は★2として、★2のステージに出る。08-02 より前は、今の「同じ★の中のどの敵かは日付の種で決まる」仕組みのまま混ざる。最初の★2が巨人になる決まりは変えない。
* 敵の名前・絵・HP・攻撃・防御・行動の決まりを持ち、ステージの加算（HP・攻撃・防御）と激昂（16 ターン目からの攻撃の倍率）が、ほかの敵と同じく効く。激昂で特別な振る舞いが要るかは、各 REQ で発注者と決める。
* 予告の札で、その敵が次に何をするかが読める。数値はほかの敵と同じく予告に出す。
* 敵を倒すと、★2として強敵の点が付く。結果の画面の倒した敵の絵に、その敵の絵が出る。
* 敵がターンをまたいで持つ状態（混乱の予告、返ってくる兵、溜めた防御、攻城兵器など）は、中断と再開で失われない。
* DEBUG で、その敵とすぐ戦える（今の DEBUG の敵の選び方に足す形。REQ 作成時に確認）。
* 絵は、今ある絵のコピーなどの仮の絵で始めてよい。仮の絵は `_doc/COWORK_STATUS.md` に「発注者の作業・仮の絵」として記録する。

### Phase 08-01: 毒キノコ（混乱）
* **目的**: 予告した列の束を勝手に放たせる★2の敵、毒キノコ（名前は仮）を足す。
* **実装要件**:
  * 毒キノコは、2〜3 ターンに1回（間隔はランダム）、ターンの始めに「混乱」を予告する。
  * 混乱の予告では、束の枚数がいちばん多い列を1つ選び、その列に印を付ける。枚数が同じなら束の数値の合計が高い列、それも同じなら左の列を選ぶ。選んだ列は、そのターンの間は変わらない。
  * そのターンの攻防が始まる直前に、印の付いた列にある束が、AP を使わずに自動で放たれる。束の補正は、自分で放つときと同じく乗る。放たれた兵は自軍のまま戦う。
  * 印の付いた列の束は、プレイヤーが自分で先に放つこともできる（AP を1使う）。束を他の列へ移すこともできる。攻防が始まる直前に印の付いた列に束がなければ、混乱は空振りになる。
  * 混乱を予告したターンも、毒キノコはふつうに攻撃・防御を行い、予告に出す。
  * 混乱しないターンは、ふつうに攻撃・防御を行う。
* **持ち越し事項**: `_doc/COWORK_STATUS.md` 3章のコードの片付け（`Game.isOver()` がどこからも呼ばれていない。`enemyPortrait.js` の `drawEnemyPortrait` に組み込みの名前を渡すと例外が起きる）。敵の絵を足すときに同じ所を触るなら、一緒に直す。
* **メモ**:
  * 混乱を予告するターンに、厚い防御（自動で放たれる剣が無駄になる）や強い攻撃を組み合わせるかは、REQ 作成時に発注者と決める。混乱の後の敵の行動しだいで「何を積むか」が変わることが、この敵のねらいである（資料の確定事項）。
  * 印の見た目と置き場所は REQ 作成時に決める。P9 のセイレーンも列に印（♫）を付けるので、同じ作りで足せるようにしておくとよい。
  * 完了（261127。REQ `_log/req/261127_1850_Phase08-01_毒キノコの混乱.md`・RES `_log/res/261127_1850_RES_Phase08-01_毒キノコの混乱.md`）。混乱のターンは半々で「厚い守り（攻撃なし・防御 8〜10）」か「強い攻撃（8〜10・防御なし）」。印の列は列を薄い紫に染めて渦巻きの印、行動を使い切ると「準備終了」の前にひとりでに放たれる。列の印は種類の表（`columnMarks.js`・`markLooks.js`）で足せる形にした（セイレーンの♫はここに1行）。持ち越しの片付けは `Game.isOver()` を消した。`enemyPortrait.js` は触らなかったので、組み込みの名前の件は `_doc/COWORK_STATUS.md` 3章に残る。

### Phase 08-02: くじ袋での出し分け
* **目的**: ★2・★3の中のどの敵を出すかを、くじ袋の決まりにする。
* **実装要件**:
  * ★2の全種を1体ずつ袋に入れ、★2のステージごとに袋から1体を引く。袋が空になったら、全種を入れ直す。
  * 最初の袋は、巨人を先頭に固定し、残りの順を混ぜる（最初の★2は巨人のまま）。
  * 袋を入れ直した直後の1体が、直前に出た★2と同じ敵にならない。
  * ★3にも同じ決まりを入れる（最初の★3はドラゴン）。P8 の間は★3がドラゴンだけなので、見た目は変わらない。
  * 袋の中身の順は、ゲームを始めた日付の種で決まる。同じ日に何度始めても同じ並びになり、中断して再開しても並びは変わらない。
  * DEBUG の先の並びの一覧で、★2の敵が袋の決まりどおりに並んでいるのを確かめられる。
* **持ち越し事項**: 08-01 で★2の動きが巨人（`cycle`）と毒キノコ（`confuse`）の2つになった。最初の1体（`first`）は「同じ動きを続けない」の数に入らないので、2番目の★2がまた巨人になる種がある。くじ袋の決まり（入れ直した直後に直前と同じ敵にならない）でこれが解消することを確かめる。
* **メモ**:
  * ★1の並びの決まり（07-04a）は変えない。
  * 08-03 以降で★2の敵が増えると、袋の中身も増える。敵を1行足すだけで袋に入る形にする。
  * 敵の種類が増えると、同じ日付でも並びが変わる。これは構わない。
  * 完了（261127。REQ `_log/req/261127_2031_Phase08-02_くじ袋での出し分け.md`・RES `_log/res/261127_2031_RES_Phase08-02_くじ袋での出し分け.md`）。どの★が袋かは `stageStars.draws` の行の設定で決まる。今の★2は巨人と毒キノコが交互に出る。DEBUG の先の並びの一覧の★2・★3の行に「袋◯の◯番目」を出した。並びは種とステージの番号から求めるので、中断データは変えていない（版 10 のまま）。

### Phase 08-03: ネクロマンサー
* **目的**: 死んだ味方の兵を敵に回す★2の敵、ネクロマンサーを足す。
* **実装要件**:
  * ネクロマンサーは、毎ターン攻撃と防御の両方を、ランダムな量で行い、両方を予告に出す。
  * 敵の攻撃で死んだ盾の兵と、敵の防御で死んだ剣の兵は、敵に回る。敵に回った兵の数は、次のターンのネクロマンサーの攻撃に足される。予告に「攻撃8 +5」のように、足される分を分けて出す。
  * 盾で攻撃を受け続けると、攻撃が増えていく。城で受けて死者を出さなければ、次のターンの足し分は 0 になる。
  * 案: 本体に当たって役目を終えた剣と、使われなかった兵は死んだことにしない。死んだ数は人数で数える（精鋭は能力の分だけ受け止めても1体分）。敵に回った兵が足されるのは次のターンだけ。
  * 案: 剣が死ぬのは、敵の防御の量まで（防御 5 なら、何人放っても死ぬのは 5 人まで）。防御を下回る剣を放つと、全員死んで攻撃に返る。
* **持ち越し事項**: 08-02 のくじ袋に★2の3種目が入る。試遊で、袋の中の出方（3種以上の袋は、並べ方がどれも同じ確率にはならない。「袋の中は1回ずつ」「境目で同じ敵が続かない」は守られる）と、DEBUG の先の並びの一覧の行が「ネクロマンサー　袋◯の◯番目」で幅に収まるかを確かめる。
* **メモ**:
  * 攻略の基本は「盾をできるだけ出さず、城の HP と修理で持ちこたえる」である（資料の確定事項）。「防御が強すぎるときは攻撃しない」「攻撃が強すぎて城が危ないときは、盾と修理で乗り切る」という判断が生まれる量にする。
  * 兵が死んで敵に回る見せ方は REQ 作成時に決める（資料の案: 本体に当たった剣は城へ帰る演出にする）。

### Phase 08-04: ゴーレム
* **目的**: 防御をターンをまたいで溜め、溜めた防御で体当たりする★2の敵、ゴーレムを足す。
* **実装要件**:
  * ゴーレムは、数ターンに1回、防御を取る。この防御はターンをまたいで持ち越され、取るたびに積み重なる。
  * 溜まった防御を攻撃に足す「体当たり」をする。体当たりで防御を使い切り、その後は防御 0 の隙になる。
  * 案: 溜まった防御は、当たった攻撃の分だけ減る。防御を取らないターンは攻撃する。防御を取る間隔はランダムで、予告に出す。
  * 案: 体当たりの1ターン前に兆し（身をかがめる）を予告し、次のターンは必ず体当たりする。体当たりの威力は兆しの予告の時点で決まり、数字で出す（攻防は敵の攻撃が先なので、威力を削れるのは兆しのターンまで）。
  * 溜まった防御の量が、画面で読める。シールドの数が多くなったら数字で出す。
* **持ち越し事項**: なし
* **メモ**:
  * 今の敵の防御は、ターンの終わりに消える（予告の `defense` 1つ。07-01）。ゴーレムだけ持ち越す扱いをどこに置くかは、REQ 作成時に実コードを見て決める。
  * 骸骨との違い: 骸骨の防御はそのターンで消える。ゴーレムは持ち越して積み重ねる。
  * 激昂の倍率が、体当たりのうち溜めた防御の分にも掛かるかは、REQ 作成時に発注者と決める。
  * 08-01 の毒キノコは、強い攻撃・厚い守りを既存の中の種類 `heavy`・`bigGuard` で見せた（画面の呼び名は「大攻撃」「防御」）。体当たり・身をかがめるの兆しに新しい中の種類と呼び名が要るかは REQ 作成時に決める。

### Phase 08-05: 侵略軍
* **目的**: 攻撃と防御を組み合わせながら、ときどき攻城兵器を出す★2の敵、侵略軍を足す。
* **実装要件**:
  * 侵略軍は、毎ターン攻撃と防御を組み合わせて行い、両方を予告に出す。
  * 数ターンに1回、攻城兵器を出す。兵器は侵略軍の HP とは別の HP を持ち、画面でその HP が読める。
  * 兵器は、発動までに壊さないと、城に大ダメージを与える。このダメージは盾で防げない。
  * 剣の当たる順は、敵の防御 → 攻城兵器 → 本体である。
  * 兵器は、プレイヤーの兵の攻撃の後に撃つ（ふつうの攻防は敵の攻撃が先）。そのターンに放った剣で壊せば間に合う。
  * 兵器は撃ったら使い捨てで、次の兵器が出るまでは本体を叩ける。
  * 案: 次の兵器が出るまでは 2〜4 ターンで、来るまで分からない。兵器が出てから発動までは 2〜3 ターンで、「発動まで あとN」を出す。最初の兵器は 2 ターン目以降に出る。兵器の傷はターンをまたいで残る。
* **持ち越し事項**: なし
* **メモ**:
  * 量が多いので、現場設計が実コードを見て、REQ を2つに分けてよい（例: 攻撃と防御の組み合わせの本体と、攻城兵器）。分けた場合はサブフェイズ一覧を 08-05a・08-05b のように分け、変更履歴に1行書く（発注者の承認を得たうえで、現場設計の判断で直してよい）。
  * REQ 作成時に確かめること: 兵器の HP の2本目のゲージの置き場所、攻防の順番の例外（兵器だけ自軍の攻撃の後に撃つ）、剣の当たる順を敵ごとに変える作り。
  * 侵略軍は人の軍勢で、群れ（ゴブリンの軍勢と同じく兵の数で描く）か1体の絵かは REQ 作成時に発注者と決める。
