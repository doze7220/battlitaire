# 設計指針書 DIR: Phase 07 : エンドレスとインゲーム強化
* ルール: `./PROJECT_CONSTITUTION.md`
* 開発資料: `./PROJECT_ARCHITECTURE.md`

## 1. 大ゴール
いまのゲームは、ゴブリンの軍勢・巨人・ドラゴンの3体を倒すと終わる。P7 では、負けるまで敵が続くエンドレスの形に変え、敵を1体倒すたびに強化を1つ選ぶ（3択）ようにする。あわせて、倒した数と使ったターン数を主な軸にしたスコアと、途中で閉じても続きから遊べる中断と再開を入れる。続く P8 では強敵と属性を、P9 ではジョーカーとメタ強化（プレイをまたいで残る強化）を足す。

P7 で確かめるのは、「強化しながら何体も倒していくのが楽しいか」である。

* **完了の目安**: ゴール型。次の状態になっている。
  * 負けるまで敵が続く。敵の並びは日付で決まり、同じ日は何度始めても同じ並びになる。
  * 敵を倒すと3択が出て、選んだ強化が次の戦闘から効く。負けると強化は消える。
  * ★1の敵が6種、★2の巨人、★3のドラゴンが出る。
  * 途中で閉じても、タイトルの「再開」から、閉じたターンの始まりに戻って続けられる。
  * 負けたときの結果の画面に、倒した数・スコア・内訳・今日のベスト・自己ベストが出る。
  * 慣れた人の1プレイが、おおよそ20〜30分になる（いまの3体は、ゴブリン約2分・巨人約3分・ドラゴン約5分）。

### 資料との関係
企画の資料は `_doc/バトリティア_アイデアメモ_成長.md`（1章）と `_doc/バトリティア_アイデアメモ_敵.md`（1章）である。この DIR と食い違うところは、この DIR を正とする（主な違い: ジョーカーと最大値の解放は P9 に送った。敵の並びは★で決める）。

## 2. やらないこと（Non-goals）
* ★2・★3の敵の追加（侵略軍・ゴーレム・バジリスク・グリフォン・ヒュドラ・ネクロマンサーなど）、盗賊 → P8
* 属性（火・氷・風・雷・土・水）と、束・山札・手札への新しい妨害 → P8
* 6〜9ステージに★2を混ぜるなど、★の並びの基本ルール（07-02）を広げること → P8
* ジョーカー、ユニークユニット、数字の最大値の解放、ジョーカーの強化 → P9
* メタ強化（通貨、解放、ユニットのレベル、永続の強化）、実績 → P9
* 自動兵士 +2 の超レア、覗き見などソリティアのルールを曲げるスキル → P9 以降
* 戦闘のボーナスを、07-08 の2つ（コンボ・無傷）より増やすこと → 機能バックログ（`_doc/PROJECT_MILESTONE.md`）。増やしやすい作りにはしておく
* 戦闘が長引くと敵が強くなる決まり → 入れない（相談のうえ、疲弊（07-01）に替えた）
* ターンボーナスの下限を 0 より下げること → P7 では 0 で始める。試遊（07-09）で必要なら設定の値を変える
* 他の人と比べるランキング、結果の共有 → 未定
* 見える枚数を2枚にする、「下なら置ける」などの詰まりへの調整 → 未定（試遊の後に考える）
* 敵・兵の構えの絵5枚（`unit_goblin_attack.js` など）を使うこと → 未定
* エンジンへの新しい要望 → 必要になったら、発注者の承認を得て連絡票で頼む（ゲーム側に回避策を書かない）

## 4. サブフェイズごとの実装要件

すべてのサブフェイズに共通:
* 数値（加算量・確率・重み・点・境目のターン数）は、試遊で変えられるよう設定に置く。下に書いた数値は、特に断りがなければ初期値である。
* 遊び方の文章（`js/view/howToText.js`）がルールと食い違うときは、そのサブフェイズで直す。
* 07-03 の後のサブフェイズでゲームの状態を足したときは、中断データにも足す。中断データの形が変わったら、その版番号を上げる。
* 足した値と状態は、`?debug` の DEBUG タブから試せるようにする（下の各節に書いたもの）。デバッグのときは、どの新しい値も保存しない。
* 描く体の数の目安は、敵と兵を合わせて 500 体。超えそうなときは 60fps を保てるか測り直す。

### Phase 07-01: 基本ルールの変更
* **目的**: エンドレスと強化の前に、土台になる戦闘のルールを変える。
* **実装要件**:
  * 4スートそろい: 放った列に4つのスート（金貨を含む）がすべてあると、攻撃・防御・修理・金貨のそれぞれに +1 が足される。1回放つごとに1度だけ。+1 された分が見て分かる。設定で切れる。
  * ゴブリンは、毎ターン、攻撃と防御の両方をランダムな量で行う（いまの、どちらか一方の抽選をやめる）。2つの量の合計は、いまの片方だけの量を目安に弱く始める。
  * 敵の予告に、攻撃と防御の両方の量を同時に出せる。
  * 巨人・ドラゴンの常時防御力（毎回固定のシールド）をやめ、ターンごとにランダムな量のシールドを張るようにする。張らないターンもある。量は予告とシールドの数で見える。
  * 敵の防御（防御の兵とシールド）は、見た目が違うだけで、そのターンだけの防御の量として同じに扱う。ターンをまたいで持ち越さない。
  * 隙: 巨人は攻撃のターン、ドラゴンは吸い込みのターンには、必ず防御 0 になる。
  * ドラゴンの HP を、隙で軽くなった分だけ少し上げる。
  * 疲弊: 1体との戦闘が 21 ターン目に入ると、その敵の防御の量が半分（端数切り捨て）になり、26 ターン目からは防御しなくなる。攻撃・行動の周期・確率は変えない。次の敵には持ち越さない。敵の名前のそばに「疲弊」と出て、予告の防御の量は減った後の数字になる。
  * 盤面の TURN の番号は、その戦闘で何ターン目かを出す（敵が替わると 1 に戻る）。
  * DEBUG タブで、疲弊を試せる（ターンの番号を進める、など）。
* **持ち越し事項**: DEBUG タブのルールの値に、常時防御力の項目とスライダーがある（`_doc/COWORK_STATUS.md` 2章 A）。新しい値に合わせて見直す。シールドの焼き付けの上限（1〜20）とも合わせる。
* **メモ**:
  * いまの TURN の番号が通しの番号かどうかは、REQ 作成時に確認。通しのターン数は 07-08 の総ターン数で使うので、別に数える。
  * 疲弊の始まり（21・26）は、ターンボーナス（07-08）が 0 になる 20 とは別の設定にする。
  * 1ターンに攻撃と防御の両方を予告することは、予告の作り・攻防の出来事・演出のすべてに関わる（`PROJECT_ARCHITECTURE.md` 2章）。量の抽選と乱数の順も、REQ 作成時に決める。
  * 兵の数のスライダーの上限 63（`_doc/COWORK_STATUS.md` 2章 A）は、4スートそろいで変わる分を見直す。
  * REQ 作成時に発注者と決めたこと: 戦闘画面に敵の名前がなかったので、敵の HP ゲージの下に名前（左詰め。いつも）と「疲弊」（右詰め）を出す。防御 0 のターンは予告に防御を出さない。4スートそろいは「4スート +1」の文字と4つの玉。初期値はゴブリン 攻撃1〜3・防御1〜2、巨人 75% で 2〜6、ドラゴン 75% で 3〜7・HP 90。

### Phase 07-02: エンドレスの進行
* **目的**: 3体で終わる形をやめ、負けるまで敵が続くようにする。
* **実装要件**:
  * ドラゴンを倒してもクリアにならず、次のステージへ進む。城の HP・盤面（山札・捨て札・手札・列）・金貨は、いまと同じく次の敵へ引き継ぐ。
  * ゲームの終わりは、城の HP が 0 になったときだけである。
  * 敵の種類ごとに★（1〜3）がある。★1: ゴブリン（と 07-04a・07-04b の敵）、★2: 巨人、★3: ドラゴン。
  * ステージの番号で★が決まる（基本ルール）。10 の倍数は★3、それ以外の 5 の倍数は★2、残りは★1。11 以降も同じ決まりで続く。
  * 同じ★のどの敵が出るかは、ゲームを始めた日付で決まる。同じ日に何度始めても、同じステージには同じ敵が出る。日付が変わると並びが変わる。
  * 戦闘中の行動・予告の量、カードの並びなどは、日付によらず毎回ランダムである。
  * ステージが進むごとに、敵の HP・攻撃・防御に加算がつく。5ステージを1章として、章ごとに1ステージあたりの加算量を設定で変えられる。加算の考え方は次のとおり。
    * HP は、同じ敵なら何ステージ目でも、倒すのにかかるターン数がおおよそ変わらないように、プレイヤーの伸びに合わせる。
    * 防御は控えめに伸ばす。
    * 攻撃は、プレイヤーの守りの伸びを少し上回るように伸ばす。
  * ステージの始まりの表示（STAGE N・敵の名前）が、2桁のステージ番号でも崩れない。
  * 敵の名前は、ふつうの文字で出す（敵ごとの名前のロゴのスプライトをやめる）。
  * 結果の表示に、倒した敵の数が出る（ほかの項目は 07-08 で作り直すまで、いまのままでよい）。クリアの結果は出なくなる。
  * DEBUG タブで、好きなステージに移れる。
* **持ち越し事項**: 動作に影響しない古い説明文が3か所ある（`layout.js` の `topGauges` の「フェーズ」、`debugLayout.js` の「ゴブリンの見出し」、`debugIntents.js` の「予告」）。このサブフェイズで同じファイルを触るなら一緒に直す（07-01）。
* **メモ**:
  * 敵は「行動の決まり・数値・絵・名前・★」の組で持ち、1種を1行足すように増やせる形にする（07-04a・07-04b・P8 で増やす）。
  * 乱数は、日付から作る乱数（敵の並びだけに使う）と、プレイ用の乱数（それ以外すべて）の2本に分ける。ルール層は日付を読まず、種を外から受け取る（憲法 3章）。日付は端末の日付でよい。
  * ルール層の並びの乱数は、ステージの番号から直接求められる形にし、途中のステージへ移っても・再開しても同じ敵になるようにする。
  * 1ステージ目から★の基本ルールに従う。同じ敵・同じ動きを続けない決まりは 07-04a で入れる（この時点では★1がゴブリンだけなので）。
  * いまの3体の通し番号・クリアの演出・BGM の対応表など、3体で終わる前提の所は REQ 作成時に洗い出す。
  * この時点では強化がないので、数値は仮でよい。本調整は 07-09 で行う。
  * REQ 作成時に発注者と決めたこと: HP の加算は元の HP の割合（1章から +5%・+7%・+9%・+12%）、攻撃は +0.5・+0.75・+1・+1.25、防御は +0.25・+0.25・+0.5・+0.5（合計の端数切り捨て）。敵の名前の後ろに「Lv（ステージの番号）」を出す。DEBUG のステージ移動は −5・−1・+1・+5 のボタン。戦闘の記録は、ここでは倒した敵の数だけ数える。

### Phase 07-03: 中断と再開
* **目的**: 途中で閉じても、続きから遊べるようにする。
* **実装要件**:
  * 各ターンの開始時（予告など、そのターンの始まりの抽選がすべて決まった後）に、中断データを上書きで保存する。
  * ブラウザを閉じて開き直すと、中断データがあるときだけ、タイトル画面に「再開」が出る。「再開」には「STAGE 6・TURN 3」のように、どこからかが添えてある。
  * 「再開」を押すと、保存したターンの始まりの演出（TURN N と予告）から続けられる。盤面・手札・捨て札・金貨・城と敵の HP・予告が、保存したときと同じである。
  * 同じ手順で遊べば、同じ札が出て、同じ結果になる（閉じて開き直しても、引き直しにならない）。
  * 「再開」しても中断データは消えない（次のターンの開始時に上書きされる）。再開の直後に閉じても、もう一度「再開」できる。
  * 城の HP が 0 になったとき、中断データは消える。
  * 中断データがあるときに「はじめる」を押すと、確かめずに新しいゲームが始まり、中断データは新しいゲームのもので上書きされる。
  * 音量・演出の速さの設定は、中断データの有無・破棄と関係なく残る。
  * デバッグ（`?debug`）では、中断データを保存せず、「再開」も出さない。
* **持ち越し事項**: 設定の保存の版番号を上げると、設定が全部既定値に戻る（`_doc/COWORK_STATUS.md` 2章 A）。デバッグで保存しない扱いは `settingsStore.js` の `writeValue` と同じにする（同）。始めた日付の種は `Game.seed`（整数。例 20261125）が持ち、「はじめる」のときに `main.js` の `createBoard` が1回だけ読む。敵の並びは種と `stageNumber` だけで求まるので、再開では保存した種を渡せば、始めた日の並びで続く（07-02）。
* **メモ**:
  * 中断データに持つもの（ルールの状態）: 山札・捨て札・手札・列（並びの順も）／城の HP・最大 HP、金貨、残り行動／敵の種類・HP・予告・行動の決まりの状態（数え下ろし・吸い込みなど）／始めた日付、ステージ、ターン、疲弊の進み／（07-05 から）取った強化、3択が出ているときの候補／（07-08 から）スコアと戦闘の記録／プレイ用の乱数の状態／版番号。
  * 持たないもの: バトルに出ているユニット（ターンの始まりには、前のターンの兵はいない。自動兵士は取った強化から出し直す）、玉・兵・エフェクト・演出の途中、カードの動きの位置、設定、最高記録、デバッグの状態。
  * 中断データは、設定とは別の版番号を持つ。版番号が合わないときは、中断データだけを捨てて「再開」を出さない。
  * 日付が変わってから再開したときは、始めた日の敵の並びで続ける。
  * 再開・はじめるの確認の見せ方（窓か、タイトルの中の表示か）は REQ 作成時に決める。
  * REQ 作成時に発注者と決めたこと: 「再開」は「はじめる」の上に大きく出す（Enter・Space も「再開」）。「はじめる」の前の確認は出さない。TURN 1 からの再開は「STAGE N」から、TURN 2 以降は敵が初めから立っていて「TURN N」から始まる。中断データが消えるのは負けの結果が出た時（負けるターンの演出の途中で閉じれば、そのターンからやり直せる）。
  * 乱数の状態を保存できる作りが要る。エンジンに使えるものがあるか（`oz/ENGINE_API.md`）は REQ 作成時に確認。

### Phase 07-04a: ★1の敵の追加（狼・猪・骸骨・スライムと並びの決まり）
* **目的**: ★1の敵に4種を足し、10ステージのうち8ステージを占める★1の顔ぶれを増やす（オーガは 07-04b で足し、★1は6種になる）。
* **実装要件**:
  * ★1の敵は、07-04b までに次の6種になる。「動き」は行動の決まりの組で、1つの動きに2種ずつある。ここでは、オーガのほかの4種を足す。

    | 動き | 標準 | 感じを変えた敵 |
    |---|---|---|
    | 攻防を同時に行う | ゴブリン（群れ。07-01 のもの） | オーガ（群れ） |
    | 溜めて大攻撃。防御しない | 狼（1体） | 猪（1体） |
    | 攻撃か防御のどちらか。防御重視 | 骸骨（群れ） | スライム（1体） |

  * 狼: 毎ターン攻撃し、ときどき溜めて（1ターン前に予告で分かる）次のターンに大攻撃する。動きが速い。
  * 猪: 狼より溜めが長く、溜めの後の一撃が重い。まっすぐ突進する。
  * 骸骨: 攻撃か防御のどちらかを行い、防御が多い。ときどき大きく防御する。攻撃するターンは防御 0（隙）。
  * スライム: 骸骨と同じ動きで、HP が高く攻撃が低い。当たるたびにへこみ、HP が減るほど小さくなる。
  * 同じ敵を続けて出さない。同じ動きの敵も続けて出さない。間に巨人・ドラゴンのステージが入っても、続いているとみなす（★1のステージだけを順に並べたとき、同じ敵・同じ動きが隣り合わない）。
  * ステージ1〜3には、3つの動きが1回ずつ出る（順番は日付で決まる）。
  * DEBUG タブで、★1の5種（ゴブリン・狼・猪・骸骨・スライム）のどれにも切り替えられる。
* **持ち越し事項**: 予告から攻撃の側を消すのは「攻撃の量 0・中の種類なし・防御あり」のとき（`intentParts.js`）で、骸骨・スライムの防御だけのターンで使う。敵の並びは `stageOrder.js` が種とステージの番号から、前のステージを計算せずに求めている。「続けて出さない」「1〜3で動きを1回ずつ」を足すときも、途中のステージから求められる形を保つ。敵を足すと、同じ日付の並びは変わる。行動の決まりを足すときは、`enemyBehaviors.js` の決まりの表に、状態の形の確かめ（`isState`）も足す（中断データの確かめに使う）。予告の形を増やす（攻撃・振りかぶり以外の種類など）ときは、`suspendData.js` の予告の確かめ（`isIntentShape`）と版番号も見直す（07-03）。
* **メモ**:
  * 敵の組に「動きの速さ」を足す。
  * 体のスプライトは、まず手書きの仮を置き、発注者がエディタで描き直して差し替える（憲法 3章。REQ で明示する）。要る絵: 狼・猪・骸骨・スライム。

### Phase 07-06: カードの強化と特別の強化
* **目的**: 札の人数を伸ばす強化と、行動・手札を増やす強化を入れる。
* **実装要件**:
  * カードの強化（重み）: スートを強化（剣・盾・ハンマー・金貨の各 0.5）、数字を強化（1〜7 の各 1）。どれも +1。
    * 強化された札には、数字の右下に「+◯」がオレンジで、数字の約 2/3 の大きさ（数字 24px に対して 16px が目安）で出る。
    * +◯ は、放つ人数（金貨なら貯まる量）に足される。並べるための数字と、束の補正の枚数は変わらない。スートと数字の両方の強化は足し合わせる。
    * 強化は、そのスート・数字のすべての札（山札・手札・列・捨て札のどこにあっても）に効く。
  * カードの強化に、次の2つを足す。どちらも1プレイに3回まで取れ、上限に着いたら出さない。
    * 4スートそろいを強化（0.5）: 4つのゲージそれぞれに足す量が 1 増える（基本の +1 から、3回で +4）。
    * コンボを強化（1）: 束の補正の、1枚ごとに足す量が 1 増え、足す量の上限（いまの +6）も同じ割合で伸びる（強化なしの 5枚 +4 が、1回で +8、3回で +16）。
  * 放ったときの「4スート」と補正の式の表示に、強化後の値が出る。
  * 特別の強化（重み）:
    * アクションポイント（2）: ターンの始まりに発動率で行動 +1。発動率は1回で 5〜10% 増え、上限 50%。行動のゲージの「ACTION POINT」の右に「+1(10%)」のように出し、上限で % がオレンジになる。0% の間は出さない。金貨で増える行動とは別枠である。
    * アクションポイントが上限に着いた後は、代わりに「次の戦闘の間、毎ターン行動 +1」の選択肢が出る。
    * 手札の枠（1。1回だけ）: 手札が2枠になる。
  * 手札が2枠になっても、ほかのカードの大きさは変えない。今の手札の枠1つ分の場所に、手札の枠を 60〜70% に縮めて2つ斜めに重ねる。奥の枠は多少押しにくくてよいが、スマホで両方の札を押せ、文字が読める。
  * 新しい抽選（アクションポイント）は中断データの保存より前に決まり、再開しても同じ結果になる。
* **持ち越し事項**: 手札の枠を増やすと、盤面のカード全体が縮む（`_doc/COWORK_STATUS.md` 2章 A の「Phase 7 へ」）。ここで配置を決める。中断データの確かめは、手札の枠の数を設定（`config.handSize`）と比べている。枠がゲームの状態で増える形にするとき、ここを見直す（07-03）。強化を足すときに書き足す所は `PROJECT_ARCHITECTURE.md` 2章「強化の種類を足すときに書き足す所」にまとまっている（`config.upgrades` に1行・`upgradeText.js` の `UPGRADE_TEXTS` に1行、効き方が新しいときは `upgradeEffects.js` の `UPGRADE_EFFECTS` に1行。DEBUG タブ・「強化」タブ・抽選は一覧から組み立てる）。枠（`config.upgradeSlots`）は城・兵士・カード・特別の4つと重み 1・1・1・0.5 がすでに入っていて、今は城の枠にしか強化がないので、残りは「埋める」で選ばれている。カード・特別の強化を足すと、枠の抽選が初めて効く。上限（「3回まで」「1回だけ」「上限 50%」）は、効き方の表の `canOffer(spec, taken)`（今はいつも真）で止める形になっている。取った強化の状態は種類ごとに `{ count, amount }`（回数と効いた量の合計）で、中断データはこの形を `isUpgradeState` で確かめている（版 3）。「次の戦闘の間、毎ターン行動 +1」のように戦闘ごとに消える状態や、この形に入らない状態を足すときは、状態の形・確かめ・版番号を見直す。選択肢の「取る前 → 後」の値は、効き方の表の `preview` だけが計算する（画面は文字に並べるだけ）。DEBUG タブの兵の数のスライダーは 07-05 で上限 99 にした（`debugTab.js` の `TROOP_SLIDER`）。カードの強化で増える分で見直す。DEBUG の強化の「+1」のボタンの文字は、強化の名前をそのまま使う（最大 HP は「城の最大 HP +1（今 N）」と出るが、1回で +5）。名前に数字が入る強化を足すときは、紛らわしくないか見る（`debugText.js` の `upgradeAddText`）。`soundCues.js`・`bgmCues.js` の「はじめる」の古い説明は、まだ残っている。同じファイルを触るなら一緒に直す（07-05）。
* **メモ**:
  * 重ねた札の見える帯（約 36px）に「+◯」が収まるか、「ACTION POINT」の右の余白が足りるかは、REQ 作成時に確認。
  * 4スートそろいの基本の量は +1 のままにする（+2 からは、作りやすい4スートが、同じスートの補正の上限 +6 を超えるため）。
  * 兵の数の上限（DEBUG タブの 65 など）を、強化で増える分で見直す。

### Phase 07-07: 兵士の強化（精鋭）
* **目的**: 放った兵に、強い兵（精鋭）が混じるようにする。
* **実装要件**:
  * 兵士の強化（重み）: 精鋭の確率（剣・盾・ハンマーの各 2）、精鋭の能力 +1（剣・盾・ハンマーの各 1。その確率が 0% の間は出さない）。
  * 確率はスートごとに持ち、初期 0%、1回で 5〜10%（整数）増え、上限 50%。上限の手前では実際に増える分を選択肢に出し、上限に着いたスートの確率は出さない。9〜10% は選択肢の数字が金色になる。能力は上限なし。
  * 能力の初めの値は +1（取る前でも、精鋭は2ポイント）で、「精鋭の能力 +1」を取るごとに 1 増える。
  * 精鋭は、放った時点で、兵1人ずつ抽選で決まる。対象はカードから出る剣・盾・ハンマーの兵だけ（金貨・自動兵士は対象外。4スートそろいで足された兵は対象）。
  * 精鋭は青い丸で描かれ、1体で 1＋能力 のポイントを持つ。敵に当たると「-2」のように出る。
  * ふつうの兵が先に、精鋭が後に当たる。1回の当たりで、能力の分のポイントを、シールド・敵の守り → 敵の順に使う。盾の精鋭はその分だけ敵兵を止め、ハンマーの精鋭はその分だけ直す。攻防の結果は「合計の引き算」のまま。
  * 数値欄は、精鋭による上振れがあると「△（＋◯）」になる。△ は人数＋上振れでオレンジ、＋◯ は右下に半分の大きさ。攻防中は、どちらも残りに合わせて減る。
  * 精鋭の確率が 0% より大きいスートは、山札の左下の角に「◯20%」（◯は青丸）が出る。能力が +2 以上なら「◯20% +2」。上限で % がオレンジになる。カードがめくれても動かない。
  * 再開しても、精鋭の抽選は同じ結果になる。

### Phase 07-08: スコアと結果の画面
* **目的**: 倒した数と使ったターン数を軸にしたスコアを入れ、結果の画面を作り直す。
* **実装要件**:
  * 敵を倒したとき、その敵の点を次の合計で出し、スコアに足す。負けた敵の分は入らない。

    | 項目 | 点 |
    |---|---|
    | 討伐 | 500 ＋（ステージ番号 − 1）× 20 |
    | 強敵 | ★1: 0、★2: +200、★3: +400 |
    | ターン | 500 − 25 × その戦闘で使ったターン数（倒したターンを含む）。下限 0 |
    | コンボ | その戦闘で、同じスートが5枚以上続いた束を1回でも放っていれば +50 |
    | 無傷 | その戦闘で、城が1度も被害を受けていなければ +25 |

  * コンボは、前の敵の間に積んだ束でも、その戦闘で放てば数える。同じ戦闘で何回放っても +50 である。
  * 無傷は、同じターンに修理で戻しても、被害を受けていれば数えない。
  * 敵を倒した後、3択の前に、「討伐 500／ターン +400／コンボ +50／無傷 +25」のように内訳が出る。取れなかった項目は出さない。

    * 倒した数とスコア（一番大きく）
