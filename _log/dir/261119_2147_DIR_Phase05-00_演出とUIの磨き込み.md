# 設計指針書 DIR: Phase 05 : 演出と UI の磨き込み
* ルール: `./PROJECT_CONSTITUTION.md`
* 開発資料: `./PROJECT_ARCHITECTURE.md`

## 1. 大ゴール
Phase 4 で攻防の段を作り変え、その後の Interrupt で遊び方・BGM・効果音を入れた。他の人に触ってもらえる段階に近づいたので、強化（Phase 6 インゲーム強化、Phase 7 メタ強化）の前に、画面の作りと段取りの流れを整える。

画面は、次のように組み直す。
* ゲージの行と最下段をなくす。
* 画面の最上部に、格闘ゲームのように左右に伸びる城と敵の HP ゲージを置く。その下に金貨のゲージを置く。
* 戦闘の段とソリティアの段の間に、行動のゲージを置く。
* 空いた分だけ盤面を広げる。

段取りの流れも変える。行動を使い切ると「準備終了」が出て、タップで攻防に入る。あわせて、始まりの演出（ステージ・フェーズ・攻防）、カードのデザイン、手触りの小さな直しを入れる。

* **完了の目安**: ゴール型。タイトルからクリアまたは負けまで通しで遊んだとき、次の状態になっている。
  * ゲージの行・最下段・「行動終了」・早送り・スキップのボタンがない。
  * 城と敵の HP、金貨、行動の残りが、新しいゲージで読める。
  * 行動を使い切ると「準備終了」が出て、タップで攻防に入る。
  * ステージ・フェーズ・攻防の始まりが演出で分かる。
  * カードが発注者の調整したスプライトで描かれている。

## 2. やらないこと（Non-goals）
* ルールの変更 → しない。例外として、段取りを途中で終える操作（いまの「行動終了」ボタン）をなくし、行動を使い切ると必ず攻防に入る形にする（発注者の決定。05-03）。数値（敵・城・束の補正・金貨の効き方）は変えない
* 早送り・スキップの操作 → ボタンを置かない（発注者が試遊で使わなかったため）。演出の途中・決着のどの時点でも、ルールの結果は変わらない（憲法 3章）
* デバッグモード → この Phase では作らない。兵が数百体のときの重さは、P5 の後に、発注者がキャンバスキャッシュ入りのエンジンに載せ替えて計測する（送り先は計測の結果を見て決める）
* タイトル画面の作り直し → 未定（`_doc/PROJECT_MILESTONE.md` に残す）
* 兵と敵の手足（丸い体に浮いた手と足）→ 未定（同上）
* 遊び方の図 → 未定（同上）。遊び方の文章のうち、画面の作りや操作が変わる所は、この Phase で直す（05-03 のメモ）
* 残りの仮の効果音の差し替え、起動時の音のロードの間の表示 → 未定（同上）
* スキルの置き場所（いままで最下段の左を空けていた）→ Phase 6 で改めて考える。最下段はなくす
* インゲーム強化・メタ強化 → Phase 6・Phase 7

## 4. サブフェイズごとの実装要件

### Phase 05-01: 画面の組み直し
* **目的**: ゲージの行と最下段をなくし、HP・金貨・行動の残りを新しいゲージで見せ、空いた分だけ盤面を広げる。
* **実装要件**:
  * ゲージの行（攻撃・防御・修理・金貨の数字）がない。攻撃・防御・修理の量は、戦闘の段の兵と人数の表示で読む。
  * 画面の最上部に、城と敵の HP ゲージがある。
    * 城のゲージは画面の中央から左へ、敵のゲージは右へ伸びる（格闘ゲームの体力ゲージの形）。
    * ゲージの左右の両端に、HP の数字が出る。
    * HP が減ると、攻防の演出に合わせてゲージが縮み、数字が減る。
  * HP ゲージの中央に、1行目に半角で「PHASE」、その下にフェーズの番号が出る。どちらも中央にそろえる。
  * HP ゲージの下に、金貨のゲージがある。
    * ゲージの基本の長さは金貨 10（次のフェーズの行動 +2 の分）。
    * 10 を超えた分は、ゲージの上に別の色で重ねて描く。ゲージの下に赤いバッジが付き、ゲージ何本分あるかを示す。
    * 金貨の玉は、このゲージへ飛ぶ。
  * 戦闘の段とソリティアの段の間に、行動のゲージがある。
    * ゲージは5つに区切ったブロックで、残りの行動の数だけ埋まっている。行動するたびに1つ減る。
    * 金貨で増えた行動（5 を超える分）は、別の色で上書きして見せる。
  * 最下段（「行動終了」ボタン、早送り・スキップのボタンの段）がない。
  * ゲージの行と最下段が空けた高さは、盤面（列）に回っている。長い列が今より見やすい。
  * スマホの縦画面で、どのゲージの数字も読める。PC でも同じように遊べる。
* **持ち越し事項**:
  * `js/view/hudView.js` の `drawHud` の使っていない引数 `outOfActions`（`_doc/COWORK_STATUS.md` 2章 A）。最下段と一緒になくなるなら片付けとして閉じる。
  * `_doc/PROJECT_MILESTONE.md` の「演出と手触り」の「演出中の最下段の色（`BATTLE_PANEL_FILL`）が盤面の背景とわずかに違って見えうる」。最下段がなくなれば閉じる。
  * 手札の枠を増やすと盤面のカードが縮む件（`_doc/COWORK_STATUS.md` 2章 A。Phase 6 へ）。盤面の高さが変わるので、P6 で見直すときの前提として記録を直す。
* **メモ**:
  * 段取りを終える操作は、05-03 で「行動を使い切ると準備終了」の形にする。05-01 の時点では、行動を使い切ったら今のまま攻防に入ってよい（「行動終了」ボタンをなくしても通しで遊べるようにする）。
  * 早送り・スキップの操作は、ボタンをなくす。キーボードの操作を残すかどうかは REQ 作成時に決める。
  * REQ 作成時に確認・決定すること。
    * 最上部の高さ、HP ゲージの長さの比率（城と敵で最大 HP が違う）、色。
    * 金貨のバッジの数え方（「10 ごとに1本」など）と、上書きの色。
    * 行動のゲージの高さと、戦闘の段・盤面との境目の見せ方。
    * 戦闘の段にいま描いている城・敵の HP の表示とフェーズの枠を消すこと。05-04 で戦闘の段の表示を整えるので、ここでは消すだけでよい。
  * 画面の配置が変わるので、遊び方の文章のうち画面の説明（ゲージの行・「行動終了」など）は、05-03 の流れの変更と合わせて直す（05-03 のメモ）。
  * **完了（261120）**: REQ `_log/req/261119_2253_Phase05-01_画面の組み直し.md`、RES `_log/res/261119_2253_RES_Phase05-01_画面の組み直し.md`（TASK1〜12、最終コミット ad6f752。テストプレイ OK）。
    * REQ で決めたこと: 最上部のゲージは戦闘の段の空（上 60px）に重ねる。HP ゲージは太さ 20px・左右同じ長さで、減ると外側の端から中央へ縮む。HP の数字はゲージの外側の端の上に縁取りで出す。金貨のゲージは城の HP ゲージの下（同じ範囲・同じ向き、太さ 10px）で、満タンは `per × maxBonus`（10）。10 以上は満タンの上に余りを別の色で重ね、10 ごとに赤い丸のバッジを1つ（数字なし）。行動のゲージは戦闘の段とソリティアの段の間の高さ 36px の帯に5ブロック、金貨で増えた分は左のブロックから金貨の色。人数の表示は段取りの間も出す。行動を使い切ったら、札・玉・兵が全部着いてから間を置かずに自動で攻防に入る（05-03 で「準備終了」に替える）。早送り・スキップのキー操作は残さない。

### Phase 05-02: カードのデザインと動き
* **目的**: カードの表の枠と裏の模様をスプライトにし、カードの動きの粗い所を直す。
* **実装要件**:
  * カードの表の枠と裏の模様が、`assets/sprites/` のスプライトで描かれている。表の数字とスートの絵は、今と同じく枠の上に重ねて描く。
  * 作り方は次の順にする。
    1. 実装側で、今の見た目をもとに仮のスプライト JS を書き出す（OZ Vector Editor で読み込んで調整できる形）。
    2. 発注者がエディタで調整し、書き出したファイルを同じ名前で差し替える。
    3. 差し替えた後も、ゲーム側のコードを変えずに描ける。
  * 長い列の詰め直しで、もとからあるカードも滑らかに動いて移る（今は一瞬で移る）。
  * 山札のめくれが、カードが山札を離れるのと同時ではなく、自然な時刻に始まる（具体は REQ で決める）。
* **持ち越し事項**: `_doc/PROJECT_MILESTONE.md` の「演出と手触り」のカードの動きの3件（詰め直し・めくれの時刻・カードの裏の色と模様は仮）。ここで扱う。

### Phase 05-03: 準備終了と始まりの演出
* **目的**: 段取りの終わり方を「行動を使い切ると準備終了」に変え、ステージ・フェーズ・攻防の始まりを演出で見せる。
* **実装要件**:
  * 段取りを途中で終える操作はない。行動（金貨で増えた分を含む）を使い切ると、画面の中央に「準備終了」のロゴが出る。
  * 「準備終了」が出ている間に画面のどこかをタップ（PC ではクリック）すると、攻防が始まる。
  * 攻防に入る瞬間に、攻防の始まりの合図（例: 「BATTLE!」）が出る。
  * 最後の行動が「放つ」で、玉と兵がまだ動いている間は、全部が着いてから「準備終了」が出る。または、出ていても、全部が着いてから攻防が始まる。
  * フェーズの始まりに、フェーズの番号と、その敵の次の行動の予告が目立って出る。
  * ステージ（敵）が替わるときに、新しい敵の名前と登場が見える。ゲームの最初のステージ（ゴブリン）も同じ。
  * 始まりの演出の間に、ルールの結果は変わらない。演出は短く、繰り返し見ても待たされない長さにする。
  * 遊び方の文章が、新しい画面の作り（05-01）と流れ（行動を使い切ると準備終了、タップで攻防）に合っている。
* **持ち越し事項**:
  * 遊び方の文章は `js/view/howToText.js` の1か所にあり、数字は `js/rules/config.js` の値を文字で書いたもの（`_doc/COWORK_STATUS.md` 2章 A）。
  * `_doc/PROJECT_MILESTONE.md` の「演出と手触り」の「玉が飛んでいる間に『行動終了』を押しても、押した時点では見た目も音も変わらない」。「行動終了」がなくなるので、上の「準備終了」の出し方で閉じる。
  * BGM の鳴り始め・止まる時刻（`_doc/COWORK_STATUS.md` 2章 A。ステージの曲はステージの始まりで鳴る）と、ステージ開始の演出の時刻を合わせる。

### Phase 05-04: 戦闘の段の表示
* **目的**: 戦闘の段に残る表示（敵の予告・数え下ろし・兵の人数）を、背景・兵・敵と重ならず、スマホで読める形に整える。

  * 巨人の数え下ろし（「攻撃まで あとN」）が、敵の予告と同じ場所の近くで読める。
  * 兵の人数の表示（攻撃・防御・修理）が、背景・兵と重ならず読める。
