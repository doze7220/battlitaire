# 設計指針書 DIR: Phase 02 : 縦画面と攻防の演出
* ルール: `./PROJECT_CONSTITUTION.md`
* 開発資料: `./PROJECT_ARCHITECTURE.md`

## 1. 大ゴール
画面を横長（1280×720）から縦長（720×1280）に組み直し、スマホを優先して配置を決めたうえで PC でも遊べるようにする。そのうえで、攻防の演出（兵の群れ、城、早送り・スキップ）、カードの動き、音を足し、結果の窓の文字だけで見せている攻防を、見て分かるものにする。演出の配置は画面の縦横で大きく変わるため、縦化を演出より先に行う。
* **完了の目安**: ゴール型。縦画面で、スマホと PC のどちらでもタップ（クリック）だけで遊べる。攻防が兵の動きで見え、早送り・スキップができる。カードの移動・めくれと効果音がある。

## 2. やらないこと（Non-goals）
* 束の移し替えのバランス（同じスートを別の列で作ってからつなぐと数が大きくなりやすい）の変更 → 変えない。数値が大きくなる分は、敵の HP・攻撃・防御で調整する（Phase 3）
* 敵の HP・攻撃・防御の数値の調整、敵の種類・特殊行動、撃退数のスコア → Phase 3
* アウトゲーム成長（ステータス、スキル、保存）、手札の枠を増やすこと → Phase 4
* ルールの調整候補（見える枚数を2枚にする、「下なら置ける」、捨てるときの得、余った攻撃・防御の扱い、倍率の強さ）→ 未定
* タイトル画面・結果の画面の作り込み、プレイ中のメニュー → 未定
* 音楽（BGM）→ 未定
* 連鎖の SE の音程の上昇（02-04 の実装要件2）→ エンジン待ち。OZ Engine の連絡票 `D:\ozlab\ozengine-web\_doc\BRIDGE_FROM_BATTLITAIRE.md`（2026-11-13）で音程の指定が入ったら、Interrupt で `js/scenes/soundCues.js` の `playChainSe(ordinal)` に足す

## 4. サブフェイズごとの実装要件

### Phase 02-01: 縦画面への組み直し
* **目的**: 画面を縦長（論理解像度 720×1280）にし、上から「戦闘」「ソリティア」「UI」の3段に配置し直す。
* **実装要件**:
  * 起動すると、画面が縦長（720×1280）で表示される。ブラウザの窓に、縦横比を保って収まる最大の大きさで出る（スマホで上下に帯が出てよい）。
  * 画面は上から3段に分かれる。
    * 最上段（戦闘）: サイドビューで、左に自分の城、右に敵が描かれる。城の HP（現在値／最大値）、敵の HP、敵の次の行動の予告（例: 攻撃10）が表示される。
    * 中段（ソリティア）: 一番上にゲージ4つ（攻撃・防御・回復・力こぶ）が横1行で並び、その下に山札4つ、捨て札、手札、列4本と、列ごとの「放つ」の操作が表示される。
    * 最下段（UI）: 「行動終了」のボタンと、残りの行動回数が表示される。
  * 最上段の高さは、配置の値1つを書き換えるだけで変えられ、ソリティアと UI の位置はそれに合わせて決まる（値を変えても段が重ならず、画面からはみ出さない範囲で）。
  * 押せるもの（山札、列のカード、手札の枠、放つ、行動終了、結果の窓を進める操作）は、論理解像度でおよそ 80px 以上の大きさがあり、指で押せる。
  * ホバーに頼らず、タップ（クリック）だけで、これまでの操作（めくる・置く・捨てる・放つ・手札に入れる／置く・束の移し替え・行動終了・結果の窓を進める）がすべてできる。
  * 結果の窓とタイトルの画面（「TAP SCREEN」）が、縦画面に収まって表示される。
  * 列が長くなっても、ソリティアの段の中に収まる（いまの長い列の詰めを、縦画面の段の高さに合わせる）。
  * PC のブラウザでも、縦画面のまま遊べ、表示が崩れない。
* **持ち越し事項**: なし
* **メモ**:
  * 解像度は `js/main.js` の値を変えるだけで切り替わる。配置の数値は主に `js/view/layout.js` にあり、ほかに `js/view/resultLayout.js`（結果の窓）、`js/scenes/MenuScene.js`、`js/ui/virtualPadConfig.js`（1280×720 前提のコメント。パッドは使っていない）が影響を受ける。
  * 戦闘の段では、配置と HP などの表示までを行う。城・敵の絵は仮の図形でよい。兵の動きは 02-03 で扱う。
  * 最上段の高さの初期値は REQ 作成時に決め、作ってから試遊して決め直す。フェーズ番号をどの段に置くかも REQ 作成時に決める。
  * 720×1280 は 9:16。最近のスマホはこれより縦長なので上下に帯が出る。解像度は、実機で見てから決め直す（このサブフェイズの試遊で判断してよい）。

### Phase 02-02: カードの動き
* **目的**: 段取りの操作の結果を、カードの動きで見せる。
* **実装要件**:
  * 山札からめくったカードが、置いた列・手札・捨て札へ動いて見える。
  * 手札から列へ置いたカード、束の移し替えで移した束が、元の位置から先の位置へ動いて見える。
  * 放った列のカードが、捨て札へ動いて見え、ゲージの数字が増えていくのが見える。
  * 動いている間も、ゲームの結果は変わらない（動きはルール層の操作の結果を見せるだけ）。
* **持ち越し事項**: なし
* **メモ**:
  * 要件の細部（めくれの見せ方、動きの速さ、動いている間に次の操作を受けるか）は、02-01 の完了後に REQ 作成時に決める。
  * 演出は `js/anim/` に置く（`PROJECT_ARCHITECTURE.md` 4章。まだフォルダはない）。

### Phase 02-03: 攻防の演出
* **目的**: 攻防の出来事の並びを、戦闘の段での兵の動きで見せ、結果の窓の文字だけの表示を置き換える。
* **実装要件**:
  * 「行動終了」を押すと、戦闘の段で、守備兵が並ぶ → 敵兵と相殺 → 城へのダメージ → 自軍の突撃 → 敵へのダメージ（敵の防御での相殺を含む）→ 大工の修理、が出来事の並びの順に見える。
  * 数が多いときは、大きなユニット1体を10人分（換算は REQ で決める）として描き、画面が兵で埋まらない。
  * 早送りとスキップの操作がある。早送りは動きが速くなり、スキップは最後の状態にすぐ移る。どちらでも結果は変わらない。
  * 演出が終わると、次のフェーズへ進む。決着したら、勝ち・負けが表示され、操作でタイトルへ戻れる。
* **持ち越し事項**: 02-02 の申し送り。カードの動きの時計は `update(dt)` の `dt` を足して進むので、`Engine.timeScale` を変えるとカードの動きも一緒に速くなる（`_log/res/261111_2313_RES_Phase02-02_カードの動き.md` 5章）。
* **メモ**:
  * 要件の細部（結果の窓を残すか・置き換えるか、兵の絵、早送り・スキップのボタンの位置）は、02-01・02-02 の完了後に REQ 作成時に決める。
  * 早送りは `Engine.timeScale`、スキップは出来事の残りを飛ばして最後の状態を見せる（`PROJECT_ARCHITECTURE.md` 3章）。

### Phase 02-04: 効果音
* **目的**: 段取りと攻防の操作・出来事に効果音を付ける。
* **実装要件**:
  * めくる・置く・捨てる・放つ・行動終了と、攻防の出来事（相殺、ダメージ、修理、決着）で効果音が鳴る。
  * 同じスートの束を放ったとき、連続の枚数が増えるほど音程の上がる効果音が鳴る。
* **持ち越し事項**: `_doc/COWORK_STATUS.md` 2-A の「SE の音程（再生速度）を指定できない」。連鎖で音程が上がる SE を、音程違いのファイルで済ませるか、OZ Engine へ連絡票を出すかを判断する。
* **メモ**:
  * 音のファイルの用意の仕方（発注者が用意する、仮の音を使う）は REQ 作成時に決める。
