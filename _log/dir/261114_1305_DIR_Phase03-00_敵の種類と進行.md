## 1. 大ゴール
いまは敵1体（種類なし）を倒すか城が落ちるかで決着する。これを、ゴブリンの軍勢 → 巨人 → ドラゴンの3体と順に戦い、ドラゴンを倒すとゲームクリアになる進行に作り変える。敵ごとに常時防御力と行動の決まり（ゴブリンは毎フェーズの攻撃と時々の防御、巨人は数え下ろしつきの周期攻撃と回復、ドラゴンは爪とブレスチャージ・ブレスで札を燃やす）を持たせ、ゲームに始まりと終わり（タイトルと結果の画面）を付ける。Phase 4（アウトゲーム成長）の前に、1回のゲームの遊びの形を固める。
* **完了の目安**: ゴール型。タイトルから始めて、3体と順に戦い、ドラゴンを倒してクリアするか、城の HP が 0 になって負けるまで遊べる。結果の画面に、かかったフェーズ数・敵に与えた総ダメージ・城が受けた総ダメージ・回復の合計が出る。敵ごとの行動の違いが、予告・数え下ろし・チャージの表示で分かる。

## 2. やらないこと（Non-goals）
* 撃退数のスコア → 作らない（ゴールがゲームクリアになったため）
* 敵と敵の間の成長（カードを足す・抜く・数字を上げる）と特殊カード（残り物、作り置き）→ 未定（`_doc/PROJECT_MILESTONE.md` の「敵と進行」に残す）
* 特殊行動（毒・硬い殻・呪いカード・山札の封じ・山札のシャッフルし直し・力溜め）→ 未定（同上）
* 敵の絵（スプライト）と、敵ごとの演出の変化（ゴブリンの兵が減って見える、など）→ Phase 5（敵の絵。`_doc/PROJECT_MILESTONE.md` に足した）
* 最高記録の保存（`Storage`）→ Phase 4（アウトゲーム成長の保存と一緒に作る）
* アウトゲーム成長（ステータス、スキル）、手札の枠を増やすこと → Phase 4
* ルールの調整候補（見える枚数を2枚にする、「下なら置ける」、捨てるときの得、余った攻撃・防御の扱い、倍率の強さ）→ 未定
* プレイ中のメニュー → 未定
* 音楽（BGM）→ 未定（タイトル画面（TITLE）で鳴らす想定。03-04 で BOOT と TITLE のシーンを分けておく）

## 4. サブフェイズごとの実装要件

### Phase 03-01: 敵の入れ替わりと進行
* **目的**: 敵に種類と常時防御力を持たせ、敵を倒すと次の敵が出て、最後の敵を倒すとゲームクリアになる進行を作る。最初の敵としてゴブリンの軍勢を入れる。
* **実装要件**:
  * 敵は種類ごとに、名前・最大 HP・常時防御力・行動の決まりを持ち、これらの値はルール層の設定のファイル（`js/rules/config.js`）にまとまっている。
  * 敵の防御はフェーズごとの壁として働く（そのフェーズの攻撃の合計から引き、残りが敵へのダメージになる。いまのルールと同じ）。壁の量は「常時防御力」に、そのフェーズに防御のスタンスを取っていればスタンスの量を足したものになる。常時防御力が 0 でない敵では、防御のスタンスを取らないフェーズでも攻撃が常時防御力の分だけ減る。
  * 敵の順番は ゴブリンの軍勢 → 巨人 → ドラゴン で固定。敵の HP を 0 にすると、次のフェーズから次の敵と戦う。戦闘の段に、いま戦っている敵の名前と HP が出る。
  * 敵が替わっても、城の HP と盤面（列・山札・捨て札・手札、ゲージはいまのフェーズの進み方どおり）はそのまま引き継ぐ。
  * 最後の敵（ドラゴン）の HP を 0 にするとゲームクリア、城の HP が 0 になるとゲームオーバーとして決着する。決着の表示はいまの勝ち・負けの表示を使ってよい（結果の画面は 03-04）。
  * ゴブリンの軍勢: 常時防御力 0。基本は毎フェーズ攻撃を予告し、ときどき防御のスタンスを予告する。戦闘の段の敵の位置に、小さな兵の群れが最初から並んで見える（色替えの仮の図形でよい。兵の数は HP と連動させない）。
  * 巨人・ドラゴンは、03-02・03-03 で作るまでの間、ゲームが最後まで通しで遊べる仮の行動（例: いまの攻撃・防御の予告）と仮の図形で出てよい。
* **持ち越し事項**: なし
* **メモ**:
  * 次の敵が出るときの見せ方（名前を一時的に出す、など）は REQ 作成時に決める。
  * 攻防の出来事の並び・演出は、常時防御力による相殺を「敵の防御で相殺」と同じ見せ方にしてよい。分けるかは REQ 作成時に決める。
  * 巨人の数え下ろし、ドラゴンのチャージ、ブレスで札を燃やすことなど、敵ごとに状態を持つ仕組みが 03-02・03-03 で必要になる。敵の行動の決まりの持たせ方は、それらを足せる形にしておく。
  * 03-04 の結果の画面で使う集計（かかったフェーズ数、敵に与えた総ダメージ、城が受けた総ダメージ、回復の合計）を、ここでルール層に持たせるか 03-04 で足すかは REQ 作成時に決める。

### Phase 03-02: 巨人
* **目的**: 2体目の敵として、周期で攻撃し、まれに回復する巨人を入れる。
* **実装要件**:
  * 巨人は常時防御力 8 を持つ。
  * 巨人は決まった数のフェーズごとに1回攻撃する（周期の長さは設定値。ランダムにしない）。攻撃しないフェーズは「振りかぶり」で、敵の行動はしない（攻撃も防御のスタンスも取らない。常時防御力は働く）。
  * 戦闘の段に、攻撃までの残りフェーズ数（数え下ろし）が常に表示される。攻撃するフェーズの1つ前には、いつもどおり攻撃が予告される。
  * 攻撃した直後に、低い確率（設定値）で巨人が HP を回復する。回復したことが戦闘の段で分かる。回復の後は、また振りかぶりから数え下ろしを始める。
  * 戦闘の段の巨人は、大きな緑の玉（仮の図形）で描かれる。
* **持ち越し事項**: なし
* **メモ**:
  * 回復の量、回復をフェーズのどの時点で見せるか（攻防の演出の段として見せるか）は REQ 作成時に決める。
  * 巨人が出た最初のフェーズの数え下ろしの初期値は REQ 作成時に決める。

### Phase 03-03: ドラゴン
* **目的**: 3体目（最後）の敵として、爪攻撃でブレスチャージを溜め、ブレスで盤面の札を燃やすドラゴンを入れる。
* **実装要件**:
  * ドラゴンは常時防御力 15 を持つ。
  * 攻撃は2種類。爪攻撃は攻撃力が低く、1回ごとにブレスチャージが 1 溜まる。ブレス攻撃は攻撃力が高い。
  * ブレスチャージが戦闘の段に「1/4」のような形（溜まった数／満ちる数）で表示される。満ちる数は設定値。
  * チャージが満ちると、以後毎フェーズ一定の確率（設定値）でブレスを予告し、予告しなければ爪攻撃を予告する（チャージは満ちたまま増えない）。ブレスを撃つとチャージは 0 に戻る。ブレスもほかの行動と同じく1フェーズ前に予告される。
  * ブレスは城へのダメージに加えて、盤面の札を 4〜6 枚（範囲は設定値）燃やす。1枚ごとに、ランダムに選んだ列の一番上（上に乗っている側）の1枚を燃やし、これを枚数分くり返す（同じ列が続けて選ばれてよい）。燃えた札はすぐ捨て札へ移る。列の途中の札は燃えない。空の列が選ばれたときの扱いは REQ で決める。
  * 札が燃えたことと、どの札が捨て札へ移ったかが、見て分かる。
  * 戦闘の段のドラゴンは、大きな赤い玉（仮の図形）で描かれる。
* **持ち越し事項**: なし
* **メモ**:
  * 燃やすのは列の札だけとする（山札・手札・捨て札は燃やさない）。見せ方（燃える演出、攻防の演出のどこで燃やすか）は REQ 作成時に決める。
  * 燃やす札の選び方はルール層で、外から渡された乱数で決める（`PROJECT_ARCHITECTURE.md` 4章）。

### Phase 03-04: タイトルと結果の画面
* **目的**: ゲームの始まりにタイトル画面を、終わりに結果の画面を置く。
* **実装要件**:
  * 起動すると、いまの「TAP SCREEN」の画面（BOOT）が出る。BOOT は最初の入力を受けて音を鳴らせるようにする役目だけを持ち、タップするとタイトル画面（TITLE）へ進む。
  * タイトル画面（TITLE）は BOOT とは別のシーンで、ゲーム名と、ゲームを始める操作がある。始める操作で盤面へ進む。
  * ゲームクリアとゲームオーバーのとき、結果の画面に、クリアか負けかと、かかったフェーズ数、敵に与えた総ダメージ、城が受けた総ダメージ、回復の合計が出る。
  * 結果の画面からタイトル画面（TITLE）へ戻り、新しいゲームを始められる。BOOT へは戻らない。
* **持ち越し事項**: なし
* **メモ**:
  * 結果の画面を別のシーンにするか、戦闘の段の決着の表示を広げるかは REQ 作成時に決める。
  * 総ダメージの数え方（敵の HP を超えた分を含めるか、防御で減った後の量か）、回復の合計の数え方（最大 HP で頭打ちになった分を含めるか）は REQ 作成時に決める。
  * 最高記録の保存は作らない（Phase 4）。
  * BOOT と TITLE を分けるのは、後でタイトル画面で BGM を鳴らすため（BGM は音を鳴らせるようになった後の TITLE から鳴らす）。BGM そのものはこの Phase では入れない。

### Phase 03-05: 試遊と調整
* **目的**: 通しで遊び、敵の HP・攻撃・防御・確率・周期などの仮の値を調整する。
* **実装要件**:
  * 発注者の試遊を受けて、`js/rules/config.js` の敵の数値（HP・常時防御力・攻撃・防御のスタンスの量・重み・巨人の周期と回復の確率・ブレスの攻撃力と確率とチャージ・燃やす枚数）と城の HP を調整する。
  * 調整後の値で、タイトルからクリア・ゲームオーバーまで通しで遊べる。
* **持ち越し事項**: なし
* **メモ**:
  * 大きな数字が作りやすいゲームなので、カードのルール（倍率など）は変えず、敵の HP・攻撃・防御で合わせる。
  * 試遊の中で出たルールや演出の要望は、小さいものはここで扱い、大きいものは `_doc/PROJECT_MILESTONE.md` に送る。
