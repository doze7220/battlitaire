# RES: 作業計画・作業レポート (Phase 03-05) : 試遊と調整
* 参照元REQ: `./_log/req/261114_2022_Phase03-05_試遊と調整.md`

## 1. 作業目的
発注者の試遊で、ドラゴンのブレス（チャージ 4・ダメージ 35）は「札が燃える」効果が強く、プレイの感触を大きく変えると分かった。ドラゴンのブレスチャージをなくし、「吸い込む」（巨人の振りかぶりが1回だけになったもの。行動しない・量 0）を挟んでからブレスを撃つ決まりに作り変え、ブレスの攻撃力を 25 に下げる。ブレスチャージの表示と、それを演出の時刻に合わせて切り替える仕組みは消す。ゴブリンの軍勢・巨人・城の数値と挙動、段取り・攻防の演出・音・画面の流れは変えない。

## 2. アーキテクチャ設計
### 要件1: ドラゴンの行動の決まり（爪・吸い込む・ブレス）
*   **決まりの種類**: `js/rules/enemyBehaviors.js` の表（`BEHAVIORS`）から `charge` を消し、新しい種類 `inhale`（吸い込んでからブレス）を足す。`weighted`・`cycle` の中身（`initialState`・`planNext`・`countdown`）は変えない。
*   **行動の表し方（新しい行動の種類は足さない）**:
    *   爪: `{ kind: 'attack', amount: claw.amount, variant: 'claw' }`（攻撃以外の効果なし。いまと同じ形）
    *   吸い込む: `{ kind: 'windup', amount: 0, variant: 'inhale' }`。種類は巨人の振りかぶりと同じ `windup` のままにし、`battle.js` の振りかぶりの扱い（行動しない・量 0・出来事 `enemyWindup`・演出の段を作らない）をそのまま通す。表示の違いだけを任意の項目 `variant: 'inhale'` で表す。
    *   ブレス: `{ kind: 'attack', amount: breath.amount, variant: 'breath', burn: breath.burn }`（いまと同じ形。燃やす効果は `burn` から `cardBurn.js` が読む。燃やし方は変えない）
*   **決まりの状態**: `{ lastVariant: null|'claw'|'inhale'|'breath' }`（直前に予告した行動の `variant`。初期値 `null`）。巨人の `cycle` と同じく、予告（`planNext`）の時点で次の状態を返す。
*   **次の行動の決め方（`planNext`）**:
    *   `lastVariant === 'inhale'` → ブレス（乱数を使わない）
    *   `lastVariant === 'breath'` → 爪（乱数を使わない）
    *   それ以外（`null`＝ドラゴンが出た最初のフェーズ・`'claw'`）→ `random() < behavior.inhaleChance` なら吸い込む、そうでなければ爪（乱数1回）
    *   返す状態は `{ lastVariant: action.variant }`。
*   **数え下ろし**: `inhale` の `countdown` は `() => null`（数え下ろしを持たない）。
*   **使われなくなるものの片付け**:
    *   表の `charge` の問い合わせ（全種類の `charge` の項目）と、公開関数 `behaviorCharge` を消す。
    *   表の `settle`（行動の攻防の後の状態）は、03-03 でチャージを溜めるためだけに足したもので、`inhale` は予告の時点で状態を進めるため、すべての種類で恒等になる。よって全種類の `settle` の項目、公開関数 `settleBehaviorAction`、`Game.resolveBattle()` の呼び出しを消す。
    *   `Game.enemyCharge()`、`BattleResult.enemyCharge`、`Game.js` の `behaviorCharge`・`settleBehaviorAction` の import を消す。
*   **設定（`js/rules/config.js`）**: ドラゴンの `behavior` を次にする。チャージの設定（`chargeMax`・`breathChance`）は消す。
    ```
    behavior: Object.freeze({
      type: 'inhale',
      claw: Object.freeze({ amount: 10 }),
      breath: Object.freeze({ amount: 25, burn: Object.freeze({ min: 4, max: 6 }) }),
      inhaleChance: 0.3,
    }),
    ```
    ドラゴンの `maxHp: 120`・`armor: 15` は変えない。型定義 `ChargeStrikeSpec`・`ChargeBreathSpec` は `ClawSpec`・`BreathSpec` に名前を変え、`EnemyBehaviorSpec` の `type` に `'inhale'` を足して `'charge'` を消し、`chargeMax`・`breathChance` を `inhaleChance` に置き換える。
*   `battle.js`・`Game.js` は敵の種類で分岐しない（`Game.js` は決まりを呼び分けるだけ。`battle.js` は変更しない）。乱数は `Game` の `random` だけを使う。

### 要件2: 表示
*   **予告の文字（`js/view/battleText.js`）**: `VARIANT_LABELS` に `inhale: '吸い込む'` を足す。`enemyActionText` は variant の表示名を先に引き、`windup` は `AMOUNTLESS_KINDS` なので量を出さず「吸い込む」になる（ロジックは変えない）。爪は「爪 10」、ブレスは「ブレス 25」。`VARIANT_LABELS` の JSDoc の「攻撃の中の種類」は「行動の中の種類」に直す。`chargeText` を消す。
*   **予告の枠の目立たせ方（`js/view/battleStageView.js`）**: `EMPHASIZED_VARIANTS`（`breath`）はそのまま。吸い込むは通常の見た目。
*   **チャージの表示を消す**: `drawBattleStage` の引数 `charge` と、数え下ろしがないときにチャージを描く分岐、`chargeText` の import を消す。数え下ろしの枠は、数え下ろしを持つ敵（巨人）のときだけ描く（いまどおり）。呼び出し元の `js/view/boardView.js`（`charge: game.enemyCharge()`）と `js/view/battleShowView.js`（`charge: look.enemyCharge` と `look` の型）からも消す。
*   **演出の時刻でチャージを切り替える仕組みを消す（`js/anim/`）**:
    *   `battleSteps.js`: `BattleSnapshot.enemyCharge` と `snapshotBattle` の `enemyCharge` を消す。
    *   `battleTimeline.js`: `BattleTimeline.enemyStrikeTime`、組み立て中の状態 `castleStrikeTime`・`enemyFrontEnd`（どちらも `enemyStrikeTime` を作るためだけに使われている）と、その記録の箇所（城への当たりで時刻を入れる行とそのコメント、`enemyMarch`・`block` の段の終わりを入れる行）を消す。
    *   `battleDirector.js`: `BattleLook.enemyCharge` と `view()` の `enemyCharge` の計算・返り値を消す。
*   **配置（`js/view/layout.js`）**: 枠の位置・大きさは変えない。先頭の責務定義の「数え下ろしの枠（ブレスチャージも同じ枠）」を「数え下ろしの枠」に直す（コメントだけの変更）。

## 5. 懸念事項・要確認ポイント
* 計画時点の判断（吸い込むの表し方）: 新しい行動の種類を足さず、`kind: 'windup'`（量 0）に任意の `variant: 'inhale'` を付ける。`battle.js` の振りかぶりの扱い（出来事 `enemyWindup`、演出の段なし）をそのまま通すので、`battle.js`・演出は変更しない。予告の文字は `battleText.js` の `VARIANT_LABELS` に足すだけで「吸い込む」（量なし）になる。
* 計画時点の判断（決まりの種類）: `charge` を置き換えず、新しい種類 `inhale` を足して `charge` を消す（設定の `type` も `'inhale'` にする）。
* 計画時点の判断（状態を進める時点と settle の削除）: 巨人の `cycle` と同じく、予告（`planNext`）の時点で「直前に予告した行動」を状態に入れる。予告した行動は必ずそのフェーズの攻防で行われ、ドラゴンを倒すとゲームクリアになるので、攻防の後に状態を進める必要がない。そのため 03-03 でチャージのためだけに足した `settle`（全種類で恒等になる）と `settleBehaviorAction`、`Game.resolveBattle()` での呼び出しを、ブレスチャージとともに消す。後で攻防の結果に応じて状態を変える決まりが必要になったら、そのときに足し直す。
* 計画時点の判断（乱数の消費）: ドラゴンの予告は、直前の予告が吸い込む・ブレスのときは乱数を使わず、それ以外（ドラゴンが出た最初のフェーズを含む）は1回使う（いまは満ちるまで使わず、満ちた後は1回）。ブレスの攻防の乱数の使い方（燃やす枚数に1回・1枚ごとに1回）、ゴブリン・巨人の乱数の使い方は変わらない。
* 計画時点の判断（作業の順番）: 表示（タスク1）→ 演出（タスク2）→ ルール層（タスク3）の順に消す。途中のタスクの後でも、`Game.enemyCharge()` などを呼ぶ側が先になくなるので、ゲームは動く状態を保つ。
* `js/view/layout.js` は先頭の責務定義のコメントだけを直す（「ブレスチャージも同じ枠」が実態と合わなくなるため）。コードは変えない。
* 目視確認推奨（実装後）: 巨人を倒してドラゴンが出たフェーズで、予告が「爪 10」か「吸い込む」（約30%）になり、戦闘の段の右上（数え下ろしの枠の位置）に何も出ないこと。「吸い込む」のフェーズの攻防で敵の兵が出ず、城がダメージを受けないこと（常時防御力 15 は働く）。その次のフェーズの予告が必ず目立つ枠の「ブレス 25」で、攻防で城への被害の後に札が4〜6枚燃えること。ブレスの次のフェーズの予告が必ず「爪 10」になること。巨人の数え下ろしと「振りかぶり」の表示、ゴブリンの予告がいまどおりであること。
