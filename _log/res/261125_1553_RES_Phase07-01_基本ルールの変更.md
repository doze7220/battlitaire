# RES: 作業計画・作業レポート (Phase 07-01) : 基本ルールの変更（4スート・敵の防御・隙・疲弊）
* 参照元REQ: `./_log/req/261125_1553_Phase07-01_基本ルールの変更.md`

## 1. 作業目的
戦闘の土台になるルールを変える。

1. 放った列に4スートがそろうと、攻撃・防御・修理・金貨のそれぞれに +1。
2. 敵の予告は「攻撃の量」と「防御の量」を同時に持つ。常時防御力（`armor`）はなくし、敵の防御を「そのターンだけの防御の量」1つに統合する。
3. ゴブリンは毎ターン攻撃と防御を両方行う。巨人・ドラゴンはターンごとのランダムな防御（75%）で、決まったターンに隙（防御 0）ができる。
4. 長引いた敵は疲弊して防御が減る（21 ターン目から半分、26 ターン目から 0）。敵の名前と「疲弊」を敵の HP ゲージの下に出す。
5. TURN の番号は戦闘ごとに数える（通しの番号 `phase` は別に持ち続ける）。
6. DEBUG タブ・遊び方をルールに合わせる。

守ること（全タスク共通）:
* 数値は `js/rules/config.js`（ルール）、`js/anim/animConfig.js`（放つ演出の時間）、`layout.js`・`releaseLayout.js` の定数（配置）に置く。座標は論理座標（720×1280）。
* ルール層は `oz`・画面・演出を import しない。乱数は渡された関数だけ。敵の種類の名前・識別子で分岐しない（設定・行動の決まりの表・見せ方の表で分ける）。
* 疲弊で減らした後の防御の量を求めるのは `js/rules/enemyDefense.js` の1か所だけ。予告・シールドの数・攻防は同じ `intent.defense` を読む。
* 新しいスプライトは作らない。`oz/` は編集しない・`oz/src/` は読まない。`draw` の中で状態を変えない。
* REQ の「今回やらないこと」（敵の並びの変更、1体＝複数ポイント、強化・スコア・保存、乱数の作り、疲弊の演出・音、4スートそろいの DEBUG 項目、自軍の数値）は行わない。

### 要件1: 4スートそろい
* **設定:** `RULES.allSuitsBonus`（数。初期値 1。0 で効果なし）。
* **計算（`release.js` の `computeRelease`）:** 区切りの計算（`segments`・`sum`・`bonus`・`amount`）は今のまま。放った札に `config.suits` のすべてのスートが1枚以上あり、`config.allSuitsBonus > 0` のとき、`config.suits` の順に `gains[config.suitGauge[suit]] += config.allSuitsBonus`（1回の放つで1度だけ）。戻り値に `allSuits` を足す。
    * `AllSuitsBonus`（typedef、`release.js`）: `{ amount: number, parts: Array<{ suit: string, gauge: string }> }`。そろわない・量が 0 以下なら `null`。
* **操作の結果:** `Game.release` が `ReleaseResult.allSuits`（`AllSuitsBonus|null`）として返す。ゲージへは今のとおり `gains` を足すだけ（+1 を含む）。
* **演出:** `ReleaseShow.start` が `result.allSuits !== null` のときだけ `allSuitsTrack.js` の記録を作る。基準の時刻は最後の区切りの `flyStart`（式が消えて最後の玉が飛び始める時刻。以下 F）。
    * 文字は F に出て `allSuitsLabelMs` の間出る（始めの `allSuitsAppearMs` で倍率 0→1（`easeOutBack`）、終わりの `allSuitsFadeMs` で濃さ 1→0）。
    * 玉 k（`parts` の順、0〜3）は F に文字の下で現れ（`allSuitsAppearMs` で直径 0→小さい玉）、`F + allSuitsHoldMs + k × allSuitsFlyStaggerMs` に飛び始め、`orbFlyMs` で弧を描いて飛び、着いて `orbBurstMs` で弾ける（弾ける見た目は区切りの玉と同じ: 小さい玉の直径から `smallSize × ORB_BURST_RATIO` まで広がり薄れる）。
    * 飛ぶ弧の式は `orbTrack.js` から `flyPoint(from, to, rise, u)`（u はイージング前の 0〜1。中で `easeInOutQuad`）として export し、区切りの玉と共用する（式を2か所に書かない）。
    * 着いたら、区切りの玉と同じ処理（`OWN_KINDS` のゲージなら `camp.land(...)` で `amount` 体、それ以外（金貨）は `coinCountMs` の数え上げ）で兵・金貨を足し、`endTime` を延ばす。同じ処理は `ReleaseShow` のメソッド `addArrival(gauge, amount, target, arriveAt)`（終わる時刻を返す）にまとめ、区切りと +1 の両方から呼ぶ。これで、人数の枠・金貨のゲージは着くにつれて増え、待つ兵の数は `gains` と一致し、`isBusy()` が真の間（＝全部着くまで）準備終了は出ない。
    * `waitingCounts()` は名簿の数なので、+1 の兵も `land` した時点で含まれる（攻防の始めの照合と一致）。
* **配置（`releaseLayout.js`）:** `releaseGeometry` に引数 `bonusGauges: string[]`（省くと空）を足し、戻り値に `allSuits: { label: {x, y, maxW}, starts: {x,y}[], targets: {x,y}[] } | null` を足す。飛ぶ先の求め方（陣地があればその中心、金貨のゲージなら `topGauges.coinBar` の中心、どちらでもなければ Error）は関数 `flyTarget(layout, gauge, coinGauge)` にくくり、区切りと共用する。
    * 玉の列の中心は、列の中心 x・`baseY`（一番下の合体位置。今の配置で y 554）、玉の間隔 `ALL_SUITS_ORB_STEP = 40`。文字の中心は `baseY - ALL_SUITS_LABEL_DY`（44。y 510）。文字の最大の幅 `ALL_SUITS_LABEL_MAX_W = 180`。x は、文字・玉の列が画面の左右の端から `ALL_SUITS_EDGE = 8` 以上空くように収める（今の列の中心は x 105・275・445・615 なので、動かない）。
* **文字:** `battleText.js` の `allSuitsText(suitCount, amount)` → 「4スート +1」（数は `parts.length` と `amount`）。`orbView.js` が太字 32px・縁取り 6px・黄色（`#ffe680`）で描く。

### 要件2・3: 敵の行動は「攻撃」と「防御」
* **型（`combatants.js`）:**
    * `EnemyAction`（行動の決まりが決める攻撃の側）: `{ kind: 'attack'|'windup', amount, variant?, burn?, sureHeal? }`。
    * `EnemyIntent`（予告）= `EnemyAction` ＋ `baseDefense: number`（抽選した防御の量。疲弊の前）＋ `defense: number`（疲弊を掛けた後の防御の量。**予告・シールド・攻防が読むのはこれだけ**）。`Enemy.intent`・`BattleResult.enemyAction` は `EnemyIntent`。
* **設定（`config.js`）:** 敵の種類ごとに同じ形の `defense: { chance, range: { min, max } }`（`EnemyDefenseSpec`）。`behavior` の外（`EnemySpec` の直下）に置く。疲弊は `RULES.fatigue`（下の要件6）。
* **`js/rules/enemyDefense.js`（新規。純粋。import は `rollAmount`・`isOpeningAction`（`enemyBehaviors.js`）だけ）:**
    * `rollDefense(spec, random)`: 張るかの抽選 `random() < chance`（1回）→ 量の抽選 `rollAmount(range, random)`（1回）。張らない結果でも必ず2回呼び、張らなければ 0 を返す。
    * `fatiguedDefense(base, battleTurn, fatigue)`: `fromTurn <= battleTurn` の最後の段の `defenseRate` を掛けて `Math.floor`。当たる段がなければ `base`。（疲弊で減らす式はここ1か所）
    * `isFatigued(battleTurn, fatigue)`: 当たる段があるか。
    * `createIntent(spec, action, battleTurn, fatigue, random)`: 隙（`isOpeningAction(spec.behavior, action)`）なら乱数を呼ばず `baseDefense = 0`、そうでなければ `rollDefense(spec.defense, random)`。`{ ...action, baseDefense, defense }` を返す。
    * `refreshIntent(intent, battleTurn, fatigue)`: 元の `baseDefense` から `defense` を数え直した新しい予告を返す（乱数は呼ばない。DEBUG 用）。
* **隙:** `enemyBehaviors.js` の決まりの表 `BEHAVIORS` の項目に `isOpening(action)` を足し、`isOpeningAction(behavior, action)` で引く。`steady` は常に偽、`cycle` は `action.kind === 'attack'`、`inhale` は `action.variant === 'inhale'`。
* **乱数の順:** 今の決まりの抽選（種類・攻撃の量）→ 張るか（1回）→ 防御の量（1回）。隙のターンは防御の乱数を呼ばない。DEBUG の「次の行動」の指定も `createIntent` を通す。
* **新しい決まり `'steady'`（ゴブリン）:** `{ type: 'steady', attackRange }`。状態 `{}`、毎ターン `steadyAttackAction(behavior, random)`（`{ kind: 'attack', amount }`。乱数1回）、数え下ろし `null`。`'weighted'`（`pickWeighted`・`weightedAction`・`EnemyActionSpec`・重みの検証・DEBUG の項目）は消す。
* **攻防（`battle.js`）:** 入力 `enemyAction` は `{ kind, amount, defense }`。`enemyArmor` を消す。出来事は、最初に `enemyAttack` か `enemyWindup`（必ず1つ）、続けて `enemyDefend`（量 = `defense`。0 なら入らない）。以後、相殺 → 城の被害 → 札 → 敵の回復 → `enemyBlock`（`min(attack, defense)`。0 なら入らない）→ 敵への攻撃 → …。`enemyArmorBlock` と行動の種類 `'defend'` を消す。余りは持ち越さない。
* **初期値（REQ 要件3）:** ゴブリン 攻撃 1〜3・防御 100% 1〜2・HP 30。巨人 防御 75% 2〜6・HP 60（攻撃・周期・回復は今のまま）。ドラゴン 防御 75% 3〜7・HP 90（爪・ブレス・吸い込む確率は今のまま）。

### 要件4: 予告の表示
* **出す側の判定（`js/view/intentParts.js`）:** `intentParts(action)` → `{ attack: boolean, defense: boolean }`。
    * `defense` は `action.defense > 0`。
    * `attack` は、「`kind === 'attack'` かつ `amount` が 0 以下かつ `variant` なし」かつ `defense` が真、のときだけ偽（＝攻撃の側がない行動。今はふつうには起きず、DEBUG で攻撃の量を 0 にしたときだけ）。それ以外は真（札が空にならない）。
* **札（`intentView.js`）:** 左から「攻撃の側（絵、量があれば数字）」「防御の側（`INTENT_IDS.defend` の絵と数字）」。間は `badge.sideGap`（10）。防御の側は防御が 0 のターンは絵も数字も出さない。ブレスの赤い札は今のまま（札全体。防御の数字も黄色）。
* **はみ出し:** 札の幅 w を測り、`left = min(spot.x - w/2, area.x + area.w - badge.edge - w)`（`badge.edge = 8`）。数え下ろしの中心は札の中心 `left + w/2`。
    * 幅の見込み: ゴブリン「3／2」約 144（x 568〜712）、巨人「振りかぶり／6」約 123（中心 x 595）、ドラゴン「ブレス 13／7」約 165（中心 x 580）。DEBUG の最大「50／20」でも約 180。札の y は 60〜104 のままで、名前の行（y 30〜58）・人数の枠（x 20〜188）・TURN の区画と重ならない。
* **始まりの文字:** `battleText.js` の `enemyActionText` が「攻撃 3 ／ 防御 2」「振りかぶり ／ 防御 4」「攻撃 20」を返す（`intentParts` で出す側を決める）。最大の幅 640 に対して最長でも約 400。
* 攻防の演出中の札も同じ関数（`result.enemyAction` は予告の写し）。

* **敵の体（`enemyBody.js`）:** 絵の見せ方のときだけ、`before.enemyDefense` の数のシールドを時刻 0 から置く（`BODY_SETUPS` の `horde` は `shieldArea: null`）。攻撃の兵が当たるたびに1つ剥がれる動きは今のまま（`hitEnemyArmor` → `hitEnemyShield`、`armorHitX` → `shieldHitX`。群れは `null`）。
* **段取りの間のシールド（`enemyView.js`）:** 絵を持つ敵だけ `enemy.intent.defense` 個。次のターンの予告が決まると新しい量に変わる。
* **城が落ちた負け:** `lose` で段が終わり、守りのゴブリンは `finishTroops` で右へ帰る（今の仕組みのまま）。

## 5. 懸念事項・要確認ポイント
*   **計画で決めたこと（試遊で確かめる）**
    *   攻撃のゴブリン（x 455〜500）と守りのゴブリン（x 525〜560）は並ぶ場所を分け、守りは攻撃の後ろから同時に走って現れる。攻撃の列が今（x 470〜550）より城寄りになる。攻防の長さは、攻撃だけのターンに比べて守りとの相打ちの段（約 0.55 秒）だけ伸びる。
    *   守りのゴブリンは段取りの間は出ない（予告の防御の数字で読む）。攻防で現れる。
    *   4スートそろいの文字と玉は、最後の区切りの玉が飛び始めるのと同時に出る。玉の弾け方は区切りの玉と同じ見た目で、新しい音は鳴らさない。
    *   金貨の +1 は、今の金貨と同じく、玉が着いてから `coinCountMs`（300ms）後に1増える。人数の +1 は、兵が家に着いたときに増える。
    *   疲弊の減らし方（半分）も設定に置くため、`fatigue` を「始まるターンと防御の倍率」の並びにした。
    *   「攻撃の側がない行動」は、攻撃の量 0 で中の種類のない攻撃とみなす（DEBUG でゴブリンの攻撃の量を 0 にしたときだけ起きる）。
*   **目視で確かめてほしい箇所**: 予告の札（3体すべて・ブレスの赤い札）の読みやすさとはみ出し、敵の名前と「疲弊」の大きさ・色、4スートそろいの文字と玉の位置（山札・手札の絵の上に重なる）、守りのゴブリンと群れの見分け、遊び方2・4ページ目。
*   **フォントの幅**: 札・文字の幅は sans-serif の見込み値で計算した。実機の幅は `measureText`・最大の幅で収まる作りにしてある。
*   **エンジンの不足**: 計画の時点では見つかっていない（新しく使うエンジンの機能はない）。
*   **タスク1 の注意点**: 既存の `Game.resolveBattle`・`startNextPhase` の戻り値の `enemyAction` は `{ ...intent }` の写しなので、`baseDefense`・`defense` が既に含まれる（タスク4以降で利用）。`createIntent` の乱数の順は「決まりの抽選 → 張るか → 量」。`Game` のコンストラクタで `battleTurn` は `planIntent` の前に作ってある。
