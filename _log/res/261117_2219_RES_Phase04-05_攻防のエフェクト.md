# RES: 作業計画・作業レポート (Phase 04-05) : 攻防のエフェクト
* 参照元REQ: `./_log/req/261117_2219_Phase04-05_攻防のエフェクト.md`

## 1. 作業目的
当たりの手応えと大きな一撃の重さが見て分かるように、攻防の演出にエフェクトを足す。当たるたびのごく短いヒットストップ（段ごとの合計に上限）と白い光、城と敵の HP が減るたびの「-1」と粒、修理の兵が城に入るときの修理の粒、大きな一撃（巨人の攻撃・ドラゴンのブレス）での戦闘の段の揺れと長めのヒットストップ、陣地で待つ自軍の兵の呼吸、攻撃の兵の加速する踏み込み、振りかぶり・吸い込みのための動きと段の暗さ、撃つ瞬間の段の光を作る。**ルール層（`js/rules/`）は変えない。** エフェクトは見た目だけで、演出の途中・早送り・スキップのどれでも、ルールの結果（城と敵の HP、燃える札、決着）と進行は変わらない。

## 2. アーキテクチャ設計

### 全体の考え方
*   **当たりは時間割が1回だけ記録する**: 当たりの時刻は、いまと同じく名簿の兵の終わり方の時刻（`TroopUnit.end.time`。`troopRoster.js` の式）と、打撃の時刻（`enemyAttacks.js` の `strikeTimes`。ヒットマークの記録）で決まる。時間割（`battleTimeline.js`）は段を組み立てるたびに、「その段で終わり方が決まった兵」と「その段で足されたヒットマーク」を新しいモジュール `impactLog.js` に渡し、`impactLog.js` が段の種類ごとの表で当たり（時刻・位置・種類・大きな一撃か・段の番号）を記録する。時刻は名簿・ヒットマークの値をそのまま写すので、兵の動き・HP の変化・音のきっかけ・エフェクトの時刻がずれない（時刻の式は増やさない）。
*   **ヒットストップは「時計の対応」で作る**: 時間割の時刻（以下「演出の時刻」）は一切変えない。演出の管理（`battleDirector.js`）は、`dt` を足して進める**壁の時計**（`wall`）を新しく持ち、ヒットストップの並び（`hitStop.js`。演出の時刻 `at` で、壁の時計の `dur` だけ止まる）から、壁の時計 → 演出の時計（今の `clock`）を求める。見た目・HP・人数・燃える札・音のきっかけは、今と同じく演出の時計だけを読むので、止まった分も含めて全部がそろって止まり、そろって進む。`Engine.timeScale`・ルール層・シーンの進行には触れない（早送りは `update` の回数が増えるので、止まる時間も同じ比率で短くなる）。
*   **毎フレームは型付き配列に書くだけ**: 光・数字・粒は、攻防の始めに1回だけ作った入れ物（`impactFx.js` の `ImpactFx`）に、毎フレーム時計から書く（04-02 の `TroopSwarm`・04-04 の `HitMarkSwarm` と同じ作り）。粒の散り方は番号から決め（黄金比の小数部）、乱数を使わない。同時に見える粒の数に上限を置く。
*   **エフェクトの終わりは時間割の終わりに含める**: 光・数字・粒・揺れ・撃つ瞬間の光が消える時刻を時間割の終わり（`endTime`）に含める。どの見た目も「出てからの時間 < 長さ」のときだけ見えるので、演出が終わった時刻（スキップ後も同じ）には光・数字・粒・揺れ・暗さ・ための動きは必ず残らない。
*   **新しい責務は新しいモジュールに分ける**（`battleTimeline.js`・`battleDirector.js`・`troopRoster.js`・`enemyBody.js`・`battleShowView.js`・`layout.js` を肥大化させない。`troopRoster.js`・`enemyBody.js`・`layout.js` は変更しない）:
    *   `js/anim/impactLog.js`（新規）: 当たりの記録。
    *   `js/anim/hitStop.js`（新規）: ヒットストップの並びと時計の対応。
    *   `js/anim/impactFx.js`（新規）: 白い光・「-1」・粒の見た目の入れ物。
    *   `js/anim/chargeShow.js`（新規）: ための段の強さと、巨人・ドラゴンのための姿勢。
    *   `js/anim/stageFx.js`（新規）: 戦闘の段の揺れ・暗さ・撃つ瞬間の光。
    *   `js/anim/battleFx.js`（新規）: 上の見た目の取りまとめ（作る・時計から書く・終わりの時刻）。
    *   `js/anim/troopBreath.js`（新規）: 待っている自軍の兵の呼吸の式。
    *   `js/view/battleFxView.js`（新規）: 光・粒・「-1」・段の暗さと光を描く。
*   **大きな一撃とための段は敵の見せ方の表に持つ**: `enemyShows.js` の `ENEMY_SHOWS` に、敵の種類ごとの「大きな一撃とみなす攻撃の中の種類」（`heavy`）と「ための動きを見せる振りかぶりの中の種類」（`charge`）を足す（後で敵・行動を増やすときは表に足すだけ）。`battleSteps.js` が表を引いて、敵の攻撃の段に `heavy: true` を付け、振りかぶりの攻防に新しい段 `charge` を足す。

### 要件1: ヒットストップと白い光
*   **当たりの記録（`impactLog.js`）**:
    *   記録 `ImpactLog`: 並んだ配列 `x`・`y`（光・数字・粒の中心）・`time`（演出の時刻 ms）・`kind`（0＝当たり `hit`／1＝敵の HP が減る当たり `enemyDamage`／2＝城の HP が減る当たり `castleDamage`／3＝修理の兵が城に入る `repair`）・`heavy`（0／1。大きな一撃の段か）・`step`（段の番号）。種類の数値は凍結した表 `IMPACT_KINDS` で export する。
    *   段の見張り `watchStep(roster, marks)`: 段を組み立てる前に呼び、そのときまだ終わり方の決まっていない兵の並び（`open`）・名簿の長さ（`firstNew`）・ヒットマークの数（`marksFrom`）を写して返す（名簿・記録は書き換えない）。
    *   段の記録 `recordStepImpacts(log, watch, step, index, bodyStyle)`: 段を組み立てた後に呼ぶ。「その段で終わり方が決まった兵」＝ `open` のうち `end !== null` になった兵 ＋ 名簿の `firstNew` 以降で `end !== null` の兵を、`end.time` の昇順（同じなら名簿の番号順）に並べ、段の種類ごとの表 `IMPACT_RULES` で記録する。位置は兵の体の中心（`end.x`、`end.y − 描く大きさ / 2`。大きさは `unit.size > 0 ? unit.size : roster.layout.size`）。
        *   `block`・`enemyBlock`・`armorBlock`・`strikeBlock`: 終わった兵すべてを `hit`（相打ちの2体・シールドと攻撃の兵・打たれた防御の兵）。
        *   `castleHit`: 終わった兵（ゴブリン・炎）の前から `step.amount` 体を `castleDamage`、残りを `hit`（城の HP が 0 で止まるときに越えた分）。
        *   `enemyHit`: 体の見せ方ごとの「HP を減らす側の種類」の表 `ENEMY_DAMAGE_KIND`（`horde`→`goblin`、`figure`→`attack`）の種類の兵の前から `step.amount` 体を `enemyDamage`、それ以外の終わった兵（群れの組の攻撃の兵）を `hit`。
        *   `strikeCastle`: その段で足されたヒットマーク（`marksFrom` 以降）の前から `step.amount` 個を、マークの位置・時刻で `castleDamage`。
        *   `heal`: 終わった兵（修理の兵）すべてを `repair`（城に入る位置 `end.x`・体の中心の y）。
        *   ほかの段（`form`・`enemyMarch`・`march`・`enemyHeal`・`burn`・`charge`）: 記録しない。
        *   `heavy` は `step.heavy === true`（`repair` は常に 0）。
    *   時間割（`battleTimeline.js`）は段ごとに `watchStep` → `builder` → `recordStepImpacts` と呼び、時間割に `impacts`（`ImpactLog`）を持つ。足すのは数行だけ。
*   **ヒットストップ（`hitStop.js`）**:
    *   `createHitStops(log)`: `repair` 以外の当たりを段の番号ごとに分け、段の中で時刻の昇順に**同じ時刻を1つにまとめ**、1つごとに `heavy ? heavyStopMs : hitStopMs` だけ止める。段の中の合計は `heavy ? heavyStopCapMs : hitStopCapMs` を上限とし、上限に届く1つは残りの分だけにして、その後の当たりでは止めない。全部の段の分を時刻の昇順に並べ（同じ時刻は長い方の1つにまとめる）、型付き配列 `at`（演出の時刻）・`dur`（止まる長さ）・`wallAt`（その止まりが始まる壁の時計 ＝ `at + それより前の dur の合計`）・`cum`（その止まりまでの `dur` の合計）と、合計 `total` を持つ `HitStops` を返す。
    *   `showTimeAt(stops, wall)`: `wallAt[i] <= wall` となる最後の i を二分探索で探し、なければ `wall`、`wall < wallAt[i] + dur[i]` なら `at[i]`（止まっている）、それ以外は `wall − cum[i]`。
    *   `wallTimeAt(stops, show)`: 演出の時刻 `show` に着いて、`at <= show` の止まりをすべて終えた壁の時計（`show + (at <= show の dur の合計)`）。スキップに使う。
    *   **演出の管理（`battleDirector.js`）**: `wall`（壁の時計）と `stops`（`createHitStops(timeline.impacts)`）を足す。`update(ms)` は `prevClock = clock; wall += ms; clock = showTimeAt(stops, wall)`。`skip()` は `wall = max(wall, wallTimeAt(stops, endTime))`・`clock = max(clock, endTime)`・`prevClock = clock`。`isFinished`・`isReadyToLeave`・`cuesInLastUpdate`・`boardView`・`view` は今のまま演出の時計を読む（止まった後は壁の時計と同じ速さで進むので、終わりの後の間も今と同じ長さ）。当たりの時刻 T に着いた `update` で演出の時計がちょうど T になり、そこで止まるので、きっかけ（`prevClock < T <= clock`）の音は当たりの瞬間に鳴り、止まった分も含めてずれない。
*   **白い光**: `repair` 以外の当たりすべてに、当たった所へ白い丸を `flashMs` の間出す（大きさは `flashSize` の半分から `flashSize` へ広がり、濃さは 1 から 0 へ）。ヒットマークは今のまま（防御の兵・城だけ）。

### 要件2: ダメージの数字と粒
*   `enemyDamage`・`castleDamage` の当たりごとに、当たった所から「-1」が `damagePopMs` の間に `damagePopRise` だけ浮き上がり、後半で薄れて消える（文字の大きさは `damagePopSize`。城は赤、敵は黄）。同時に `sparkCount` 個の粒が散る。
*   `repair` ごとに、城に入る位置から `repairSparkCount` 個の修理の粒（緑）が上へ散る。数字は出さない。
*   粒の動き（`impactFx.js` の1か所）: 当たり i の j 番目の粒は、角度 `θ = 2π (j + frac(i × G)) / n`（`G` は黄金比の小数部 0.6180339887、n は粒の数）、速さ `v = sparkSpeed × (SPARK_SPEED_MIN + (1 − SPARK_SPEED_MIN) × frac((i + j + 1) × G))`（`SPARK_SPEED_MIN` は 0.6 の形の定数）、位置 `x = x0 + cosθ·v·τ`、`y = y0 + sinθ·v·τ + g·τ²/2`（g はダメージの粒は `sparkGravity`、修理の粒は `−sparkGravity`＝上へ）、濃さ `1 − τ / sparkMs`。乱数は使わない。
*   **重さ**: `ImpactFx` は攻防の始めに1回だけ、光・数字・粒それぞれの型付き配列（位置・濃さ・見えるか・種類の印）を作る。`sample(clock)` は配列に書くだけで、オブジェクトを作らない。粒は見える数が `sparkMax` に届いたら、その後の粒は見えないとする（番号の順なので決まった見え方になる）。
*   **敵の回復（「+20」）は今のまま**（`popTrack.js`・`battleShowView.js` の `drawEnemyHealPop` は変えない）。
*   **「-1」の形**: `battleText.js` に `damagePopText()`（「-1」。1体の当たりで減る HP の表示）を足し、描画は毎フレーム1回だけ呼んで全部の数字に使う。

### 要件3: 大きな一撃で揺れる
*   **表**: `enemyShows.js` の `ENEMY_SHOWS` の各項目に `heavy`（大きな一撃とみなす、攻撃の行動の中の種類の並び）と `charge`（ための動きを見せる、振りかぶりの行動の中の種類の並び）を足す。行動の中の種類がない行動は `'default'` として引く（`attacks` の引き方と違い、表にない中の種類は `'default'` に置き換えない。ドラゴンの爪 `claw` は大きな一撃にならない）。
    *   `goblins`: `heavy: []`、`charge: []`
    *   `giant`: `heavy: ['default']`（攻撃）、`charge: ['default']`（振りかぶり）
    *   `dragon`: `heavy: ['breath']`、`charge: ['inhale']`
    *   引く関数 `isHeavyAttack(typeId, variant)`・`hasChargeShow(typeId, variant)`。
*   **段の印**: `battleSteps.js` は、予告の行動（`result.enemyAction`）が攻撃で `isHeavyAttack` なら、敵の攻撃の段（`enemyMarch`、攻撃から作る `block`・`castleHit`・`strikeBlock`・`strikeCastle`）に `heavy: true` を付ける。
*   **長いヒットストップ**: 要件1の `heavyStopMs`・`heavyStopCapMs`。
*   **揺れ（`stageFx.js`）**: 大きな一撃の当たり（`heavy` の `hit`・`castleDamage`）の時刻の昇順の並びを攻防の始めに作る。演出の時計 s で、s 以下の最後の大きな一撃の時刻 t（二分探索）から `0 <= s − t < shakeMs` なら強さ `A = shakeAmp × (1 − (s − t) / shakeMs)`、ずれは `shakeX = A·sin(2π·wall / shakePeriodMs)`、`shakeY = A·cos(2π·wall / shakePeriodMs)`（揺れの向きの拍子は壁の時計で進めるので、ヒットストップで止まっている間も震える。強さは演出の時計で決まるので、止まっている間は強いまま）。
*   **揺らす範囲**: `battleShowView.js` が、戦闘の段の矩形で切り抜いた中で `ctx.translate(shakeX, shakeY)` してから、戦闘の段（背景・城・敵の絵・HP などの枠）・兵・ヒットマーク・光・粒・「-1」を描く。人数の表示・敵の回復の量・敵を倒したときの案内・最下段・ソリティアの段・ゲージの行は揺らさない（ソリティアの段とゲージの行は背面の `BoardScene` が描くので、もともと揺れない）。

### 要件4: 待っている兵の呼吸
*   **待っているか**: `troopMotion.js` の `sampleTroop` が、見た目の入れ物に `idle`（見えていて、終わり方が始まっておらず、脚の途中でなく、家の位置（`homeX`・`homeY`）にいる）を書く。段取りの間の兵は家へ跳び終わった後、攻防の間の兵は最初の脚の前（と、家へ戻っていればその後）が `idle`。
*   **呼吸の式（`troopBreath.js`）**: `breathScale(kind, index, clock, out)` が、自軍の種類（`OWN_KINDS`）のときだけ `s = breathDepth × sin(2π·clock / breathPeriodMs + φ)` から `out.scaleY = 1 + s`・`out.scaleX = 1 − s / 2` を書く（ほかの種類は 1・1）。位相 `φ = 2π × frac(index × G + KIND_PHASE[kind])`（`G` は黄金比の小数部、`KIND_PHASE` は攻撃 0・防御 1/3・修理 2/3）。乱数は使わない。
*   **入れ物（`troopSwarm.js`）**: `TroopSwarm` に `scaleX`・`scaleY`（Float64Array。初めは 1）と `idle`（Uint8Array）を足す。`sample(clock)` は `idle` を書き、`idle` の兵だけ `breathScale` で伸び縮みを書く（ほかは 1）。新しい `breathe(clock)` は、`idle` の兵の `scaleX`・`scaleY` だけを書き直す（位置・描く順は書かない）。
*   **段取りの間（`campTroops.js`）**: `sample(clock)` は、全員が家に着くまでは今のとおり `swarm.sample`、着いた後は `swarm.breathe(clock)` だけを呼ぶ（04-02 の「着いた後は書き直さない」軽さを保つ）。
*   **攻防の間**: `BattleDirector` は今のとおり毎回 `swarm.sample(clock)` を呼ぶ（演出の時計なので、ヒットストップの間は呼吸も止まる）。
*   **描画**: `spriteView.js` の `drawTroopFigure` の末尾に引数 `scaleX`・`scaleY` を足し、足元へ移した後（傾きの後）に 1 でなければ `ctx.scale(scaleX, scaleY)`（足元が軸）。`troopView.js` の `drawTroop` の末尾にも `scaleX`・`scaleY` を足して渡し、`drawTroopSwarm` は名簿の見た目の `scaleX[i]`・`scaleY[i]` を渡す。`enemyView.js` の群れ（`drawHorde`）は 1・1 を渡す。

### 要件5: 突撃の踏み込み
*   **脚の印**: `troopMotion.js` の脚 `TroopLeg` に `rush`（boolean。`addTroopLeg` では false）を足す。`setTroopEnd` で終わり方が `'fall'` で、種類が踏み込む種類の表 `RUSH_KINDS`（`attack`）にあり、最後の脚が終わり方の時刻ちょうどに終わり（`leg.end === time`）、右（敵の方）へ進む脚（`leg.toX > leg.fromX`）なら、その脚を `rush = true` にする。敵・シールド・群れに当たる脚（`chargeTo`・`chargePairs`）が当たる。
*   **式**: `sampleTroop` の脚の補間で、`rush` の脚は進み具合 `u` を `u ** BATTLE_ANIM.rushPower`（出だしはゆっくり、当たる前に速い）にして位置を求める。弾み・揺れは今のまま `u` で求める。
*   **時刻はずれない**: 脚の始まり・終わりの時刻（＝当たる時刻）は変えない（名簿の式のまま）。行進の段の長さ・当たる時刻・音・HP の変化・当たりの記録は、どれも今と同じ値を読む。

### 要件6: ための動きと撃つ瞬間の光
*   **ための段**: `battleSteps.js` は、出来事に振りかぶり（`enemyWindup`）があり、`hasChargeShow(敵の種類, result.enemyAction.variant)` なら、段の並びの先頭に `{ type: 'charge', amount: 0 }` を足す（巨人の振りかぶり・ドラゴンの吸い込み）。時間割の `charge` の組み立ては、長さ `chargeMs` を返すだけ（きっかけの時刻なし＝音は鳴らない。新しい効果音は足さない）。攻防の結果・出来事は変わらない。
*   **強さ（`chargeShow.js`）**: `chargeWindows(steps)` で時刻つきの段から `charge` の段の始め・終わりを写し、`chargeLevel(windows, clock)` は段の中の進み具合 u（0〜1）から `sin(π·u)`（始めと終わりが 0）、段の外は 0。
*   **姿勢**: `sampleChargePose(windows, clock, out)` が `out.tilt = chargeLean × k`（後ろ＝右へ反る。敵は左向き）、`out.scaleX = out.scaleY = 1 + chargeSwell × k`（膨らむ）を書く。`enemyView.js` は攻防の演出中の絵を、足元（絵の矩形の下辺の中心。倒れる動きのずれ `dy` の後）を軸に回して伸ばしてから描く（`save`／`restore` の中）。
*   **暗さ**: `stageFx.js` が `dim = chargeDim × chargeLevel(...)` を書き、`battleShowView.js` が揺れの外で段の矩形に黒を `dim` の濃さで重ねる（`save`／`restore`）。
*   **撃つ瞬間の光**: `stageFx.js` は時刻つきの段のうち最初の `heavy` の段の始め（ブレスは `enemyMarch` の始め、巨人の攻撃は `strikeBlock`／`strikeCastle` の始め）を撃つ時刻とし、`0 <= s − t < fireFlashMs` で `flash = fireFlashAlpha × (1 − (s − t) / fireFlashMs)`。`battleShowView.js` が暗さの後に段の矩形へ白を `flash` の濃さで重ねる。

### 要件7: 早送り・スキップ
*   ヒットストップは演出の管理の中の時計の対応だけで、ルール層・シーンの進行（`BattleShowScene` は変更しない）・`Engine.timeScale` に触れない。早送りは `update` の回数が増えるので、止まる時間・揺れの拍子も同じ比率で短くなる。
*   スキップ: 要件1のとおり、壁の時計と演出の時計を終わりへ移す。エフェクトの終わりは時間割の終わりに含めてあり（`battleFxEnd`）、どの見た目も「経過 < 長さ」のときだけ見えるので、スキップ後は光・数字・粒・揺れ・暗さ・ための姿勢・撃つ瞬間の光が残らない。
*   音: きっかけの時刻は今のまま（時間割の `cueTimes`）で、演出の時計で問い合わせるので、止まった分も含めて見せ方の瞬間に合う。新しい効果音・きっかけの種類は足さない（`soundCues.js`・`battleCues.js` は変更しない）。
*   **時間割の終わり**: `battleFx.js` の `battleFxEnd(impacts, steps)` は、当たりごとの見た目が消える時刻（`hit` は `flashMs`、ダメージは `flashMs`・`damagePopMs`・`sparkMs` の長い方、`repair` は `sparkMs`）、大きな一撃の揺れ（`+ shakeMs`）、撃つ瞬間の光（`+ fireFlashMs`）の最大（なければ 0）を返し、`battleTimeline.js` が `endTime` に含める。ための段は段の終わりで終わる。

## 5. 懸念事項・要確認ポイント
*   **途中のタスクの見た目**: 各タスクの終わりで、アプリ全体は読み込める（import の解決・構文が通る）。
    *   タスク2の後: 巨人の振りかぶり・ドラゴンの吸い込みの攻防の先頭に、何も動かない `chargeMs` の間が入る（ための姿勢・暗さはタスク10から見える）。
    *   タスク3・4の後: 待っている兵が呼吸し、攻撃の兵が加速して当たる。
    *   タスク6の後: 当たるたびに止まる（光などはまだ出ない）。
    *   タスク9の後: エフェクトの値は作られるが描かれない（演出の終わりはエフェクトの分だけ少し延びる）。
    *   タスク10の後: すべて見える（通しの確認はここから）。
*   **揺れで見える縁**: 戦闘の段を揺らすと、段の矩形の縁に、揺れの幅（`shakeAmp`）の分だけ背面の `BoardScene` が描いた戦闘の段（攻防の後の HP の枠などを含む背景）がのぞく。背景の空・地面なのでほぼ目立たない見込みだが、目視で気になるなら、揺れの幅を小さくするか、段の描き方を後で決め直す。
*   **大きな一撃の表の置き場所**: REQ の「設定の表」は、敵の種類ごとの見せ方の表（`enemyShows.js` の `ENEMY_SHOWS` の `heavy`・`charge`）に置いた（敵・行動を足すときは表に足すだけ）。`battleAnimConfig.js` は数値の設定だけを持つ。
*   **演出の終わりが少し延びる**: 光・数字・粒・揺れ・撃つ瞬間の光が消える時刻を演出の終わりに含めるので、決着の表示・次のフェーズへ進むのが、ヒットストップの合計とエフェクトの残りの分だけ今より遅くなる（結果は変わらない）。
*   **ための段で増える時間**: 振りかぶり・吸い込みの攻防は、先頭のための段（`chargeMs`）の分だけ長くなる。自軍の兵がいない振りかぶりの攻防は、今は段がなくすぐ終わるが、ための段だけ見せて終わる。
*   **相打ちの光**: 相打ちは2体とも当たりとして光が2つ出る（ヒットストップは同じ時刻を1回にまとめる）。ずれた時刻の2体（相打ちの時刻がそろわない場合）は2回止まりうる。
*   **ヒットストップの上限の効き方**: 兵が多い段では、段の前の方の当たりだけで上限に届き、後ろの当たりでは止まらない。止まり方が前に偏って見えるなら試遊で値を決め直す（間引き方を変える仕掛けは作らない）。
*   **呼吸の位相のつながり**: 段取りの間と攻防の間で時計が別なので、攻防に入る瞬間に呼吸の伸び縮みが少し飛ぶことがある。
*   **踏み込みの範囲**: 加速するのは、攻撃の兵が当たる時刻ちょうどに終わる、敵の方へ進む脚（敵の絵・シールド・群れのゴブリンに当たる脚）だけ。防御のゴブリンとの相打ち（行進の後に段を分けてぶつかる）は今のまま。
