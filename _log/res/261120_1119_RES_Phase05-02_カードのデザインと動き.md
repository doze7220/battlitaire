# RES: 作業計画・作業レポート (Phase 05-02) : カードのデザインと動き
* 参照元REQ: `./_log/req/261120_1119_Phase05-02_カードのデザインと動き.md`

## 1. 作業目的
カードの表の枠と裏の模様を、`assets/sprites/` のスプライトで描くようにする。このサブフェイズでは、今の見た目と同じ仮のスプライト JS（OZ Vector Editor の「開く」で開いて図形を編集できる形）を実装側で書き出す。後で発注者がエディタで調整して同じ名前で書き出し直したファイルに差し替えても、ゲーム側のコードを変えずに描けるようにする。
あわせて、カードの動きの粗い所を2つ直す。
* 長い列の詰め直し: 列が詰まる・広がるとき、列にもとからあったカードが、動くカードが着いた後に新しい位置へ滑らかに動く（今は一瞬で移る）。
* 山札のめくれの時刻: 抜けたカードが半分ほど離れた頃（目安 120ms 後）に、下のカードがめくれ始める（今は抜けた瞬間）。

ルール層（`js/rules/`）は変えない。タイトルからクリア・負けまで、スマホの縦画面と PC で通しで遊べることを保つ。

## 2. アーキテクチャ設計

### 今のカードの描き方と動き（調べた結果）
* カードの大きさ: `layout.card` は 幅 100 × 高さ 140（`createLayout` の `cardW = floor((720 − 20×2 − 16×5) / 6) = 100`、`cardH = round(100 × 1.4) = 140`。山札・捨て札・手札の枠・列・動いているカードはすべてこの大きさ）。
* カードの表・裏を描くのは `js/view/cardView.js` の `drawCardFace`・`drawCardBack` だけで、ほかはすべてこの2つを通る。
    * `drawCardFace` を呼ぶ所: `columnView.js`（列）、`deckView.js`（山札の一番上）、`handView.js`（手札）、`orbView.js`（玉に変わる前の札）、`boardView.js`（動いているカード・燃えて飛ぶ札）、`cardView.js` の `drawCardFlip`（めくれの表）。
    * `drawCardBack` を呼ぶ所: `drawCardFlip`（めくれの裏）だけ。
    * `drawCardFlip` は中心へ `translate` し `scale(scaleX, 1)` してから表・裏を描く（スプライトにしても同じ変換の上に描かれる）。
* 動き: 操作のたびに `BoardScene.onPointer` が `buildPlanningMotion(result, before, after, layout)`（`planningMotion.js`）で動き（`Motion` = カードの移動 `tweens` と山札のめくれ `flips`）を作り、`BoardAnimator.start` に渡す。`BoardAnimator.view()` が、着いていない移動中のカード（`flying`。最後に手前へ描く）・列と手札で隠すカードの ID（`hiddenCardIds`）・めくれ中の山札（`deckFlips`）を返し、`boardView.js` が描く。`BoardAnimator.isBusy()` の間はタップを無視し、自動の攻防にも入らない。
* 列のカードの位置は `layout.js` の `columnCardYs(columnLayout, count)`（`columnCardRects` も同じ）で、枚数だけから決まる。列の領域の高さは 576px で、14枚以上で詰まる。`ys[0]`（一番下のカード）はいつも列の上端 `y`。描画は `columnView.js` の `drawColumn` が今の枚数で毎回求めるため、枚数が変わった瞬間にもとからあったカードが一瞬で移る。
* めくれ: `deckFlip.js` の `sampleDeckFlip` は、時計が `delay` より前なら `{ scaleX: 1, faceUp: false }`（裏のまま）を返す仕組みをすでに持つ。今は `planningMotion.js` が `delay: 0` で作っている。
* 放つ: ルール層の `Game.release(c)` は列の札を**すべて**放つ（`this.columns[c].splice(0)`）。放った列は空になり、ほかの列は変わらない（5章の懸念事項1）。

**エディタでの描き方の約束**（開発資料にも書く）: 原点 (0, 0) をカードの中心にし、カードの外形を 幅 100 × 高さ 140（x −50〜50、y −70〜70）の実寸で描く。ゲームはこの範囲をカードの矩形（`layout.card` の幅×高さ）に合わせて縦横それぞれの倍率で拡大縮小して描き、範囲の外にはみ出した部分も同じ倍率でそのまま描く。倍率の元の 100×140 は `js/view/spriteView.js` の定数 `CARD_ART_RANGE` の1か所に持ち、スプライトの `bounds` は実行時に読まない。

**図形の中身（今の見た目を写す）**: 角丸は、角ごとに 15° 刻みの 6 区間（角1つに7点）の短い直線で近似した、閉じたパス（28点・28区間）にする。半径 8 の円弧と比べたずれは最大 8 × (1 − cos 7.5°) ≈ 0.07px で、見た目は変わらない。
* 角丸の矩形の点の求め方（外形・内側の枠で共通）: 角の中心 (cx, cy) と半径 r、始めの角度 θ0（度）から、k = 0〜6 について θ = (θ0 + 15k)° のとき 点 = (cx + r·cos θ, cy + r·sin θ)。角は時計回り（y は下向き）に 右上（θ0 = −90）→ 右下（θ0 = 0）→ 左下（θ0 = 90）→ 左上（θ0 = 180）の順に並べ、続けて 28 点にする（角と角の間の辺は、前の角の最後の点から次の角の最初の点への直線）。座標は小数第3位に丸める（`Math.round(v * 1000) / 1000`。`-0` は `0` にする）。
* 外形: 角の中心 右上 (42, −62)・右下 (42, 62)・左下 (−42, 62)・左上 (−42, −62)、r = 8。最初の点は (42, −70)、x の範囲 −50〜50、y の範囲 −70〜70 になる。
* 内側の枠（裏だけ）: 今の `drawCardBack` の「内側へ 6、角の半径 4」を写した x −44〜44、y −64〜64。角の中心 右上 (40, −60)・右下 (40, 60)・左下 (−40, 60)・左上 (−40, −60)、r = 4。
* 表の枠（4つとも同じ中身）: 図形1つ（`shape-1`）= 外形、`strokeColor: "#333333"`・`strokeWidth: 2`・`fillColor: "#fdfaf0"`。
* 裏: 図形2つ。`shape-1` = 外形、`strokeColor: "#333333"`・`strokeWidth: 2`・`fillColor: "#2f4a8a"`。`shape-2` = 内側の枠、`strokeColor: "#9fb4e6"`・`strokeWidth: 2`・`fillColor: null`（塗りなし）。描く順は `shape-1` → `shape-2`（今と同じ）。
* `bounds`（エディタの定義: 中心線の外接矩形を、線のある要素だけ線の太さの半分ずつ広げた和）: 5つとも `{ "minX": -51, "minY": -71, "maxX": 51, "maxY": 71 }`（内側の枠は −45〜45・−65〜65 で外形の中に入る）。

**ファイルの形**（既存の `effect_hit.js`・`suit_sword.js` と同じ形。他のファイルに依存しない）:
1. 先頭のコメント（`/**` 〜 ` */`。中身は3行。1行目「OZ Vector Editor 形式のスプライト（ESモジュール）。他のファイルに依存しない。」、2行目「既定のexportは、スプライトデータと draw(ctx) を持つ1つのオブジェクト（単位px、基準点は原点、y軸は下向き）。」、3行目はそのファイルの説明（例「カードの表の枠（剣）の仮のスプライト（原点がカードの中心、幅100×高さ140）で、OZ Vector Editor で調整して差し替える。」）。`const spriteData = ` で始まる行をコメントの中に置かない（エディタの取り出しの目印のため）。

### 要件3: 長い列の詰め直しを滑らかにする
**考え方**: もとからあったカードを「飛んでいるカード（`flying`）」として描くと、着いたカード（列の描画で描く）より手前に重なってしまい、重なりの順が崩れる。そこで、列ごとに「各カードの上端 y」を時計から求めて、列の描画（`drawColumn`。下から順に重ねる）にそのまま渡す。重なりの順はいつも列の順になる。

* **新しいファイル `js/anim/columnSettle.js`**（責務: 長い列の詰め直し（列にもとからあったカードが、操作前の枚数での位置から操作後の枚数での位置へ動くこと）の記録を配置から組み立て、時計から列の各カードの上端 y を求める。描画も状態の変更も行わず、ルール層は import しない）。`planningMotion.js` に入れると操作の種類の振り分けと位置の比べ方が混ざって肥大化するため分ける。
    * typedef `ColumnSettle`: `columnIndex`（列の番号）・`fromYs`（動き始める前の各カードの上端 y。下から順で、長さは操作後の枚数）・`toYs`（動き終えた後の各カードの上端 y。同じ長さ）・`delay`（開始の遅れ ms）・`duration`（かかる時間 ms）。
    * `buildColumnSettle(layout, columnIndex, beforeCount, afterCount, delay, duration)` → `ColumnSettle|null`:
        * `beforeYs = layout.columnCardRects(columnIndex, beforeCount).map((r) => r.y)`、`afterYs` も同じく `afterCount` で求める。
        * `i < min(beforeCount, afterCount)` のどれかで `beforeYs[i] !== afterYs[i]` なら詰め直しが起きる。どれも同じ（列が領域に収まったまま等）なら `null`（今と同じ動きのまま）。
        * `toYs = afterYs`。`fromYs[i] = i < beforeCount ? beforeYs[i] : afterYs[i]`（新しく来たカードは最初から着く位置。動いている間は `hiddenCardIds` で隠れていて、着いた後はその位置に描かれる）。
    * `sampleColumnSettle(settle, clock)` → `number[]|null`: `clock >= delay + duration` なら `null`（普通の描画に戻る）。それ以外は `e = easeOutCubic(clamp01((clock − delay) / duration))`（`duration` が 0 以下なら `clock >= delay` で 1）で `fromYs[i]` から `toYs[i]` へ `lerp` した新しい配列。`clock < delay` の間は `fromYs` のまま（もとの位置で待つ）。
    * `columnSettleEnd(settle)` → `delay + duration`。
* **`js/anim/animConfig.js`**: `columnSettleMs: 200`（長い列の詰め直しで、もとからあったカードが新しい位置へ動く時間。試遊で決め直す）を足す。
* **`js/anim/planningMotion.js`**: `Motion` に `settles: ColumnSettle[]`（列の詰め直し）を足す（`default` の空の動きも `settles: []` を持つ）。動き始める時刻は、動くカードが着く時刻 = `ANIM_TIMING.cardMoveMs`（動くカードは `delay` 0・時間 `cardMoveMs`）。時間は `ANIM_TIMING.columnSettleMs`。
    * `place`（山札から置く）・`placeFromHand`（手札から置く）: 置いた列 `result.columnIndex` について `buildColumnSettle(layout, c, before.columnLengths[c], after.columnLengths[c], cardMoveMs, columnSettleMs)`。`null` でなければ `motion.settles` に足す。
    * `move`（束の移し替え）: 先の列 `result.toColumn` と元の列 `result.fromColumn` の両方について同じく作る（元の列も「動いた札が先の列に着いてから」= 同じ `cardMoveMs` から動き始める）。
    * `release`（放つ）: 列の札をすべて放ち列が空になるので、残るカードがなく詰め直しは起きない。詰め直しは作らない（そのことをコメントに書く）。
    * `discard`・`hold`: 列は変わらないので作らない。
    * 攻防の演出中にブレスで札が燃える場合は今回扱わない（`burnTrack.js` の盤面の見た目は変えない）。
* **`js/anim/boardAnimator.js`**:
    * `start`: 終わりの時刻 `endTime` に `columnSettleEnd` の最大も含める（詰め直しの間も `isBusy()` が真になり、タップを無視する。今のカードの移動の間と同じ）。
    * `view()`: `BoardAnimView` に `columnYs: Map<number, number[]>`（列の番号 → 詰め直し中の各カードの上端 y。下から順）を足す。`motion.settles` のうち `sampleColumnSettle` が `null` でないものを入れる。動きがないときは空の `Map`。
* **`js/view/columnView.js`**: `drawColumn` に最後の引数 `cardYs = null`（詰め直し中の各カードの上端 y。下から順）を足す。`cardYs` が配列で長さが `cards.length` と同じならそれを使い、そうでなければ今のとおり `columnCardYs` で求める。カード・選んだ束の枠・置ける列の強調は、どれもその y で描く。
* **`js/view/boardView.js`**: 列を描くとき、燃える段の見た目がない（`burn === null`）なら `anim.columnYs.get(c) ?? null` を、ある（攻防の演出中）なら `null` を `drawColumn` に渡す。
* `js/scenes/BoardScene.js` は変えない（`buildPlanningMotion` の結果をそのまま `BoardAnimator` に渡しており、詰め直しは `isBusy()` に含まれるのでタップの無視・自動の攻防の待ちにそのまま効く）。当たり判定（`hitTest`）は操作後の枚数の位置のままでよい（詰め直しの間はタップを無視するため）。

時刻の例（14枚以上の列に山札から置く）: 0〜250ms 置くカードが山札から列の一番上の位置へ動き、列のもとからのカードは操作前の位置で待つ → 250〜450ms もとからのカードが詰まった位置へ動く（置いたカードは一番上に着いたまま）→ 450ms 以後タップを受ける。山札のめくれ（要件4）は 120〜320ms。

### 要件4: 山札のめくれの時刻
* **`js/anim/animConfig.js`**: `deckFlipDelayMs: 120`（山札からカードが抜けてから、下のカードがめくれ始めるまでの待ち。抜けたカードが半分ほど離れた頃。試遊で決め直す）を足す。
* **`js/anim/planningMotion.js`**: めくれを作るとき（`createDeckFlip`）の `delay` を `0` から `ANIM_TIMING.deckFlipDelayMs` にする。めくれは今もこの1か所で作っているので、置く・捨てる・手札に入れるで山札からカードが抜けたときと、山札が空になって捨て札から補充されたとき（`result.refills`。放つの後の補充を含む）のめくれが全部対象になる。
* 待っている間は `sampleDeckFlip` が `{ scaleX: 1, faceUp: false }` を返し、`deckView.js` が `drawCardFlip` で裏のまま描く（`deckFlip.js`・`deckView.js` は変えない）。めくれの時間（`deckFlipMs`）は変えない。終わりの時刻は `delay + duration` なので、`BoardAnimator.isBusy()` のタップを無視する間が待ちの分だけ延びる（今のとおりでよい）。

### 参照する責務
*   **憲法（`PROJECT_CONSTITUTION.md` 3章）からの要点**: ルールの判定や計算を画面の側に書き写さない。演出はルール層が出した結果を見せるだけ。`update` の中で描画しない、`draw` の中で状態を変えない。経過時間は `dt` と `draw` の `time` だけ。`ctx` の状態の変更は `save`／`restore` で囲む。`window` にプロパティを足さない。すべてのソースファイルの先頭に3行以内の責務の JSDoc を書き、その責務を外れる処理を足さない。関数・データ構造には JSDoc を書く。`js/` に `requestAnimationFrame`・`addEventListener`・`getContext`（REQ により `setTimeout`・`setInterval`・`performance.now()`・`Date.now()` も）を書かない。エンジンは `import { … } from 'oz'` だけで使う。スプライトJSは、エディタで描けない絵が必要な場合に限り、REQ で明示されたときだけ手で書いてよい（今回は REQ で明示。既定の export で `draw(ctx)` を持つ形）。

## 5. 懸念事項・要確認ポイント
1. **放つで列が短くなる場合（要件3）は起きない**: ルール層の `Game.release(c)` は列の札をすべて放つ（`splice(0)`）ので、放った後の列は空で、残って広がるカードがない（放った札はもとの位置のまま `releaseShow.js` が玉に変える）。このため放つの場合の詰め直し（「放った札が全部玉に変わってから」動き始める仕組み）は作らない（先回りの禁止）。テストプレイの「長い列から放つと、残ったカードが広がった位置へ滑らかに動く」は、今のルールでは見られない。発注者の意図と違う（たとえば放つ札が列の一部になる予定がある）なら、ルールを変えるサブフェイズで扱う。
2. **置いたカードが、もとの一番上のカードに一瞬重なる**: 詰まった列に置くと、置くカードは詰め直した後の一番上の位置（詰まった列では、もとの一番上のカードと同じ位置）へ動いて着き、その後にもとのカードが下から現れるように詰まった位置へ動く。REQ の「動くカードが着いてから動き始める」のとおりだが、見え方を試遊で確かめてほしい。
3. **自動の攻防に入る時刻が少し遅れる**: 行動を使い切る操作で詰め直し・めくれの待ちが起きると、`BoardAnimator.isBusy()` が長くなる分（最大でめくれは +120ms、詰め直しは +200ms）だけ、攻防に入るのが遅れる（`BoardScene` は変えない）。
4. **角丸の近似**: 角丸は 15° 刻みの直線（角ごとに6区間）で近似する。半径 8 で最大約 0.07px のずれで、今の `arcTo` の角丸と見た目は変わらない見込み。線の継ぎ目はスプライトの `draw` が `miter`（`miterLimit` 10）に固定する（今のゲームの `ctx` の既定と同じ）。目視で確かめてほしい。
5. **手で書いたスプライトとエディタの往復**: エディタの取り出しは「改行 + `const spriteData = `」から「`;` + 改行」までで、手で書いたファイルもエディタの書き出しと同じ形にする（タスク1で取り出しを模して確かめる）。実際にエディタの「開く」で開けるかは、テストプレイで確かめてほしい。
6. **カードの矩形が 100×140 以外になったとき**: 今の配置ではカードはちょうど 100×140 なので倍率は 1。配置を変えて縦横比が変わると、枠は縦横別々に伸び縮みし、線の太さも向きによって変わる（REQ の約束どおり）。
