## 1. 作業目的
発注者の試遊を受けて、次の2つを行う。
*   **要件1・2（ルールの変更）**: 束の補正を「合計 ＋（枚数 − 1）」に弱めたのに合わせて、敵の数値を下げ、敵の攻撃力・防御のスタンスの量を「最小〜最大の幅」から毎回抽選する値にする。量は予告を決めるとき（`Game.planIntent` → 行動の決まりの `planNext`）に、`Game` に渡された乱数で幅の中の整数を1つ（最小・最大を含む等確率）抽選する。予告の枠には抽選した値をそのまま出し、攻防はその値のとおりに行う。
    *   ゴブリンの軍勢: 最大 HP 30、攻撃 2〜5、防御のスタンス 2〜5（常時防御力 0・重み 3:1 は今のまま）。
    *   巨人: 最大 HP 60、攻撃 18〜22、常時防御力 3（周期 4・攻撃の直後の回復 25% で +20 は今のまま）。
    *   ドラゴン: 最大 HP 80、爪 4〜6、ブレス 10〜13、常時防御力 4（吸い込む 30%・燃やす札 4〜6 枚は今のまま）。
*   **要件3（見た目）**: 兵の陣地（自軍の攻撃・防御・修理、敵の側の陣地）の足元の範囲を、下の端は今のまま、上方向へ今の倍に広げる。ゴブリンの HP の群れも、一番手前の行の足元は今のまま、奥（上）へ今の倍に広げる。
*   **変えないもの**: 束の補正の式・カードのルール・城の数値・攻防の計算（`battle.js`）と順番・行動の種類の選び方・行動回数・金貨の換算。当たる位置・弾かれて落ちる動き・跳ねる高さなど、ほかの見た目の値。攻防の演出・早送り・スキップ・兵の移動の見せ方（`moveStyle: 'hop'`）は今のまま動く。

## 2. アーキテクチャ設計

### 全体の考え方
*   **抽選はルール層の `enemyBehaviors.js` の1か所**: 幅から整数を1つ抽選する関数 `rollAmount(range, random)`（`min + Math.floor(random() * (max − min + 1))`。乱数を必ず1回呼ぶ）を `enemyBehaviors.js` に置き、3つの決まり（`weighted`・`cycle`・`inhale`）の `planNext` が、攻撃・防御の行動を作るときにだけ呼ぶ。返す行動（`EnemyAction`）の `amount` は今と同じく「数」なので、予告（`enemy.intent`）・攻防（`Game.resolveBattle` → `computeBattle` の `enemyAction.amount`）・表示（`battleText.js` の `enemyActionText`）・演出（`battleSteps.js` の出来事の `amount`）は **変えずに** 抽選した値をそのまま使う。予告と攻防の値は同じオブジェクトから読むので食い違わない。
*   **幅の形は `config.js` の行動の設定**: 量の幅を `{ min, max }`（新しい型 `AmountRangeSpec`）で持つ。1つの値の量の項目（`EnemyActionSpec.amount`・`ClawSpec.amount`・`BreathSpec.amount`・`cycle` の `attack`）は幅の項目に置き換えて消す。最小と最大が同じなら一定の値になる（乱数は呼ぶが、結果は常に同じ）。
*   **乱数の呼び順（同じ種から同じ展開）**: 予告を決める1回の `planNext` の中で、次の順に呼ぶ。
    *   `weighted`: 行動の種類の抽選（1回。今のまま）→ 量の抽選（1回）。
    *   `cycle`: 振りかぶりのフェーズは呼ばない。攻撃のフェーズだけ量の抽選（1回）。
    *   `inhale`: 直前が吸い込む → ブレスの量の抽選（1回）。直前がブレス → 爪の量の抽選（1回）。それ以外 → 吸い込むかの抽選（1回。今のまま）→ 外れて爪なら爪の量の抽選（1回）、吸い込むなら量の抽選はしない。
    *   攻防のとき（`resolveBattle`）の乱数の順（回復の抽選 → 燃やす枚数 → 燃やす列）は変えない。
*   **`battle.js`・`Game.js` は敵の種類で分岐しない（今のまま）**: `Game.planIntent` は `planBehaviorAction` を呼ぶだけなのでコードは変えない（乱数の回数を書いた JSDoc の文だけ合わせる）。`battle.js` は変えない。
*   **陣地とゴブリンの群れは `layout.js` の定数だけ**: 陣地の矩形は `campTop = groundY − CAMP_FOOT_ABOVE`・`campH = CAMP_FOOT_ABOVE + CAMP_FOOT_BELOW` から作られ、家の位置（`campSlot`）は矩形の中の割合（R2 列）で決まるので、`CAMP_FOOT_ABOVE` を変えるだけで、下の端（地面の下 2px）を保ったまま上へ広がる。ゴブリンの群れは `hordeSlots` の `footY = groundY − TROOP_SIZE × HORDE_ROW_RISE × row` なので、`HORDE_ROW_RISE` を倍にするだけで、手前の行（row 0）の足元を保ったまま奥へ倍に広がる。`campSlots.js`・`campTroops.js`・`troopRoster.js`・`enemyBody.js`・`enemyAttacks.js`・`enemyView.js` は配置を読むだけで、コードは変えない（家の位置は番号だけで決まり、描く順は `sortY`（家の y）・`row` の奥から手前の順のまま）。

### 要件1: 敵の行動の量を幅から抽選する（ルールの変更）
*   **`js/rules/enemyBehaviors.js`**:
    *   新しい関数 `rollAmount(range, random)`（モジュールの中だけで使う。export しない）: `range.min + Math.floor(random() * (range.max − range.min + 1))` を返す。JSDoc に「`random()` は必ず1回呼ぶ」「min・max は整数で min ≤ max（設定の責任）」を書く。
    *   `pickWeighted(actions, random)`: 重みで行動の設定（`EnemyActionSpec`）を1つ選び、その `kind` と、`rollAmount(spec.range, random)` で抽選した `amount` の新しい行動を返す。乱数は種類で1回 → 量で1回の順（JSDoc の「`random()` は1回だけ呼ぶ」を「2回呼ぶ（種類 → 量の順）」に直す）。引数の型の JSDoc を `{ kind, range: { min, max }, weight }` にする。
