# RES: 作業計画・作業レポート (Phase 08-01) : 毒キノコ（予告した列の束を、攻防の前にひとりでに放たせる★2の敵）
* 参照元REQ: `./_log/req/261127_1850_Phase08-01_毒キノコの混乱.md`

## 1. 作業目的
★2の敵「毒キノコ」（識別子 `mushroom`）を足す。毒キノコは 2〜3 ターンに1回「混乱」を予告し、そのターンの始めに選んだ列（印の列）の束を、そのターンの攻防の前に、行動（AP）を使わずにひとりでに放たせる。放たれた兵は自軍のまま戦う。混乱のターンの敵の行動は「厚い守り」（攻撃しない・防御 8〜10）か「強い攻撃」（攻撃 8〜10・防御なし）のどちらかで、プレイヤーは予告を読んで、印の列の剣を逃がすか、盾を積み増すかを選ぶ（狙い「予告された束を、出撃の前に組み直せ」）。★2は巨人と毒キノコの2種になる。

* **列の印（新しい仕組み）**: 予告の任意の項目 `mark`（`{ kind, column, settled }`）として持つ。印の列はルール層（新しい `columnMarks.js`）が、予告を決めるとき（ターンの始め）に「束の枚数 → 束の数値の合計（放つ計算の区切りの合計と同じ。札の数字 + 札の +◯）→ 左」の順で1回だけ選ぶ（乱数を呼ばない）。印の種類の表（ルール層は「ひとりでに放つか」、画面は色・印の絵）を持ち、P9 の別の印を1行で足せる形にする。
* **ひとりでに放つ（新しい操作 `Game.releaseMarked`）**: 行動を使い切り盤面の動きが止まった後・「準備終了」の前に、盤面の流れが呼ぶ。自分で放つ `Game.release` と同じ本体（`releaseColumn`）を通り、違うのは行動を使わないことだけ。列が空なら空振り（何も放たない）。どちらでも印は「済み」になり、済むまでは `canResolveBattle` が偽（攻防に入れない）。
* **毒キノコの行動の決まり `confuse`（新しい種類）**: 初めの混乱は戦闘の 2〜3 ターン目、以後の間隔は 2〜3 ターン（設定）。混乱のターンは半々（設定）で強い攻撃（既存の中の種類 `heavy`）か厚い守り（既存の中の種類 `bigGuard`）に、混乱の印の求め（`mark: { kind: 'confuse' }`）を付ける。ふつうのターンは攻撃 3〜5 と防御（設定の `defense`。75%・2〜4）。加算・激昂はほかの敵と同じ道（`createIntent`）。
* **見た目**: 印の列を薄い紫に染め、放つ矢印の上に渦巻きの印。予告の札に紫の「混乱」の札、ターンの始まりの文字に「混乱 ＋ …」。ひとりでに放つとき列の上に「混乱！」。毒キノコの絵はスライムのコピーの仮のスプライト。
* **中断データ**: 予告の `mark` の形の確かめを足し、版を 10 に上げる。
* **DEBUG**: 敵の切り替えに毒キノコ（設定から自動）、次の行動「攻撃と防御」「混乱＋厚い守り」「混乱＋強い攻撃」、ルールの値に毒キノコの 13 本。
* **変えないもの**: ほかの8種の敵（数値・動き・見た目・予告・乱数を呼ぶ順と回数・攻防・時間割）、自軍の数値と放つ計算、1ターンの流れ（混乱のターンを除く）、★の抽選・★1の並び・最初の★2が巨人・ステージの加算・激昂、スコア・強化・精鋭の仕組み。数値はすべて設定に置く。
* ついでの直し: どこからも呼ばれていない `Game.isOver()` を消す（`js/` を検索して呼び出しがないことを確かめ済み）。`enemyPortrait.js` は変えない（`ENEMY_FIGURES` に行を足すだけで毒キノコの絵が出るため）。

### 要件1: 毒キノコの数値と行動（タスク6・タスク7）

mushroom: Object.freeze({
  name: '毒キノコ',
  star: 2,
  maxHp: 56,
  defense: Object.freeze({ chance: 0.75, range: Object.freeze({ min: 2, max: 4 }) }),
  behavior: Object.freeze({
    type: 'confuse',
    attackRange: Object.freeze({ min: 3, max: 5 }),
    heavyChance: 0.5,

    bigGuardRange: Object.freeze({ min: 8, max: 10 }),

* 型（タスク6で `EnemyBehaviorSpec` に先に足す。値がなくても型の説明だけなので壊れない）: `type` の並びに `'confuse'`（混乱の周期。ふつうのターンは攻撃と防御、混乱のターンは強い攻撃か厚い守りに列の印を付ける）。新しい項目 `heavyChance`（混乱のターンを強い攻撃にする確率。外れれば厚い守り。0〜1。`confuse` のみ）・`firstConfuseTurn`（その戦闘で最初に混乱するターンの幅。1 以上の整数。`confuse` のみ）・`confuseInterval`（混乱のターンから次の混乱のターンまでのターン数の幅。1 以上の整数。`confuse` のみ）。既存の `attackRange`・`heavyRange`・`bigGuardRange` の説明の対象に `confuse` を足す（`heavyRange`＝強い攻撃、`bigGuardRange`＝厚い守りの防御の量（加算の前））。`config.js` の先頭の説明の行動の決まりの並びに「混乱の周期（強い攻撃か厚い守り・列の印）」を足す（タスク7）。
* HP 56 は DEBUG のスライダーの刻み 2 の倍数。

**行動の決まり `confuse`（`enemyBehaviors.js`・タスク6）** 表 `BEHAVIORS` に1行足す。状態は `untilConfuse`（いま予告したターンから、次の混乱のターンまでのターン数。0 なら次のターンの予告で混乱。`null` はその戦闘でまだ予告していない＝最初のターン）。
```js
// 行動に混乱の印の求めを付ける（export。debugIntents.js も使う）
export function confusedAction(action) {
  return { ...action, mark: { kind: CONFUSE_MARK } };   // CONFUSE_MARK は columnMarks.js から import（'confuse'）
}

confuse: Object.freeze({
  initialState: () => ({ untilConfuse: null }),
  isState: (state) =>
    isPlainObject(state) &&
    (state.untilConfuse === null || (Number.isInteger(state.untilConfuse) && state.untilConfuse >= 0)),
  planNext: (behavior, state, random, unit) => {
    const remaining = state.untilConfuse === null
      ? rollAmount(behavior.firstConfuseTurn, random) - 1   // 最初のターン: その戦闘の何ターン目に初めて混乱するか（1回）
      : state.untilConfuse - 1;
    if (remaining > 0) {
      return { action: steadyAttackAction(behavior, random, unit), state: { untilConfuse: remaining } };
    }
    const base = random() < behavior.heavyChance
      ? heavyAction(behavior, random, unit)        // 強い攻撃（攻撃・variant 'heavy'・heavyRange）
      : bigGuardAction(behavior, random, unit);    // 厚い守り（防御だけ・variant 'bigGuard'・guard は bigGuardRange）
    return { action: confusedAction(base), state: { untilConfuse: rollAmount(behavior.confuseInterval, random) } };
  },
  countdown: () => null,                            // 次の混乱までの数え下ろしは画面に出さない
  isOpening: (action) => action.variant === 'heavy',// 強い攻撃のターンは隙（防御 0・防御の乱数を呼ばない）
}),
```
* 確かめ（数え方）: 最初の抽選が 2 → 1ターン目 `remaining` 1（ふつう、状態 1）→ 2ターン目 0（混乱）。3 → 1ターン目 2 → 2ターン目 1 → 3ターン目 0（混乱）。混乱のターンに間隔 2 を引けば、次は 2ターン後（例: 3 ターン目に混乱し、間隔 2 なら 5、3 なら 6 ターン目）。設定の最小が 1 でも Error にならない（`remaining` が 0 以下なら混乱）。
* **乱数を呼ぶ順と回数**（`planBehaviorAction` の説明に足す）:
  * 戦闘の最初のターン: 最初の混乱のターンの抽選 1 → （ふつうなら）攻撃の量 1 → `createIntent` の防御（張るか 1・量 1）＝ 4 回。
  * ふつうのターン: 攻撃の量 1 → 防御（張るか 1・量 1）＝ 3 回。
  * 混乱のターン: 強い攻撃か厚い守りかの抽選 1 → 量 1 → 次の混乱までの間隔 1 ＝ 3 回（防御の乱数は呼ばない。厚い守りは行動が `guard` を持つので抽選せず `guard` + 防御の加算、強い攻撃は隙なので 0）。
  * 印の列を選ぶとき: 0 回。
* `isBehaviorState` の説明の形の並び・`planBehaviorAction` の説明の乱数の並び・先頭の責務（決まりの一覧に「混乱の周期」。3行以内のまま）を書き足す。
* `heavyAction`・`bigGuardAction` は今の関数をそのまま使う（ほかの敵の行動は変わらない）。
* **加算と激昂**: 強い攻撃・ふつうの攻撃は `kind: 'attack'` なので `createIntent` が攻撃の加算を足し激昂の倍率をかける。厚い守りは `guard` に防御の加算、ふつうのターンの防御も張ったときだけ加算（今の決まりのまま）。混乱の間隔・印の列の選び方は激昂で変わらない。毒キノコだけの扱いはない。
* 予告（ふつう）: `{ kind: 'attack', amount, baseAmount, defense }`。強い攻撃: `{ kind: 'attack', amount, baseAmount, defense: 0, variant: 'heavy', mark }`。厚い守り: `{ kind: 'guard', amount: 0, baseAmount: 0, defense: guard + 加算, variant: 'bigGuard', mark }`。

### 要件2: 混乱の印の列（タスク1。ルール層）

**持ち方** 予告の任意の項目 `mark`（型 `ColumnMark`）: `{ kind: string, column: number, settled: boolean }`。`kind` は印の種類（`MARK_KINDS` のキー。今は `'confuse'`）、`column` は印の列の番号（0 から）、`settled` はその印の効き目（ひとりでに放つ・空振り）が済んだか。ふつうのターン・ほかの敵の予告は `mark` を持たない。
* 行動の決まりは列を知らないまま、行動に「印の求め」`mark: { kind }` を付けるだけ（`confusedAction`）。`createIntent` は `...rest` でそれを予告へ写し、`Game.intentOf` が最後に `withMarkColumn` で列を選んで `{ kind, column, settled: false }` にする（選ぶのはゲーム。行動の決まりに列を渡さない）。
* **型の書き分け（`combatants.js`・タスク1）**: 今の `EnemyIntent` は `EnemyAction & { … }` なので、`EnemyAction` に `mark?: MarkRequest`、`EnemyIntent` の側に `mark?: ColumnMark` を足すだけだと、予告の `mark` の型が `MarkRequest & ColumnMark` の交差になり、どちらの `mark` の説明か読み分けられない。そこで行動の `mark` と予告の `mark` を書き分ける:
  * `EnemyAction` の `@property {import('./columnMarks.js').MarkRequest} [mark]`: 「行動が持つ印の求め（任意。種類だけで列はまだない）。行動の決まりが付け、`createIntent` が予告へ写し、`Game.intentOf` が `withMarkColumn` で列の印（`ColumnMark`）に置き換える」。
  * `EnemyIntent` の `@typedef` を `Omit<EnemyAction, 'mark'> & { baseAmount: number, defense: number, minions?: number, mark?: import('./columnMarks.js').ColumnMark }` にし（`Omit` は `resultLayout.js` に前例がある）、型の説明の文に「予告の `mark` は列の印（種類・列・済んだか）。行動の `mark`（印の求め）とは形が違い、`enemy.intent` に入る予告（`Game.intentOf` の戻り値）は必ずこちら。印を求めない行動・ほかの敵の予告は持たない」を足す。
  * `createIntent`（`enemyIntent.js`。変えない）の戻り値は `withMarkColumn` の前の途中の形で、`mark` は印の求めのまま写っている。このことは `withMarkColumn` の引数の説明（「印の求め `MarkRequest` を持ちうる途中の予告」）に書き、`enemyIntent.js` の型の記述は変えない。
* 予告を作るのは `Game.intentOf` だけ（`planIntent`（コンストラクタ・`advancePhase`・DEBUG の敵の切り替え・ステージ移動・親を 0 にしたときの決め直し）と DEBUG の `chooseEnemyIntent`）なので、どの道でも、その時点の列から選ばれる。`refreshIntent`（DEBUG のターン・激昂）・`intentWithMinions`（子の数）は予告を写すだけで、`mark` はそのまま残る（選び直さない）。

## 5. 懸念事項・要確認ポイント
* **予告の札の「混乱」は、ひとりでに放たれた後もそのターンの間は出したままにする**（予告の一部として扱う。列の染めと渦巻きの印は放たれた時に消える）。放った後は札からも消したい場合は、`intentParts` の `mark` を「済んでいない印」だけにする1行の違いで直せる。
* **DEBUG の道だけ、1ターンに2回ひとりでに放たれることがある**: 行動を使い切ってから準備終了が出るまでの間はメニューを開けるので、ひとりでに放った後に DEBUG で次の行動を「混乱＋…」に替えると、新しい（済んでいない）印になり、閉じた後にもう一度放たれる（新しい予告として扱うため）。ふつうのプレイでは起きない。
* **DEBUG で指定した行動の乱数の順はふつうの抽選と違う**（ふつう: 強い攻撃か厚い守りかの抽選 → 量 → 間隔。DEBUG: 量 → 間隔。DEBUG の指定では種類の抽選をしない）。DEBUG の「攻撃と防御」は、次の混乱までの残りを変えない。
* **最初の混乱のターン（`firstConfuseTurn`）は DEBUG のスライダーに出さない**（今の敵には効かないため）。試すときは敵を切り替え直す（`switchEnemy` で決まりの状態が初期値に戻り、次の予告で引き直す）か、設定で変える。
* **強い攻撃・厚い守りの画面の名前**: 既存の中の種類 `heavy`・`bigGuard` を使うので、予告の札・ターンの始まりの文字では「大攻撃 9」（赤い札）・「防御 9」になる（狼の大攻撃・骸骨の大防御と同じ見え方）。DEBUG の項目名と選択肢は REQ の呼び名（強い攻撃・厚い守り）にする。画面でも「強い攻撃」「厚い守り」と出したい場合は、新しい中の種類を足す形に変える必要がある（`VARIANT_LABELS`・`INTENT_ICONS`・`EMPHASIZED_VARIANTS`・`ENEMY_SHOWS.mushroom.heavy` に行を足す）。
* **厚い守りのシールドの数**: 防御 8〜10＋加算（ステージ 100 で約 +24）のシールドを、スライムの形を元にしたシールドの範囲（`shield: { cx: 0.5, cy: 0.55, w: 0.75, h: 0.5 }`）に並べる。ドラゴン・巨人より多くなりうるので、目視で並びを確かめてほしい。
* **印の位置と色**（目視で確かめてほしい）: 渦巻きの印は、列の領域の下端と放つボタンの上端のすき間（16px）の中ほどに直径 30 で置くため、長い列では一番上の札の下端に約 7px かかる。紫の染めは不透明度 0.22 で札より奥に描く。「混乱！」は列の中ほどに 44px で約 0.9 秒。出始めは倍率 1.4 から `easeOutBack` で縮み、行き過ぎて一瞬 約 0.96 まで沈んでから 1 に落ち着く（意図した見え方。沈ませたくなければ `markCallShow.js` の補間を `easeOutCubic` に替える1か所の違い）。どれも試遊で決め直す値（`columnMarkView.js`・`markLooks.js`・`animConfig.js`）。
