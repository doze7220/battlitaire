## 1. 作業目的
試遊で見つかった小さな引っかかりを片付ける。
* 放った直後の待ち（札が全部玉に変わるまで盤面のタップを受け付けない間）を、最大で約 0.8 秒から約 0.4 秒に詰める（`animConfig.js` の値だけ）。
* 兵の陣地の縦の範囲を広げ（約 1.8 倍。地面の線より手前にも広げる）、兵が縦にばらけて並ぶようにする。手前の兵が城・敵に当たる・城に入るときの高さは、今までの範囲に収める。
* 05-01 で使われなくなった早送り・スキップの仕組み（`battleDirector.js` の `skip`・`skipped`、`hitStop.js` の `wallTimeAt`、`battleAnimConfig.js` の `fastScale`）を消す。
* 攻防で兵が出ていく・進む・帰る動きと、段取りの間に兵が陣地へ跳ぶ動きに、兵1体ごとの動き出しと速さのずれを入れる（乱数を使わず、種類と番号から決める）。
* 攻撃の兵が敵（ゴブリンの群れ・巨人とドラゴンの絵・シールド）に当たる時刻を1体ずつずらし、ダメージの数字（「-1」）・白い光・粒・ヒットストップ・当たりの音・敵の HP の表示値が、ずらした当たりの時刻に合わせてぱらぱらと出るようにする。
* ルール層（`js/rules/`）・攻防の結果・合図の長さ・カードの動き・最上部のゲージと予告と人数の表示の出し方は変えない。

### 要件4: 兵の動きにばらつきを入れる（`js/anim/troopJitter.js`（新規）・`js/anim/troopRoster.js`・`js/anim/battleAnimConfig.js`）
**ずれの値**（新規 `js/anim/troopJitter.js`。`campSlots.js` と同じく、種類と番号だけから決まる純粋関数。乱数は使わない）:
* 先頭の責務: 「兵1体ごとの動きのずれ（動き出しのずれの割合・動きの長さの倍率）を、種類と種類の中の番号から決める純粋関数を持つ。乱数は使わず、同じ種類と番号から必ず同じ値を返す。」
* 定数（JSDoc つき）:
    * `START_STEP = 0.6180339887498949`（動き出しのずれの列の増分。黄金比の小数部分）
    * `SPEED_STEP = 0.41421356237309515`（動きの長さの列の増分。√2 の小数部分）
    * 家の位置の R2 列（0.7548…・0.5698…）と別の増分にして、家の位置とずれがそろわないようにする。
    * `KIND_PHASES = Object.freeze({ attack: 0, defense: 0.2, heal: 0.4, enemy: 0.6, enemyGuard: 0.8 })`（ずれを入れる種類 → 列の始めのずらし。同じ番号の攻撃と防御の兵がそろわないように。表にない種類（`goblin`・`shield`・`flame`・`figure`）にはずれを入れない）
* 関数:
    * `frac(v)`（内部）: 小数部分。
    * `export function startJitter(kind, index)`: 表にある種類なら `frac(KIND_PHASES[kind] + index × START_STEP)`（0 以上 1 未満）、ない種類は 0。
    * `export function durationScale(kind, index, spread)`: 表にある種類なら `1 + spread × (2 × frac(KIND_PHASES[kind] + 0.5 + index × SPEED_STEP) − 1)`（`1 − spread` 以上 `1 + spread` 未満）、ない種類は 1。
    * 表の引き方は `Object.prototype.hasOwnProperty.call` を使う（ほかのファイルと同じ）。

**設定の値**（`battleAnimConfig.js` に足す。JSDoc に「試遊で決め直す」）:
* `moveJitterMs: 300` — 攻防で兵が出ていく・進む・帰る動きの、兵ごとの動き出しのずれの最大（ms。前からの遅れに足す）。
* `landJitterMs: 300` — 段取りの間に兵が陣地へ跳ぶ動きの、兵ごとの動き出しのずれの最大（ms）。
* `speedSpread: 0.15` — 兵ごとの動きの長さのばらつきの幅（割合。0.15 なら基準の 0.85〜1.15 倍）。
* 前からの遅れ（`moveStaggerMs` 12・`moveStaggerMaxMs` 300・`landStaggerMs` 10・`landStaggerMaxMs` 300）は変えない。動き出しの広がりは最大で 300 + 300 = **600ms**（今の 2 倍。REQ の目安 2〜3 倍の下の端にし、演出が長くなりすぎないようにした）。

**足し方**（`troopRoster.js`。前から遅らせる式の1か所に置く）:
* `import { durationScale, startJitter } from './troopJitter.js';`
* 内部の関数 `launchDelays(units, staggerMs, maxMs, jitterMs)`: 前から並んだ兵（`{kind, index}` を持つもの）の k 番目に `staggerDelay(k, n, staggerMs, maxMs) + jitterMs × startJitter(kind, index)` を求め、**一番小さい値が 0 になるように全員から引いて**返す（段の始め `t` に一番早い兵が出るので、段の始めに鳴る音のきっかけ（敵の攻撃の始まりなど）と動き出しがずれない）。`jitterMs` が 0 なら今の `staggerDelay` と同じ値になる。
* 内部の関数 `legMs(kind, index, baseMs, spread)`: `baseMs × durationScale(kind, index, spread)`。
* ずれを入れる動き（REQ の対象）:
    * `marchSquad`（攻撃の兵の行進・敵の側の兵の行進）: 遅れは `launchDelays(squad, moveStaggerMs, moveStaggerMaxMs, moveJitterMs)`、長さは `legMs(unit.kind, unit.index, marchMs, speedSpread)`。組の相手の脚も、進む側の兵と同じ遅れ・同じ長さにする（2体が同じ時刻にぶつかる位置に着く）。始まりは今と同じく `Math.max(t + 遅れ, freeAt)`。段の長さは「全員の `遅れ + 長さ` の最大」（兵がいなければ `marchMs`。ずれがなければ今の `marchMs + 広がり` と同じ）。
    * `enterCastle`（修理の兵が城へ入る・使われなかった自軍の兵が城へ帰る）: 遅れは `launchDelays(chosen, moveStaggerMs, moveStaggerMaxMs, moveJitterMs)`、長さは `legMs(…, moveMs, speedSpread)`。
    * `exitTroops`（敵の側の余りが右の画面の外へ帰る）: `enterCastle` と同じ。
    * `landTroops`（段取りの間に陣地へ跳ぶ）: `jumpTroops` に `jitterMs`・`spread` の引数を足し、`landTroops` は `landJitterMs`・`speedSpread` を渡す。`jumpTroops` は先に番号（`first + i`）から遅れを求め（`launchDelays` に `{kind, index}` の並びを渡す）、兵 i の現れる時刻と脚の始まりを `t + 遅れ`、脚の長さを `legMs(kind, index, moveMs, spread)` にする。返り値は「全員の `t + 遅れ + 長さ` の最大」（count が 0 以下なら `t`）。`releaseShow.js` は返り値（全員が家に着く時刻）を人数の表示の数え上げと演出の終わりに使っているので、そのまま合う。
* ずれを入れない動き:
    * `enterTroops`（敵の側の兵が画面の外・口から陣地へ現れる）: `jumpTroops` に `jitterMs = 0`・`spread = 0` を渡し、今と同じ動きにする（REQ の対象「出ていく・進む・帰る・陣地へ跳ぶ」に入らず、ブレスの炎の出方と敵の攻撃の始まりの音を崩さないため）。
    * `chargeTo`・`chargePairs`（当たりに行く動き）は要件5の決め方に従う（速さのばらつきは入れない）。
    * `clashPairs`（相打ちで落ちる）・`popTroops`（打撃で落ちる）・`spawnTroops`・`placeTroops` は変えない。
    * 炎（`flame`）・ゴブリンの群れ・シールドは、`troopJitter.js` の表にないので、どの動きでもずれが 0・倍率 1 になる。
* 名簿は攻防の始めに1回作るだけなので、ずれの計算は毎フレームには走らない。

### 要件5: 突撃の当たりをばらけさせる（`js/anim/troopRoster.js`・`js/anim/enemyBody.js`・`js/anim/battleTimeline.js`・`js/anim/battleAnimConfig.js`）
**当たりの間隔の設定**（`battleAnimConfig.js` に足す。JSDoc に「試遊で決め直す」）:
* `hitStaggerMs: 80` — 攻撃の兵が敵（群れ・絵・シールド）に1体ずつ当たる間隔の上限（ms）。
* `hitStaggerMaxMs: 1000` — 当たりの間隔の広がり全体の上限（ms）。
* 敵の打撃（90ms・上限 1200ms）と同じくらいの感触にし、兵が多いときに長くなりすぎないよう、上限を少し短くした。

**当たりに行く動き**（`troopRoster.js`）:
* `chargeTo` と `chargePairs` に、最後の引数 `pace`（`'move'` | `'hit'`。省くと `'move'`）を足す。表 `CHARGE_PACES = Object.freeze({ move: ['moveStaggerMs', 'moveStaggerMaxMs'], hit: ['hitStaggerMs', 'hitStaggerMaxMs'] })` から `BATTLE_ANIM` の設定名を引き、`staggerDelay(k, m, …)` で遅れを求める（内部の関数 `chargeDelay(pace, k, n)`。未知の `pace` は Error）。脚の長さは今と同じ `moveMs`（速さのばらつきは入れない）。
    * 速さを変えないので、当たる時刻は `t + hitMoveMs + 遅れ` で、1体ずつ等しい間隔になる（兵の `freeAt` が段の始めより後のときを除く。攻撃の兵は行進の段が終わってから当たるので、ふつうは等しい間隔）。
* `'move'` のときは今と同じ遅れ（`moveDelay`）。城に当たる敵の側の兵・炎（`battleTimeline.js` の `addCastleHit`）は `'move'` のままにし、敵の攻撃の時刻は変えない。
* 行き先の y は要件2のとおり（`chargeTo` は `contactY`、`chargePairs` は相手の y）。

**敵に当たる動き**（`enemyBody.js`）:
* `BODY_HITS` の `horde`（`chargePairs`）と `figure`（`chargeTo`）、`hitEnemyArmor`（`chargeTo`）に `'hit'` を渡す。これでゴブリンの群れ・巨人とドラゴンの絵・シールドに当たる時刻がずれる。

**当たりの時刻に合わせて出るもの**（`battleTimeline.js`）:
* 当たりの記録（光・「-1」・粒・ヒットストップ）: 今と同じく名簿の終わり方の時刻から作られるので、`battleTimeline.js` の変更は要らない（ヒットストップの段ごとの上限も今のまま）。
* **敵の HP の表示値**: `addEnemyHit` が使う関数を、内部の関数 `dropEnemyHpByHits(state, amount, arrivals, t)`（新規）に替える。
    * 当たった数 `arrivals.length` が `amount` と同じなら、当たり1つごとに「表示値を 1 減らす長さ 0 の変化」（`createHpChange({ from: shown, to: shown − 1, start: arrivals[k], duration: 0 })`）を時刻の順に足す。表示値は当たるたびにちょうど 1 減る。
    * 数が違うとき（念のため）は、今の `dropHp(state, 'enemy', amount, arrivals, t)` に任せる。
    * 段の長さは今の `dropHp` と同じ式（`最初 + max(hpMs, 最後 − 最初) − t`）にして、段の時間割と `defeatEnemyBody(state.body, t + d)`（巨人・ドラゴンが倒れ始める時刻）は今と同じ決め方のままにする。
    * `knockoutTime`（BGM を止める時刻）は、`to <= 0` になる最初の変化（とどめの当たり）の時刻になる。
    * 城の HP（`addCastleHit`・`addStrikeCastle` の `dropHp`）・修理（`addHeal`）・敵の回復は変えない。
* **当たりの音**: `dropEnemyHpByHits` は当たりの時刻をすべて `state.cueTimes` に足す（今は最初の1つだけ）。`addArmorBlock` も `arrivals` をすべて足す（空なら今と同じく `t + hitMoveMs` の1つ）。きっかけの種類（`enemyHit`・`armorBlock`）は今のまま。当たるたびに `enemyHit` の音・シールドの `block` の音が鳴る。80ms 間隔なので、1フレームで2つ以上鳴ることはふつうない。
* **ずらしを入れないと決めたもの**:
    * 相打ち（`block`・`enemyBlock`。敵の守り（敵の防御）との相打ちを含む）: 落ちる遅れは今の `fallDelay`（15ms・上限 250ms）のまま。行進（要件4のずれ入り）が全員終わってからぶつかる今の流れ（`clashStartOf`）と、段の最初のぶつかりで1回鳴る音を崩さないため。行進がばらけるので、ぶつかる前の動きはばらけて見える。
    * 修理の兵: 要件4のずれ（動き出し・速さ）だけを入れ、当たりの間隔は足さない（HP の表示値は今と同じく最初の兵から量番目の兵が城に入るまでの直線）。
    * 敵の攻撃（打撃・城に当たる敵の側の兵・炎）: 今のまま。

**演出の長さの見積もり**:
* 当たりの段（`enemyHit`・`armorBlock`）: 広がりが `min(12 × (n−1), 300)` から `min(80 × (n−1), 1000)` になる。5 体で +272ms、10 体で +612ms、14 体以上で +700ms（段ごと）。
* ずれを入れた動きの段（行進・修理・帰る）: 1つの段で最大およそ +300ms（動き出しのずれ）+ 基準の長さの 15%（行進 +105ms・修理 +90ms・帰る +68ms）。兵の数が多いほど上限に近づく。
* 1回の攻防の合計: ふつうの量で **+1〜2 秒**、兵が多く全部の段があるとき最大で約 **+2.3 秒**（例: ゴブリンの攻撃の行進 +0.4・攻撃の兵の行進 +0.4・当たり +0.7・修理 +0.4・帰る +0.4）。巨人・ドラゴンでシールドがあると、シールドの段の分（最大 +0.7 秒）がさらに足される。
* 段取りの間: 1回の放つで、兵が全員陣地に着くまでが最大およそ +360ms 延びる（行動を使い切ったときの「準備終了」が出るのもその分遅れる）。一方、要件1で玉に変わる時刻が最大 420ms 早まるので、放つ演出全体の長さはほぼ変わらない。
* 長すぎれば、`moveJitterMs`・`hitStaggerMs`・`hitStaggerMaxMs` を下げて決め直す（1か所）。

## 5. 懸念事項・要確認ポイント
* **当たりの音の数**: 攻撃の兵が敵・シールドに当たるたびに音（`enemyHit`・`block`）が鳴る（今は段で1回）。兵が多いと 80ms 間隔で十数回続けて鳴る。うるさければ `hitStaggerMs` を広げるか、音を間引く仕組みを別の REQ で決める（今回は作らない）。音の長さ・重なりは試遊で確かめてほしい。
* **HP の表示の減り方の変化**: 敵の HP の表示値は、当たるたびにちょうど 1 減るようになる（今は最初の当たりから最後の当たりまでの直線で、当たりより少し遅れて減っていた。1体だけ当たるときは 300ms 遅れていた）。そのため、とどめの当たりで BGM が止まる時刻も、1体だけのときは今より最大 300ms 早くなる。巨人・ドラゴンが倒れ始める時刻は今と同じ決め方（段の終わり）のまま。
* **敵の防御（敵の守り）との相打ちはずらさない**: REQ の「シールドで止められる兵（敵の防御・常時防御力で相殺される当たり）」のうち、常時防御力のシールドは当たりの間隔でずらす。敵の防御は相打ち（`enemyBlock`）で見せているので、相打ちの今の時刻の決め方（行進が全員終わってから 15ms ずつ）のままにした。行進がばらけるので、早く着いた組はぶつかるまで少し待つ。ぱらぱらと落ちるようにしたい場合は、次の REQ で相打ちの時刻の決め方を見直す。
* **演出の長さ**: 2章「演出の長さの見積もり」のとおり、1回の攻防でふつう +1〜2 秒、最大で約 +2.3 秒（シールドの段があるとさらに最大 +0.7 秒）延びる。長すぎれば `moveJitterMs`・`hitStaggerMs`・`hitStaggerMaxMs` を下げる。
* **動き出しの広がり**: REQ の目安（今の 2〜3 倍）の下の端（2 倍、最大 600ms）にした。少ない兵（2〜3 体）でも最大 300ms ずれるので、少ない兵ほど今よりばらけて見える。
* **城・敵の絵と兵の前後**: 描く順は変えない（城・敵の絵は兵全員より奥）。陣地の x は城・敵の絵とほとんど重ならないが、行進・帰る兵が城の絵の前を通るときは、地面の線より奥の兵も城の手前に描かれる（今と同じ）。不自然に見えれば、次の REQ で絵と兵を足元の y で混ぜて描く仕組みを決める。
* **玉の飛ぶ先**: 陣地の矩形の中心が下がるので、攻撃・防御・修理の玉が飛んで弾ける位置が 24px 下がる（時間は変わらない）。
* **手前の兵の当たる高さ**: 地面の線より手前（y 262 より下）の兵は、城・巨人・ドラゴン・シールドに当たる・城に入るとき、斜めに奥へ寄って y 262 で当たる。ゴブリンには相手のゴブリンの y で当たる。見え方は試遊で確かめてほしい。
* **攻撃の兵の当たりにヒットマークはない**: 攻撃の兵が敵・シールドに当たるときには、今もヒットマークは出ない（ヒットマークを作るのは敵の打撃のときだけ。`js/anim/enemyAttacks.js` の `addHitMark`）。今回もヒットマークは足さず、白い光・「-1」・粒（とヒットストップ・当たりの音）で当たりを見せる。REQ 要件5 はヒットマークがあるものとして書いているが、実コードに合わせた。

### テストプレイで確かめること（発注者が見る点）
* 列の札を放つと、札が玉に変わり終わるのが今より早く（最大でおよそ 0.4 秒）、すぐ次の操作ができる。連鎖の音は、玉に変わるのに合わせて鳴る。
* 兵が陣地で、今より縦にばらけて並ぶ。兵がたくさんいても、重なりが今より少ない。
    * 兵が空・行動のゲージの帯・人数の表示にはみ出さない。
    * 城や敵の絵との前後の重なりが自然に見える。
* 攻防の演出で、兵が出ていく・当たる・帰る動きが自然に見える（手前の兵も、奥の兵も）。手前の兵が城・巨人・ドラゴンに当たるときの高さがおかしくない。
* 兵が出る・進む・陣地へ跳ぶ動きが、そろわずにばらけて見える。
* 攻撃の兵が敵に当たるのが少しずつずれていて、白い光・ダメージの数字（「-1」）・粒・当たりの音がぱらぱらと続けて出る。敵の HP のゲージと数字も、当たるたびに減る。巨人・ドラゴンのシールドも1つずつ剥がれる。
* 攻防の結果（HP の増減・決着）は今と同じ。演出が長くなりすぎていない。
