## 1. 作業目的
いまの巨人は、03-01 で入れた仮の行動（攻撃・防御のスタンスの重みによる抽選）と仮の玉で出ている。今回は、巨人を「決まった周期で1回だけ重い攻撃をし、攻撃の直後にまれに HP を回復する」敵に作り変える。

* 巨人の行動の決まり（周期の攻撃と振りかぶり・数え下ろしの状態）と、攻撃の直後の回復の抽選・計算はルール層（`js/rules/`）に置く。行動の決まりは `js/rules/enemyBehaviors.js` の表に新しい種類（`'cycle'`）として足し、既存の重みによる抽選（`'weighted'`。ゴブリンの軍勢・ドラゴン）は変えない。
* 攻撃の直後の回復は、敵の行動の決まりの設定（`behavior.attackHeal`）から読み取る形にし、`battle.js`・`Game.js` に巨人専用の分岐を書かない。
* 戦闘の段に、巨人と戦っている間は常に数え下ろし（「攻撃まで あと3」〜「攻撃！」）を出し、振りかぶりのフェーズの予告の枠は「振りかぶり」にする。数え下ろしの残りはルール層から読む（描画の側で周期から計算し直さない）。
* 攻防の演出に「巨人の回復」の段（城への被害の後、自軍の突撃の前）を足し、敵の HP が増えて見え、巨人の上に緑の「+20」が出る。音はいまの城の回復と同じ音。
* 戦闘の段の巨人を、いまより大きな緑の玉にする（シールドマーク8個は大きな玉に合わせて並べ直す）。
* ゴブリンの軍勢・ドラゴンの行動と見た目、段取り・攻防の演出のほかの挙動・敵の入れ替わり・決着・音は変えない。ドラゴンの行動・見た目、結果の画面、タイトルの分離、振りかぶりの特別な演出、BGM は作らない。

### 要件1: 巨人の行動の決まり（周期の攻撃と振りかぶり）

#### 設定（`js/rules/config.js`）
* `enemies.giant.behavior` を次に置き換える（重みつきの `actions` は削除）。すべて `Object.freeze` で凍結する。`name: '巨人'`・`maxHp: 80`・`armor: 8` はいまのまま。
    ```js
    behavior: Object.freeze({
      type: 'cycle',
      cycleLength: 4,
      attack: 40,
      attackHeal: Object.freeze({ chance: 0.25, amount: 20 }),
    }),
    ```
    * `cycleLength`: 1周期のフェーズ数（最後のフェーズで攻撃、ほかは振りかぶり。1以上の整数）。
    * `attack`: 周期の最後のフェーズの攻撃の量。
    * `attackHeal`: 攻撃の直後の回復（`chance`: 確率 0〜1、`amount`: 回復の量）。任意の項目で、どの決まりの種類にも書ける（書かなければ回復しない）。
* ゴブリンの軍勢・ドラゴンの `behavior`（`'weighted'`）は変えない。
* 型（JSDoc）:
    * `EnemyBehaviorSpec` を次に直す: `type`（`'weighted'`＝重みによる抽選、`'cycle'`＝周期の攻撃）、`actions?`（`'weighted'` のみ）、`cycleLength?`・`attack?`（`'cycle'` のみ）、`attackHeal?`（任意。`Readonly<AttackHealSpec>`）。
    * `AttackHealSpec`（新規）: `{ chance: number, amount: number }`。
    * 先頭の責務定義に「巨人の周期と攻撃の直後の回復」が分かるよう「行動の決まり（重みによる抽選・周期の攻撃と攻撃の直後の回復）」と書き足す（3行以内を保つ）。

#### 行動の決まり（`js/rules/enemyBehaviors.js`）
* `BEHAVIORS` の表の項目の形を `{ initialState(behavior), planNext(behavior, state, random), countdown(behavior, state) }` にする（`countdown` を足す）。
    * `weighted`: いまの `initialState`・`planNext` はそのまま。`countdown: () => null` を足す。
    * `cycle`（新規）:
        * `initialState: () => ({ countdown: null })`（まだ周期が始まっていない）。
        * `planNext: (behavior, state) => { ... }`（乱数は使わない）:
            * `const countdown = state.countdown === null || state.countdown <= 0 ? behavior.cycleLength - 1 : state.countdown - 1;`
            * `countdown === 0` なら `action = { kind: 'attack', amount: behavior.attack }`、それ以外は `action = { kind: 'windup', amount: 0 }`。
            * 戻り値 `{ action, state: { countdown } }`（引数の `state` は書き換えない）。
            * 結果: 周期 4 で、巨人が出た最初のフェーズから 3（振りかぶり）→ 2 → 1 → 0（攻撃）→ 3 → …。攻撃の次のフェーズは回復の有無に関係なく 3 から始まる。
        * `countdown: (behavior, state) => state.countdown`（この フェーズの攻撃までの残りフェーズ数。0 なら攻撃するフェーズ）。
* 公開する関数を足す:
    * `behaviorCountdown(behavior, state)` → `number|null`。`lookupBehavior(behavior).countdown(behavior, state)` を返す（数え下ろしを持たない決まりは `null`）。未知の種類は Error。
    * `rollAttackHeal(behavior, action, random)` → `number`（攻撃の直後の回復の候補の量。外れ・対象外は 0）。
        * `action.kind !== 'attack'`、または `behavior.attackHeal` がない、または `attackHeal.amount <= 0` なら、`random` を呼ばずに 0。
        * それ以外は `random()` を1回だけ呼び、`random() < attackHeal.chance` なら `attackHeal.amount`、そうでなければ 0。
        * 最大 HP での頭打ちはここでは行わない（`battle.js` が行う）。
* 先頭の責務定義を「敵の行動の決まり（種類ごとの状態の初期値・次の行動の決め方・数え下ろしの問い合わせ）の表と呼び分け、攻撃の直後の回復の抽選。渡された乱数だけを使う純粋な関数（ルール層）。」の趣旨に直す（3行以内）。
* `BEHAVIORS` の `@type` の JSDoc に `countdown` を足す。

#### 数字の浮き出しの記録（`js/anim/popTrack.js`。新規）
* 責務: 数字の浮き出し（敵の回復の量など）1つの記録（量と、時刻ごとの濃さ）と、時計からの見た目を求める純粋な関数。描画も状態の変更も行わない。
* `@typedef PopKey`: `{ time: number, alpha: number }`（ms、濃さ 0〜1）。
* `@typedef PopTrack`: `{ amount: number, keys: PopKey[] }`（keys は time の昇順）。
* `createPopTrack(amount, keys)` → `PopTrack`（keys は写して持つ）。
* `popTrackEnd(track)` → 最後の点の時刻（点がなければ 0）。
* `samplePopTrack(track, clock)` → `{ amount, alpha }|null`。最初の点より前は `null`。点の間は濃さを直線で補間（`easing.js` の `clamp01`・`lerp` を使う）。最後の点より後は最後の点の濃さ。濃さが 0 以下なら `null`。

## 5. 懸念事項・要確認ポイント
* 計画時点の判断（回復の設定の置き場所）: 攻撃の直後の回復は、行動の決まりの設定の任意の項目 `behavior.attackHeal` に置き、抽選は `enemyBehaviors.js` の `rollAttackHeal`、頭打ちと出来事は `battle.js` で行う。`Game.js` は設定を渡すだけで、巨人の識別子で分岐しない。
* 計画時点の判断（振りかぶりの表し方）: 振りかぶりは新しい行動の種類 `'windup'`（量 0）として予告に入れる（予告を `null` にすると「－」になり、要件2の「振りかぶり」の表示と攻防の出来事の「敵の行動は必ず入る」が崩れるため）。攻防の出来事は `enemyWindup`（量 0）で、演出の段は作らない。
* 計画時点の判断（数え下ろしの状態）: 決まりの状態 `{ countdown }` は「このフェーズの攻撃までの残りフェーズ数」で、フェーズの頭の予告（`planBehaviorAction`）で進む。初期値 `null` は「まだ周期が始まっていない」を表し、最初の予告で `cycleLength - 1` になる。`Game.attackCountdown()` で描画の側が読む。
* 計画時点の判断（乱数の消費）: 回復の抽選は、攻撃のフェーズでかつ `attackHeal` があるときだけ `random()` を1回呼ぶ（城が落ちる攻防でも呼ぶ）。巨人の `cycle` の予告は乱数を使わない（03-01 の仮の巨人は予告ごとに1回使っていた）。ゴブリンの軍勢・ドラゴンの乱数の使い方は変わらない。
* 計画時点の判断（表示の文言・位置）: 数え下ろしは段の右上の枠（幅 220、「フェーズ」の枠と同じ高さ・フォント）に「攻撃まで あと3」〜「攻撃！」、予告の枠は「次の行動 振りかぶり」。回復の量は巨人の玉の真上（数え下ろしの枠との間）に緑の 40px 太字「+20」。文字の幅は `drawBox` の最大の幅で必ず枠に収まる。実際の見た目は目視で確認してほしい。
* 計画時点の判断（巨人の玉の大きさと兵の当たる位置）: 巨人の玉はいまの敵の矩形と中心の x をそろえて 160（いまは 120）にし、右端を HP・予告の枠の右端にそろえる。兵の配置（`armorHitX`・`enemyHitX`・敵兵の出る位置）は変えないので、兵士は玉の左端の少し内側（20px）でシールドマークに当たり、敵兵は玉の左端に少し重なって出る。不自然なら、敵ごとの兵の当たる位置を `layout.js` に足す形で直せる（目視で確認してほしい）。
