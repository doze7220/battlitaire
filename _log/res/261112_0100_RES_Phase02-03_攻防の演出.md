# RES: 作業計画・作業レポート (Phase 02-03) : 攻防の演出
* 参照元REQ: `./_log/req/261112_0100_Phase02-03_攻防の演出.md`

## 1. 作業目的
02-02 までは、「行動終了」を押した後の攻防は、結果の窓（`BattleResultScene`）が出来事を文字で並べるだけである。今回は、攻防の出来事の並びを、最上段（戦闘）での兵の動き（守りが並ぶ → 敵兵の突撃 → 相殺 → 城へのダメージ → 自軍の突撃 → 敵の防御での相殺 → 敵へのダメージ → 大工の修理）で見せ、結果の窓を廃止する。兵の数が多いときは10人ごとに大きなユニットにまとめる。演出の間は最下段に「早送り」（等速と3倍速の切り替え。`Engine.timeScale`）と「スキップ」を出す。決着していなければ演出の後に少し間を置いて自動で次のフェーズへ進み、決着したら最上段に「勝ち」「負け」と案内を出して、タップでタイトルへ戻る。

ルール層（`js/rules/`）は変えない。攻防は今までどおり「行動終了」の時点で `Game.resolveBattle()` が一度に結果を決め、演出はその戻り値 `BattleResult` と、攻防の前にシーンが読んだ値（城・敵の HP、攻撃・防御ゲージの値）だけから作る。効果音・兵の画像・敵の種類ごとの見た目・タイトルや結果の画面の作り込みは作らない。段取り（カードの動き）の挙動は変えない。

### 画面の重なり方（今の作りの把握と方針）
* `Engine.pushScene` で積むと、背面の `BoardScene` は `update` と入力が止まり、`draw` は続く（`oz/ENGINE_API.md` 6章）。同じレイヤー `'main'` で、背面 → 手前の順に描かれる（10章）。
* `resolveBattle()` の直後、ルール層の城・敵の HP はすでに攻防後の値である。背面の `BoardScene` はそれで最上段を描くので、手前の演出のシーンは**最上段（戦闘）全体と最下段（UI）全体を不透明に描き直して覆う**。最上段は `drawBattleStage` が段全体を空の色で塗るので、そのまま覆える。最下段は、演出用の最下段の描画で、段全体を不透明の色で塗ってから早送り・スキップを描く。ソリティアの段（ゲージ・山札・列・手札）は背面の盤面がそのまま見えてよい（ゲージは `startNextPhase` まで攻防の前の値のまま）。
* 敵の予告: `resolveBattle()` は `game.enemy.intent` を変えない（`startNextPhase` で変わる）。演出は `result.enemyAction`（この攻防の行動）を予告の枠に出す。

### 要件1: 兵の動きで出来事の並びを見せる

#### 段の並び（`js/anim/battleSteps.js`）
* `snapshotBattle(game)` → `BattleSnapshot` = `{ castleHp, enemyHp, attack, defense }`。`game.castle.hp`・`game.enemy.hp`・`game.gauges.attack ?? 0`・`game.gauges.defense ?? 0` を読むだけ（ルール層は import しない。`game` は引数）。`BoardScene` が `resolveBattle()` を呼ぶ**前に**呼ぶ。
* `buildBattleSteps(result, before)` → `BattleStep[]`。`BattleStep` = `{ type, amount }`（`type` は下の表）。`result.events` を先頭から読み、次の規則で並べる。
    | 段（`type`） | 量（`amount`） | 入れる条件 |
    | --- | --- | --- |
    | `'form'` | （使わない。0）。代わりに `guards`（守備兵の数 = `before.defense`）と `enemyGuards`（敵の守りの数 = `enemyDefend` の量。なければ 0）を持つ | `guards > 0` または `enemyGuards > 0` のとき、先頭に1つ |
    | `'enemyMarch'` | `enemyAttack` の量 | `enemyAttack` があり量が 0 より大きいとき、`form` の次 |
    | `'block'` | `block` の量 | 出来事 `block` があるとき |
    | `'castleHit'` | `castleDamage` の量 | 出来事 `castleDamage` があるとき |
    | `'march'` | `before.attack` | `before.attack > 0` で、出来事 `lose` で止まっていないとき。`enemyBlock`・`enemyDamage`・`heal`・`win` のうち最初に出てきたものの直前に入れる（どれも出てこなければ並びの最後） |
    | `'enemyBlock'` | `enemyBlock` の量 | 出来事 `enemyBlock` があるとき |
    | `'enemyHit'` | `enemyDamage` の量 | 出来事 `enemyDamage` があるとき |
    | `'heal'` | `heal` の量 | 出来事 `heal` があるとき |
    * 出来事 `lose`・`win` に来たら、そこで読むのをやめる（残りの段は作らない）。ルール層の並びは `lose` を `castleDamage` の直後、`win` を `enemyDamage` の直後に置くので、要件の「負けは4の後、勝ちは7の後」になる。
    * `BattleStep` の `@typedef` は `{ type: 'form'|'enemyMarch'|'block'|'castleHit'|'march'|'enemyBlock'|'enemyHit'|'heal', amount: number, guards?: number, enemyGuards?: number }`。
* ルールの判定や計算はしない（量は出来事の量・攻防の前の値をそのまま使う）。

#### 兵の群れと位置
* 群れの種類（`SquadKind`）は5つ: `'guard'`（守備兵）・`'enemyGuard'`（敵の守り）・`'enemy'`（敵兵）・`'soldier'`（兵士）・`'carpenter'`（大工）。群れは種類ごとに1つ（1本の動きの記録 `SquadTrack`）。
* 戦場の横の位置は `layout.js` の `TroopLayout`（後述）から読む。城の前から敵の前までを4つの区画に分け、その中心を左から `guardX`（A: 守備兵が並ぶ・兵士が出る）、`defenseClashX`（B: 敵兵が守備兵とぶつかる位置）、`offenseClashX`（C: 兵士が敵の守りとぶつかる位置）、`enemyGuardX`（D: 敵の守りが並ぶ・敵兵が出る）とする。城に当たる位置は `castleHitX`（城の中心）、敵に当たる位置は `enemyHitX`（敵の中心）、大工が現れる位置は `carpenterX`（城の中心）。

#### 時間割（`js/anim/battleTimeline.js`）
* `buildBattleTimeline(steps, before, troopLayout)` → `BattleTimeline`。時刻の位置 `t` を 0 から進め、段ごとに群れの記録（キー）と HP の変化を足す。2つ目以降の段の前に `stepGapMs` を足す。各段の時間（`T` は `BATTLE_ANIM`）と中身:
    | 段 | 時間 | 群れのキー（`{time, x, count, alpha}`） | HP の変化 |
    | --- | --- | --- | --- |
    | `form` | `formMs` | `guards > 0` なら guard: `(t, A, guards, 0)` → `(t+formMs, A, guards, 1)`。`enemyGuards > 0` なら enemyGuard: `(t, D, enemyGuards, 0)` → `(t+formMs, D, enemyGuards, 1)` | なし |
    | `enemyMarch` | `marchMs` | enemy: `(t, D, n, 1)` → `(t+marchMs, B, n, 1)` | なし |
    | `block` | `clashMs` | 中間 `tm = t + clashMs/2` に、guard: `(tm, 今のx, 今の数−k, 1)`、enemy: `(tm, 今のx, 今の数−k, 1)`。その前に両方の今の状態を `(t, …)` で1つ置いておく | なし |
    | `castleHit` | `hitMoveMs + hpMs` | enemy: `(t, 今のx, m, 1)` → `(t+hitMoveMs, castleHitX, m, 1)` → `(t+hitMoveMs, castleHitX, 0, 0)`（`m` は今の数。量を超える分も一緒に消える） | 城: 今の表示値 → 今の表示値 − 量、開始 `t+hitMoveMs`、長さ `hpMs` |
    | `march` | `marchMs` | soldier: `(t, A, s, 1)` → `(t+marchMs, C, s, 1)` | なし |
    | `enemyBlock` | `clashMs` | `block` と同じ形で soldier と enemyGuard を減らす | なし |
    | `enemyHit` | `hitMoveMs + hpMs` | soldier: `castleHit` と同じ形で `enemyHitX` へ進んで消える | 敵: 今の表示値 → 今の表示値 − 量、開始 `t+hitMoveMs`、長さ `hpMs` |
    | `heal` | `formMs + hpMs + fadeMs` | carpenter: `(t, carpenterX, h, 0)` → `(t+formMs, carpenterX, h, 1)` → `(t+formMs+hpMs, carpenterX, h, 1)` → `(t+formMs+hpMs+fadeMs, carpenterX, h, 0)` | 城: 今の表示値 → 今の表示値 + 量、開始 `t+formMs`、長さ `hpMs` |
    * 「今のx・今の数」は、その群れの最後のキーの値。HP の「今の表示値」は、`before.castleHp`・`before.enemyHp` から始めて、足した変化の `to` で更新していく値。
* **余りの消え方**（使われずに余った群れ。ルールでも余りは消える）: 最後のキーの数が 0 より大きく alpha が 0 より大きい群れに、`(time, 今のx, 今の数, 1)` → `(time+fadeMs, 今のx, 今の数, 0)` を足して、`fadeMs` かけて消す（次の段と重なって進み、時刻の位置 `t` は進めない）。
    * `march`・`enemyBlock`・`enemyHit`・`heal` のうち最初の段を始めるとき（その段の開始時刻）: guard・enemy の余りを消す。
    * `heal` を始めるとき: enemyGuard・soldier の余りを消す。
    * すべての段の後（最後の段の終わりの時刻）: 5種すべての余りを消す。
* `BattleTimeline` = `{ steps: TimedStep[], squads: SquadTrack[], castleHpChanges: HpChange[], enemyHpChanges: HpChange[], castleHpStart: number, enemyHpStart: number, endTime: number }`。`TimedStep` = `BattleStep` に `start`・`end`（ms）を足したもの。`endTime` は、最後の段の終わりと、すべての群れの記録の終わり（`squadTrackEnd`）の最大。段が1つもなければ 0。
* 時間・換算の数値は `BATTLE_ANIM` から読み、位置は `troopLayout` から読む（直書きしない）。

#### 群れの動きの記録（`js/anim/squadTrack.js`）
* `SquadKey` = `{ time, x, count, alpha }`。`SquadTrack` = `{ kind: SquadKind, keys: SquadKey[] }`（`time` の昇順。同じ時刻のキーが続いてよい）。
* `createSquadTrack(kind)`、`addSquadKey(track, key)`（最後のキーより前の時刻なら Error を投げる）、`lastSquadKey(track)`（なければ `null`）、`squadTrackEnd(track)`（最後のキーの時刻。キーがなければ 0）。
* `sampleSquadTrack(track, clock)` → `SquadSample` = `{ kind, x, count, alpha }` または `null`:
    * `time ≤ clock` の最後のキーを `i` とする（なければ `null`。まだ出ていない）。
    * 次のキー `i+1` があれば、`u = clamp01((clock − key[i].time) / (key[i+1].time − key[i].time))`（時間の差が 0 なら 1）、`x = lerp(x_i, x_{i+1}, easeInOutQuad(u))`、`alpha = lerp(alpha_i, alpha_{i+1}, u)`。なければ `x_i`・`alpha_i`。
    * `count` は `key[i].count`（数はキーの時刻で一度に変わる）。
    * `count ≤ 0` または `alpha ≤ 0` なら `null`（見えない）。

#### HP の表示値（`js/anim/hpTrack.js`）
* `HpChange` = `{ from, to, start, duration }`。`createHpChange({ from, to, start, duration })`、`hpChangeEnd(change)`。
* `sampleHp(initial, changes, clock)` → 整数: `initial` から始め、`changes` を順に見て、`start ≤ clock` のものについて、`clock ≥ start + duration`（または `duration ≤ 0`）なら `to`、それ以外は `from + Math.trunc((to − from) × (clock − start) / duration)`（0の向きに切るので、途中で `to` が先に出ない）。

#### 演出全体の管理（`js/anim/battleDirector.js`）
* クラス `BattleDirector`。コンストラクタ `({ timeline, result, troopLayout })`。フィールド: `timeline`、`result`（`BattleResult`。終わったときの HP の値に使う）、`troopLayout`、`clock`（ms、0）、`skipped`（`false`）。
* `update(ms)`: `clock += ms`（終わった後も進める。終わりの後の間を数えるため）。
* `skip()`: `skipped = true`、`clock = Math.max(clock, timeline.endTime)`。
* `isFinished()`: `clock ≥ timeline.endTime`。
* `isReadyToLeave()`: `isFinished() && (skipped || clock ≥ timeline.endTime + BATTLE_ANIM.endDelayMs)`。
* `currentStepType()`: `start ≤ clock < end` の段の `type`。なければ `null`。
* `view()` → `BattleLook`（状態は変えない）:
    * `finished`: `isFinished()`。
    * `castleHp`・`enemyHp`: 終わっていれば `result.castleHp`・`result.enemyHp`（ルール層の攻防後の値と必ず一致させる）。それ以外は `sampleHp(timeline.castleHpStart, timeline.castleHpChanges, clock)`・`sampleHp(timeline.enemyHpStart, timeline.enemyHpChanges, clock)`。
    * `units`: 終わっていれば空の配列。それ以外は、各群れの `sampleSquadTrack` が `null` でないものを `formationUnits(sample, troopLayout, BATTLE_ANIM.unitSize)` で兵の並びにして、つないだもの。
    * `stepType`: `currentStepType()`。
* ルール層の状態・`BattleResult` は読むだけで書き換えない。

### 要件2: 数が多いときは大きなユニットにまとめる（`js/anim/troopFormation.js`）
* `splitUnits(count, unitSize)` → `{ big: Math.floor(count / unitSize), small: count % unitSize }`（例: 36人・10 → 大3・小6）。
* `formationUnits(sample, troopLayout, unitSize)` → `UnitLook[]`。`UnitLook` = `{ kind, big: boolean, x, footY, w, h, alpha }`（`x` は中心、`footY` は足元の y）。
    * 大きなユニットは後ろの列（足元 `troopLayout.backFootY`、大きさ `bigW`×`bigH`）、小さな兵は前の列（足元 `troopLayout.groundY`、大きさ `smallW`×`smallH`）に並べる。片方しかなければ、その種類を前の列（足元 `groundY`）に置く。
    * 1つの列の `n` 体は、`sample.x` を中心に横に並べる。間隔 `pitch = n ≤ 1 ? 0 : Math.min(w × troopLayout.spacing, (troopLayout.zoneW − w) / (n − 1))`（区画の幅に収まるよう詰め、重なってよい）。左から `i` 番目の中心 `x = sample.x + (i − (n − 1) / 2) × pitch`。
    * 返す順は、後ろの列（大）→ 前の列（小）（後ろから描くため）。
    * `alpha` は `sample.alpha`。
* 換算の人数 `unitSize`（10）は `BATTLE_ANIM.unitSize` の1か所。相殺・ダメージで数が変わると、その時点の数で並べ直す（大きなユニットが小さな兵に割れて見えてよい）。

### 要件3: 早送りとスキップ
* **配置（`layout.js`）**: `Layout` に `battleControls` = `{ fastForward: Rect, skip: Rect }` を足す。今の「行動終了」の矩形 `hud.actionEnd` を左右に2つに分ける（各幅 `(actionEnd.w − UI_GAP_X) / 2`、高さは `actionEnd.h`（100）。論理解像度 720 では幅およそ 228）。左が早送り、右がスキップ。
* **当たり判定（`layout.js`）**: `Layout` に `battleHitTest(x, y)` を足す → `'fastForward'|'skip'|null`。`hitTest` は変えない。
* **描画（`hudView.js` に関数を足す）**: `drawBattleHud(ctx, hudLayout, controls, { fast, showButtons })`。段全体（`hudLayout.panel`）を不透明の色 `BATTLE_PANEL_FILL`（盤面の背景に今の半透明の帯を重ねた色に近い不透明色、例 `'#172b23'`）で塗り、背面の残りの行動回数・「行動終了」を覆う。`showButtons` なら2つのボタンを描く: 早送りは「早送り」と、`fast` のときは押し込んだ見た目（明るい地と縁）と「×3」（倍率の文字は引数 `fastLabel` で受け取る。後述）、スキップは「スキップ」。文字・色・フォントは見た目の定数。
    * 倍率の表示: `drawBattleHud` の引数に `fastLabel`（例 `'×3'`）を足し、シーンが `` `×${BATTLE_ANIM.fastScale}` `` を渡す（3の数値を描画の側に直書きしない）。
* **シーン**: 早送りを押すたびに `this.fast = !this.fast`、`Engine.timeScale = this.fast ? BATTLE_ANIM.fastScale : 1`。スキップを押すと `this.director.skip()`、`this.fast = false`、`Engine.timeScale = 1`。演出の間は、この2つ以外のタップは何もしない（背面の盤面には入力が届かない。`oz/ENGINE_API.md` 6章）。
* **等速に戻す**: `update` で `director.isFinished()` になったら、`Engine.timeScale` が 1 でなければ 1 にし、`this.fast = false` にする。シーンを抜ける2つの道（`update` の `popScene`、`onPointer` の `changeScene`）の直前でも `Engine.timeScale = 1` にする。`destroy` では戻さない（抜ける道はこの2つだけで、どちらも先に戻すため）。

### 要件4: 演出の終わり
* **決着していない**（`result.outcome === null`）: `update` で `director.isReadyToLeave()`（終わってから `endDelayMs`、スキップならすぐ）かつ `game.canStartNextPhase()` なら、`Engine.timeScale = 1`、`game.startNextPhase()`、`Engine.popScene()`。タップは要らない。
* **決着した**: 終わったら最上段に、段の上に半透明の暗幕・大きな「勝ち」または「負け」（`battleText.js` の `outcomeText`）・「タップでタイトルへ」を描く。早送り・スキップのボタンは消す（`showButtons: false`）。終わった後の `'down'` は、画面のどこでも `Engine.timeScale = 1` → `Engine.changeScene(this.createTitle())`。
* 決着の表示の位置は `layout.js` の `BattleLayout.outcome` = `{ x, textY, hintY }`（段の中央の x と、段の高さに対する割合から求めた y）。
* 終わった後（決着していないときの間の途中も含む）は、早送り・スキップのボタンを出さない。
* 結果の窓は廃止する（後述「結果の窓の廃止」）。

### 要件5: 速さは1か所で変えられる（`js/anim/battleAnimConfig.js`）
* 凍結したオブジェクト `BATTLE_ANIM` に次をまとめる（JSDoc に「試遊で決め直す」と書く）。ほかのファイルにこれらの数値を書かない。
    | 名前 | 初期値 | 意味 |
    | --- | --- | --- |
    | `formMs` | 500 | 守り（守備兵・敵の守り）が並ぶ時間、大工が現れる時間 |
    | `marchMs` | 700 | 敵兵・兵士が出てからぶつかる位置まで進む時間 |
    | `clashMs` | 400 | ぶつかって消える段の時間（中間で数が減る） |
    | `hitMoveMs` | 350 | 残った兵が城・敵に当たるまで進む時間 |
    | `hpMs` | 300 | HP の表示が変わる時間（大工が直す時間も同じ） |
    | `fadeMs` | 250 | 余った兵・大工が消える時間 |
    | `stepGapMs` | 150 | 段と段の間 |
    | `endDelayMs` | 500 | 演出が終わってから次のフェーズへ進むまでの間（決着していないとき） |
    | `unitSize` | 10 | 大きなユニット1体にまとめる人数 |
    | `fastScale` | 3 | 早送りの倍率（`Engine.timeScale` の値） |
* 長さの見積もり（等速）: 敵が攻撃し、守備・攻撃・回復がすべてある場合がいちばん長く、`500 + (150+700) + (150+400) + (150+650) + (150+700) + (150+650) + (150+1050)` ≈ 5.55秒。兵の数で長さは変わらない（数は並べ方だけに効く）。
* 補間: `easing.js` に `easeInOutQuad(t)` を足す（`t < 0.5 ? 2t² : 1 − (−2t + 2)² / 2`）。群れの移動に使う。

### 要件6: ゲームの結果は変わらない
* `BoardScene` は「行動終了」で `before = snapshotBattle(game)` → `result = game.resolveBattle()` → `result !== null` なら演出のシーンを積む。ルール層の攻防は今までどおり即座に呼び、遅らせない。
* 演出は `result`（`BattleResult`）と `before` だけから作る。演出の途中で描く戦闘の段は、ルール層の状態（フェーズ・最大 HP）と演出の見た目の値（表示する HP・兵）を組み合わせて描く。ルール層は書き換えない。
* `startNextPhase` は演出が終わってから（`isReadyToLeave()`）呼ぶ。早送り・スキップは時計を進めるだけで、ルール層には触れない。終わったときの HP の表示はルール層の攻防後の値（`result.castleHp`・`result.enemyHp`）そのもの。

### 配置（`js/view/layout.js` に足すもの）

* `TroopLayout` = `{ groundY, backFootY, zoneW, smallW, smallH, bigW, bigH, spacing, guardX, defenseClashX, offenseClashX, enemyGuardX, castleHitX, enemyHitX, carpenterX }`。求め方（定数はすべて `layout.js` の名前付き定数）:
    * `fieldL = castle.x + castle.w + FIELD_GAP`、`fieldR = enemy.x − FIELD_GAP`、`F = fieldR − fieldL`。区画の幅 `F / 4`。`guardX = fieldL + F/8`、`defenseClashX = fieldL + 3F/8`、`offenseClashX = fieldL + 5F/8`、`enemyGuardX = fieldL + 7F/8`。`zoneW = F/4 − ZONE_PAD`。

## 5. 懸念事項・要確認ポイント
* 計画時点の判断（背面の盤面の覆い方）: `resolveBattle()` の直後、ルール層の HP はすでに攻防後の値で、背面の `BoardScene` はそれで最上段を描き続ける（`oz/ENGINE_API.md` 6章: 積んでも背面の `draw` は続く）。演出のシーンが最上段と最下段を不透明に描き直して覆うことで、演出の途中で攻防後の値が見えないようにした。`boardView.js`・`battleStageView.js` は変更しない。最下段の不透明の色は、今の盤面の背景と半透明の帯を重ねた色に近い値にするが、わずかに色が違って見える場合は `hudView.js` の定数で合わせる。
* 計画時点の判断（`Engine.timeScale` を `destroy` で戻さない）: 演出のシーンを抜ける道は、`update` の `popScene`（決着していないとき）と `onPointer` の `changeScene`（決着したとき）の2つだけで、どちらも直前に `Engine.timeScale = 1` にする。さらに演出が終わった時点（`update` で `isFinished()`）でも等速に戻す。このため、`oz/ENGINE_API.md` 7章で操作を呼ばない場所とされる `destroy` では戻さない。
* 計画時点の判断（ルール層は変えずに足りるか）: 演出に必要な量は、出来事の並び（敵の行動・相殺・ダメージ・回復の量、決着）と、攻防の前にシーンが読む値（守備兵の数 = 防御ゲージ、兵士の数 = 攻撃ゲージ、城・敵の HP）で足りる。ルール層の変更は不要と判断した。
* 計画時点の判断（量を超える兵）: 城・敵の HP が残りの兵より少ないとき（とどめ）、ルールのダメージ量は HP で止まるが、演出では残った兵すべてが当たって消え、HP の表示は出来事の量だけ減る（ルールでも余りは消える）。
* 計画時点の判断（余った兵の消え方）: 余った守備兵は自軍の突撃（またはその後の最初の段）の始まりに、余った敵の守り・兵士は修理の始まりに、それ以外は演出の終わりに、`fadeMs` かけて消える。決着の表示のときは兵を描かない（`view()` が終わったら兵を空にする）。
* 計画時点の判断（ぶつかる見え方）: 相殺の段は、両方の群れがぶつかる位置で止まったまま、段の中間で数が一度に減る（光や揺れなどの当たった印は作らない）。物足りなければ、試遊の後に別の指示がほしい。
* 計画時点の判断（兵の重なり）: 区画の幅は、論理解像度 720 でおよそ 81px（城の右から敵の左までの約356pxの4分の1から余白を引いた値）。小さな兵が9体並ぶと半分ほど重なる。大きなユニットが多い（例: 100人を超える）と大きく重なるが、区画の幅からははみ出さない。
* 計画時点の判断（演出の設定のファイル）: 02-02 の `animConfig.js`（カードの動き）とは分け、`js/anim/battleAnimConfig.js` に攻防の演出の設定をまとめた（REQ で選んでよいとされた点）。
* 計画時点の判断（決着していないときの間の途中）: 演出が終わってから次のフェーズへ進むまでの間（約0.5秒）は、ボタンを出さず、タップも受けない。
* 目視確認推奨（実装後）: 敵が攻撃のとき・防御のときのそれぞれで段の順に見えること、防御ゲージや攻撃ゲージが0のときに守備兵・兵士が出ないこと、36人が大3体＋小6体に見えること、5種の兵が色と持ち物で見分けられること、HP の表示が当たった時点で変わり演出の終わりに攻防後の値と一致すること、早送りで3倍になり押し込んだ見た目と「×3」が出ること、スキップですぐ終わり HP が攻防後の値になること、決着していなければ約0.5秒後に段取りへ戻ること、勝ち・負けの表示とタップでタイトルへ戻ること、早送りのまま終わっても次の段取りのカードの動きが等速であること、`BATTLE_H` を 300・480 にしても兵が段に収まること、全体の長さが等速でおよそ4〜6秒であること。
