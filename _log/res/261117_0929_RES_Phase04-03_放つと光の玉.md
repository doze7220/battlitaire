# RES: 作業計画・作業レポート (Phase 04-03) : 放つと光の玉
* 参照元REQ: `./_log/req/261117_0929_Phase04-03_放つと光の玉.md`

## 1. 作業目的
札を放つと、列の札が下から順に光の玉になって列の上で区切りごとに合体し、「12 ×3 = 36」の式を出してから、戦闘の段の陣地（攻撃・防御・修理）へ飛んで弾け、加算量と同じ数の兵になって陣地の家で待つようにする（金貨の玉はゲージの行の金貨の数字へ飛び、着くと数字が増える）。玉と兵の動きはタップを止めず、続けて放てば重なって飛ぶ。「行動終了」では飛んでいるものが全部着いてから攻防に入り、待っていた兵が同じ位置からそのまま戦う。**ルール層（`js/rules/`）は変えない。** 放った時点で確定した `ReleaseResult`（`segments`・`gains`）を、時間をかけて見せるだけにする。

## 2. アーキテクチャ設計

### 要件1: 札が玉になって列の上で合体する
*   放つ演出の全体は、新しい管理クラス `ReleaseShow`（`js/anim/releaseShow.js`）が持つ。盤面の動き（`BoardAnimator`。札の移動・山札のめくれ）とは別の時計を持ち、放つたびに `start(result, geometry)` で記録を足していく（前の玉が飛んでいる間も、同じ時計の上に次の玉が出る）。
*   1回の放つの、札1枚ごと・区切りごとの時刻と位置の記録は `js/anim/orbTrack.js`（新規）が組み立てる。**時刻の式はここ1か所だけ**に置く。
    *   放った札の枚数を n、放った時計の値を t0 とする。ずらし `stagger = n <= 1 ? 0 : min(orbConvertStaggerMs, orbConvertMaxMs / (n - 1))`。
    *   k 枚目（列の下から 0 始まり）が玉に変わる時刻 `convertAt_k = t0 + orbStartDelayMs + k × stagger`（最初の間 `orbStartDelayMs` は、放つ音と1枚目の連鎖の音が重ならないため）。連鎖の音のきっかけは `convertAt_k`（何枚目か＝k+1）。
    *   玉に変わるまで、札は元の矩形（放つ前の列の `columnCardRects(c, n)[k]`）に表のまま描く。変わった後は小さい玉が札の中心から区切りの合体する位置へ `orbRiseMs` かけて上る（`easeOutCubic`）。
    *   区切り s の最後の札を L とすると、`gatherAt = convertAt_L + orbRiseMs`（小さい玉が全部集まる）、`mergeEnd = gatherAt + orbMergeMs`（その間、大きい玉が小さい玉の大きさから大きい玉の大きさへ育つ。小さい玉は gatherAt で消す）、`flyStart = mergeEnd + orbFormulaMs`（`mergeEnd ≦ 時計 < flyStart` の間、式を玉のそばに出す）。
*   札が全部玉に変わるまで（`holdUntil = convertAt_{n-1}` まで）は「札の移動」として扱い、盤面へのタップを止める（REQ 要件6が許す範囲）。ルール上は列が空なので、そのまま操作を許すと、残っている札と新しく置いた札が重なるため。玉に変わった後（上る・合体・式・飛ぶ・弾ける・兵が跳ぶ）はタップを止めない。
*   捨て札の山は放った時点で増えた値をそのまま出す（`discardPending` に足さない）。放った札が捨て札へ飛ぶ動きは消す。
*   合体する位置・玉の大きさ・飛ぶ先は、新しい配置のファイル `js/view/releaseLayout.js` の `releaseGeometry(layout, columnIndex, cardCount, segmentGauges, gaugeKeys)` が `layout.js` の矩形（列のカードの矩形・陣地・ゲージの枠・段の領域）から求め、シーンが `ReleaseShow.start` に渡す（`layout.js` は変更しない。`planningMotion` が `layout` を受け取るのと同じく、`anim` は配置を値として受け取るだけで `view` を import しない）。
    *   合体する位置: x は列の中心、y は区切り s ごとに `baseY − s × step`。「列の真上」は **画面で見た上** とし、列の画面上の上端（列の [0] の札の上端。`layout.columns[columnIndex].y`。`columnCardYs` は詰めるときも [0] を常にこの y に置く）より上に置く。`baseY = max(minY, layout.columns[columnIndex].y − ORB_MERGE_GAP − bigSize / 2)`。`step = 区切りが1つなら 0、それ以外は min(ORB_SEGMENT_STEP, max(0, (baseY − minY) / (区切りの数 − 1)))`、`minY = layout.sections.solitaire.y + bigSize / 2`。下の区切りほど下に出る。列の札はすべて列の画面上の上端より下にあるので、どの札の玉も上へ動く。
    *   重なりの扱い: 玉は戦闘の段（`layout.sections.battle`）には入れない（`minY` で止め、区切りが多いときは間隔を詰める。戦闘の段より上には出ないので画面の上端にもはみ出さない）。ソリティアの段の中の、列より上の行（山札・捨て札・手札の枠と見出し、ゲージの行）とは重なってよい（玉と式はそれらの上に重ねて描き、玉が飛び去れば消える）。いまの配置（縦 1280 想定）では、区切りが1つなら玉は手札の見出しの行のあたり、区切りが増えると山札・手札の行、さらにゲージの行に重なる。`baseY` が `minY` を下回る配置（列が段の上端に近すぎる配置）は今の配置では起きないが、起きたときは `minY` に置く（そのときは上る量が小さくなる）。
    *   玉の大きさ: 小さい玉の直径 `smallSize = layout.card.w × ORB_SMALL_RATIO`、大きい玉 `bigSize = layout.card.w × ORB_BIG_RATIO`、弾けて広がり切ったとき `burstSize = bigSize × ORB_BURST_RATIO`。
    *   式を出す向き `labelDir`: 列の中心が画面の中央より左なら 1（玉の右に出す）、それ以外は -1（左に出す）。
*   玉の色は区切りのスートの色（`suitStyle.js` の `suitLook(suit).color`）。描くのは新しい `js/view/orbView.js`。式の文字の形「12 ×3 = 36」は `battleText.js` に `releaseFormulaText(sum, multiplier, amount)` として足す（1枚だけの区切りも同じ形）。
*   連鎖の音は `ReleaseShow.chainCuesInLastUpdate()`（直前の `update` の間 `prevClock < 時刻 ≦ clock` に変わった札の何枚目か）を `BoardScene.update` が読み、`playChainSe(ordinal)` で鳴らす（`soundCues.js` は変えない）。いまの `BoardAnimator` の連鎖のきっかけ（`chainTimes`・`chainCuesInLastUpdate`）は消す。

### 要件2: 大きな玉が飛んで、弾けて兵になる
*   飛ぶ道筋は **弧**（2次ベジェ）とする。元＝合体する位置、先＝飛ぶ先、制御点 `(元と先の x の中点, min(元の y, 先の y) − arcRise)`。進み具合は `easeInOutQuad`。`arriveAt = flyStart + orbFlyMs`。`arcRise` は `releaseLayout.js` の定数 `ORB_ARC_RISE` を配置の値として渡す。
*   飛ぶ先: 攻撃・防御・修理は `layout.battle.troops.camps[gauge]` の矩形の中心、金貨（`muscle`）はゲージの枠（`layout.gauges[gaugeKeys.indexOf('muscle')]`）の中心。
*   着いたら弾ける: `arriveAt ≦ 時計 < burstEnd（= arriveAt + orbBurstMs）` の間、玉は飛ぶ先で `bigSize` から `burstSize` へ広がりながら薄れる（濃さ 1 → 0）。粒などのエフェクトは作らない。
*   兵: 攻撃・防御・修理の区切りは、`arriveAt` に区切りの加算量と同じ数の兵を、飛ぶ先（陣地の中心）から家（`campSlot(camp, index)`。その種類ですでに待っている兵の続きの番号）へ跳ばせる。兵1体ごとに `troopRoster.js` に足す `landTroops` で `TroopUnit` を作り（現れる時刻 = `arriveAt + 遅れ`、元の位置 = 飛ぶ先、脚 1本で家へ `BATTLE_ANIM.landMs`）、跳び方は `troopMotion.js` の `sampleTroop`（`moveStyle` の弾む／揺れる）にそのまま任せる。遅れは `staggerDelay(i, count, landStaggerMs, landStaggerMaxMs)`（遅れの式は `troopRoster.js` の1か所のまま）。陣地の中心から家へ動くので、家の散らばりに応じて四方へ飛び出して見える。
*   段取りの間の兵は新しい `js/anim/campTroops.js` の `CampTroops` が持つ（`TroopRoster` を1つと、見た目の入れ物 `TroopSwarm`）。兵を足したときだけ `TroopSwarm` を作り直す（放つたびに1回。毎フレームは作らない）。全員が家に着いた後は `sample` を省く。作り直した直後の入れ物は `visible` がすべて 0 で、エンジンは `update` が0回のフレームがありうる（`oz/ENGINE_API.md`）ため、`ReleaseShow.start` で兵を足した後に今の時計で `CampTroops.sample` を呼び、作り直したフレームでも待っている兵が消えないようにする（`BattleDirector` が作った直後に `sample` するのと同じ形）。
*   兵は戦闘の段の中だけに描く（`boardView.js` で段の矩形 `layout.battle.area` を切り抜いて `drawTroopSwarm` を呼ぶ。`battleShowView.js` と同じ形）。

### 要件3: 金貨の玉
*   金貨の区切りの大きな玉は、兵を作らず、ゲージの行の金貨の枠の中心へ飛ぶ。着いた時刻から `coinCountMs` かけて金貨の数字が増える（0 なら着いた瞬間に増える）。弾ける見た目は他の玉と同じ。

### 要件4: ゲージの数字と兵の数
*   ゲージの表示値は「ルール層の値 − まだ数えていない分」で作る。区切りごとに `gaugeCount.js` の数え上げ（`from: 0, to: 加算量`）を1つ持ち、まだ数えていない分 = `加算量 − sampleGaugeCount(count, 時計)`。
    *   攻撃・防御・修理: `delay = arriveAt`、`duration = 最後の兵が家に着く時刻 − arriveAt`（弾けてから全員が着くまでに数え上がり、着いた時点で兵の数と一致する）。
    *   金貨: `delay = arriveAt`、`duration = coinCountMs`。
*   複数の放つが重なっても、ゲージごとにまだ数えていない分を足し合わせて引くだけなので、全部が着けばルール層の値と一致する。`ReleaseShow.view(gauges)` が、まだ数えていない分のあるゲージだけ表示値を返し（`gaugeValues`）、`drawGauges` の `shownValues` に渡す。いまの `BoardAnimator` のゲージの数え上げ（`Motion.counts`・`BoardAnimView.gaugeValues`）は消す。

### 要件5: 段取りの間、兵は陣地で待つ
*   段取りの間、`CampTroops` の兵は家に立ったまま（呼吸などは作らない）。放つたびに増える。人数の表示は `BoardScene`（`boardView.js`）では描かない（攻防の演出の `battleShowView.js` だけが描く。今のまま）。
*   **引き継ぎの形**: 段取りの間の兵の並びは「種類ごとの数（家の番号は 0 から数−1。`campSlot` で番号から家が決まる）」として攻防に渡す。`ReleaseShow.waitingCounts()` → `BoardScene` → `BattleShowScene`（オプション `waiting`）→ `buildBattleTimeline(..., waiting)`。時間割は名簿を作った直後に、自軍の3種類を `spawnTroops(roster, kind, waiting[kind], 0, 0)`（時刻 0・現れる時間 0）で置く。家の位置は `campSlot(camp, index)` だけで決まるので、待っていた兵と同じ位置に、時刻 0 から濃さ 1 で立つ（消えない・ちらつかない・位置が飛ばない）。`waiting[kind]` が攻防の前の写し `before[kind]` と違えば Error を投げる（食い違いを知るため。04-02 の `marchSquad` と同じ方針）。
*   **使われなかった兵が城へ帰ること**: いまの時間割は段が1つもないと `finishTroops` を呼ばない。`form` の段がなくなると、敵が振りかぶり（攻撃も守りもしない）で自軍が防御だけ（攻撃 0）のとき段が空になり、待っていた兵が城へ帰らなくなる。そこで `finishTroops` を呼ぶ条件を「段がある、または待っていた兵がいる（`waiting` の3種類の合計が 0 より大きい）」にする。段がないときは時刻 0（`stepEnd = 0`）で城へ帰り始める。
*   `form` の段は敵の守りだけを現す段にする（`battleSteps.js` の `form` は敵の守りがいるときだけ作り、`troops` の項目を消す。`battleTimeline.js` の `addForm` は `enemyGuard` だけを出す）。攻防の始めに自軍の兵を薄く出し直す処理は消す。
*   攻防に入るとき、`BoardScene` は `ReleaseShow` を新しい空のものに作り直す（攻防の演出のシーンが戦闘の段を上から全部描くので、裏で兵が消えても見えない）。次のフェーズは兵がいない状態から始まる。

### 要件6: 玉が飛んでいる間も操作できる
*   `BoardScene.onPointer` でタップを無視する条件は「攻防待ち（`pendingBattle`）」「`BoardAnimator.isBusy()`（札の移動・山札のめくれ）」「`ReleaseShow.isHoldingCards()`（玉に変わっていない札が残っている）」だけにする。玉・兵の動き（`ReleaseShow.isBusy()`）ではタップを止めない。
*   「行動終了」を押したとき、攻防に入れる（`game.canResolveBattle()`）なら、`ReleaseShow.isBusy()` が真なら `pendingBattle = true` にして待ち（待つ間はタップをすべて無視）、偽ならすぐ攻防に入る。`update` で `pendingBattle` かつ `!ReleaseShow.isBusy()` になったら攻防に入る。攻防に入る処理は `BoardScene` の `startBattle()` 1か所（攻防の前の写し → 待っている兵の数 → `game.resolveBattle()` → 行動終了の音 → `ReleaseShow` の作り直し → 攻防の演出のシーンを積む）。`resolveBattle` は攻防に入る瞬間に呼ぶ（待つ間は盤面の HP などが攻防の後の値にならない）。待つ間はほかの操作を受け付けないので、ルール層の状態も乱数の並びも、待たずに始めた場合と同じになり、攻防の結果は変わらない。

### 要件7: 調整できること
*   段取りの動きの設定 `js/anim/animConfig.js` の `ANIM_TIMING` に足す: `orbStartDelayMs`（放ってから1枚目が玉に変わるまで）・`orbConvertStaggerMs`（札が玉に変わるずらしの上限）・`orbConvertMaxMs`（玉に変わるずらしの広がり全体の上限）・`orbRiseMs`（玉が上る時間）・`orbMergeMs`（合体にかかる時間）・`orbFormulaMs`（式を出しておく時間）・`orbFlyMs`（飛ぶ時間）・`orbBurstMs`（弾ける時間）・`coinCountMs`（金貨の数字が増える時間）。いまの `releaseStaggerMs`・`releaseTotalMaxMs` は使われなくなるので消す。
*   兵の動きの設定 `js/anim/battleAnimConfig.js` の `BATTLE_ANIM` に足す: `landMs`（兵が家へ跳ぶ時間）・`landStaggerMs`（1体ごとの遅れ）・`landStaggerMaxMs`（遅れの広がり全体の上限）。`formMs` の説明を「敵の守りが陣地で現れる時間（敵の回復の段の時刻にも使う）」に直す。
*   配置の値（玉の大きさの割合・合体する位置の間隔・弧の持ち上がり）は `js/view/releaseLayout.js` の定数に置く。

### 要件8: 今と同じく使えること
*   めくる・置く・捨てる・手札・束の移し替えの動きと音は変えない（`planningMotion.js` の `release` 以外の分岐・`BoardAnimator` の札の移動とめくれはそのまま）。放つ音はタップの時点で今のまま鳴らす。新しい効果音は足さない。
*   攻防の演出（兵の動き・相打ち・跳ねて落ちる・修理の兵・使われなかった兵・人数の表示・早送り・スキップ）は、自軍の兵の出し方（`form` の段）以外は変えない。人数の表示の最初の値は今どおり `before` の値。

*   **`js/scenes/`**: シーン（`Scene` の継承）。入力を受けてルール層の操作を呼ぶこと、`anim` の時間を進めること、`view` を呼んで描くこと、シーンの切り替え、効果音を鳴らすこと（`Sound.playSe` は `js/scenes/soundCues.js` の中でだけ呼ぶ）。書いてはいけない: ルールの判定や計算、細かい描画の処理。

## 5. 懸念事項・要確認ポイント
* **札が玉に変わるまではタップを止める**: ルール上は放った瞬間に列が空になるため、玉に変わっていない札が残っている間（最大 `orbStartDelayMs + orbConvertMaxMs` ≒ 0.8 秒）は「札の移動」としてタップを止める。玉に変わった後は止めない。止める時間が長く感じれば `orbConvertMaxMs` を詰める。
* **行動終了の音の時刻**: 玉・兵が動いている間に「行動終了」を押すと、攻防に入る瞬間（全部が着いた後）に行動終了の音が鳴る（今の「攻防に入った音」の意味のまま）。押した時点では見た目も音も変わらないので、待っていることが分かりにくければ後で扱う。
* **攻防の始まり方の変化**: `form` の段は敵の守りがいるときだけになる。敵の守りがいないときは、自軍の兵が時刻 0 から立っていて、すぐに次の段（敵兵の行進など）が始まる（今は自軍の兵が 0.5 秒かけて現れていた）。
* **段のない攻防**: 敵が振りかぶりで自軍が防御だけ（攻撃 0）のときは段が1つもなく、待っていた兵は攻防の演出の始め（時刻 0）からすぐ城へ帰る（今は `form` の段で現れてから帰っていた）。段がなくても待っていた兵がいれば `finishTroops` を呼ぶことで、使われなかった兵が残らないようにする。
* **合体する位置の重なり**: 玉は列の画面上の上端（[0] の札の上端）より上に縦に並び、区切りが多いと詰まる（戦闘の段には入れない）。列より上の行（手札の見出し・山札・捨て札・手札の枠・ゲージの行）とは重なってよいとし、玉と式はそれらの上に重ねて描く。玉に変わった後に同じ列へ札を置くと、上っている玉や式と重なって見える。式は列の中心が画面の左半分なら玉の右、右半分なら左に出すが、隣の列を同時に放つと重なりうる。試遊で見る。
* **待っている兵の重さ**: 段取りの間も、待っている兵を毎フレーム描く（1回の放つで最大 196 体、重なれば数百体）。計算側は兵が動いている間だけ見た目を書き直し、入れ物は放つたびに1回だけ作り直すが、描画の重さの対策は後の Phase で扱う。
* **待っていた兵の数の食い違い**: 攻防の時間割は、引き継いだ兵の数が攻防の前のゲージの値と違えば Error を投げる（攻防の演出に入れなくなる）。全部が着いてから攻防に入るので、通常は起きない。
* **タスク8の終わりの途中の状態**: タスク8の後・タスク9の前は、攻防に入っても段取りの間の兵が `ReleaseShow` に残り、攻防の演出の裏（見えない）と次のフェーズの盤面に前の兵が残って見える（攻防の演出も今の `form` で兵を出し直す）。タスク9で直る。各タスクの終わりで、アプリ全体は読み込める（import の解決・構文が通る）。
* **テストプレイで確かめること（発注者が見る点）**
