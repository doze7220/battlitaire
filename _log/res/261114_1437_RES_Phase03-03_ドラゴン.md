# RES: 作業計画・作業レポート (Phase 03-03) : ドラゴン
* 参照元REQ: `./_log/req/261114_1437_Phase03-03_ドラゴン.md`

## 1. 作業目的
03-01 の仮の行動（重みによる攻撃・防御の抽選）と仮の玉で出ているドラゴンを、「爪攻撃でブレスチャージを溜め、満ちたら確率でブレスを撃ち、ブレスで盤面の列の札を燃やす」最後の敵に作り変える。
* ルール層: 行動の決まりの新しい種類（ブレスチャージ）、攻撃の系統の中の種類（爪・ブレス）、ブレスで列の一番上の札を燃やして捨て札へ移すこと、攻防の出来事の並びに「札が燃えた」出来事を足す。
* 表示・演出: 戦闘の段のブレスチャージ（「ブレス 1/4」）と予告（「爪 10」「ブレス 35」）、攻防の演出の「札が燃える段」（赤く明滅して捨て札へ飛ぶ）、ドラゴンの大きな赤い玉。
* ゴブリンの軍勢・巨人の行動と見た目、段取り・ほかの攻防の演出・敵の入れ替わり・決着・音の挙動は変えない。結果の画面・タイトル・最高記録・敵の絵・凝った演出（炎の粒など）・特殊行動は作らない（03-04 以降）。

## 2. アーキテクチャ設計

### 要件1: ドラゴンの行動の決まり（爪・ブレス・ブレスチャージ）
* **予告の形（攻撃の系統の中の種類）**: 爪とブレスは、どちらも `EnemyAction.kind === 'attack'` のまま、任意の項目 `variant`（`'claw'|'breath'`）で種類を分ける。城へのダメージは `battle.js` の既存の `'attack'` の分岐だけで扱い、種類ごとに攻撃の扱いを重複させない。行動に付く盤面への効果は任意の項目 `burn`（`{ min, max }`。燃やす札の枚数の範囲）で表し、`battle.js`・`Game.js` は `burn` の有無だけを見る（敵の種類・`variant` で分岐しない）。
    * `EnemyAction`（`combatants.js` の typedef）: `kind`・`amount` に、任意の `variant?: 'claw'|'breath'`・`burn?: { min: number, max: number }` を足す。ゴブリン・巨人の予告はこれらを持たない（いまと同じ）。
* **設定（`config.js`）**: ドラゴンの `behavior` を次に置き換える（仮の重みつきの攻撃・防御は消す）。
    ```js
    behavior: Object.freeze({
      type: 'charge',
      claw: Object.freeze({ amount: 10 }),
      breath: Object.freeze({ amount: 35, burn: Object.freeze({ min: 4, max: 6 }) }),
      chargeMax: 4,
      breathChance: 0.5,
    }),
    ```
    `armor: 15`・`maxHp: 120` はいまのまま。typedef: `EnemyBehaviorSpec.type` に `'charge'`、任意の `claw`（`ChargeStrikeSpec`: `{ amount }`）・`breath`（`ChargeBreathSpec`: `{ amount, burn: BurnSpec }`）・`chargeMax`・`breathChance` を足し、`BurnSpec`（`{ min, max }`）を足す。先頭の責務定義に「ブレスチャージ（爪・ブレス・燃やす札の枚数）」を足す。
* **行動の決まりの表（`enemyBehaviors.js`）**: 表の各決まりに `settle`（行動の攻防が行われた後の決まりの状態）と `charge`（チャージの問い合わせ）を足し、`'charge'` の決まりを足す。既存の `weighted`・`cycle` の `initialState`・`planNext`・`countdown` は変えない（`settle` は状態をそのまま返し、`charge` は `null`）。
    * `charge.initialState`: `{ charge: 0 }`。
    * `charge.planNext(behavior, state, random)`: `state.charge < behavior.chargeMax` なら乱数を呼ばず爪 `{ kind: 'attack', amount: claw.amount, variant: 'claw' }`。満ちていれば `random()` を1回呼び、`< breathChance` ならブレス `{ kind: 'attack', amount: breath.amount, variant: 'breath', burn: breath.burn }`、そうでなければ爪。状態はそのまま返す（チャージは予告では変えない）。
    * `charge.settle(behavior, state, action)`: `action.variant === 'claw'` なら `{ charge: min(charge + 1, chargeMax) }`、`'breath'` なら `{ charge: 0 }`、ほかはそのまま。
    * `charge.charge(behavior, state)`: `{ current: state.charge, max: behavior.chargeMax }`。
    * `charge.countdown`: `null`。
    * 公開する関数を2つ足す: `settleBehaviorAction(behavior, state, action)`（新しい状態を返す。引数は書き換えない）、`behaviorCharge(behavior, state)`（`{ current, max }|null`）。
* **ゲーム（`Game.js`）**: `enemyCharge()` を足す（`behaviorCharge` を呼ぶだけ。巨人・ゴブリンは `null`）。`resolveBattle()` で、攻防の後に `this.enemy.behaviorState = settleBehaviorAction(spec.behavior, this.enemy.behaviorState, enemyAction)` を呼ぶ（敵の種類で分岐しない。決着で終わる攻防でも呼ぶ）。予告は1フェーズ前（`startNextPhase` の `planIntent`）に決まるので、「爪を撃つ → 攻防でチャージ +1 → 次のフェーズの頭で、満ちていれば確率でブレスを予告」の順になる。ドラゴンが出たとき（`createEnemy`）はチャージ 0 で、最初の予告は爪。

### 要件2: ブレスチャージと予告の表示
* **ルール層から読む値**: 段取り中は `game.enemyCharge()`。攻防の演出中は、攻防の前の写し（`BattleSnapshot.enemyCharge`。`snapshotBattle` で `game.enemyCharge()` を写す）と攻防の後の値（`BattleResult.enemyCharge`。`resolveBattle` が `settle` の後の `this.enemyCharge()` を入れる）の2つを、演出の時刻で切り替える。描画の側でチャージを計算し直さない。
* **切り替わる時刻**: 時間割（`battleTimeline.js`）に `enemyStrikeTime`（敵の攻撃が城に届いた時刻）を足す。`castleHit` の段があればその当たりの時刻（`start + hitMoveMs`。`addHit` の城の HP の変わり始めと同じ式）、なければ最後の `enemyMarch`・`block` の段の終わり、どちらもなければ 0。`BattleDirector.view()` は `clock < enemyStrikeTime` かつ終わっていない間は写しの値、それ以降は結果の値を `BattleLook.enemyCharge` に入れる。スキップ（終わり）では結果の値。爪なら当たりで +1、ブレスなら当たりで 0 に見える。
* **描画（`battleStageView.js`）**: `drawBattleStage` の状態に `charge?: {current, max}|null` を足す。数え下ろしが `null` でなく出ているときはいまどおり数え下ろし、そうでなく `charge` が `null` でなければ同じ `battleLayout.countdown` の枠に `chargeText(charge)`（「ブレス 1/4」）を描く。満ちているとき（`current >= max`）は、枠の塗りと文字の色を目立つ色（例: 濃い赤の塗り・明るい黄色の文字）に変える。文字は `drawBox` の最大の幅で必ず枠に収まる（いまの仕組み）。
    * `drawBox(ctx, rect, text, style?)` に任意の見た目 `{ fill, color }` を足す（省くといまの色）。
    * 予告の枠: `enemyActionText` が `variant` があればその表示名（`爪`・`ブレス`）に量をつける（「爪 10」「ブレス 35」）。`variant` が目立たせる種類（`'breath'`。`battleStageView.js` の集合 `EMPHASIZED_VARIANTS`）のときは予告の枠を目立つ見た目にする。
* **文字（`battleText.js`）**: `VARIANT_LABELS`（`claw: '爪'`・`breath: 'ブレス'`）と `chargeText({ current, max })`（「ブレス 1/4」）を足す。
* **出す・出さない**: `charge` はルール層が `null` を返す敵（ゴブリンの軍勢・巨人）では描かない。巨人の数え下ろしはいまどおり。
* **渡す場所**: `boardView.js` は `charge: game.enemyCharge()`、`battleShowView.js` は `charge: look.enemyCharge` を `drawBattleStage` に渡す。

### 要件3: ブレスで札を燃やす（ルール）
* **新しいファイル `js/rules/cardBurn.js`**（責務: 行動に付く「列の札を燃やす」効果の、燃やす札の決め方と、列から捨て札への移し。ルール層。乱数は渡されたものだけ）。
    * typedef `BurnedCard`: `{ columnIndex: number, cardIndex: number, card: Card }`（`cardIndex` は燃えた時点のその列の下から数えた位置＝その時点の一番上）。
    * `planActionBurns(action, columns, random)`: `action.burn` がなければ乱数を呼ばず `[]`。あれば `count = min + floor(random() * (max - min + 1))`（乱数1回）。列の長さの写しを使い、1枚ごとに「長さが1以上の列」の番号を集め、空なら止める。`random()` を1回呼んで1本を選び、その列の一番上を `BurnedCard` として並びに入れ、写しの長さを1減らす。`columns` は書き換えない（純粋関数）。
    * `applyBurns(columns, discard, burns)`: 並びの順に、`columns[columnIndex]` の一番上を取り除いて `discard` の末尾へ入れる（書き換える。`refillEmptyDecks` と同じく渡された配列を変える関数）。
* **攻防の計算（`battle.js`）**: `BattleInput` に任意の `burns`（`BurnedCard[]`。省くと `[]`）を足す。負けの判定（城の HP 0 でここで終わり）の直後・敵の回復の前に、`burns` が1枚以上なら出来事 `{ type: 'cardBurn', amount: burns.length, burns: [...] }` を入れる。`BattleCalc` に `burned`（実際に燃えた札の並び。負けで終わったときは `[]`）を足す。`BattleEvent` に任意の `burns` を足し、種類に `'cardBurn'` を足す。順序の説明を「城の被害（0なら負け）→ 札が燃える → 敵の回復 → …」に直す。自軍の攻撃（`attack`）は燃えた札で変わらない。
* **ゲーム（`Game.js`）の `resolveBattle()`**: `rollAttackHeal` の後に `const burns = planActionBurns(enemyAction, this.columns, this.random)` を作って `computeBattle` に渡し、計算の後に `applyBurns(this.columns, this.discard, calc.burned)` を呼ぶ。`Game.js` は「行動の予告に `burn` があれば」の判定も持たない（`planActionBurns` が見る）。山札・手札・捨て札は燃やさない。燃えた後の山札の補充（`refillEmptyDecks`）は呼ばない（5章）。
    * 予告の写しは、`variant`・`burn` を落とさないよう `{ ...enemyAction }` で写す（`BattleResult.enemyAction`・`NextPhaseResult.enemyAction`）。`computeBattle` には今までどおり `{ kind, amount }` を渡す。
    * `BattleResult` に `enemyCharge`（攻防の後のチャージ。`{current, max}|null`）を足す。
* **乱数の使い方**: 攻防で使う乱数は、回復の抽選（`attackHeal` があるときだけ）→ 燃やす枚数（`burn` があるときだけ1回）→ 燃やす列（1枚ごとに1回）。城が落ちる攻防でも燃やす札は先に決める（乱数は使うが、`burned` が `[]` になり札は燃えない）。

### 要件4: 札が燃える見せ方
* **演出の考え方**: ルール層の列・捨て札は「行動終了」の時点で燃えた後になる。演出の側は、攻防の前の写し（`BattleSnapshot.columns`: 列ごとのカードの並びの写し）と出来事の `burns` から、燃える段までの盤面（元の列・燃える前の捨て札の枚数）を作る。ルール層の状態は巻き戻さない・書き換えない。
* **段の並び（`battleSteps.js`）**: `snapshotBattle` に `columns`（`game.columns.map((col) => col.slice())`）と `enemyCharge` を足す。出来事 `cardBurn` から段 `{ type: 'burn', amount, burns }` を作る（`burns` は出来事のものを写す）。`cardBurn` は `castleDamage` の後・`enemyHeal` の前に並ぶので、段は「城への被害 → 札が燃える → （敵の回復）→ 自軍の突撃」になる（`MARCH_BEFORE` は変えない）。
* **新しいファイル `js/anim/burnTrack.js`**（責務: 札が燃える段の、1枚ごとの時刻（明滅・飛び立ち・着く）と移動の記録の組み立てと、時計からの盤面の見た目（残っている列・飛んでいる札・明滅・着いていない枚数）を求めること。描画も状態の変更もしない）。
    * `burnCardOffsets(k)`: 段の開始から k 枚目（0から）の `{ flash, fly, arrive }`（ms）。`flash = k * (burnFlashMs + burnFlyMs)`、`fly = flash + burnFlashMs`、`arrive = fly + burnFlyMs`。**燃える段の時刻の式はこの関数1か所にだけ置き**、時間割と音のきっかけの両方がこれを呼ぶ（二重化しない）。
    * `burnStepDuration(count)`: `count * (burnFlashMs + burnFlyMs)`。
    * typedef `BurnTrack`: `{ card, columnIndex, cardIndex, from: Rect, flashStart, tween: CardTween }`（`tween` は `cardTween.js` の `createCardTween`。`delay = fly`、`duration = burnFlyMs`、`to = 捨て札の矩形`、`dest: 'discard'`）。
    * `createBurnTracks(burns, start, boardLayout)`: `from = boardLayout.columnCardRects(columnIndex, cardIndex + 1)[cardIndex]`（燃える時点の一番上の札の矩形）、`to = boardLayout.discard`。
    * typedef `BurnBoardLook`: `{ columns: Card[][], flying: Array<{card, x, y, w, h}>, flash: {rect: Rect, alpha: number}|null, discardPending: number }`。
    * `sampleBurnBoard(tracks, beforeColumns, clock)`: 飛び立った札（`clock >= tween.delay`）を写しの列から除いた列、飛んでいる札（飛び立ち後・着く前。`sampleCardTween`）、明滅中の札（`flashStart <= clock < tween.delay`。濃さは `0.5 - 0.5 * cos(2π * burnBlinks * 進み)`）、着いていない枚数（`clock < 着く時刻` の数）を返す。
* **時間割（`battleTimeline.js`）**: `buildBattleTimeline(steps, before, troopLayout, boardLayout)` に `boardLayout`（`Layout`。`columnCardRects`・`discard` だけ使う）を足す。段の組み立て `burn: addBurn`（`createBurnTracks` で記録を作り `state.burns` に足し、長さは `burnStepDuration`）を `STEP_BUILDERS` に足す。`FRONT_FADE_STEPS` に `'burn'` を足す（03-02 の `enemyHeal` と同じく、燃える段の始まりで守備兵の余りを消し始める）。`BattleTimeline` に `burns`・`enemyStrikeTime` を足し、`endTime` に燃える札の着く時刻の最大を含める。兵の動きは変えない。
* **音のきっかけ（`battleCues.js`）**: 1つの段から複数のきっかけを出す表 `MULTI_CUE_STEPS`（`burn: (step) => 0..amount-1 の burnCardOffsets(k).fly`）を足し、飛び立つ時刻ごとに `type: 'burn'` のきっかけを作る。ほかの段の `CUE_OFFSET_MS` は変えない。
* **演出の管理（`battleDirector.js`）**: コンストラクタに `before`（攻防の前の写し）を足す。`view()` に `enemyCharge` を足す（要件2）。`boardView()` を足す: 燃える札の記録がない、または演出が終わっていれば `null`（ルール層の盤面をそのまま描く）、そうでなければ `sampleBurnBoard(timeline.burns, before.columns, clock)`。スキップすれば終わりなので `null`（燃えた後の盤面）。
* **演出の設定（`battleAnimConfig.js`）**: `burnFlashMs: 400`（1枚の明滅の時間）、`burnFlyMs: 250`（捨て札へ飛ぶ時間）、`burnBlinks: 2`（明滅の回数）を足す（仮の値）。
* **盤面への渡し方（シーン）**: 攻防の演出中は盤面のシーン（`BoardScene`）が背面で `draw` を続ける（`oz/ENGINE_API.md` 6章）。`BoardScene` は積んだ `BattleShowScene` を `this.battleShow` に持ち、`draw` で `this.battleShow.boardLook()`（`director.boardView()` を返すだけ。`null` あり）を読んで `drawBoard` に渡す。`BoardScene.update` は最前面のときだけ呼ばれるので、`update` の頭で `this.battleShow = null` に戻す（演出のシーンが外れた後）。外れた直後のフレームで参照が残っていても、演出は終わっているので `null` が返る。
* **描画（`boardView.js`・`cardView.js`）**: `drawBoard(ctx, layout, game, ui, anim, burn = null)`。`burn` があれば、列は `burn.columns[c]` を描き、捨て札の着いていない枚数に `burn.discardPending` を足し、列の後に `burn.flash` の矩形に赤い明滅（`cardView.js` の新しい `drawCardTint(ctx, x, y, w, h, color, alpha)`。色は `boardView.js` の定数）を重ね、最後に `burn.flying` の札を手前に描く。`burn` が `null` ならいまと同じ。
* **シーン（`BattleShowScene.js`）**: `init` で `buildBattleTimeline(steps, this.before, troopLayout, this.layout)`、`new BattleDirector({ ..., before: this.before })`。`boardLook()` を足す（`this.director === null ? null : this.director.boardView()`）。
* **音（`soundCues.js`）**: `BATTLE_CUE_SE` に `burn: 'discard'` を足す（`js/audio/` は変えない）。
* **早送り・スキップ**: 早送りは `update` の呼ばれる回数で進むので、燃える段もほかの段と同じく速くなる。スキップは `director.skip()` で終わりへ移り、`boardView()` が `null`・`enemyCharge` が結果の値になるので、燃えた後の盤面・チャージが見える。スキップで飛ばした燃える音は鳴らない（いまの仕組み）。

### 要件5: ドラゴンの見た目
* `enemyView.js` の `ENEMY_LOOKS.dragon` を `{ shape: 'orb', color: '#c0392b', size: 'big', shieldArea: 'inner' }` にする。大きさは巨人と同じ `battleLayout.enemyBig`。
* シールドマーク15個（3行×5）が大きな玉からはみ出さないよう、`layout.js` に `enemyBigInner`（`enemyBig` の玉に内接する正方形。中心は同じ、辺 = 直径 / √2）を足し、`shieldArea: 'inner'` の敵は `shieldRects(armor, battleLayout.enemyBigInner)` に並べる。巨人は `shieldArea` を持たないので、いまと同じ `enemyBig` に並ぶ（巨人の見た目は変えない）。
* 兵の当たる位置（`armorHitX`・`enemyHitX`）は変えない（巨人と同じ扱い。5章）。

### 要件6: ほかは変えない
* ゴブリンの軍勢の `weighted`・巨人の `cycle`・`attackHeal` の動き、乱数の使い方（ゴブリン・巨人）は変えない。段取りの操作と動き（`planningMotion.js`・`boardAnimator.js`）、ほかの段の時刻と兵の動き、敵の入れ替わり・決着・音は変えない。

### 時刻の式の二重化について
* 既存の当たり・修理・敵の回復・常時防御力の時刻の式（`battleCues.js` の `CUE_OFFSET_MS` と `battleTimeline.js`）はいまのまま2か所に残す（今回は触らない。変えるとほかの段の挙動に触れるため）。
* 新しい燃える段の時刻は `burnTrack.js` の `burnCardOffsets` 1か所に置き、`battleTimeline.js`（`createBurnTracks` 経由）と `battleCues.js` の両方がこれを呼ぶ。チャージの切り替わる時刻（`enemyStrikeTime`）は音のきっかけに使わないので、`battleTimeline.js` の1か所だけ（`addHit` の城の HP の変わり始めと同じ式 `t + hitMoveMs` を使い、コメントで示す）。

### 参照する責務
*   **データ構造（2章より）**: 敵は種類（名前・最大 HP・常時防御力・行動の決まり）を持ち、行動の決まりは種類ごとの設定から選ばれ、決まりの状態を敵ごとに持つ。重みによる抽選（ゴブリンの軍勢・いまはドラゴンも）・周期の攻撃（巨人。数え下ろしを決まりの状態に持ち、ゲームが問い合わせに答える）。攻撃の直後の回復は行動の決まりの設定の任意の項目で、ゲーム・攻防の計算は設定を渡すだけで、特定の敵の名前や識別子では分岐しない。捨て札は1つの山。列は `[0]` が一番下。乱数はゲームを作るときに外から渡す関数だけを使う。操作は状態を変えるとともに「何が起きたか」を返し、演出はこの結果を見て動く。攻防の出来事の並びは種類と量を持ち、量が0の相殺・ダメージ・回復は並びに入れない（敵の行動は必ず入る）。
*   **処理フロー（3章より）**: 行動終了でルール層が攻防を計算し出来事の並びを返す。攻防中は `BattleShowScene` を `Engine.pushScene` で積み、出来事を最上段の兵の動きとして順に見せる。早送り・スキップでも結果は変わらない。`update(dt)` で `anim` の時計を進め、直前の進みの間のきっかけを見て効果音を鳴らす（`draw` では鳴らさない）。`draw` はルール層の状態と `anim` の見た目の値から描き、状態を変えない。
*   **`js/rules/`**: 書いてよい: ルール（山札、捨て札、列、置けるかの判定、放ったときの計算、ゲージ、行動回数、敵の行動、攻防の計算、決着）と、その設定（調整値）。乱数は外から受け取る。違反: `oz` や `js/` のほかのフォルダの import、Canvas・DOM・音・時間（`dt` を含む）を扱うこと、`Math.random` の直接の呼び出し、画面の座標や色。
*   **`js/scenes/`**: 書いてよい: シーン（`Scene` の継承）と入力を補助するモジュール。入力を受けてルール層の操作を呼ぶこと、`anim` の時間を進めること、`view` を呼んで描くこと、シーンの切り替え、効果音を鳴らすこと（`Sound.playSe` は `soundCues.js` の中でだけ呼ぶ）。違反: ルールの判定や計算を書くこと、細かい描画の処理。
*   **`js/view/`**: 書いてよい: カード・山札・列・ゲージ・城・敵・兵などの描き方、画面の配置（座標と大きさ）と当たり判定。違反: ゲームの状態を変えること、ルールの判定、時間で進む動き（`anim` に置く）、`Sound` の import。
*   **`js/anim/`**: 書いてよい: 時間で進む見た目の動きと補間。ルール層の操作の結果を受けて見た目の値を作る。音を合わせるきっかけ（いつ・何が起きたか）を答えること。違反: ゲームの状態を変えること、ゲームの結果を決めること、描画そのもの、`Sound` の import・音の名前を持つこと。

## 5. 懸念事項・要確認ポイント
* 計画時点の判断（爪・ブレスの表し方）: 新しい行動の種類を足さず、`kind: 'attack'` のまま任意の `variant`（`'claw'|'breath'`）で分ける。城へのダメージ・守備兵の相殺・兵の演出は既存の攻撃と同じ経路を通り、`battle.js` の攻撃の扱いを重複させない。燃やす効果は予告に写した任意の `burn`（設定のブレスの `burn`）から `cardBurn.js` が読む。
* 計画時点の判断（チャージを溜める時点）: 決まりの表に `settle`（行動の攻防の後の状態）を足し、`Game.resolveBattle()` が敵の種類によらず毎回呼ぶ。予告（`planNext`）ではチャージを変えない。城が落ちる攻防でも呼ぶ（決着後は使われない）。
* 計画時点の判断（乱数の消費）: ドラゴンの予告は、チャージが満ちるまで乱数を使わず、満ちた後は1回使う（03-01 の仮のドラゴンは毎回1回）。ブレスの攻防では、燃やす枚数に1回・1枚ごとに1回使う。城が落ちるブレスの攻防でも燃やす札は先に決める（乱数は使うが、札は燃えない）。ゴブリン・巨人の乱数の使い方は変わらない。
* 計画時点の判断（燃えた後の山札の補充）: 燃えた札を捨て札へ移した後、`refillEmptyDecks` は呼ばない（REQ は「燃えた札はすぐ捨て札へ移る」のみで、段取りの操作以外で山札が変わると演出が必要になるため）。空の山札は、次の段取りの操作（置く・捨てる・手札に入れる・放つ）の後のいまの補充で戻る。
* 計画時点の判断（ブレスが守備兵で全部防がれたとき）: 城への被害の出来事がなくても、城が落ちていなければ札は燃える（ブレスの攻撃の後）。そのときチャージが 0 に見える時刻は、敵兵の段（`enemyMarch`・`block`）の終わりにする。
* 計画時点の判断（背面の盤面の差し替え）: 攻防の演出中の列・捨て札は背面の `BoardScene` が描くので、`BoardScene` が積んだ `BattleShowScene` を参照に持ち、`draw` で `boardLook()` を読む。参照は `BoardScene.update`（最前面のときだけ呼ばれる）の頭で外す。シーン同士を直接つなぐ形なので、別の形（例: `BoardScene` が演出の管理を作って渡す）がよければ指示がほしい。
* 計画時点の判断（時刻の式の二重化）: 既存の時刻の式（`battleCues.js` と `battleTimeline.js`）は今回1か所にまとめ直さない（ほかの段の挙動に触れるため）。新しい燃える段の時刻は `burnTrack.js` の `burnCardOffsets` 1か所に置き、両方から呼ぶ。チャージの切り替わる時刻は `battleTimeline.js` だけ。
* 計画時点の判断（守備兵の余りの消え始め）: `FRONT_FADE_STEPS` に `'burn'` を足し、燃える段の始まりで守備兵の余りを消し始める（03-02 の `enemyHeal` と同じ扱い）。燃える段がないフェーズの見え方は変わらない。
* 計画時点の判断（ドラゴンの玉とシールドマーク）: ドラゴンの玉は巨人と同じ `enemyBig`（160）。シールドマーク15個は玉に内接する正方形（`enemyBigInner`。約113）に並べてはみ出さないようにする。巨人のマークの並べ先は変えない。兵の当たる位置（`armorHitX`・`enemyHitX`）は巨人と同じく変えない（目視で確認してほしい）。
* 計画時点の判断（燃える段の時間・音）: 1枚ごとに 400ms 明滅（2回）→ 250ms で捨て札へ飛ぶ、を順に（重ねず）くり返す（6枚で約 3.9 秒）。音（「捨てる」）は1枚ごとに飛び立つ時刻に鳴らす。長すぎれば `battleAnimConfig.js` の値で調整できる。
* 目視確認推奨（実装後）: 巨人を倒してドラゴンが出たフェーズで「ブレス 0/4」「次の行動 爪 10」になり、爪の攻防で爪が城に当たったときに「ブレス 1/4」に増えること。4/4 で満ちた見た目になり、以後ブレス（目立つ予告の枠で「ブレス 35」）か爪が予告されること。ブレスの攻防で、城への被害の後に列の一番上の札が1枚ずつ赤く明滅して捨て札へ飛び、捨て札の枚数が1枚ずつ増え、自軍の突撃の前に終わること。「行動終了」の時点で燃える札が列から消えて見えないこと。スキップで燃えた後の盤面とチャージ 0 になること。早送りで速くなること。大きな赤い玉にシールドマーク15個がはみ出さずに見えること。ゴブリン・巨人の段でチャージが出ないこと。
