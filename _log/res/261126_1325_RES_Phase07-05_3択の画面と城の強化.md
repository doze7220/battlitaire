# RES: 作業計画・作業レポート (Phase 07-05) : 3択の画面と城の強化
* 参照元REQ: `./_log/req/261126_1325_Phase07-05_3択の画面と城の強化.md`

## 1. 作業目的
敵を1体倒すたびに、強化を1つ選ぶ3択（＋いつも選べる「城を修理」）が出るようにする。

* ルール層に強化の仕組み（枠・重み・一覧・取った強化の状態・抽選・「3択を選んでいる」段階と選ぶ操作）を作り、城の強化4種（最大 HP・自動兵士の剣・盾・ハンマー）と城の修理を入れる。
* 3択の画面（次の敵の絵・名前・Lv、右から少しずつずれてスライドして入る選択肢、入りきるまで押せない、1タップで決まり短い反応の後に次のステージへ）を作る。
* 自動兵士を、ターンの始まり（TURN の表示と同時）に陣地に現れる薄いオレンジの兵として見せ、攻防ではふつうの兵と混じって動かす（人数の表示に含める・焼き付けも作る）。
* メニューの「強化」タブ（盤面だけ）、中断データの版 3（3択の段階からの再開）、タイトルの「STAGE N・強化を選ぶ」、DEBUG タブ（強化の +1・外す・3択を出す・兵のスライダー 99）を足す。
* 攻防の計算・敵・ステージの加算・疲弊・1ターンの流れ（段取り → 攻防）は変えない。強化を取らないゲームでは、攻防の結果・予告・乱数の呼び出し（3択の抽選の分を除く）が変更の前と同じ。

### 要件1: 強化の仕組み（ルール層）
* **設定（`js/rules/config.js`）**（値は初期値。先頭の1行の説明と `Rules` の型に足す）:
    * `upgradeSlots: { castle: 1, troop: 1, card: 1, special: 0.5 }`（枠の識別子 → 重み。書いた順が枠の並び）。
    * `upgradeChoiceCount: 3`（3択の候補の数）。
    * `castleRepairPercent: 30`（城を修理で戻す割合の百分率。量は `Math.floor(maxHp * 30 / 100)`。小数の掛け算の誤差を避けるため百分率の整数で持つ）。
    * `upgrades`（強化の種類の識別子 → 設定。書いた順が一覧の並び・「強化」タブと DEBUG の並び）:
        * `castleMaxHp: { slot: 'castle', weight: 3, effect: 'castleMaxHp', range: { min: 5, max: 10 } }`
        * `autoSword: { slot: 'castle', weight: 2, effect: 'autoTroop', gauge: 'attack', amount: 1 }`
        * `autoShield: { slot: 'castle', weight: 2, effect: 'autoTroop', gauge: 'defense', amount: 1 }`
        * `autoHammer: { slot: 'castle', weight: 2, effect: 'autoTroop', gauge: 'heal', amount: 1 }`
    * 型 `UpgradeSpec`（`slot`・`weight`・`effect`・任意の `range`・`gauge`・`amount`）を JSDoc で足す。すべて `Object.freeze`。デバッグの写し（`createDebugRules`）にも同じ形で入る（DEBUG のルールの値の項目は足さない）。
* **効き方の表（`js/rules/upgradeEffects.js` 新規）**: `UPGRADE_EFFECTS`（効き方の種類 → 行。凍結）。行は次の口を持つ（`game` は `Game`、`spec` は `UpgradeSpec`、`taken` は `{ count, amount }`）。
    * `canOffer(spec, taken)`: 出せるか（今の2種はどちらもいつも `true`。上限なし）。
    * `roll(spec, random)`: 3択が出たときに決める値。`castleMaxHp` は `rollAmount(spec.range, random)`（`enemyBehaviors.js`。乱数1回。5〜10 の整数）、`autoTroop` は `spec.amount`（乱数を呼ばない）。
    * `fixedValue(spec)`: DEBUG の「+1」の値（乱数なし）。`castleMaxHp` は `spec.range.min`、`autoTroop` は `spec.amount`。
    * `take(game, spec, value)`: 取ったときにすぐ効くこと。`castleMaxHp` は `game.castle.maxHp += value; game.castle.hp += value`、`autoTroop` は何もしない。
    * `untake(game, spec, taken)`: DEBUG で外すとき。`castleMaxHp` は `game.castle.maxHp -= taken.amount` の後、今の HP が最大 HP を超えれば最大 HP に下げる。`autoTroop` は何もしない（今のターンのゲージはそのまま）。
    * `castleMaxHpBonus(spec, taken)`: 城の最大 HP に足している量（`castleMaxHp` は `taken.amount`、`autoTroop` は 0）。
    * `turnGains(spec, taken)`: ターンの頭にゲージへ足す量（`{ ゲージ: 量 }`。`autoTroop` は `{ [spec.gauge]: taken.amount }`、`castleMaxHp` は `{}`）。
    * `preview(game, spec, taken, value)`: 選択肢の文字に出す、取る前と後の値 `UpgradePreview`＝`{ before, after }`（状態は変えない。`castleMaxHp` は `{ before: game.castle.maxHp, after: game.castle.maxHp + value }`、`autoTroop` は `{ before: taken.amount, after: taken.amount + value }`（1ターンに足す兵の数））。**効き方の式はここだけに書き、画面は返った値を文字にするだけ**（憲法 3章。画面の側で足し算しない）。
    * 表にない効き方の種類は Error（`effectOf(spec)` で引く）。
* **取った強化の状態（`js/rules/upgrades.js` 新規）**: 形は `UpgradeState`＝`{ [強化の種類]: { count, amount } }`（取った種類だけが入る。`count` は取った回数（1 以上）、`amount` は効いた量の合計（最大 HP は増えた量、自動兵士は1ターンに足す兵の数））。口:
    * `createUpgradeState()` → `{}`。
    * `upgradeIds(config)`（一覧の識別子。書いた順）・`upgradeSpecOf(config, id)`（知らない識別子は Error）。
    * `upgradeTakenOf(state, id)` → `{ count, amount }`（取っていなければ `{ count: 0, amount: 0 }`。写し）。
    * `takenUpgradeList(config, state)` → `[{ id, count, amount }]`（取った種類だけ、一覧の順）。
    * `takeUpgrade(game, id, value)`: `game.upgrades` を新しいオブジェクトにして回数 +1・効いた量 +value し、効き方の `take` を呼ぶ（値は 0 以上の整数。違えば Error）。
    * `clearUpgrades(game)`: 取った種類ごとに効き方の `untake` を呼び、`game.upgrades` を `{}` にする（DEBUG 用）。
    * `fixedUpgradeValue(config, id)`: 効き方の `fixedValue`。
    * `castleMaxHpBonus(config, state)`: 全種類の `castleMaxHpBonus` の合計。
    * `turnGainsOf(config, state)`: 全種類の `turnGains` をゲージごとに足した `{ ゲージ: 量 }`（0 のゲージは入れない）。
    * `castleRepairAmount(castle, percent)`: `Math.min(Math.floor(castle.maxHp * percent / 100), castle.maxHp - castle.hp)`（最大 HP で頭打ち。満タンなら 0）。
    * `upgradePreview(game, id, value)`: 効き方の `preview(game, spec, upgradeTakenOf(game.upgrades, id), value)`（`UpgradePreview`。状態は変えない）。
    * `castleRepairPreview(castle, percent)` → `RepairPreview`＝`{ amount, before, after }`（`amount` は `castleRepairAmount(castle, percent)`、`before` は `castle.hp`、`after` は `castle.hp + amount`。状態は変えない）。
    * `isUpgradeState(value, config)`: プレーンなオブジェクトで、キーがすべて `config.upgrades` にあり、値が `{ count: 1 以上の整数, amount: 0 以上の整数 }`（例外を投げない）。
* **抽選（`js/rules/upgradeOffer.js` 新規）**: 型 `UpgradeChoice`＝`{ id, value }`、`UpgradeOffer`＝`{ choices: UpgradeChoice[], next: 'stage'|'planning' }`。
    * `drawUpgradeChoices(config, state, random)` → `UpgradeChoice[]`（0〜`upgradeChoiceCount` 個。同じ強化は2つ出ない）。手順と乱数の順（決まった順。重みの抽選は候補が1つでも必ず `random()` を1回呼ぶ）:
        1. 出せる強化 = `config.upgrades` の書いた順で、`weight > 0` かつ効き方の `canOffer` が真のもの。
        2. 候補の枠 = `config.upgradeSlots` の書いた順で、重み > 0 かつ出せる強化が1つ以上ある枠（今は `castle` だけ）。
        3. 枠を `min(N, 候補の枠の数)` 個、まだ選んでいない枠から枠の重みで1つずつ選ぶ（1つにつき乱数1回）。
        4. 選んだ枠の順に、その枠の出せる強化から強化の重みで1つ選ぶ（1つにつき乱数1回）。
        5. まだ N 個に足りなければ、候補の枠（手順2：重み > 0 かつ出せる強化が1つ以上ある枠）に属する出せる強化のうち、まだ選ばれていないものから強化の重みで1つずつ選んで埋める（1つにつき乱数1回。残りがなくなれば止める。重み 0 の枠の強化は埋めるときも出ない）。
        6. 選んだ順に、効き方の `roll` で値を決める（`castleMaxHp` は乱数1回、`autoTroop` は 0 回）。
        * 重みの抽選の式は1か所（`pickWeighted(weights, random)`: `r = random() * 合計` から重みを順に引き、負になった番号。端は最後の番号）。
        * 今の設定では: 枠 1回 → 強化 1回 → 埋める 2回 → 最大 HP が候補にあれば 1回（計 4〜5 回）。城の強化4種のうち3つが出る。
    * `isUpgradeOffer(value, config)`: `choices` が `upgradeChoiceCount` 以下の長さの配列で、各 `id` が一覧にあり重ならず、`value` が 0 以上の整数、`next` が `'stage'`・`'planning'`（例外を投げない）。
* **ゲーム（`js/rules/Game.js`）**:
    * 状態: `this.upgrades`（`createUpgradeState()`。負けると新しいゲームになるので消える）、`this.upgradeOffer`（`UpgradeOffer|null`）。段階 `stage` に `'choosing'`（3択を選んでいる）を足す。
    * 問い合わせ: `isChoosingUpgrade()`（`stage === 'choosing'`）・`canBeginUpgradeChoice()`（`stage === 'result'` かつ敵の HP 0）・`castleRepairAmount()`・`autoTroopGains()`（`turnGainsOf(config, upgrades)`）・`upgradeTaken(id)`（`upgradeTakenOf` の写し）・`upgradePreview(id, value)`（`upgradePreview(this, id, value)`。選択肢の取る前と後の値）・`repairPreview()`（`castleRepairPreview(this.castle, config.castleRepairPercent)`。修理の量と前後の HP）・`nextStageEnemy()`（`{ stageNumber: this.stageNumber + 1, typeId: enemyTypeIdOfStage(config, seed, その番号), name }`。乱数なし）。
    * `canStartNextPhase()` を `stage === 'result' && this.enemy.hp > 0` にする（**3択を選ぶ前に次のステージへ進めない**）。この1行だけは画面の流れと一緒に変える（タスク6。それまでは今のまま）。
    * `beginUpgradeChoice()`: `canBeginUpgradeChoice()` でなければ `null`。`offerUpgrades('stage')` を呼んで候補の写しを返す。
    * `offerUpgrades(next)`: `this.upgradeOffer = { choices: drawUpgradeChoices(config, upgrades, random), next }`・`this.stage = 'choosing'`（`beginUpgradeChoice` と DEBUG の口から呼ぶ。条件は呼ぶ側が確かめる）。
    * `chooseUpgrade(choice)`（`choice` は候補の番号（0 から）か `'repair'`）: 段階が `'choosing'` でない・番号が範囲外なら `null`。候補なら `takeUpgrade(this, id, value)`、`'repair'` なら `castle.hp += castleRepairAmount()`。候補を `null` に戻し、`next` が `'stage'` なら段階を `'result'` にして `advancePhase()` を呼び、`'planning'` なら段階を `'planning'` に戻す。戻り値 `UpgradeChoiceResult`＝`{ type: 'upgrade', picked: UpgradeChoice|null, repaired: number, nextPhase: NextPhaseResult|null }`。
    * `startNextPhase()` は条件を確かめて `advancePhase()` を呼ぶだけにする。`advancePhase()`（内部用。`startNextPhase`・`chooseUpgrade` から呼ぶ）は今の `startNextPhase` の中身で、`computePhaseStart` の後に **`turnGainsOf` の量をゲージへ足す**（自動兵士。取った回数だけ攻撃・防御・修理に足す。次のステージの最初のターンにも足す）。`NextPhaseResult` に `autoTroops`（足した `{ ゲージ: 量 }`）を足す。強化がなければ足す量は 0 で、乱数・予告・ゲージは今と同じ。
    * 修理の量は結果の集計（`healed`＝修理の合計）に入れない（集計は攻防の出来事だけから数える。5章）。
    * 先頭の責務の説明（3行以内）に「取った強化と3択の段階（候補・選ぶ操作）」を足す。
* **デバッグのルールの値（`js/rules/debugRules.js`）**: `applyNow` の城の最大 HP を `value + castleMaxHpBonus(game.config, game.upgrades)` にする（DEBUG で城の最大 HP を変えても、強化で増えた分が消えない。今の HP は超えるときだけ下げる。今と同じ）。

### 要件2: 城の強化と自動兵士（ルール）
* 最大 HP: 3択が出たときに 5〜10 の整数を決め、選ぶと最大 HP と今の HP がその量だけ増える（すぐ効く）。最上部の城の HP ゲージは `game.castle.maxHp` を読むので、増えた最大 HP に合う（攻防の演出の最上部も同じ）。
* 自動兵士: ターンの頭（`advancePhase` のゲージの戻しの後）に、取った回数ぶん攻撃・防御・修理の値へ足す。札と関係なく加わり、攻防ではふつうの兵と同じに数える（ゲージの値なので `computeBattle` は変えない）。選んだターンのゲージには足さず、次のステージの最初のターンから足す（`chooseUpgrade` → `advancePhase` の中で足すので、選んだ強化も最初のターンから入る）。
* 城を修理: いつも選べる。最大 HP の 30%（切り捨て）だけ回復し、最大 HP で頭打ち（満タンでも選べて 0）。

### 要件2の続き: 自動兵士の見た目（anim・view・scenes）
* **いつ現れるか**: 盤面の段階の管理（`js/scenes/boardFlow.js`）の `update` が、フェーズの始まり（TURN の表示）を出した `update` で `'turn'` を返すようにする（戻り値を `'battle'|'turn'|null` にする。今の `true` は `'battle'`）。`BoardScene.update` は戻り値を比べ、`'battle'` のときだけ `startBattle()`（`'turn'` も真になるので `if (戻り値)` のままにしない）、`'turn'` のとき `this.releaseShow.landAuto(this.game.autoTroopGains())` を呼ぶ。
* **現れるまでの人数の表示**: `BoardFlow.isTurnStartPending(game)`（`this.introPhase !== game.phase`。読むだけ）を足す。`BoardScene.draw` は `this.releaseShow.view(game.gauges, flow.isTurnStartPending(game) ? game.autoTroopGains() : null)` を渡し、`ReleaseShow.view(gauges, held = null)` は `held` のゲージの量を表示値から引く（ステージの始まりの間など、まだ現れていない自動兵士を数えない）。現れた後は、現れる時間で 0 から数え上げる（`createGaugeCount`。放つ玉と同じ式）。

* **タスク4b（`troopView.js` の薄いオレンジ）**: `drawAutoFigure` は体の絵 → 円の塗り → 持ち物の絵の順で、体と持ち物を別々に描く（`drawTroopFigure` は持ち物込みのため、体だけの呼び出し＋`drawSpriteCentered` で持ち物を描いた。大きさ・ずれはふつうの兵と同じ定数）。`:auto` の焼き付けの範囲はふつうの絵と同じ（塗りは体の円の内側なので範囲に収まる）。色 `#ffc98a`・比率 0.84 は目視で調整したい（体の黒い線の残り具合）。`auto` が効くのは `autoTint` の見た目（自軍の3種）かつ `wounded` 偽のときだけ。確かめは `main.js` の読み込み・シーンの通し実行（`BoardScene` → `BattleShowScene` → 次のフェーズ）・攻防の時間割の見た目（`:auto` を引くのは印のある兵だけ）まで行った（シーンの配線で `auto` が実際に入るのはタスク4c 以降。4c でも同じ確かめを行う）。
* **タスク5（3択の画面の部品）**: 盾・ハンマーの名前は「毎ターン 盾の兵」「毎ターン ハンマーの兵」にした（2章は「同じ書き方」とだけあり文言の指定がないため。変えたいときは `upgradeText.js` の `autoTroopText` の呼び出し2行）。群れの敵の絵は兵3体（大きさ 96・奥の2体を 30px 上、左右 ±64）で、絵の敵は `drawSpriteFit`。配置・フォント・色・板の濃さ・暗幕（`backdrop` を板・札にも掛けている）はすべて試遊で目視して決め直す値（スマホで読める大きさか、札の文字が `maxWidth` で縮まないか、修理の札の「枠の名前」を描かないのでよいか）。札の光は白い丸み板を重ねるだけ。`UpgradeChoiceShow.choose` は範囲外の番号も偽にする。まだどこからも使っていない（タスク6 で `UpgradeChoiceScene` がつなぐ）。

* **タスク6（3択の画面のシーンと流れ）**: `UpgradeChoiceScene` は外れる処理（`finish`）の後は候補が `null` になるため `draw` を止める（`finished`）。3択の間は盤面の `update` が止まるので、倒した敵の姿・BGM（HP 0 で止まったまま）は 5章の記述どおり。`BoardScene.update` の頭の `isChoosingUpgrade` の道は再開と DEBUG の「3択を出す」（タスク8）のためで、ふつうの流れ（倒した後のタップ）は `BattleShowScene` が積む。盤面が3択なしで1フレーム見えることはなかった（同じ入力の中で `popScene` → `pushScene` が代用の `oz` で動いた。実エンジンでの見え方は試遊で確認したい）。倒した直後の `entranceLook` が HP 0 で見えなくなるため、攻防の演出の終わりの盤面側の敵（背面）が消える見え方も試遊で確認したい。
