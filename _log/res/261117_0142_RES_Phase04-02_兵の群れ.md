# RES: 作業計画・作業レポート (Phase 04-02) : 兵の群れ
* 参照元REQ: `./_log/req/261117_0142_Phase04-02_兵の群れ.md`

## 1. 作業目的
攻防の演出で、自軍の兵（攻撃の兵＝剣・防御の兵＝盾・修理の兵＝ハンマー）を **1人＝1体** で描き、役割ごとの陣地（右から「防御 → 城 → 攻撃 → 修理」）に並べる。兵は弾みながら（設定で揺れながら）移動し、相打ち・ダメージの後に **ぽこんと跳ねてから画面の下へ落ちて消える**。修理の兵は城へ入って消え、使われなかった兵は終わりに城へ走って帰って消える。戦闘の段の左上に攻撃・防御・修理の人数を出し、兵が消えるたびに減らす。
**ルール（`js/rules/`）は変えない。** 攻防の出来事の並びを演出の時間に合わせて見せ方だけを作り変え、途中・早送り・スキップのどれでも結果（城と敵の HP・決着）は変わらない。あわせて、音のきっかけの時刻の式を時間割の1か所にまとめ（要件9）、要件10の片付け2件を行う。

## 2. アーキテクチャ設計

### 全体の考え方（群れ → 兵1体ずつの名簿）
* いまの「群れを位置・数・濃さの記録（`squadTrack.js`）で動かし、描くときに大きなユニットと小さな兵に換算して並べる（`troopFormation.js`）」作りをやめ、**攻防の始め（時間割を作るとき）に1回だけ、兵1体ずつの名簿（`TroopUnit` の並び）を作る**。名簿の兵1体は「陣地の中の家の位置・現れる時刻・移動の区間（脚 `TroopLeg`）の並び・終わり方（跳ねて落ちる／城に入って消える／薄れて消える）」を持つ。誰が誰と相打ちになるか、何番目が先に出るかも、このときに決めて記録する。
* 毎フレームは、時計の値から兵1体ごとの位置を **計算するだけ**（名簿は書き換えない）。結果は攻防の始めに1回だけ用意した型付き配列（`Float64Array` など）の入れ物に書き込み、描画はそれを読むだけにする（兵1体ごとに毎フレームオブジェクトを作らない）。
* 書き込みは `BattleDirector` の `update`（と `skip`・コンストラクタ）で行い、`draw` からは読むだけにする（`draw` の中で状態を変えない）。
* 乱数は使わない。家の位置は「何番目か」から決まる低食い違い列（R2 列）で決める。毎フレーム・毎回の呼び出しで同じ値になり、1体が消えてもほかの兵は動かない。

### 要件4: 移動の見せ方
* `BATTLE_ANIM.moveStyle`（`'hop'`＝弾む／`'sway'`＝揺れる。初期値 `'hop'`）で切り替える。未知の値は Error。
* 移動の脚（`TroopLeg`: `start`・`end`・`fromX`・`fromY`・`toX`・`toY`）の間は、位置を直線で補間し（`lerp`。弾みが等間隔に見えるようイージングしない）、
    * 弾む: 脚の長さから跳ねる回数 `n = max(1, round((end - start) / hopPeriodMs))` を決め、持ち上がり `lift = hopHeight * |sin(π * n * u)|`（u は脚の進み 0〜1）。脚の始めと終わりで 0 になる。
    * 揺れる: 揺れる回数 `n = max(1, round((end - start) / swayPeriodMs))`、傾き `tilt = swayAngle * sin(2π * n * u)`（ラジアン。足元を軸）。脚の始めと終わりで 0。
* 群れは陣地の中の並び（相対位置）を保ったまま進む（行き先 = 家の位置 ＋ 進む距離。相打ちの相手のいる兵だけ相手の前へ）。
* 出るのは前の兵から少しずつ遅らせる: 前から k 番目（0から、n 体のうち）の遅れ = `n <= 1 ? 0 : k / (n - 1) * min(moveStaggerMs * (n - 1), moveStaggerMaxMs)`。全体の広がりに上限があるので、数百体でも段が延びすぎない。
* 調整値は `BATTLE_ANIM` に置く: `moveStyle`・`hopHeight`（px）・`hopPeriodMs`・`swayAngle`（rad）・`swayPeriodMs`・`moveStaggerMs`・`moveStaggerMaxMs`。

### 要件5: 跳ねて落ちる消え方
* 終わり方 `TroopEnd`（`type`: `'fall'`・`'vanish'`・`'fade'`、`time`: 終わり方の始まる時刻、`doneAt`: 見えなくなる時刻、`x`・`y`: 始まる位置）。
* 跳ねて落ちる（`'fall'`）: 始まりからの経過 τ で、足元の y のずれ
    * τ ≤ `popMs`: `-(v0 * τ - g1 * τ² / 2)`（`v0 = 2 * popHeight / popMs`、`g1 = 2 * popHeight / popMs²`。`popMs` で `popHeight` の頂点）
    * τ > `popMs`: `-popHeight + fallAccel * (τ - popMs)² / 2`
    * `doneAt = time + popMs + sqrt(2 * (fallOutY - (y - popHeight)) / fallAccel)`（足元が `fallOutY` に着く時刻。作るときに1回だけ求める）。
* 相打ち（防御の兵と敵兵、攻撃の兵と敵の守り）: 相打ちの段の始め t から、組の前から k 番目が `t + 遅れ` で2体とも跳ねて落ちる（遅れは要件4と同じ式で `fallStaggerMs`・`fallStaggerMaxMs`）。1対1。
* ダメージを与えた後（敵兵が城に、攻撃の兵が敵に当たった後）、攻撃の兵と常時防御力のシールドマーク: 当たる位置へ移動し（遅れは要件4の式）、着いた時刻にその兵だけ跳ねて落ちる。
* 落ちる兵は戦闘の段の中だけに描く: `battleShowView.js` が兵を描く前後を `save` → `beginPath` → `rect(段の矩形)` → `clip` → 兵を描く → `restore` で囲む。
* 調整値は `BATTLE_ANIM` に置く: `popHeight`（px）・`popMs`・`fallAccel`（px/ms²）・`fallStaggerMs`・`fallStaggerMaxMs`。

### 要件6: 修理の兵と、使われなかった兵
* 修理の段（`heal`）: 修理の兵を全員、前から遅らせて（要件4の式）陣地から `castleEntryX`（y は各自の家の y のまま）へ `healMoveMs` かけて移動させ、着いた時刻に消す（`'vanish'`）。城の HP の表示は、1体目が着いた時刻から、量（ルールの回復の量 `step.amount`）番目の兵が着いた時刻までをかけて増える（`HpChange`。長さは `max(hpMs, その間)`）。量を超える兵（最大 HP で頭打ちの分）も同じく城に入って消える。
* 使われなかった兵: 最後の段が終わった時刻 `stepEnd` に、まだ終わり方の決まっていない自軍の兵（敵が攻撃しなかったフェーズの防御の兵・相打ちで余った防御の兵・負けで突撃しなかった攻撃の兵・修理の段がなかったときの修理の兵）を、いまいる位置から `castleEntryX` へ `returnMs` かけて（前から遅らせて。移動の見せ方は要件4と同じ）移動させ、着いたら消す（`'vanish'`。跳ねて落ちない）。
* 敵の側の余りは、REQ（敵の側は今の流れのまま）に従い、**今の `fadeLeftoversAtStart` と同じ時刻**に `fadeMs` かけて薄れて消える（`'fade'`。位置はいまいる位置）:
    * 敵の守りの余り（相打ちで余った敵の守り）: 修理の段（`heal`）の始め（今の `if (type === 'heal')` の分岐）。
    * 敵兵の余り: `FRONT_FADE_STEPS`（`march`・`enemyBlock`・`armorBlock`・`enemyHit`・`heal`・`enemyHeal`・`burn`）のうち最初に来た段の始め（今の `frontFaded` の分岐。新しい流れでは相打ちにならない敵兵は `castleHit` で全員当たりに行くので、ふつうは残らない）。
    * それらの段がなく、`stepEnd` にまだ終わり方の決まっていない敵の側の兵は、今の `ALL_KINDS` の後片付けと同じく `stepEnd` から薄れて消える（`finishTroops`）。
    * 自軍の側（今の `guard`・`soldier` の余りを消す分岐）は、上の「使われなかった兵」（`stepEnd` に城へ帰る）に置き換える。
* `fadeLeftover` は消し、名簿の `fadeTroops`（下記）に置き換える。`fadeLeftoversAtStart` は敵の側（`enemy`・`enemyGuard`）だけを `fadeTroops` で消す中身に直して残す。`fadeMs` は敵の回復の量の浮き出しと敵の側の余りに残す（説明を直す）。
* 調整値は `BATTLE_ANIM` に置く: `healMoveMs`・`returnMs`。

### 要件8: 今と同じく使えること

### 要件9: 時刻の式の一本化

### 新しい anim のモジュールと流れ
* `js/anim/campSlots.js`（新規）: 陣地の矩形と何番目かから家の位置を求める純粋関数 `campSlot(camp, index)`。
* `js/anim/troopMotion.js`（新規）: 兵1体の動きの記録（`TroopUnit`・`TroopLeg`・`TroopEnd`）の作成と追記（`createTroopUnit`・`addTroopLeg`・`setTroopEnd`）、跳ねて落ちる長さ（`fallDuration`）、時計からの1体の見た目（`sampleTroop(unit, clock, out)`。渡された入れ物 `out` に書き込み、オブジェクトを作らない）。弾む・揺れる・跳ねて落ちる・薄れる・城に入って消えるの式はここだけに置く。
    * `TroopUnit`: `kind`・`index`（種類の中の何番目か）・`homeX`・`homeY`・`appearAt`・`appearMs`（0 ならすぐ）・`legs: TroopLeg[]`・`end: TroopEnd|null`、作るときだけ使う記録 `x`・`y`（最後の脚の行き先＝いまいる位置）・`freeAt`（最後の脚の終わり）・`partner: TroopUnit|null`（相打ちの相手）。
    * `TroopSample`（`out`）: `visible`・`x`・`footY`（持ち上がり・跳ね・落ちを含む）・`sortY`（含まない）・`tilt`・`alpha`。
    * `sampleTroop`: 時計 < `appearAt` は見えない。`alpha` は `appearMs` で 0→1。`end` があり時計 ≥ `end.time` なら: `vanish` は見えない、`fade` は `end` の位置で濃さを `doneAt` に向けて 0 へ、`fall` は `end` の位置から跳ね・落ちのずれ（`doneAt` 以降は見えない）。それ以外は脚を順に見て、終わった脚の行き先・進行中の脚の補間（要件4の持ち上がり・傾き）・始まる前の脚ならその元の位置。
* `js/anim/troopRoster.js`（新規）: 名簿（`TroopRoster`: `layout`・`units`・種類ごとの前からの並び `ranked`）を作り、段ごとに兵へ脚と終わり方を割り当てる。
    * `createTroopRoster(troopLayout)`、`spawnTroops(roster, kind, count, t, appearMs)`（陣地の家に置く。陣地は `attack`/`defense`/`heal` は同名、`enemy`/`enemyGuard` は `camps.enemy`。前からの並び: 自軍は家の x の大きい順、敵の側は小さい順、同じなら番号順）
    * `marchSquad(roster, { kind, partnerKind, pairs, dir, advanceX, t })`: `kind` の前から k 番目（k < `pairs`）は `partnerKind` の前から k 番目と組（`partner` を両方に記録）。相手は `t + 遅れ` から `marchMs` かけて `-dir * blockStepX` だけ踏み出し、兵は相手の踏み出した位置の `-dir * contactGap` へ。組でない兵は家 ＋ `dir * advanceX` へ。戻り値は段の長さ（`marchMs + 遅れの広がり`）。
    * `clashPairs(roster, kind, amount, t)`: `kind` のうち相手のいる、まだ終わっていない兵を前から `amount` 組、`t + 遅れ（fall 側）` に2体とも `fall`。戻り値は遅れの広がり（ms）。
    * `chargeTo(roster, kind, count, targetX, t, moveMs)`: まだ終わっていない `kind` の兵を前から `count` 体（`Infinity` で全員）、`targetX`（y は今の y）へ移動させ、着いた時刻に `fall`。戻り値は着く時刻の昇順の配列。
    * `enterCastle(roster, kind, t, moveMs)`: まだ終わっていない `kind` を全員 `castleEntryX` へ移動させ、着いた時刻に `vanish`。戻り値は着く時刻の昇順の配列。
    * `fadeTroops(roster, kind, t)`: まだ終わっていない `kind` の兵を全員、`max(t, unit.freeAt)` から `fade`（敵の側の余りを段の始めに消す。要件6）。
    * `finishTroops(roster, t)`: 要件6の使われなかった兵（自軍は `returnMs` で城へ帰って `vanish`、まだ終わっていない敵の側は `fadeTroops` と同じく `t` から `fade`）。
    * `rosterEndTime(roster)`（全員の `doneAt` の最大）、`rosterEndTimes(roster, kind)`（その種類の `end.time` の昇順。人数の表示用）。
    * 脚の始まりは `max(t + 遅れ, unit.freeAt)`。遅れの式（要件4）はこのファイルの1か所。
* `js/anim/troopSwarm.js`（新規）: クラス `TroopSwarm`。コンストラクタで名簿の兵の数だけ型付き配列（`x`・`footY`・`tilt`・`alpha`・`sortY` は `Float64Array`、`visible` は `Uint8Array`、`order` は `Int32Array`）と種類の配列 `kinds`（文字列）と `sampleTroop` 用の入れ物1つを作る。`sample(clock)` が全員を `sampleTroop` して書き込み、`order` を `sortY` で挿入ソートする。描画にはこのインスタンスを `TroopSwarmLook`（`count`・`kinds`・`order`・`visible`・`x`・`footY`・`tilt`・`alpha`。読むだけ）として渡す。
* `js/anim/troopCounter.js`（新規）: 要件7の人数（`createTroopCounter(entries)`・`sampleTroopCounts(counter, clock)`）。
* `js/anim/battleSteps.js`（更新）: `BattleSnapshot.heal` を足す。`form` の段は `troops: {attack, defense, heal}` と `enemyGuards` を持つ（`guards` は消す）。`enemyMarch` の段に `pairs`（`block` の出来事の量。なければ 0）、`march` の段に `pairs`（`enemyBlock` の出来事の量。なければ 0）を足す。段の並びと順番は変えない。
* `js/anim/battleTimeline.js`（作り直し）: 段の builder は名簿の関数を呼んで段の長さを返し、HP の変化・きっかけの時刻（`state.cueTimes`）を記録する。各段の長さ:
    * `form`: 自軍3種と敵の守りを `spawnTroops(..., t, formMs)`。長さ `formMs`。
    * `enemyMarch`: 敵兵を `spawnTroops('enemy', amount, t, 0)`、`marchSquad({ kind: 'enemy', partnerKind: 'defense', pairs, dir: -1, advanceX: enemyAdvanceX, t })`。
    * `block`・`enemyBlock`: `clashPairs(roster, 'enemy' または 'attack', amount, t)`、きっかけ `t`。長さ `広がり + clashMs`。
    * `castleHit`・`enemyHit`: `chargeTo(roster, 'enemy' または 'attack', Infinity, castleHitX または enemyHitX, t, hitMoveMs)`。HP の変化は1体目の着く時刻から `max(hpMs, 最後 − 最初)`、きっかけは1体目の着く時刻（兵がいなければ `t + hitMoveMs`）。長さ `hitMoveMs + max(hpMs, 広がり)`。
    * `march`: `marchSquad({ kind: 'attack', partnerKind: 'enemyGuard', pairs, dir: 1, advanceX: attackAdvanceX, t })`。
    * `armorBlock`: `chargeTo(roster, 'attack', amount, armorHitX, t, hitMoveMs)`。きっかけは1体目の着く時刻。長さ `hitMoveMs + 広がり + clashMs`。
    * `heal`: 要件6。長さ `healMoveMs + max(hpMs, 広がり)`。
    * `enemyHeal`・`burn`: 今どおり（きっかけの記録を足す）。

    * 段がひとつでもあれば、最後に `finishTroops(roster, stepEnd)`。`endTime` は段の終わり・`rosterEndTime`・浮き出し・燃える札の最大。
    * `BattleTimeline` は `squads` をやめ、`roster`（名簿）・`troopCounter` を持つ。
* `js/anim/battleDirector.js`（更新）: コンストラクタは `{ timeline, result, before }`（`troopLayout` をやめる）。`TroopSwarm` を作って `sample` をコンストラクタ・`update`・`skip` で呼ぶ。`view()` の `BattleLook` は `units` をやめ、`troops`（`TroopSwarmLook`）・`troopCounts`（`{attack, defense, heal}`）を持つ。

## 5. 懸念事項・要確認ポイント
* **途中のタスクで攻防の演出が動かない範囲**: 各タスクの終わりで、アプリ全体は読み込める（import の解決・構文が通る）。名前つき export を消すのはタスク4（`drawTroops`。import 元の `enemyView.js`・`battleShowView.js` も同じタスクで差し替える）とタスク9（`squadTrack.js`・`troopFormation.js` の削除。import 元の `battleDirector.js` も同じタスクで差し替える）だけ。`hordeSlots` の戻り値の変更と `enemyView.js` の対応もタスク4で同時に行うので、タイトル・段取り（ゴブリンの軍勢の絵を含む）はどのタスクの終わりでも今どおり動く。
    *   タスク1〜3の終わり: 足すだけなので、攻防の演出も今どおり動く。
    *   タスク4〜8の終わり: 攻防の演出（`BattleShowScene`）に入ると正しく動かない。タスク4で `TroopLayout` の古い項目が消えるので、古い時間割・`troopFormation.js` の兵の位置が計算できず、`battleShowView.js` は `BattleDirector` がまだ返さない `look.troops`・`look.troopCounts` を読むため、描画で例外が出る。タスク8の後は `battleDirector.js` が時間割に無くなった `squads` を読むため、`BattleDirector` を作る時点で例外が出る。この間は攻防の演出に進めず、フェーズをまたいだ通しの確認はできない。
    *   タスク9の終わり: 新しい作りにつながり、通しで動く（通しの確認はここから）。
* **ゴブリンの軍勢の絵の兵の大きさ**: `hordeSlots` が `smallW`・`smallH`（丸の直径 約 21px）から `TROOP_SIZE`（24px）に変わるので、ゴブリンの軍勢の絵が少し大きくなる（並びの数・位置の決め方は今のまま）。
* **敵の側の余りが消える時刻**: REQ（敵の側は今の流れのまま）に従い、今の `fadeLeftoversAtStart` と同じく、敵の守りの余りは修理の段の始め、敵兵の余りは `FRONT_FADE_STEPS` の最初の段の始め（どちらもその段がなければ `stepEnd`）から薄れて消える。自軍の使われなかった兵（終わりに城へ帰る）とは消える時刻がそろわないが、敵の側の見せ方は後のサブフェイズで作り直す。
* **城に当たる位置**: `castleHitX` を城の中心から右端寄り（右端 − 10）に変える。敵兵が城の絵の手前で跳ねて落ちるように見えるため。違和感があれば `CASTLE_HIT_INSET` で動かす。
* **HP の表示の増減は直線**: 兵が1体ずつ当たる・城に入るのに合わせて、HP は最初の兵の時刻から最後（修理は量番目）の兵の時刻までを直線で変わる（1体ごとの段差ではない）。ずれが目立つか試遊で見る。
* **音は段ごとに1回**: 数百体でも、相打ち・当たり・修理の音は段の最初の瞬間に1回だけ鳴らす（1体ごとには鳴らさない）。
* **兵の数が多いときの重さ**: 兵1体ごとに体と持ち物のベクタースプライトを描くので、数百体では描画が重くなりうる。計算側は型付き配列で毎フレームのオブジェクトを作らないが、描画の重さの確認と対策（まとめ方）は後の Phase のデバッグモードで行う。
* **陣地の重なり**: 突撃した攻撃の兵の待つ位置（約 x 350〜440）と防御の兵の陣地（x 300〜400）は重なる（防御の兵が余っていると同時にいる）。重なってよい前提だが、見え方を試遊で見る。
* **段取りの間の人数の表示**: 今回は攻防の演出の間だけ出す（ゲージの行と二重にならないため）。
* **テストプレイで確かめること（発注者が見る点）**
    *   攻防の演出で、自軍の兵が1人＝1体で、丸い体に剣・盾・ハンマーを持って描かれている。大きな兵が出ない。
    *   陣地が右から「防御 → 城 → 攻撃 → 修理」と並び、兵が奥から手前の順に重なって見える。兵が消えても、ほかの兵が並び替わらず、ちらつかない。
    *   兵が弾みながら（設定 `BATTLE_ANIM.moveStyle` を `'sway'` に切り替えれば揺れながら）移動する。
    *   相打ちと、城・敵に当たった後に、兵がぽこんと跳ねて画面の下へ落ちる。落ちる兵がソリティアの段に描かれない。
    *   修理の兵が城へ弾みながら向かって消え、城の HP が増える。使われなかった防御の兵が、終わりに城へ走って帰って消える。
    *   戦闘の段の左上に攻撃・防御・修理の人数が出て、兵が消えるたびに減る。スキップすると最後の値になる。
    *   音が、ぶつかった・当たった・城に入った瞬間に合って鳴る。早送り・スキップが今と同じく使え、結果（城と敵の HP、決着）が変わらない。
    *   常時防御力の段・敵の回復・ブレスで札が燃える段・敵を倒したときの案内・決着の表示が今の流れのまま動き、タイトルからクリア・負けまで通しで遊べる。
