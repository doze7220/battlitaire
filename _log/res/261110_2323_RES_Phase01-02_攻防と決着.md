# RES: 作業計画・作業レポート (Phase 01-02) : 攻防と決着
* 参照元REQ: `./_log/req/261110_2323_Phase01-02_攻防と決着.md`

## 1. 作業目的
01-01 で作った段取り（めくる・置く・捨てる・放つ）の後に、城と敵の攻防を計算し、フェーズを繰り返して勝ち・負けの決着まで遊べるようにする。攻防の計算（出来事の並びを作る）・フェーズの進行（ゲージの戻し、力こぶの換算、行動回数、敵の予告）・段階の管理・決着の判定はルール層 `js/rules/` に、責務ごとにファイルを分けて書く。画面は、城・敵・フェーズの文字表示、行動終了のボタン、攻防の結果の窓（`Engine.pushScene` で積む別シーン）を作り、ルール層の状態と出来事の並びを文字で見せるだけにする。決着したらタイトル（「TAP SCREEN」）に戻り、そこから新しいゲームを始められるようにする。攻防の演出・効果音・敵の種類などは作らない。

## 2. アーキテクチャ設計

### 共通の前提（全タスク共通）
*   ルール層 `js/rules/` は `oz` も `js/` のほかのフォルダも import しない。Canvas・DOM・音・時間・`Math.random` に触れない。import してよいのは `js/rules/` の中のファイルだけ。表示文字（「城が受けたダメージ」など）をルール層に持たせない。
*   ルールの数値（城の最大 HP 50、敵の最大 HP 100、敵の行動「攻撃10」、力こぶの換算 5ごと・最大+2）は `js/rules/config.js` の `RULES` にだけ書く。ほかのファイル（`js/view/`・`js/scenes/` を含む）に直書きしない。画面はルール層の状態（`game.castle.maxHp` など）から読む。
*   画面の座標・色・大きさ・フォント・表示する文字は `js/view/` に置く（調整値ではない）。
*   ファイル名: クラスを export するファイルはクラス名（`BattleResultScene.js`）、関数や定数を export するファイルは camelCase（`battle.js`）。
*   すべてのファイルの先頭行に、責務を JSDoc で3行以内に書く。すべての関数・クラス・メソッド・データ構造（`@typedef`）に JSDoc を書く。既存ファイルの先頭の責務は、今回の変更で責務が広がる場合に限り、新しい内容に合わせて書き直す（タスクで明示したファイルのみ）。
*   シーンの入力は `onPointer` の `'down'` だけで受ける。`Engine.addButton` は使わない。`js/` に `addEventListener`・`requestAnimationFrame`・`getContext`・`performance.now()`・`Date.now()` を書かない。シーンの操作（`pushScene`・`popScene`・`changeScene`）は `onPointer` の中でだけ呼ぶ（`oz/ENGINE_API.md` 7章。`draw`・`init`・`destroy` の中では呼ばない）。

*   `layout.hitTest` の当たりの種類に `'actionEnd'` を足す（`{ kind: 'actionEnd', index: 0 }`。`Hit` の形をそろえるため `index` は 0 固定）。調べる順は「行動終了 → 放つボタン → 山札 → 列」（重ならないので順は結果に影響しない）。
*   `BoardUi`（`boardView.js`）に `battleReady: boolean` を足し、シーンが `game.canResolveBattle()` で作る。`drawHud` は引数 `battleReady` を受け取り、ボタンの見た目を切り替える。
*   `BoardScene.onPointer`（`'down'` のときだけ）の流れ:

### 要件3: 攻防の計算（ルール層）
*   攻防の計算は新しいファイル `js/rules/battle.js` の純粋関数 `computeBattle(input)` に書く（01-01 の `release.js` と同じ考え方。引数を書き換えない）。
    *   入力 `BattleInput`: `{ attack, defense, heal, enemyAttack, castleHp, castleMaxHp, enemyHp }`（すべて0以上の整数）。
    *   出力 `BattleCalc`: `{ events: BattleEvent[], castleHp, enemyHp, outcome: 'win'|'lose'|null }`（`castleHp`・`enemyHp` は攻防の後の値）。
    *   計算の順（REQ 要件3の順どおり）:
        1.  出来事 `enemyAttack`（量 = 敵の攻撃）を入れる。
        2.  相殺 `blocked = min(defense, enemyAttack)`。
        3.  `damage = min(enemyAttack − blocked, castleHp)`。城の HP から引く。
        4.  城の HP が0なら `lose` を入れて `outcome = 'lose'` で終える（以降は計算しない）。
        5.  `dealt = min(attack, enemyHp)`。敵の HP から引く。
        6.  敵の HP が0なら `win` を入れて `outcome = 'win'` で終える（回復は計算しない）。
        7.  `healed = min(heal, castleMaxHp − castleHp)`。城の HP に足す。
    *   余った防御は使われずに消える（持ち越しは作らない）。
*   **出来事 `BattleEvent` の形**: `{ type, amount }`。`type` は次のいずれか。量は実際に変わった値。
    *   `'enemyAttack'`: 敵の攻撃（量 = 敵の攻撃の値）。攻防の最初に必ず入る（敵が攻めてきたこと自体を Phase 2 の演出・結果の窓の1行目で見せるため）。
    *   `'block'`: 防御で相殺した量。
    *   `'castleDamage'`: 城が受けたダメージ。
    *   `'enemyDamage'`: 敵に与えたダメージ。
    *   `'heal'`: 城の回復量。
    *   `'lose'`・`'win'`: 決着。量は 0（量を持たない出来事として 0 を入れる）。
*   **量が0の出来事の扱い（本計画の決定）**: `block`・`castleDamage`・`enemyDamage`・`heal` は、量が0のときは並びに入れない（省く）。結果の窓に「相殺 0」のような行は出ない。Phase 2 の演出も、起きなかったことは見せない。`enemyAttack` は量にかかわらず必ず入れ、`win`・`lose` は決着したときだけ入れる。
    *   確認用の例: 城 50/50・敵 100、敵の攻撃 10、攻撃 36・防御 6・回復 3 → `enemyAttack 10`・`block 6`・`castleDamage 4`・`enemyDamage 36`（城 46・敵 64）・`heal 3`（城 49）。城 3、敵の攻撃 10、防御 0 → `enemyAttack 10`・`castleDamage 3`・`lose 0`（攻撃・回復は計算しない）。防御 16、敵の攻撃 10 → `block 10`（`castleDamage` は省く）。敵 20、攻撃 36 → `enemyDamage 20`・`win 0`（回復は計算しない）。城 48/50、回復 10 → `heal 2`。
*   `Game.resolveBattle()`（`js/rules/Game.js`）: `canResolveBattle()` でなければ `null`。ゲージ（`gauges.attack`・`gauges.defense`・`gauges.heal`）と城・敵の値、敵の予告の量（`enemy.intent.amount`）から `computeBattle` を呼び、城・敵の HP を結果の値にする。`outcome` が `null` なら段階を `'result'`（攻防の結果を見ている）に、そうでなければ段階を `'over'`（決着）にし `this.outcome` に入れる。結果 `BattleResult` を返す。
    *   敵の行動の種類による分岐は作らない（今の種類は「攻撃」だけなので、予告の量をそのまま敵の攻撃として渡す）。
*   **段階 `stage`**（`Game` が持つ）: `'planning'`（段取り中）・`'result'`（攻防の結果を見ている）・`'over'`（決着）。
    *   既存の問い合わせ `canSelectDeck`・`canRelease` は「段階が `'planning'`」も条件に加える（`placeableColumns`・`canDiscard` は `canSelectDeck` を通るので自動的に拒まれる。`place`・`discardTop`・`release` はこれらの問い合わせを通るので、段取り中以外は `null` を返す）。
    *   `canResolveBattle()`: 段階が `'planning'` で、行動回数が0。
    *   `canStartNextPhase()`: 段階が `'result'`。
    *   `isOver()`: 段階が `'over'`。

### 要件4: 攻防の結果の窓
*   新しいシーン `js/scenes/BattleResultScene.js`（`Scene` を継承）。盤面のシーンから `Engine.pushScene` で積む。積むと背面の盤面のシーンは `draw` だけ続き、入力は届かない（`oz/ENGINE_API.md` 6章）。
    *   constructor `({ screen, layer, game, result, createTitle })`: `game` はルール層のゲーム（次のフェーズの操作と決着の問い合わせに使う）、`result` は `game.resolveBattle()` の戻り値、`createTitle` はタイトルの画面のシーンを作る関数。`init()` で窓の配置（`createResultLayout(screen)`）を作る。
    *   `onPointer`: `'down'` のときだけ反応し、画面のどこを押しても次を行う（窓の外を含む。当たり判定は不要なので `hitTest` は作らない）。`'up'`・`'move'` は無視する（ボタンを押した `'down'` の後に届く `'up'` で閉じないため。`oz/ENGINE_API.md` 16章の最後の項目）。
        *   `game.isOver()` なら `Engine.changeScene(this.createTitle())`（タイトルへ戻る。盤面のシーンと窓のシーンはどちらも外れる）。
        *   そうでなく `game.canStartNextPhase()` なら、`game.startNextPhase()` を呼び、`Engine.popScene()` で窓を外す（盤面のシーンに戻り、次のフェーズの段取りが始まる）。次のフェーズの操作の結果は、今回の画面では使わない（捨てる）。
    *   `draw(ctx, layer)`: 自分のレイヤーのときだけ `drawResultWindow(ctx, this.resultLayout, this.result, this.game.isOver())` を呼ぶ。状態は変えない。
    *   レイヤーは `'main'` 1つだけなので、スタックの順（盤面 → 窓）に `draw` が呼ばれ、窓が盤面の上に重なる（`oz/ENGINE_API.md` 10章）。
*   窓の配置は新しいファイル `js/view/resultLayout.js` の `createResultLayout(screen)` が作る（`ResultLayout`: `{ screen, panel: Rect, titleY, lineTop, linePitch, outcomeY, hintY }`）。目安: 窓 640×520 を画面中央（x=320〜960、y=100〜620）。見出し y=140、行の先頭 y=200・間隔 44（行は最大5行: `enemyAttack`・`block`・`castleDamage`・`enemyDamage`・`heal`）、決着の大きな文字 y=460、案内 y=570。
*   描画は新しいファイル `js/view/resultWindowView.js` の `drawResultWindow(ctx, resultLayout, result, over)`:
    *   画面全体を半透明の黒（例 `rgba(0, 0, 0, 0.5)`）で塗って盤面を暗くし（盤面は見えたまま）、窓の枠を描き、見出し「攻防の結果」を出す。
    *   出来事の行は `js/view/battleText.js` の `battleEventLines(result.events)` が返す文字の配列を、上から順に1行ずつ出す。
    *   `over` が `true` なら、行の後に `outcomeText(result.outcome)`（「勝ち」／「負け」）を大きく出し、その下に「タップでタイトルへ」。`false` なら「タップで次のフェーズへ」。案内の文字は `resultWindowView.js` の先頭の定数。
*   **出来事を表示文字に直す**のは新しいファイル `js/view/battleText.js` の仕事（ルール層は表示文字を持たない）:
    *   `eventLine(event)`: `enemyAttack` → 「敵の攻撃 N」、`block` → 「防御で相殺 N」、`castleDamage` → 「城が受けたダメージ N」、`enemyDamage` → 「敵に与えたダメージ N」、`heal` → 「城の回復 N」、`win`・`lose` → `null`（決着は別に大きく出すので行にしない）。未知の種類も `null`。
    *   `battleEventLines(events)`: 各出来事を `eventLine` に通し、`null` を除いた文字の配列を返す（並びの順を保つ）。
    *   `outcomeText(outcome)`: `'win'` → 「勝ち」、`'lose'` → 「負け」、それ以外 → 空文字。
    *   `enemyActionText(action)`: 行動の種類の表示名（`attack` → 「攻撃」。未知は「？」）と量で「攻撃 10」を作る（要件1の予告の表示に使う）。
    *   計算はしない（出来事の量をそのまま出す）。
*   **タイトルへ戻る**: `js/main.js` に「盤面のシーンを作る関数」と「タイトルの画面（`BootScene`）を作る関数」を置き、互いに渡す。
    *   `function createBoard() { return new BoardScene({ screen, layer: 'main', random: Math.random, createTitle }); }`
    *   `function createTitle() { return new BootScene({ screen, layer: 'main', next: createBoard }); }`
    *   `config.scene` は `createTitle()` にする（関数宣言で書き、巻き上げで互いを参照できるようにする）。
    *   `BoardScene` は受け取った `createTitle` を `BattleResultScene` に渡すだけ。`BoardScene`・`BattleResultScene` は `BootScene` を import しない。
    *   `BootScene` は `next()` を進むたびに呼ぶので、毎回新しい `BoardScene` → `init()` で新しい `Game`（山札を混ぜ直し、フェーズ1）になる。`BootScene` は自分で `'down'` を受けるまで `'up'` で進まないので、窓を閉じた `'down'` の後の `'up'` でタイトルが飛ばされることはない（`BootScene` は変更しない）。

### 要件5: 次のフェーズ（ルール層）
*   フェーズの頭の計算は新しいファイル `js/rules/phase.js` の純粋関数 `computePhaseStart(gauges, config)` に書く（引数を書き換えない）。
    *   出力 `PhaseStart`: `{ gauges, bonusActions, muscleSpent, actions }`。
    *   `gauges`: 新しいゲージ。`config.gauges` の各キーについて、`config.keptGauges` に含まれるものは今の値を残し、それ以外（攻撃・防御・回復）は0にする。そのうえで力こぶの換算分を力こぶのゲージから引く。
    *   力こぶの換算: `m = gauges[config.muscleConversion.gauge]`、`bonusActions = min(floor(m / per), maxBonus)`、`muscleSpent = bonusActions × per`。
    *   `actions = config.baseActions + bonusActions`。
    *   確認用の例（`per: 5`・`maxBonus: 2`）: 力こぶ12 → +2行動・残り2・7行動。力こぶ17 → +2行動・残り7。力こぶ4 → +0・残り4・5行動。力こぶ5 → +1・残り0・6行動。
*   敵の次の行動は新しいファイル `js/rules/combatants.js` の `planEnemyAction(config)` が決める（今回は毎回 `config.enemyAction` の写し `{ kind: 'attack', amount: 10 }` を返す。種類ごとの分岐や敵の種類の仕組みは作らない）。
*   `Game.startNextPhase()`: `canStartNextPhase()` でなければ `null`。フェーズの番号を1増やし、`computePhaseStart(this.gauges, this.config)` の結果でゲージを置き換え、`actionsMax`・`actionsLeft` を `actions` にし、`enemy.intent = planEnemyAction(config)`、段階を `'planning'` に戻す。山札・列・捨て札・城と敵の HP には触れない。結果 `NextPhaseResult` を返す。
*   ゲーム開始時（constructor）: `phase = 1`、行動回数は `config.baseActions`（力こぶは0なので換算は起きない。開始時は `computePhaseStart` を呼ばずに直接設定してよい）、`castle = createCastle(config)`、`enemy = createEnemy(config)`（`intent` は `planEnemyAction(config)` で埋める）、`stage = 'planning'`、`outcome = null`。

### 要件6: 決着
*   `computeBattle` の `outcome` が `'win'`／`'lose'` のとき、`Game.resolveBattle` が段階を `'over'` にする。`'over'` では、置く・捨てる・放つ（段階の条件）、攻防（`canResolveBattle` は `'planning'` のみ）、次のフェーズ（`canStartNextPhase` は `'result'` のみ）がすべて拒まれる（`null` を返す）。
*   表示と遊び直しは要件4のとおり。

### 要件7: 調整値
*   `js/rules/config.js` の `RULES` に次を足す（`Rules` の `@typedef` にも項目を足す。中のオブジェクト・配列も凍結する）:
    *   `castleMaxHp: 50`
    *   `enemyMaxHp: 100`
    *   `enemyAction: Object.freeze({ kind: 'attack', amount: 10 })`（敵が毎フェーズ予告する行動。種類と量）
    *   `keptGauges: Object.freeze(['muscle'])`（フェーズをまたいで残すゲージ）
    *   `muscleConversion: Object.freeze({ gauge: 'muscle', per: 5, maxBonus: 2 })`（力こぶのゲージ `per` ごとに+1行動、最大 `maxBonus`）
*   ファイル先頭の責務の文に「城・敵の数値、力こぶの換算」を足す。

### ルール層のデータ構造（JSDoc の `@typedef` で書く）
*   `EnemyAction`（`combatants.js`）: `{ kind: string, amount: number }`（今の `kind` は `'attack'` だけ）。
*   `Castle`（`combatants.js`）: `{ hp: number, maxHp: number }`。
*   `Enemy`（`combatants.js`）: `{ hp: number, maxHp: number, intent: EnemyAction|null }`（`intent` は次の行動の予告）。敵の「種類」は今回は持たない（REQ 要件7。Phase 3 で扱う）。
*   `BattleInput`・`BattleEvent`・`BattleCalc`（`battle.js`）: 要件3のとおり。
*   `PhaseStart`（`phase.js`）: 要件5のとおり。
*   操作の結果（`Game.js`）:
    *   `BattleResult`: `{ type: 'battle', enemyAction: EnemyAction, events: BattleEvent[], castleHp: number, enemyHp: number, outcome: 'win'|'lose'|null }`
    *   `NextPhaseResult`: `{ type: 'nextPhase', phase: number, bonusActions: number, muscleSpent: number, muscleLeft: number, actionsMax: number, actionsLeft: number, enemyAction: EnemyAction }`
