# RES: 作業計画・作業レポート (Phase 07-10) : 加算と激昂（ステージの加算の HP・防御を下げ、1体との戦闘の疲弊をやめて激昂にする。戦闘の BGM を1曲にし、激昂で切り替える）
* 参照元REQ: `./_log/req/261127_1602_Phase07-10_加算と激昂.md`

## 1. 作業目的
発注者の試遊で「防御をしていれば負けないが、勝てもしない」戦闘が長引いた。原因は、HP と防御が両方伸びることと、守りに行動を回すぶん攻撃が減ることの重なりにある。疲弊（長引くと敵の防御が減る）は、守りを固めて粘るほど得になるので逆向きである。そこで、長く戦わせるのではなく、攻撃の痛さで「死ぬか倒すか」を突きつける形に改める。

* **ステージの加算**: HP は 1ステージごとに +2%（章で変えない）、防御は全章で 1ステージごとに +0.25（合計の端数の切り捨ては今のまま）。攻撃は変えない（章ごとの 0.5・0.75・1・1.25 のまま）。数え方は今のまま（ステージ 1 は加算 0、ステージ 2 から足す）。
* **疲弊をやめる**: 防御が減る決まり（設定 `fatigue`・`fatiguedDefense`・`isFatigued`・`Game.isEnemyFatigued`）・「疲弊」の表示・予告の疲弊の前の防御 `baseDefense` をなくす。21 ターン目以降も敵の防御はふつうどおり。
* **激昂**（どの敵も同じ決まり。敵の識別子で分岐しない）: 戦闘のターン（`battleTurn`）が 15 までは今のまま。16 ターン目から敵が激昂し、予告の攻撃の量（ステージの加算を足した後の最後の量）に倍率がかかる（16 で ×1.2、17 で ×1.4 …と 1ターンごとに 0.2 ずつ。上限なし）。倍率は百分率の整数で持ち、量は整数で計算する（切り捨て。1体のポイントを持つ敵はその倍数に切り捨て）。攻撃の量 0 の行動は 0 のまま。防御・行動の型・周期・確率・攻撃の直後の回復・燃やす札の数・子スライムの数にはかけない。次の敵には持ち越さない。
* **表示**: 激昂の間、敵の名前の行の右詰め（今の「疲弊」の場所）に「激昂 ⚔×1.2」（倍率は小数第1位まで）。合図・予告（あと N ターン）は出さない。
* **BGM**: 戦闘の BGM はどの敵でも同じ曲（今の `stage`）。激昂に入るターンの TURN の表示で激昂の曲（今のドラゴン戦の曲 `assets/bgm/dragon.mp3`）にクロスフェードし、次の敵でふだんの曲に戻る。再開・DEBUG でも、そのときの激昂の状態に合う曲。
* **中断データ**: 予告の形が変わる（`baseDefense` をなくし、倍率の前の量 `baseAmount` を足す）ので版を 9 に上げる。
* **DEBUG**: ターンの番号のスライダーで激昂を試せる（予告の攻撃の量・表示・曲が合う）。ルールの値に「激昂」の組（始まるターン・上がる量の2本）。
* **古い説明コメントの直し**（REQ 要件7。動きは変えない）。
* **数値はすべて設定（ルールは `config.js`、音は `soundConfig.js`）に置く。攻撃の加算・敵の行動の型・周期・確率・防御の抽選・攻防の計算・強化・スコア・★の並び・1ターンの流れ・ほかの機能は変えない。**

### 要件1: ステージの加算（ルール。タスク1）
* **設定の形は今の章の形のまま、値だけを変える**（`stageBonusOf`・`grownMaxHp`・呼ぶ側（`combatants.js` の最大 HP・`enemyIntent.js` の予告の加算）は変えない）:
  ```js
  stageGrowth: Object.freeze({
    stagesPerChapter: 5,
    chapters: Object.freeze([
      Object.freeze({ hpPercent: 2, attack: 0.5, defense: 0.25 }),
      Object.freeze({ hpPercent: 2, attack: 0.75, defense: 0.25 }),
      Object.freeze({ hpPercent: 2, attack: 1, defense: 0.25 }),
      Object.freeze({ hpPercent: 2, attack: 1.25, defense: 0.25 }),
    ]),
  }),
  ```
  * 章の形を残すのは、攻撃が章ごとに違うため（HP・防御だけを別の形にすると、`stageBonusOf` の式と型を変えることになる。要件は「値だけ変えてもよい」）。
  * 期待値: ステージ n の加算は HP の百分率 = 2 × (n − 1)、防御 = floor(0.25 × (n − 1))。ステージ 10 は +18%・防御 +2、20 は +38%・+4、30 は +58%・+7。攻撃は変更前と同じ（10 は floor(0.5×4 + 0.75×5) = 5、20 は floor(2 + 3.75 + 5 + 1.25×5) = 17、30 は floor(2 + 3.75 + 5 + 1.25×15) = 29。数字は確かめで変更前の `stageBonusOf` と比べる。計画の時点で変更前のコードで求めた値は、変更前 HP% 55・160・280・防御 2・7・12、変更後の値の写しで HP% 18・38・58・防御 2・4・7・攻撃 5・17・29）。
* `ChapterGrowth` の JSDoc（今は値が全章で同じ HP・防御も、章ごとに書ける形であること）と、`Rules.stageGrowth` の説明は形が変わらないので、説明の言い回しだけ必要なら直す（「HP・防御は今は全章で同じ値」と一言足す）。

### 要件2: 激昂のルール（タスク2・タスク3）
* **設定**（`config.js`。`fatigue` の代わり。タスク2で足し、`fatigue` はタスク3で消す）:
  ```js
  rage: Object.freeze({ fromTurn: 16, stepPercent: 20 }),
  ```
  * 型 `RageSpec`（`fromTurn`＝激昂が始まる戦闘のターン（1 以上の整数）・`stepPercent`＝激昂の1ターンごとに上がる倍率の量（百分率の整数。0 以上））。`Rules.rage` の JSDoc。先頭の説明の「疲弊（長引いた敵の防御の減り方）」を「激昂（長引いた戦闘で敵の攻撃が上がる倍率）」に（タスク3で疲弊を消すときに直す。タスク2では激昂を足すだけ）。
* **新規 `js/rules/enemyRage.js`**（純粋関数。import は `unitPoints.js` の `floorToUnit` だけ。敵の識別子を読まない）:
  * `rageStatusOf(rage, battleTurn)` → `RageStatus`（`{ enraged: boolean, percent: number }`）。`battleTurn >= rage.fromTurn` なら `enraged: true`・`percent = 100 + rage.stepPercent × (battleTurn − rage.fromTurn + 1)`、そうでなければ `enraged: false`・`percent = 100`。16 → 120、17 → 140、20 → 200。上限なし。
    * 100 は「倍率 ×1.0 の百分率」という単位の定数で、ルールの数値ではない（`const BASE_PERCENT = 100` として JSDoc を付ける）。
  * `ragedAmount(amount, percent, unit)` → `floorToUnit(Math.floor((amount * percent) / 100), unit)`（整数だけで計算。`amount * percent` は整数で、100 で割った値の切り捨ては、割り切れるときは正確な整数、割り切れないときは整数から 0.01 以上離れるので、浮動小数の誤差で数字が変わらない。この理由を JSDoc に書く）。例: 7 × 120 → 8、3 × 120 → 3、0 → 0、オーガ（unit 2）6 × 120 = 7.2 → 7 → 6。
  * 倍率 100 のときは、量が1体のポイントの倍数なら量そのもの（予告の加算前の量は幅の中の倍数・加算も倍数に切り捨て済みなので、激昂していない予告は今と同じ数字）。
  * 先頭の責務（3行以内）: 「戦闘のターンと激昂の設定から、敵が激昂しているか・倍率（百分率の整数）と、倍率をかけた攻撃の量を求める（純粋関数。ルール層）。激昂の式はこのファイルだけ。」
* **予告の組み立て**（`enemyIntent.js`。予告にステージの加算を足し、激昂の倍率をかけるのはここ1か所）:
  * `createIntent(spec, action, bonus, battleTurn, rage, random)`（今の `fatigue` の引数を `rage` に）:
    * 防御: 今の `baseDefense` の求め方（`guard` → 加算を足す／隙でなく防御の設定があれば `rollDefense`（必ず2回）→ 張れば加算を足す／それ以外 0）をそのまま `defense` にする（疲弊をかけない。乱数の順・回数は今と同じ）。
    * 攻撃: `baseAmount` = 今の `amount`（攻撃なら `action.amount + floorToUnit(bonus.attack, unit)`、ほかは `action.amount`（0））。`amount = ragedAmount(baseAmount, rageStatusOf(rage, battleTurn).percent, unit)`。
    * 戻り値は `{ ...rest, amount, baseAmount, defense }`（`guard` は残さない。`baseDefense` は持たない）。
  * `refreshIntent(spec, intent, battleTurn, rage)` → `{ ...intent, amount: ragedAmount(intent.baseAmount, rageStatusOf(rage, battleTurn).percent, unitPointsOf(spec)) }`（乱数は呼ばない。防御・`minions`・`variant`・`burn`・`sureHeal` はそのまま）。
  * import: `enemyBehaviors.js`（`isOpeningAction`）・`enemyDefense.js`（`rollDefense` だけ）・`enemyRage.js`・`unitPoints.js`。先頭の責務を「敵の行動に、ステージの加算（攻撃・防御）と防御の量と激昂の倍率を付けて予告を作り、戦闘のターンを変えたときに倍率を数え直す」に。
* **予告の型**（`combatants.js` の `EnemyIntent`）: `EnemyAction & { baseAmount: number, defense: number, minions?: number }`。`amount` は倍率をかけた後の最後の攻撃の量（予告の札・ターンの始まりの文字・攻防が読むのはこれだけ）、`baseAmount` は加算の後・倍率の前の量（DEBUG でターンの番号・激昂の値を変えたときに数え直す元になるだけ）、`defense` は加算の後の防御の量（疲弊なし）。`EnemyAction.amount` の説明（加算の前）はそのまま。
* **ゲーム**（`Game.js`。足すのは薄い口だけ）:
  * `intentOf(action)`: `createIntent(spec, action, this.stageBonus(), this.battleTurn, this.config.rage, this.random)`。JSDoc の「疲弊を付けた」を「激昂の倍率をかけた」に。
  * 問い合わせ `enemyRage()` → `rageStatusOf(this.config.rage, this.battleTurn)`（`RageStatus`。乱数は呼ばず状態も変えない。毎回新しいオブジェクト）。画面・BGM はこれを読むだけ。
  * `isEnemyFatigued()` と `import { isFatigued }` はタスク3で消す（タスク2では残す）。
  * 戦闘のターンの決まり（`spawnEnemy` で 1、`advancePhase` で敵が替わらなければ +1 してから `planIntent`）は今のまま。これで「次の敵には持ち越さない」が決まる（敵が替わると 1 で激昂していない）。
* **DEBUG のターンの番号**（`debugControls.js` の `setBattleTurn`）: `game.enemy.intent = refreshIntent(enemySpecOf(game.config, game.enemy.typeId), game.enemy.intent, turn, game.config.rage)`。JSDoc の「防御の量を数え直す」を「攻撃の量を激昂の倍率で数え直す（乱数は呼ばない。元の番号に戻すと元の量）」に。先頭の責務の「戦闘のターンの番号」はそのまま。
* **中断データ**（`suspendData.js`）: `isIntentShape` の `baseDefense` を `baseAmount`（0 以上の整数）に替え、JSDoc を直す。`SUSPEND_VERSION` を 9 にし、版の履歴に「9: 予告の疲弊の前の防御 `baseDefense` をなくし、激昂の倍率の前の攻撃の量 `baseAmount` を足したとき 8 から上げた」を足す。`FIELDS` の行は足さない（激昂は `battleTurn` と設定から決まる。`check` は形だけで設定の数値と比べない（`amount` と `baseAmount` の合い方も比べない））。
  * 版を上げる理由（RES に書く分）: 予告の形が変わり、版 8 のデータの予告は `baseAmount` を持たない（DEBUG の数え直しの元がない）。版 8 の途中のゲームは一度だけ捨てられる。
* **疲弊の整理**（タスク3。消す前に `grep` で使う所がないことを確かめる）: `config.js` の `fatigue`・型 `FatigueStage`・`Rules.fatigue`・先頭の説明の疲弊、`enemyDefense.js` の `fatigueStageOf`・`fatiguedDefense`・`isFatigued`（`rollDefense` だけが残る。先頭の責務を「敵の防御の量（張るかと量の抽選）の計算」に）、`Game.js` の `isEnemyFatigued`・`isFatigued` の import。古くなる説明: `battle.js`（`enemyAction` の `defense` の「疲弊の後」→「加算の後」）・`battleSteps.js`（`enemyDefense` の「疲弊の後」）・`intentParts.js`（「疲弊で 0 になっても」→「量が 0 でも」）・`enemySplit.js`（`minionBirths` の「上限・ステージの加算・疲弊はない」→「上限・ステージの加算・激昂の倍率はない」）。`debugTab.js` の `TURN_SLIDER` の説明はタスク5で直す。
* **かけないもの**の守り方: 倍率は `createIntent` の `amount` にだけかける。防御（`defense`）・行動（`kind`・`variant`・決まりの状態）・攻撃の直後の回復（`enemyBehaviors.js` の `attackHeal` の量）・燃やす札（`burn`）・子の数（`minions`。`intentWithMinions` が `createIntent` の後に写す）は通らない。ゴーレムなど量を組み立てで決める敵の扱いは今回やらない。

## 5. 懸念事項・要確認ポイント
* **「⚔」の字**（U+2694）: 端末のフォントに字がないと豆腐（□）になり、ある端末では絵文字の色つきの絵で出る（縁取り `strokeText` が絵文字に合わないことがある）。目視で確かめ、出ないときは、字を `battleText.js` の `RAGE_LABEL.mark` の1か所で替える（例: 「†」や省く）か、つなぎの絵にするかを発注者に決めてもらう（今回は字のまま）。
* **敵の名前と重なるおそれ**: 敵の HP ゲージの幅は 290、敵の名前とレベルの最大の幅は 220（縮む）で、「激昂 ⚔×1.2」は全角 20px の見積もりで約 100〜110 px。7 文字の名前と 2〜3 桁の Lv（約 195〜205 px）では右詰めの激昂の文字と 10〜20 px 重なりうる（タスク3・タスク7で見積もって書く）。配置・大きさは今回変えず（「疲弊」と同じ初期値）、試遊で決め直す。
* **オーガ（1体のポイント 2）の倍率**: 倍数に切り捨てるので、小さい量では上がらないターンがある（例: 6 × 1.2 = 7.2 → 7 → 6、6 × 1.4 = 8.4 → 8）。REQ の決まりどおりだが、試遊で目に付くかもしれない。
* **激昂の表示と曲の時刻の差**: 激昂の表示と予告の数字は、ルール層が 16 ターン目に進んだ時点（盤面に戻った直後。TURN の表示の直前）から出るが、曲は TURN の表示で切り替わる（REQ の決まり）。差はわずか。
* **中断データの版 9**: 版 8 の途中のゲームは一度だけ捨てられる（予告の形が変わるため）。
* **DEBUG の上がる量 0%**: 始まるターン以降は「激昂 ⚔×1.0」と激昂の曲になり、量は変わらない（DEBUG だけで起きる。ルールとしては正しい）。
* **攻撃の直後の回復・燃やす札**: 激昂の倍率はかけない（REQ の決まり）。巨人の回復の量・ドラゴンの燃やす枚数は長引いても変わらない。
