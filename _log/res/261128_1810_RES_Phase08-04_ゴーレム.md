## 1. 作業目的
★2の敵「ゴーレム」（識別子 `golem`）を足す。ゴーレムは数ターンに1回「防御を取る」を予告し、**その防御はターンをまたいで残って積み重なる**（溜め）。溜まった防御を攻撃に足す「体当たり」で溜めを使い切り、そのターンは防御 0 の隙になる。狙いは「溜めさせるな、削り続けろ」（剣で溜めを削るほど体当たりが弱くなり、放っておくと守りが厚く、体当たりも重くなる）。★2は巨人・毒キノコ・ネクロマンサー・ゴーレムの4種になり、くじ袋（08-02）に入る。

* **溜めた防御（新しい仕組み）**: 設定の `carryDefense: true` を持つ敵だけが、攻防の後に残った防御（そのターンの防御 − 剣で削られた分 `enemyBlock`）を敵の状態 `enemy.defenseStock` に持ち越す。次の予告を作るとき、持ち越した溜めを予告の防御に足す（防御を取るターンはさらに今回の量を足す）か、溜めを攻撃に移す（体当たり）。ほかの敵（`carryDefense` を持たない）は今のまま、防御はそのターンの終わりに消える（`defenseStock` はいつも 0）。計算は新しい純粋関数のファイル `js/rules/enemyStock.js` に置き、敵の識別子で分岐しない。攻防の計算 `computeBattle` は変えない。
* **行動の決まり（新しい `hoard`）**: 「防御を取る」（防御だけ・中の種類 `fortify`）・「攻撃」・「身をかがめる」（振りかぶり・中の種類 `crouch`）・「体当たり」（攻撃・中の種類 `tackle`・溜めを攻撃に移す印 `spendStock`）の並びを、状態（次の防御を取るまで・身をかがめるまでの残りの回数・次が体当たりか）で決める。
* **見せ方**: ゴーレムは巨人のコピーの仮の絵（高さ 200。肌の緑 `#229b24` を石の灰色 `#8a8d91` に置き換え）。体の前のシールドの印は溜めの量（10 個で止める）で、その左に溜めの量の数字をいつも出す（0 なら出さない）。攻防の中では剣が当たるたびに印が剥がれ、数字が減る（数字は時間割が出来事の量から求める）。ふつうの攻撃は巨人と同じ打撃、体当たりは猪の親子の突進と同じ駆け寄り（`dashStraight`）で大きな一撃、身をかがめるはための動き。体当たりの始まりに巨人の攻撃の音。
* **予告の札と文字**: 防御を取るは「防御 9」の札に今回足した量「+5」を添え、文字は「防御を取る +5 ／ 防御 9」。攻撃は「攻撃 4 ／ 防御 9」。身をかがめるは振りかぶりの絵と「身をかがめる」の文字＋防御の側（「身をかがめる ／ 防御 9」）。体当たりは威力（攻撃＋溜め）を1つの数字で赤い札に出す（「体当たり 13」）。
* **中断データ**: 敵の状態に `defenseStock` を足すので形が変わる。版を 10 → 11 に上げる（版 10 のデータは今の決まりどおり捨てる）。
* **DEBUG**: 敵の切り替え・先の並び・ルールの値（9 本。87 → 96 個）・次の行動の指定（防御を取る・攻撃・身をかがめる・体当たり）・溜めの操作（「溜め +5」「溜めを 0 にする」）。
* **変えないもの**: ほかの10種の敵の数値・動き・見た目・予告・乱数を呼ぶ順と回数・攻防の計算と出来事・時間割（ほかの敵の防御はそのターンの終わりに消える）。自軍の数値・放つ計算・精鋭の抽選・1ターンの流れ。★の抽選・★1の並び・くじ袋の決まり・ステージの加算・激昂の決まり。スコアの項目・強化の仕組み。数値はすべて設定に置く。

### 要件1: ゴーレムの数値と行動（タスク1・タスク7）
* **設定の行**（タスク7。`config.js` の `enemies` に、ネクロマンサーの次・ドラゴンの前に1行。書いた順が DEBUG の並びと★の中の数え方になる。★2の袋の大きさが 3 → 4）:
  ```js
  golem: Object.freeze({
    name: 'ゴーレム',
    star: 2,
    maxHp: 48,
    carryDefense: true,
    behavior: Object.freeze({
      type: 'hoard',
      attackRange: Object.freeze({ min: 3, max: 5 }),      // 攻撃と体当たりの攻撃の分（加算の前）
      fortifyRange: Object.freeze({ min: 4, max: 6 }),     // 防御を取るで溜めに足す量（加算の前）
      firstFortifyTurn: Object.freeze({ min: 1, max: 2 }), // 最初（戦闘の始まり・体当たりの後）の防御を取るのターン
      fortifyInterval: Object.freeze({ min: 2, max: 3 }),  // 防御を取るから次の防御を取る（または身をかがめる）までのターン数
      fortifyCount: Object.freeze({ min: 2, max: 3 }),     // 身をかがめるまでに防御を取る回数
    }),
  }),
  ```
  行動と別に防御を抽選しないので `defense` は書かない（攻撃・身をかがめる・体当たりの新しい防御は 0。`createIntent` は乱数を呼ばない）。
* **型**（タスク1。`config.js`）: `EnemySpec` に `@property {boolean} [carryDefense]`（真の敵だけ、攻防の後に残った防御を次のターンへ持ち越す）。`EnemyBehaviorSpec.type` に `'hoard'`（防御を溜めて体当たり）と、`fortifyRange`・`firstFortifyTurn`・`fortifyInterval`・`fortifyCount`（どれも `'hoard'` のみ）。`attackRange` の説明に `'hoard'`（攻撃と体当たりの攻撃の分）。
* **行動を作る関数**（タスク1。`enemyBehaviors.js`。JSDoc に乱数の回数）:
  * `fortifyAction(behavior, random, unit)` → `{ kind: 'guard', amount: 0, guard: rollAmount(behavior.fortifyRange, random, unit), variant: 'fortify' }`（量1回）。
  * `crouchAction()` → `{ kind: 'windup', amount: 0, variant: 'crouch' }`（乱数なし）。
  * `tackleAction(behavior, random, unit)` → `{ kind: 'attack', amount: rollAmount(behavior.attackRange, random, unit), variant: 'tackle', spendStock: true }`（量1回）。`spendStock` は「この行動の予告で、溜めの全部を攻撃に移す」印（任意の項目。持つのはこの行動だけ）。
  * ふつうの攻撃は既存の `steadyAttackAction`（`attackRange`）。
* **決まりの行 `BEHAVIORS.hoard`**（タスク1）:
  * 状態 `{ untilFortify, fortifiesLeft, tackleNext }`。`untilFortify`＝いま予告したターンから次の防御を取るの番まであと何ターンか（`null`＝その並びがまだ始まっていない＝戦闘の始まり・体当たりの後）。`fortifiesLeft`＝身をかがめるまでに残っている防御を取るの回数（`null` は同じく未開始）。`tackleNext`＝次のターンが体当たりか（身をかがめるを予告したターンだけ真）。初期値 `{ untilFortify: null, fortifiesLeft: null, tackleNext: false }`。
  * `isState`: プレーンなオブジェクトで、`untilFortify` が `null` か 0 以上の整数、`fortifiesLeft` が `null` か 0 以上の整数、`tackleNext` が真偽値。
  * `planNext(behavior, state, random, unit)`:
    1. `tackleNext` が真 → 体当たり（`tackleAction`。量1回）。状態は初期値に戻す（体当たりの次のターンから、戦闘の始まりと同じ数え方で始め直す）。
    2. それ以外: `untilFortify` が `null` なら、`first = rollAmount(firstFortifyTurn, random)`（1回）・`count = rollAmount(fortifyCount, random)`（1回）を引き、`remaining = first − 1`・`left = count`。`null` でなければ `remaining = untilFortify − 1`・`left = fortifiesLeft`。
    3. `remaining > 0` → 攻撃（`steadyAttackAction`。量1回）。状態 `{ untilFortify: remaining, fortifiesLeft: left, tackleNext: false }`。
    4. `remaining <= 0` かつ `left > 0` → 防御を取る（`fortifyAction`。量1回）→ 次の間隔 `rollAmount(fortifyInterval, random)`（1回）。状態 `{ untilFortify: 間隔, fortifiesLeft: left − 1, tackleNext: false }`。
    5. `remaining <= 0` かつ `left === 0` → 身をかがめる（`crouchAction`。乱数なし）。状態 `{ untilFortify: null, fortifiesLeft: null, tackleNext: true }`。
    * 間隔・回数・最初のターンは1体のポイントの刻みを使わない（`rollAmount(range, random)`。毒キノコの混乱の間隔と同じ）。
    * 乱数の回数: 並びの始まりのターン（戦闘の1ターン目・体当たりの次のターン）は +2（最初のターン・回数）。攻撃のターン 1、防御を取るのターン 2（量・次の間隔）、身をかがめるのターン 0、体当たりのターン 1。
    * 例（最初 1・間隔 2・回数 2）: 1 防御を取る → 2 攻撃 → 3 防御を取る → 4 攻撃 → 5 身をかがめる → 6 体当たり → 7 から始め直し（7 か 8 が防御を取る）。REQ の例と同じ。
  * `countdown`: いつも `null`（数え下ろしは持たない）。`isOpening(action)`: `action.spendStock === true`（隙は体当たりのターン。ゴーレムは防御の設定を持たないので、隙かどうかで `createIntent` の乱数は変わらない）。
  * `isBehaviorState`・`planBehaviorAction` の JSDoc の決まりごとの並びに `hoard` を足す。

### 要件2: 溜めた防御（ルール層。タスク1）
* **持ち方**: 敵の状態 `enemy.defenseStock`（0 以上の整数）＝**攻防の後に残り、次のターンへ持ち越した溜め**（＝今のターンの予告を作る前の溜め）。`createEnemy` で 0（敵が替わる・DEBUG の切り替え・ステージ移動でも 0）。持ち越さない敵はいつも 0。行動の決まりの状態には入れない（溜めは攻防の結果で減るので、予告の時点で進む決まりの状態とは別に持つ。子の数 `enemy.minions` と同じ置き方）。
* **予告での付け方**（`enemyStock.js` の `intentWithStock(spec, intent, stock)`。`Game.intentOf` が `createIntent` の直後・`intentWithMinions` の前に `this.enemy.defenseStock ?? 0` で呼ぶ）:
  * 持ち越さない敵（`carriesDefense(spec)` が偽）は予告をそのまま返す（同じオブジェクト。キーも増えない）。
  * 持ち越す敵は、まず予告から前の溜めの分を外した「素の量」を求める（`intent.stock` があれば 素の防御 = `stock.gain`・素の攻撃 = `amount − stock.spent`。なければ予告の `defense`・`amount`。何度呼んでも同じ結果になり、DEBUG の溜めの操作が付け直しに使える）。
  * `intent.spendStock === true`（体当たり）: `amount` = 素の攻撃 + 溜め、`defense` = 素の防御（体当たりは 0）、`stock: { gain: 素の防御, spent: 溜め }`。
  * それ以外: `amount` = 素の攻撃、`defense` = 溜め + 素の防御、`stock: { gain: 素の防御, spent: 0 }`。防御を取るでは素の防御 = 量 + 防御の加算（今回足す量）、攻撃・身をかがめるでは 0。
  * 予告の任意の項目 `stock`（`{ gain, spent }`。`gain`＝このターンに溜めに足した量、`spent`＝攻撃に移した溜め）は、持ち越す敵の予告だけが持つ。予告の `defense` がそのターンの防御で、持ち越す敵では「予告の後の溜め」と同じ（体当たりのターンは 0）。予告の札・シールドの数・攻防は今のまま `defense`・`amount` だけを読む。
* **攻防の後の溜め**（`stockAfterBattle(spec, intent, events, defeated)`。`Game.resolveBattle` が `computeBattle` の後に `this.enemy.defenseStock` に入れる）: 持ち越さない敵は 0。倒した攻防は 0（戦闘が終わるので次の敵に残らない）。それ以外は `intent.defense − (出来事 enemyBlock の量。なければ 0)`。
  * 剣が溜めより少ない・同じ・多い: `enemyBlock` = min(剣, 防御) なので、残りは 防御 − 剣・0・0（多いときは残りが本体に当たる。今の式のまま）。
  * 城が落ちた攻防は `enemyBlock` がない（剣が当たる前に終わる）ので溜めはそのまま（ゲームは終わる。親と子の HP が「入力のまま」になる今の作りに合わせる）。
  * 体当たりのターンは防御 0 なので `enemyBlock` はなく、溜めは 0。
* **体当たりの威力の決まる時**: 身をかがめるのターンの攻防の後の溜めが `enemy.defenseStock` に入り、次のターン（体当たり）の予告を作る `intentOf` で攻撃に移る。体当たりのターンは敵の攻撃が先なので、そのターンの剣では威力は変わらない（`computeBattle` の今の順のまま）。
* **攻防の計算は変えない**: `computeBattle` には今のまま予告の `kind`・`amount`・`defense` だけを渡す。ほかの敵の出来事・結果は今と同じ。`battle.js` は説明の1文だけ直す。
* **`refreshIntent`**（`enemyIntent.js`）: `amount = ragedAmount(baseAmount, 倍率, unit) + stockSpentOf(intent)`（`stockSpentOf` は `intent.stock` があれば `spent`、なければ 0）。ほかの敵は今と同じ値。
* 溜めの量に上限は付けない。
* **ファイルの置き方の検討（REQ の求め）**: `battle.js` は変えず（出来事の量から `Game` が求める）、`Game.js` は import 1つと2か所の呼び出しだけ、溜めの計算は新しい `enemyStock.js` に分けた。`battleTimeline.js` は変えない（シールドの上限と数は `enemyBody.js` の中）。行動の決まりの行は `enemyBehaviors.js` に置く（ほかの8種と同じ表の1行で、`rollAmount`・`steadyAttackAction` を使う。別のファイルに分けると `enemyBehaviors.js` との循環の import になるため）。
