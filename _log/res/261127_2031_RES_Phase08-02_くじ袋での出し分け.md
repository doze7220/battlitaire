# RES: 作業計画・作業レポート (Phase 08-02) : くじ袋での出し分け（★2・★3の中のどの敵を出すかを、くじ袋の決まりにする）
* 参照元REQ: `./_log/req/261127_2031_Phase08-02_くじ袋での出し分け.md`

## 1. 作業目的
★2・★3のステージに、同じ★の中のどの敵を出すかを **くじ袋の決まり** にする。その★の全種を1体ずつ袋に入れ、その★のステージごとに袋から1体を引き、空になったら全種を入れ直す。最初の袋は `first`（★2 巨人・★3 ドラゴン）を先頭に固定し、入れ直した直後の1体は直前のその★の敵と同じにしない（種類が1つの★を除く）。★1の並び（動きの組の決まり）・各ステージの★の抽選・`position` の数え方は変えない。

* **狙い**: 強敵のステージで同じ敵ばかり続かず、どの強敵もまんべんなく出る。後で★2の敵が増えても、`config.js` の `enemies` に1行足すだけで袋に入る。
* **今の★2で見えること**: 巨人と毒キノコの2種なので、巨人 → 毒キノコ → 巨人 → 毒キノコ… と必ず交互になる。★3はドラゴンだけなのでドラゴンが続く。
* **どの★が袋か**: 設定で決める（`stageStars.baseOrder`＝`base` の★の決まり、`stageStars.draws` の各行の `order`＝その★の決まり。名前は `'motion'`（動きの組）か `'bag'`（くじ袋））。★の数字・敵の識別子で分岐する if は書かない（決まりの名前で表を引く）。
* **DEBUG**: 先の並びの一覧の★2・★3の行に「袋◯の◯番目」を足す。★1の行・行数（20）・ほかの項目は変えない。
* **中断データ**: 形と版（10）は変えない（並びは種とステージの番号から求めるため）。

### 要件1: くじ袋の決まり（ルール層。タスク1・タスク2）

#### 1-1. 袋の決まりの純粋関数 `js/rules/bagOrder.js`（新規。タスク1）
* 先頭の責務（3行以内の JSDoc）の案:
  `/** 種・袋の列・「同じ★の中の何番目か」から、くじ袋の決まりで中身の番号を決める純粋関数（袋の大きさずつの区切りの中は全部が1回ずつ・入れ直した直後は直前と違う・最初の袋の先頭は固定できる）。`
  ` * 前の袋を順に計算せず、隣の袋の最後だけを直接求める。乱数は呼ばない。 */`
* import は `./seededIndex.js` の `seededIndex`・`STREAM` だけ。敵・★・設定のことは知らない（中身は「番号 0〜size−1」として扱う）。
* 型:
  ```js
  /**
   * 袋の列の見分け（種と、同じ種の中のどの袋の列か）。
   * @typedef {Object} BagLane
   * @property {number} seed 種（整数）。
   * @property {number} lane 袋の列の番号（0 以上 lanes 未満の整数）。
   * @property {number} lanes 袋の列の数（1 以上の整数）。
   */
  ```
* 公開する関数:
  * `bagSlotOf(position, size)` → `{ bag, slot }`（どちらも 0 から）。`bag = Math.floor(position / size)`・`slot = position % size`。`position` は 0 以上の整数・`size` は 1 以上の整数でなければ Error。
  * `bagMemberAt(lane, position, size, firstIndex)` → 0 以上 size 未満の中身の番号。`firstIndex` は最初の袋（bag 0）の先頭に固定する中身の番号（なければ `-1`）。`size` が 1 以上の整数でない・`firstIndex` が −1 か 0 以上 size 未満の整数でない・`position` が 0 以上の整数でないときは Error。
* 内部の決め方（`motionOrder.js` と同じ組み立て。袋の「最後」を先に決め、袋の「最初」を「この袋の最後・前の袋の最後」を除いた候補から選ぶ）:
  * 番号の鍵: `keyOf(lane, bag) = bag * lane.lanes + lane.lane`（袋ごと・列ごとに別の番号にする。★2と★3の袋が同じ並びにならない）。
  * **袋の最後** `lastOfBag(lane, bag, size, firstIndex)`:
    * `b = size >= 3 ? bag : 0`（大きさ 2 の袋は、最後をいつも bag 0 と同じにする。最後が袋ごとに変わると、次の袋の最初の候補がなくなるため。`motionOrder.js` の `lastOfGroup` と同じ扱い）。
    * 候補は 0〜size−1 から、`b === 0` のとき `firstIndex` を除いたもの（最初の袋の先頭は `first` なので、最後にはしない）。
    * `candidates[seededIndex(lane.seed, STREAM.bagLast, keyOf(lane, b), candidates.length)]`。
  * **袋の最初** `firstOfBag(lane, bag, size, firstIndex)`:
    * `bag === 0 && firstIndex >= 0` なら `firstIndex`。
    * それ以外は、候補を 0〜size−1 から「この袋の最後」と「前の袋の最後（bag が 0 なら除かない）」を除いたものにし、`candidates[seededIndex(lane.seed, STREAM.bagFirst, keyOf(lane, bag), candidates.length)]`。
    * 候補の数: size 2 は最後が全袋で同じなので候補はいつも1つ（交互になる）。size 3 以上は少なくとも size − 2 個。
  * **真ん中**: 最初と最後を除いた残りを、Fisher-Yates で `seededIndex(lane.seed, STREAM.bagMiddle, keyOf(lane, bag) * size + i, i + 1)` によって並べ替え、`slot − 1` 番目を返す（`motionOrder.js` の真ん中と同じ書き方）。
  * `bagMemberAt` の流れ: `size === 1` なら 0（種類が1つなら同じでよい）。`{ bag, slot } = bagSlotOf(position, size)`。`slot === 0` なら袋の最初、`slot === size − 1` なら袋の最後、ほかは真ん中。
* これで成り立つこと:
  * 1つの袋（size ずつの区切り）の中は、全部が1回ずつ（最初・最後・真ん中が重ならない）。
  * 入れ直した直後（bag ≥ 1 の slot 0）は、前の袋の最後（bag − 1 の slot size−1）と違う（size ≥ 2）。
  * 最初の袋の先頭は `firstIndex`（あれば）。
  * 前の袋を順に計算しない（求めるのは、この袋の最後と前の袋の最後だけ）。覚える値もないので、`starDraw.js` のような写しは持たない。
* 入れ直した直後に直前と同じにしない方法（REQ の「計画で決める」）: 「混ぜ直し」や「入れ替え」ではなく、**袋の最後を先に決め、袋の最初を『この袋の最後・前の袋の最後』を除いた候補から選ぶ** 形にする（各袋の最後は前の袋に依らず種と袋の番号だけで決まるので、どの袋も前を順にたどらずに求まる）。
* 数値の直書きについて: `3`（size の閾値）は「最後を袋ごとに変えてよい大きさ」という決まりの形の定数で、ルールの調整値ではない（`motionOrder.js` の `motionCount >= 3` と同じ扱い）。JSDoc に理由を書く。

#### 1-4. 並びの選び方の切り替え（`js/rules/stageOrder.js`。タスク2）
* 先頭の責務を次に直す（3行以内）:
  `/** ステージの番号と種から、そのステージの敵の種類と、くじ袋の決まりの★では袋の何番目かを決める純粋関数（★と同じ★の中の何番目かは `starDraw.js` の抽選の並びから。`
  ` * ★ごとの並びの決まり（動きの組・くじ袋）は設定の名前で表を引く。最初の1体は設定の `first`）。乱数は呼ばない。 */`
* import: `enemyMotionsOfStar`・`enemySpecOf`・`enemyTypeIdsOfStar`（`enemyTypes.js`）、`motionIndexAt`（`motionOrder.js`）、`bagMemberAt`・`bagSlotOf`（`bagOrder.js`）、`seededIndex`・`STREAM`（`seededIndex.js`）、`starDrawAt`（`starDraw.js`）。
* 内部の型:
  ```js
  /**
   * そのステージの選び方に要る値（starDrawAt の答えと、その★の行の決まり）。
   * @typedef {Object} StagePick
   * @property {number} star ステージの★。
   * @property {number} position 同じ★の中の何番目か（0 から）。
   * @property {number} stageNumber ステージの番号。
   * @property {string[]} members その★の敵の種類の識別子（設定に書いた順。空でない）。
   * @property {string|undefined} first その★の最初の1体（行の first。なければ undefined）。
   * @property {number} lane 袋の列の番号（draws の行の番号。base の★は draws の数）。
   * @property {number} lanes 袋の列の数（draws の数 + 1）。
   */
  ```
* 内部の関数:
  * `starRuleOf(stageStars, star)` → `{ order, first, lane, lanes }`。`lanes = draws.length + 1`。`lane = draws.findIndex((d) => d.star === star)` が 0 以上ならその行の `order`・`first`・`lane`、なければ `stageStars.baseOrder`・`first` なし・`lane = draws.length`（★の数字では分岐せず、★の行を探すだけ）。
  * `pickOf(config, seed, stageNumber)` → `{ pick, order }`:
    1. `stageNumber` が 1 以上の整数でなければ Error（今の文言 `enemyTypeIdOfStage: ステージの番号は 1 以上の整数です` を、呼び元の名前を引数で受けて出してよい）。
    2. `starDrawAt(config.stageStars, seed, stageNumber)` で `{ star, position }`。
    3. `starRuleOf` で行の決まり。`members = enemyTypeIdsOfStar(config, star)` が空なら Error（今の `★${star} の敵がいません`）。
    4. `first` があり `enemySpecOf(config, first).star !== star` なら Error（今の `first の敵 … は★… ではありません`。設定にない識別子は `enemySpecOf` が Error）。今は position 0 のときだけ確かめているが、袋では最初の袋の全部で `first` を使うので、`first` を書いた行ではいつも確かめる（正しい設定での答えは変わらない）。
    5. `order` の名前を `STAGE_ORDERS` で引く。表にない名前は Error（`stageOrder: 知らない並びの決まりです: …`）。
* 選び方の表（凍結。決まりの名前 → `{ typeIdAt, slotAt }`）:
  ```js
  const STAGE_ORDERS = Object.freeze({
    motion: Object.freeze({ typeIdAt: motionTypeIdAt, slotAt: () => null }),
    bag: Object.freeze({ typeIdAt: bagTypeIdAt, slotAt: (pick) => bagSlotOf(pick.position, pick.members.length) }),
  });
  ```
  * `motionTypeIdAt(config, seed, pick)`: **今の選び方そのまま**。`pick.position === 0 && pick.first !== undefined` なら `pick.first`。それ以外は `motions = enemyMotionsOfStar(config, pick.star)`、`members = motions[motionIndexAt(seed, pick.position, motions.length)]`、`members[seededIndex(seed, STREAM.member, pick.stageNumber, members.length)]`。
  * `bagTypeIdAt(config, seed, pick)`: `firstIndex = pick.first === undefined ? -1 : pick.members.indexOf(pick.first)`、`pick.members[bagMemberAt({ seed, lane: pick.lane, lanes: pick.lanes }, pick.position, pick.members.length, firstIndex)]`。
* 公開する関数:
  * `enemyTypeIdOfStage(config, seed, stageNumber)`（引数・戻り値・投げる Error の条件は今のまま）: `pickOf` → `order.typeIdAt(config, seed, pick)`。
  * `stageBagSlotOf(config, seed, stageNumber)` → `{ bag, slot } | null`（どちらも 0 から。袋の決まりでない★のステージは `null`）: `pickOf` → `order.slotAt(pick)`。状態を持たず乱数も呼ばない。
* `config` の JSDoc の型は `{enemies: …, stageStars: import('./config.js').StageStarsSpec}` のまま（`enemies` の型に `motion?` があることも今のまま）。

### 要件4: 確かめ（タスク4。一時スクリプトで行い、結果を RES に書く）
* 一時スクリプトは実装AIの作業用の一時フォルダ（スクラッチパッド）に置き、リポジトリには置かない。`js/` の各ファイルは絶対パスの file URL で import する（Node 24 は `export` を含む `.js` を ES Modules として読める）。
* 種: 2026-01-01〜2035-12-31 の毎日（`js/scenes/dateSeed.js` の `seedOfDate` の式 年×10000＋月×100＋日。`seedOfDate` を import してよい）。ステージ 1〜500。
* **袋の決まり**（`RULES` で）: ★2・★3のステージを順に並べ、

## 5. 懸念事項・要確認ポイント
* **袋の中の順の偏り**: 大きさ 3 以上の袋は、最後を一様に選び、最初を残りの候補（size−2 か size−1 個）から選ぶので、すべての並べ方が同じ確率にはならない（決まりの「区切りの中は1回ずつ・境目で同じが続かない」は守る）。今の★2は2種なので交互で一定。ネクロマンサーなどを足した後の出方は試遊で確かめてほしい。
* **★の行の番号を袋の列に使う**: 袋の列の番号は `stageStars.draws` の行の番号（`base` は `draws` の数）なので、`draws` の行の順を入れ替えると、★の抽選と同じく袋の並びも変わる。
* **`first` の確かめの時期**: 今は position 0 のときだけ `first` を確かめているが、袋では最初の袋の全部で使うため、`first` を書いた行ではいつも確かめる形にする（正しい設定での答えは変わらず、Error になる条件も同じ。間違った設定が早く Error になるだけ）。
* **今のステージの行の袋の位置**: DEBUG で敵を切り替えた後も、今のステージの行の袋の位置は並びの上の位置を出す。★の違う敵に切り替えると、★と袋の位置が食い違って見える（例「★1　ゴブリンの軍勢　袋2の1番目」）。
* **一覧の1行の長さ**: ★2・★3の行が「　袋◯の◯番目」の分長くなる。今の★2・★3の名前は短い（巨人・毒キノコ・ドラゴン）が、08-03 以降で長い名前（ネクロマンサーなど）を足したときに行の幅に収まるかは `?debug` で目視確認してほしい。
