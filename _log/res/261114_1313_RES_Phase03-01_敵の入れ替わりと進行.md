## 1. 作業目的
いまは種類のない敵1体（`RULES.enemyMaxHp`・`RULES.enemyActions`）を倒すか、城が落ちるかで決着する。今回は、敵に種類（名前・最大 HP・常時防御力・行動の決まり）を持たせ、ゴブリンの軍勢 → 巨人 → ドラゴンの順に戦い、ドラゴンを倒すとゲームクリアになる進行に作り変える。

* 敵の種類・順番・入れ替わり・決着・攻防の計算（常時防御力の壁を含む）はルール層（`js/rules/`）に置く。行動の決まりは、敵の種類ごとの設定から選ぶ表の形にし、今回は「重みによる抽選」の1種類だけを作る（03-02・03-03 で状態を持つ決まりを足せる形にする）。
* 途中の敵（ゴブリンの軍勢・巨人）を倒したフェーズは、攻防が止まらずに回復まで進み、演出の終わりに「（敵の名前）を倒した！」「次は（次の敵の名前）」「タップで次へ」を出し、タップで次のフェーズへ進んで次の敵（HP 最大）と戦う。最後の敵（ドラゴン）を倒すとゲームクリア（いまの勝ちの表示。文字を「クリア」にする）、城の HP が 0 でゲームオーバー（いまの負けの表示）。
* 戦闘の段に、いま戦っている敵の名前と HP、ゴブリンの軍勢の兵の群れ（仮の図形）、巨人・ドラゴンの玉（色違い）、常時防御力の数だけのシールドマークを出す。攻防の演出に「シールドマークに当たって兵士が消える」段を足す。
* 巨人・ドラゴンの固有の行動（数え下ろし・回復・ブレスチャージ・札を燃やす）、作り込んだ見た目、結果の画面と集計、タイトル画面の分離、BGM は作らない。段取り・攻防の演出の他の挙動・音は変えない。

#### 行動の決まり（`js/rules/enemyBehaviors.js`。新規）
* 責務: 敵の行動の決まり（決まりの種類ごとの、状態の初期値と次の行動の決め方）の表と、その呼び分け。渡された乱数だけを使う純粋な関数。
* 中身:
    * `pickWeighted(actions, random)` → `EnemyAction`（`{ kind, amount }`。重みは含めない）。いまの `combatants.js` の `planEnemyAction` の抽選の中身をそのまま移す（`random()` は1回だけ呼ぶ。最後の要素への逃げも同じ）。
    * `BEHAVIORS`（モジュール内の凍結した表）: 決まりの種類 → `{ initialState(behavior), planNext(behavior, state, random) }`。
        * `weighted`: `initialState` は `{}`（状態を持たない）。`planNext` は `{ action: pickWeighted(behavior.actions, random), state }`（状態はそのまま返す）。
    * `createBehaviorState(behavior)` → 決まりの状態の初期値。未知の `behavior.type` は Error を投げる。
    * `planBehaviorAction(behavior, state, random)` → `{ action: EnemyAction, state: object }`。引数の `state` は書き換えず、新しい状態を返す（呼ぶ側が敵の状態に入れ直す）。未知の `behavior.type` は Error を投げる。
    * `@typedef EnemyAction` は `combatants.js` の既存の型を JSDoc の `import('./combatants.js')` で参照する（型の置き場所は変えない）。
* 拡張の想定（今回は作らない。計画の記録）:
    * 03-02 巨人: `BEHAVIORS` に `cycle`（例）を足す。`initialState` が数え下ろし `{ countdown }` を返し、`planNext` が数え下ろしを1つ進めて「振りかぶり」（新しい行動の種類。例 `'windup'`）か攻撃を返す。`battle.js` の `computeBattle` の敵の行動の分岐に新しい種類を足す（今は未知の種類で Error を投げるので、足し忘れに気づける）。攻撃後の回復のように攻防の後に起きることは、表の項目に任意の「攻防の後の処理」（例 `afterBattle(behavior, state, calc, random)`）を足し、`Game.resolveBattle` から呼ぶ形を想定する。`weighted` はその項目を持たない（呼ばない）だけで、既存の決まりは変えずに済む。
    * 03-03 ドラゴン: 同じく `BEHAVIORS` に足す（状態はブレスチャージ。爪・ブレスは新しい行動の種類）。札を燃やすのは盤面に触れるので、「攻防の後の処理」が燃やす枚数などの結果を返し、盤面の書き換えは `Game`（または盤面の操作を受け持つ新しい小さなファイル）が行う形を想定する。
    * 戦闘の段の数え下ろし・チャージの表示は、敵の状態の `behaviorState` を描画の側が読む形を想定する。

#### 敵の進行（`js/rules/enemyProgress.js`。新規）
* 責務: 敵の順番（`config.enemyOrder`）の上での問い合わせ（何番目の敵の種類と設定、最後の敵か、次の敵の名前）。純粋な関数。

### 要件2: 常時防御力とフェーズごとの壁（`js/rules/battle.js`）
* `BattleInput` に2つ足す: `enemyArmor`（敵の常時防御力。0以上の整数）、`lastEnemy`（いまの敵が最後の敵か。boolean）。
* 自軍の攻撃の減り方（いまの「敵の防御での相殺」の後に1段足す）:
    1. `enemyBlocked = min(attack, enemyDefense)`（いまと同じ。防御のスタンスの分）。0 より大きければ出来事 `enemyBlock`。
    2. `armorBlocked = min(attack − enemyBlocked, enemyArmor)`（常時防御力の分）。0 より大きければ出来事 `enemyArmorBlock`（新規）。
    3. `dealt = min(attack − enemyBlocked − armorBlocked, enemyHp)`。0 より大きければ出来事 `enemyDamage`。
    * 防御のスタンスの余り・常時防御力の余りは、どちらもそのフェーズで消える（いまと同じく、次のフェーズへ持ち越さない）。
* 敵の HP が 0 になったとき:
    * `lastEnemy` が true: いまと同じく出来事 `win` を入れて、回復の前で終わる（`outcome: 'win'`）。
    * `lastEnemy` が false: 出来事 `enemyDefeat`（新規。量 0）を入れ、止まらずに回復へ進む（`outcome: null`）。
* `BattleCalc` に `enemyDefeated: boolean`（このフェーズで敵の HP が 0 になったか。最後の敵でも true）を足す。
* 出来事の並びの順: 敵の行動 → `block` → `castleDamage`（0 なら `lose` で終わり）→ `enemyBlock` → `enemyArmorBlock` → `enemyDamage` →（`win` で終わり、または `enemyDefeat`）→ `heal`。
* `BattleEvent.type` の型に `'enemyArmorBlock'|'enemyDefeat'` を足す。量が 0 の `enemyArmorBlock` は入れない（「量が0の相殺・ダメージ・回復は並びに入れない」を守る）。関数の JSDoc の「順序」を直す。決着の値は `'win'|'lose'` のまま（内部の名前は変えない。表示の文字だけ「クリア」にする。要件4）。

### 要件3: 敵の入れ替わりと決着（`js/rules/Game.js`）
* 状態に `enemyIndex`（いま戦っている敵の、`enemyOrder` の中の番号。0 から）を足す。コンストラクタで `enemyIndex = 0`、`enemy = createEnemy(enemyTypeIdAt(config, 0), enemySpecAt(config, 0))` とし、最初の予告を決める（下の「予告を決める」）。
* 予告を決める（モジュール内の非公開関数か `Game` の非公開メソッド。例 `planIntent()`）: `const { action, state } = planBehaviorAction(spec.behavior, this.enemy.behaviorState, this.random)` で、`this.enemy.intent = action`、`this.enemy.behaviorState = state`。コンストラクタと `startNextPhase` の両方からこれを呼ぶ（`random()` を呼ぶ回数・順番はいまと同じ1回）。
* `resolveBattle()`:
    * `computeBattle` に `enemyArmor: this.enemy.armor`、`lastEnemy: isLastEnemy(this.config, this.enemyIndex)` を足して渡す。
    * 段階: `outcome` が null なら `'result'`、そうでなければ `'over'`（いまと同じ。途中の敵を倒したフェーズは `outcome` が null なので `'result'`）。
    * `BattleResult` に `defeat` を足す: 途中の敵を倒したとき（`calc.enemyDefeated && calc.outcome === null`）は `{ enemyName: this.enemy.name, nextEnemyName: nextEnemyName(this.config, this.enemyIndex) }`、それ以外は `null`。
    * このとき敵は入れ替えない（`this.enemy` は倒した敵のまま、HP 0）。演出の間、戦闘の段は倒した敵のままでよい（REQ）。
* `startNextPhase()`:
    * いまの処理（ゲージの戻し・力こぶの換算・行動回数・フェーズ数 +1）の後、敵の予告を決める前に、`this.enemy.hp === 0` なら入れ替える: `this.enemyIndex += 1`、`this.enemy = createEnemy(...)`（HP 最大・予告 null・決まりの状態は初期値）。`stage === 'result'` で HP が 0 なのは途中の敵を倒したときだけ（最後の敵なら `'over'` で進めない）なので、この条件で足りる。
    * そのあと「予告を決める」（次の敵の行動の決まりで決まる。REQ 要件3）。
    * 城の HP・山札・列・捨て札・手札には触れない。フェーズ数は通しで数える（敵ごとに戻さない）。
    * `NextPhaseResult` に `enemyChanged: boolean`（このフェーズの頭で敵が入れ替わったか）を足す。
* `import` を差し替える: `combatants.js` から `createCastle`・`createEnemy`、`enemyBehaviors.js` から `planBehaviorAction`、`enemyProgress.js` から `enemyTypeIdAt`・`enemySpecAt`・`isLastEnemy`・`nextEnemyName`。
* 先頭の責務定義に「敵の順番の中の今の敵」を足す（3行以内）。`BattleResult`・`NextPhaseResult` の `@typedef`、変えたメソッドの JSDoc を直す。

### 要件4: 戦闘の段の表示

#### 配置（`js/view/layout.js`）
* 敵の HP と予告の枠を広げる: 新しい定数 `ENEMY_INFO_W = 340`（敵の HP・予告の枠の幅。城の HP の枠は `INFO_W` のまま）。`enemyHp.x = width − SIDE_MARGIN − ENEMY_INFO_W`、`intent` も同じ x・幅。720 幅で城の枠（20〜260）と重ならない（360〜700）。
* `TroopLayout` に `armorHitX`（兵士がシールドマークに当たる位置の x。敵の矩形の左端 `enemy.x`）を足す。
* `BattleLayout` に次を足す（どれも `createBattleLayout` の中で作る）:
    * `defeat: { x, titleY, nextY, hintY, maxW }`: 敵を倒したときの案内の位置（段の中央の x、「〜を倒した！」・「次は〜」・「タップで次へ」の y、文字の最大の幅）。y は段の高さに対する割合の定数（例 `DEFEAT_TITLE_RATIO = 0.3`・`DEFEAT_NEXT_RATIO = 0.5`・`DEFEAT_HINT_RATIO = 0.7`）、`maxW = area.w − SIDE_MARGIN * 2`。
    * `shieldRects(count)` → `Rect[]`: シールドマーク `count` 個の矩形。敵の矩形（`enemy`）の中に、横 `SHIELD_COLS`（定数。5）個ずつの格子で並べる。行の数 `rows = ceil(count / SHIELD_COLS)`、1マスの大きさ `cell = min(enemy.w / SHIELD_COLS, enemy.h / rows)`、マークの大きさは `cell × SHIELD_FILL`（定数。0.8）。格子全体を敵の矩形の中心にそろえ、最後の行が埋まらないときはその行を中央にそろえる。`count <= 0` なら空配列。15 個なら 5×3、8 個なら 5＋3。
    * `hordeSlots(count)` → `Array<{ x, footY, w, h }>`（後ろの列から順）: ゴブリンの兵の群れの並び。敵の矩形の横幅に、`HORDE_ROWS`（定数。2）列に分けて並べる。1列の数 `perRow = ceil(count / HORDE_ROWS)`、兵の大きさは `troops.smallW`・`troops.smallH`、横の位置は `enemy.x` から `enemy.x + enemy.w` を均等に割った各区間の中心（後ろの列は半区間ずらす）、足元は前の列が `groundY`、後ろの列ほど `troops.smallH × HORDE_ROW_RISE`（定数。0.35）ずつ上げる。`count <= 0` なら空配列。
* `BattleLayout`・`TroopLayout` の `@typedef` と、新しい定数の JSDoc を書く。先頭の責務定義の括弧の中に「敵の図形の上のシールドマーク・ゴブリンの群れの並び・敵を倒したときの案内」を足す（3行以内）。いまの配置・`hitTest`・`battleHitTest` は変えない。

### 要件4（続き）: 攻防の演出での常時防御力（`js/anim/`）
* 段の並び（`battleSteps.js`）:
    * `EVENT_TO_STEP` に `enemyArmorBlock: 'armorBlock'` を足す。
    * `MARCH_BEFORE` に `'enemyArmorBlock'` を足す（自軍の突撃は常時防御力の段より前に来る）。`'enemyDefeat'` は段を作らず読み飛ばす（`EVENT_TO_STEP` にないので今の書き方で飛ぶ。`MARCH_BEFORE` にも入れない。`enemyDefeat` の前には必ず `enemyDamage` があり、突撃はその前に入る）。
    * `BattleStep.type` の型に `'armorBlock'` を足す。段の並びは …`march` → `enemyBlock` → `armorBlock` → `enemyHit` → `heal`。
* 時間割（`battleTimeline.js`）:
    * `addArmorBlock(state, step, t)` を足す（段の長さ `hitMoveMs + clashMs`）。兵士 `soldier` の今の点 `(t, 今のx, 今の数, 1)` → `(t + hitMoveMs, armorHitX, 今の数, 1)`（シールドマークまで進む）→ `(t + hitMoveMs + clashMs / 2, armorHitX, max(0, 今の数 − 量), 1)`（当たって量だけ消える）。兵士の記録がなければ何もしない（時間だけ返す）。HP の変化はない。
    * `STEP_BUILDERS` に `armorBlock: addArmorBlock` を足す。`FRONT_FADE_STEPS` に `'armorBlock'` を足す（最初に来た段で守備兵・敵兵の余りを消す決まりを、この段にも当てる）。
    * 続く `enemyHit` は、いまの `addHit` のとおり兵士の今の位置（`armorHitX`）から `enemyHitX` へ進んで消える（変更なし）。
    * 新しい時間の値は足さない（`hitMoveMs`・`clashMs` を使い回す）。
* 音のきっかけ（`battleCues.js`）: `CUE_OFFSET_MS` に `armorBlock: BATTLE_ANIM.hitMoveMs`（シールドマークに当たった時刻）を足す。
* 時刻の式の二重化: `battleCues.js` の `CUE_OFFSET_MS` は `battleTimeline.js` の各段の当たりの時刻と合わせる必要がある（REQ）。今回は1か所にまとめ直さず、両方を同じタスク（タスク3）で直し、両ファイルのコメントに「`addArmorBlock` の当たりの時刻（`start + hitMoveMs`）と合わせる」を足す。理由: まとめ直すと既存の段（`castleHit`・`enemyHit`・`heal`）の時刻の作り方まで変わり、REQ 要件5（演出の他の挙動を変えない）の確認範囲が広がるため。
* シールドマークの光り: `BattleLook.stepType`（いま進行中の段）が `'armorBlock'` の間、シールドマークを明るく描く（`battleShowView.js`）。段の中の時刻をもう1か所で計算しない（式の三重化を避ける）ため、段全体で光らせる。
* 効果音（`js/scenes/soundCues.js`）: `BATTLE_CUE_SE` に `armorBlock: 'block'` を足す（いまの「敵の防御での相殺」と同じ音）。

### 要件3（続き）: 演出の終わりと次の敵への進み方（`js/scenes/BattleShowScene.js`）
* `update(dt)`: 自動で次のフェーズへ進む条件を `this.result.outcome === null && this.result.defeat === null && this.director.isReadyToLeave() && this.game.canStartNextPhase()` にする（敵を倒したフェーズは自動で進まない）。ほか（時計・きっかけの音・決着の音・終わったら等速に戻す）は変えない。
* `onPointer(pointer)`: 演出が終わっているとき、`this.game.isOver()` ならいまどおりタイトルへ。そうでなく `this.result.defeat !== null && this.game.canStartNextPhase()` なら、`Engine.timeScale = NORMAL_SCALE`、`this.game.startNextPhase()`、`Engine.popScene()`（タップで次のフェーズへ。次の敵に入れ替わる）。画面のどこをタップしてもよい。演出が終わる前は、いまどおり早送り・スキップだけを受ける。
* 早送り・スキップのボタンは、いまの `showButtons: !look.finished` で終わったら消える（変更なし）。敵を倒したときの効果音は足さない（REQ 要件5。音の挙動は変えない）。
* 責務定義の「決着後のタップ」を「決着後・敵を倒した後のタップ」に、`BattleShowOptions` の型の説明は変えない。`onPointer`・`update` の JSDoc を直す。

### 要件5: 他は変えない
* 段取り（`BoardScene`・`boardSelection`・`planningMotion` ほか）・演出の時間（`BATTLE_ANIM`）・早送り・スキップ・ほかの段の時刻・音の対応は変えない。決着も敵の撃破もないフェーズは、いまどおり演出の後に自動で次のフェーズへ進む。
* 攻防はいまどおり `resolveBattle()` の時点で結果（敵の撃破と、次の敵の名前を含む）が決まり、演出はそれを見せるだけ。敵の入れ替わりは、演出（と案内のタップ）の後の `startNextPhase()` で起きる。スキップ・早送りしても結果は変わらない。
