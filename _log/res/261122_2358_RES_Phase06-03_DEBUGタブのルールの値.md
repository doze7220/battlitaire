# RES: 作業計画・作業レポート (Phase 06-03) : DEBUG タブのルールの値
* 参照元REQ: `./_log/req/261122_2358_Phase06-03_DEBUGタブのルールの値.md`

## 1. 作業目的
デバッグスタートから始めたゲームの DEBUG タブで、城と敵のルールの値（25 個。最大 HP・常時防御力・行動の量・重み・確率・周期・燃やす札の枚数）をスライダーでその場で変えて試せるようにする（Phase 7 の数値の調整に備える）。

* ルールの値の正本は `js/rules/config.js` の `RULES`（凍結。数値は変えない）。DEBUG タブで変えるのは、デバッグスタートのゲームが使う**同じ形の写し**である。写しを作り・読み・変え・元に戻し・ゲームの状態に効かせる口はルール層に作り、DEBUG タブ（`js/scenes/`）はその口を盤面のデバッグの口（`BoardDebug`）経由で呼ぶだけにする。
* 値ごとに、いちばん早く効く時期で効かせる（すぐ／次の予告から／次の周期から／次の攻防から／今戦っていない敵は出てきたときから）。効く時期を項目名の横に文字で出す。
* 変えた値は保存しない。ページを読み込み直すまで残り、次のデバッグスタートのゲームにも効く。「はじめる」のゲームはいつも `RULES` で遊ぶ。
* 座標はすべて論理座標（720×1280）。部品の大きさ・位置・スライダーの範囲は定数に置く（試遊で決め直す値）。窓の見た目はエンジンの標準のまま。
* 06-02 の DEBUG タブの項目（兵の数・敵・次の行動・HP・FPS）の動きは変えない。

### 要件1: 変えられる値と置き場所

#### 値の写し（ルール層。`debugRules.js` の `createDebugRules()`）
* `createDebugRules()` は `RULES`（`./config.js` から import）を**同じ形のまま深く写した、凍結していないオブジェクト**を返す（プレーンなオブジェクトと配列だけを再帰で写す小さな関数 `copyPlain(value)` をこのファイルに書く。`structuredClone` は使わない）。`Rules` の項目の名前と入れ子は変えない。ほかのルール層の関数（`Game`・`enemyProgress.js`・`enemyBehaviors.js`・`combatants.js` など）は、写しを `config` として今と同じように読む。
* 写しの持ち主は `js/main.js` のモジュールの中の変数 `debugRules`（初めは `null`）。`createDebugBoard()` の中で `null` なら `createDebugRules()` で作り、`new BoardScene({ ..., rules: debugRules, createMenu: createDebugMenu })` へ渡す。同じ写しを次のデバッグスタートのゲームにも渡すので、変えた値はページを読み込み直すまで残る。`createBoard()`（「はじめる」）は `rules` を渡さない（`Game` の既定の `RULES`）。定数 `DEBUG_TOOLS_ENABLED` が OFF なら `createDebugBoard` は呼ばれず、写しは作られない。
* `BoardScene` は `rules` を `this.rules` に持ち、`init` で `new Game({ random: this.random, config: this.rules })`（`undefined` なら `Game` の既定の `RULES`）。
* `Storage` には書かない（どこからも保存しない）。

#### 項目の表（ルール層。`debugRuleItems.js` の `RULE_ITEMS`）
* モジュールを読んだときに1回、`RULES` の形から組み立てて凍結する（写しは同じ形なので、同じ表で写しも `RULES` も読み書きできる）。並びは「城 → `enemyOrder` の順の敵」。敵の項目は**行動の決まりの種類（`behavior.type`）ごとの組み立ての表**で作り、敵の種類の識別子では分岐しない（`debugIntents.js` の表と同じ考え方）。
* 項目 `RuleItem`（凍結）:
    * `id`: 識別子（文字列。下の表）
    * `group`: 組（`'castle'` か敵の種類の識別子）
    * `kind`: 値の種類（`'castleMaxHp'`・`'enemyMaxHp'`・`'armor'`・`'amount'`・`'weight'`・`'chance'`・`'cycleLength'`・`'burn'`）。ルール層は値の確かめ方に、DEBUG タブはスライダーの範囲に使う
    * `name`: 項目の名前の識別子（DEBUG タブが文字を引く。下の表）
    * `timing`: 今の敵（城）のときに効く時期（`'now'`・`'nextIntent'`・`'nextCycle'`・`'nextBattle'`）
    * `pairId`・`side`: 最小と最大の組の相手の `id` と、自分が `'min'`・`'max'` のどちらか（組でなければ `null`・`null`）
    * `get(config)`: 設定から値を読む。`set(config, value)`: 設定の値を書く（写しにだけ使う）
* 組み立て（`kind`・`name`・`timing`。`T` は敵の種類の識別子）:

| 組・決まり | `id` | `kind` | `name` | `timing` | 読む場所 |
| --- | --- | --- | --- | --- | --- |
| 城 | `castle.maxHp` | `castleMaxHp` | `maxHp` | `now` | `castleMaxHp` |
| 敵（共通） | `T.maxHp` | `enemyMaxHp` | `maxHp` | `now` | `enemies[T].maxHp` |
| 敵（共通） | `T.armor` | `armor` | `armor` | `now` | `enemies[T].armor` |
| `weighted`（行動ごと。`K` は `kind`） | `T.K.min`・`T.K.max` | `amount` | `${K}Min`・`${K}Max` | `nextIntent` | `actions[i].range.min`・`.max` |
| `weighted`（行動の量の後に、行動ごと） | `T.K.weight` | `weight` | `${K}Weight` | `nextIntent` | `actions[i].weight` |
| `cycle` | `T.cycleLength` | `cycleLength` | `cycleLength` | `nextCycle` | `cycleLength` |
| `cycle` | `T.attack.min`・`T.attack.max` | `amount` | `attackMin`・`attackMax` | `nextIntent` | `attackRange.min`・`.max` |
| `cycle`（`attackHeal` があるときだけ） | `T.heal.chance` | `chance` | `healChance` | `nextBattle` | `attackHeal.chance` |
| `cycle`（同上） | `T.heal.amount` | `amount` | `healAmount` | `nextBattle` | `attackHeal.amount` |
| `inhale` | `T.claw.min`・`T.claw.max` | `amount` | `clawMin`・`clawMax` | `nextIntent` | `claw.range.min`・`.max` |
| `inhale` | `T.breath.min`・`T.breath.max` | `amount` | `breathMin`・`breathMax` | `nextIntent` | `breath.range.min`・`.max` |
| `inhale` | `T.burn.min`・`T.burn.max` | `burn` | `burnMin`・`burnMax` | `nextIntent` | `breath.burn.min`・`.max` |
| `inhale` | `T.inhaleChance` | `chance` | `inhaleChance` | `nextIntent` | `inhaleChance` |

* 今の `RULES` では、城 1・ゴブリンの軍勢 8（最大 HP・常時防御力・攻撃の量 最小・最大・防御の量 最小・最大・攻撃の重み・防御の重み）・巨人 7（最大 HP・常時防御力・周期・攻撃の量 最小・最大・回復の確率・回復の量）・ドラゴン 9（最大 HP・常時防御力・爪 最小・最大・ブレス 最小・最大・燃やす札 最小・最大・吸い込む確率）＝ **25 個**になり、REQ の並びと同じ順になる。`weighted` の `K` は `attack`・`defend`。
* 知らない `behavior.type` は `Error`（`unknown enemy behavior type: ...`）。
* export: `RULE_ITEMS`（凍結した配列）、`ruleItemById(id)`（なければ `null`）。

#### 問い合わせと操作（ルール層。`debugRules.js`）
* 共通の条件 `isTunable(game)`: `game.config !== RULES`（写しを使うゲーム）かつ `game.stage === 'planning'`。偽なら操作は何もせず `false`。問い合わせは条件なしで答える。
* 問い合わせ（状態を変えない）:
    * `ruleGroups(config)`: 組の並び `[{ group, enemyName, itemIds }]`（`group` は `'castle'` か敵の種類の識別子、`enemyName` は敵なら `config.enemies[group].name`、城は `null`。`itemIds` は `RULE_ITEMS` の順の `id` の配列）。`RULE_ITEMS` から作る。
    * `ruleItemInfo(id)`: `{ kind, name }`（DEBUG タブがスライダーの範囲と文字を決めるため。知らない `id` は `null`）。
    * `ruleValue(game, id)`: `ruleItemById(id).get(game.config)`（知らない `id` は `null`）。
    * `ruleTiming(game, id)`: 項目の `group` が `'castle'` でなく、`game.enemy.typeId` と違えば `'onAppear'`（出てきたときから）。そうでなければ項目の `timing`。
* 操作 `setRuleValue(game, id, value)` → `boolean`（変えたら `true`）:
    1. `isTunable(game)` が偽、知らない `id`、値が種類に合わない（下の確かめ方）、今の値と `===` で同じ → `false`。
    2. 重みの決まり: `kind === 'weight'` で `value === 0` のとき、同じ `group` のほかの重みの項目の値がすべて 0 なら `false`（両方 0 にはしない）。
    3. 値を書く（`item.set(game.config, value)`）。
    4. 組の決まり: `pairId` があり、`side === 'min'` で `value > 相手の値` なら相手にも `value` を書く。`side === 'max'` で `value < 相手の値` なら相手にも `value` を書く（いつも 最小 ≤ 最大）。
    5. すぐ効く値を効かせる（`applyNow(game, item)`。下の要件2）。
    6. `true`。
* 値の確かめ方（`kind` ごと）: `castleMaxHp`・`enemyMaxHp`・`cycleLength` は 1 以上の整数、`armor`・`amount`・`weight`・`burn` は 0 以上の整数、`chance` は 0 以上 1 以下の有限の数。上限はルール層では決めない（スライダーの範囲が決める）。
* 操作 `resetRuleValues(game)` → `boolean`: `isTunable(game)` が偽なら `false`。全部の項目に `item.set(game.config, item.get(RULES))` を書き（`RULES` の値は組の決まり・重みの決まりを満たしているので、そのまま写す）、全部の `timing === 'now'` の項目に `applyNow` をかけて `true`。
* `debugRules.js` の import は `./config.js` の `RULES` と `./debugRuleItems.js` だけ。`Math.random` を呼ばない。数値を直書きしない。

#### スライダー（DEBUG タブ。`debugRuleSliders.js`）
* 範囲と刻みの表 `RULE_SLIDERS`（凍結。`kind` → `{ min, max, step }`。JSDoc に「DEBUG タブのスライダーの範囲で、ルールの値ではない。試遊で決め直す値。`config.js` の値を範囲の外にしたら見直す」）:

| `kind` | min | max | step | 値の文字 |
| --- | --- | --- | --- | --- |
| `castleMaxHp` | 5 | 200 | 5 | 数 |
| `enemyMaxHp` | 5 | 300 | 5 | 数 |
| `armor` | 0 | 20 | 1 | 数 |
| `amount`（攻撃・防御・爪・ブレスの量、回復の量） | 0 | 50 | 1 | 数 |
| `weight` | 0 | 10 | 1 | 数 |
| `chance` | 0 | 1 | 0.05 | 百分率（`percentText`。例「25%」） |
| `cycleLength` | 1 | 8 | 1 | 数 |
| `burn` | 0 | 10 | 1 | 数 |

* 確率は 0〜1 の値のまま渡す（エンジンの刻みの値は小数の桁で丸められるので、0.25・0.3 などは誤差なく渡る。26章「スライダーの値の決まり方」）。文字だけ百分率にする。今の `RULES` の値（城 50、敵 30・60・80、常時防御力 0・3・4、量 2〜22、重み 3・1、確率 0.25・0.3、周期 4、燃やす札 4〜6）は、どれも範囲の中で刻みに合う。
* 各スライダー: `area.addSlider({ ...矩形, label: () => ruleItemText(name, debug.ruleTiming(id)), min, max, step, read: () => debug.ruleValue(id), write: (v) => debug.setRuleValue(id, v) })`。`chance` のときだけ `format: percentText` を足す（ほかは書かない＝`String(value)`）。`label`・`read`・`format` は状態を変えない。
* `RULE_SLIDERS` にない `kind` は `Error`（`unknown rule kind: ...`）。

#### 置き場所（1つの DEBUG タブに入れる）
* **タブは分けない**。今の DEBUG タブのスクロールする領域の、FPS の値の下に続けて、上から「ルールの値を元に戻す」ボタン → 「城」の見出しとスライダー → 「ゴブリンの軍勢」→「巨人」→「ドラゴン」（それぞれ見出しとスライダー）を並べる。
* 分けない理由: スクロールする領域の中身の高さに上限はなく（26章「スクロールの動き」）、25 個のスライダーを足しても1つの領域に入る。スライダーはスクロールする領域の中でも、横に動かせば値を変え、縦に動かせばスクロールになる（26章「スクロールする領域の中の部品のポインタの受け方」）ので、スマホでも PC でも同じ操作で使える。組ごとの見出しで場所が分かる。分けると `MenuScene` に渡すタブが増え、タブの列の幅（592）を 4 つで割って1つが 148 になる。中身が長い（下の高さ）ことは「5. 懸念事項」に書き、試遊で使いにくければ発注者の決定のとおり「DEBUG2」に分ける。
* 「ルールの値を元に戻す」ボタンは、ルールの値の並びの先頭（FPS の値のすぐ下）に置く。FPS の近くからすぐ押せ、どの組のスライダーからも見出しをたどって戻れる。
* 見出し: 城は `DEBUG_TEXT.rulesCastle`（「城」）。敵は `config.js` の `name`（`ruleGroups` の `enemyName`。06-02 の敵の選択肢と同じく、敵の名前を二重に持たない）。見出しは `area.addValue({ ...矩形, label: 見出しの文字, read: () => '' })`（06-02 の見出しと同じ形）。

### 要件2: いつから効くか
* **すぐ効く値**（`applyNow(game, item)`。`debugRules.js` の中の関数。`timing === 'now'` の項目だけ）:
    * `castleMaxHp`: `game.castle.maxHp` に新しい値を入れ、`game.castle.hp` がそれを超えるときだけ最大 HP に下げる。
    * `enemyMaxHp`（項目の `group === game.enemy.typeId` のときだけ）: `game.enemy.maxHp` に入れ、`game.enemy.hp` が超えるときだけ下げる。
    * `armor`（同じく今の敵のときだけ）: `game.enemy.armor` に入れる。
    * 今の HP は上げない（満タンにしたいときは 06-02 の「満タンにする」。そのボタンは `target().maxHp` を読むので、新しい最大 HP まで満たす）。
* **見た目**: 段取りの間の最上部の HP のゲージと数字（`boardView.js` の `topGaugeValues` が `game.castle`・`game.enemy` を渡す）、ゴブリンの群れの数（`enemyView.js` の `drawHorde` が `enemy.hp`）、シールドマークの数（`enemy.armor`）、DEBUG タブの HP の表示は、描くたびにルール層の状態を読むので、次の描画で新しい割合・文字・数になる（06-02 の HP のボタンと同じ。動きは付けない）。段取りの間の HP・最大 HP・常時防御力を写して持つ anim はないので、合わせる anim の口は要らない（`EnemyIdle` は毎回の `update` で `enemy.hp` を受け取り、群れの数が減ったときは描画が `i < idle.count` で読む）。

## 5. 懸念事項・要確認ポイント
* **中身の長さ（目視で確かめてほしい）:** DEBUG タブの中身の高さが 1412 から 5504 になる（領域 456、スクロールできる量 5048）。慣性がないので、スマホでは下のドラゴンまで何度も指でずらすことになる。試遊で使いにくければ、発注者の決定のとおり「DEBUG2」（ルールの値だけのタブ）に分ける（`debugRuleSliders.js` を別のタブの領域に足すだけで済む形にしてある）。
* **スクロールする領域の中のスライダー:** 動かさずに離すと押した位置の値になる（26章）。スクロールしようとして短く触れただけで値が変わることがある。値は「元に戻す」で戻せる。
* **スライダーの刻みの細かさ:** 幅 580 の溝で、敵の最大 HP（59 刻み）・量（50 刻み）は1刻みが約 9〜10（論理座標）で、遊び 8 があるため、スマホで狙った値に合わせにくいかもしれない（試遊で範囲を見直す）。
* **項目名の長さ:** 「攻撃後に回復する確率（次の攻防から）」など長い項目名は、スライダーの文字の段で横に縮んで描かれる（26章）。読みにくければ `debugText.js` の文字を短くする。
* **大きな値の見た目と重さ:** ゴブリンの軍勢の最大 HP を 300 にすると、群れを 300 体描く（攻防でも 1 体ずつ動く）。常時防御力 20 ではシールドマークが 20 個並ぶ。動き・重さは目視で確かめてほしい（キャンバスキャッシュは 06-04）。
* **06-02 の項目への影響（動きは変えないが、値によって見え方が変わる）:** 巨人の回復の量を 0 にすると、06-02 の次の行動の選択肢から「攻撃して回復」が消え（枠は「－」）、すでに「攻撃して回復」を指定していた予告は、選ばれている選択肢がなくなる（回復は量 0 なので起きない）。巨人の周期を 1 にしてから 06-02 で「振りかぶり」を指定すると、数え下ろしが 0 のまま振りかぶりの予告になり、数え下ろしの表示が「攻撃！」になる（次の予告からはふつうに毎ターン攻撃）。
* **敵の見出しの文字:** 敵の組の見出しは、`debugText.js` ではなく `config.js` の敵の名前（`name`）を使う（06-02 の敵の選択肢と同じで、名前を二重に持たないため）。城の見出しだけ `debugText.js` に置く。
* **量 0:** 攻撃・防御・爪・ブレスの量を 0 にできる（予告の札の数字は 0）。攻防の計算は量 0 の行動もそのまま扱う（敵の行動の出来事は必ず入る）が、演出の見え方は目視で確かめてほしい。
