## 1. 作業目的
3体を倒すと終わる形をやめ、城の HP が 0 になるまで敵が続くようにする。

1. 終わりは城の HP が 0 になったときだけ。「最後の敵」「勝ち」「クリア」の仕組みと表示をなくす。
2. ステージの番号（1 から。何体目の敵か）で敵の★が決まり、同じ★のどの敵かは、始めた日付（種）とステージの番号から決まる。
3. 乱数は2本。敵の並びは日付の種だけ、それ以外は今までどおりプレイ用の乱数（`Math.random`）。
4. ステージが進むごとに、敵の HP・攻撃・防御が章ごとの加算量で強くなる。
5. ステージの始まりの敵の名前を文字にし（名前のロゴ3枚は削除）、敵の名前に「Lv（ステージの番号）」を付け、結果に「倒した敵の数」を足す。
6. DEBUG タブにステージを移るボタンを足し、遊び方・古い説明文を直す。

守ること（全タスク共通）:
* 数値は `js/rules/config.js`（ルール）・`layout.js` などの配置の定数に置く。座標は論理座標（720×1280）。画面の呼び名は TURN・ターン（内部は phase）。
* ルール層は `oz`・画面・演出を import せず、`Math.random`・日付を読まない。敵の種類の識別子で分岐する if を足さない。
* 名前: 「ステージの番号」は `stageNumber`。既存の段階 `game.stage`（'planning' など）とは別物で、混ぜない。
* 1ターンの流れ・攻防の計算の順・行動の回数・束の補正・4スートそろい・疲弊・敵の行動の決まりと元の数値・自軍の数値は変えない。**プレイ用の乱数を呼ぶ順と回数も変えない。**
* `oz/` は編集しない・`oz/src/` は読まない。`draw` の中で状態を変えない。スプライトは、タスク7の3枚の削除のほか変えない。
* 確かめの一時スクリプトは、リポジトリの外（スクラッチパッド）に置き、終わったら消す。
* REQ の「今回やらないこと」（新しい敵、★の決まりを広げる、次の敵の表示、中断と再開、3択・強化・スコア、加算量・日付を変える DEBUG の項目、`README.md`・`_doc/` の書き換え など）は行わない。

    * `seededIndex(seed, stageNumber, count)`（export。一時スクリプトの確かめにも使う）: 32 ビット整数の混ぜ合わせ。計画で確かめた式は次のとおり（この式で書く。定数はルールの数値ではなく混ぜ合わせの定数なので、このファイルに置く）。
        ```js
        function mix32(v) {
          let h = v >>> 0;
          h ^= h >>> 16; h = Math.imul(h, 0x85ebca6b);
          h ^= h >>> 13; h = Math.imul(h, 0xc2b2ae35);
          h ^= h >>> 16;
          return h >>> 0;
        }
        // seededIndex の中身
        const h = mix32(mix32(seed ^ 0x9e3779b9) + Math.imul(stageNumber, 0x9e3779b1));
        return Math.floor((h / 0x100000000) * count);
        ```
        （計画時の確かめ: 10 年分の日付・候補 2〜7 で、候補ごとの割合は 1/候補の数 から ±0.051 以内（種ごとに 1000 ステージ）・±0.022 以内（ステージごとに 3650 日）、10 の倍数のステージだけでも均等、隣り合う日・ステージの一致率は 1/候補の数 とほぼ同じ、先頭 30 ステージの並びは 3650 日すべて違う）

### 要件4: ステージの加算
* **設定**: `RULES.stageGrowth = { stagesPerChapter: 5, chapters: [{ hpPercent: 5, attack: 0.5, defense: 0.25 }, { hpPercent: 7, attack: 0.75, defense: 0.25 }, { hpPercent: 9, attack: 1, defense: 0.5 }, { hpPercent: 12, attack: 1.25, defense: 0.5 }] }`（章ごとの、1ステージあたりの加算量。最後の要素を、それより先の章でも使う。`hpPercent` は百分率の整数、`attack`・`defense` は 0.01 刻みまで。凍結）。
* **`stageBonus.js`**（加算を求める計算はここ1か所）:
    * `stageBonusOf(stageGrowth, stageNumber)` → `{ hpPercent, attack, defense }`（どれも 0 以上の整数）。章を先頭から見て、その章に入る「進んだ先のステージ」の数 `count = max(0, last − max(first, 2) + 1)`（i は 0 から、L は `stagesPerChapter`。`first = i × L + 1`、`last` は最後の要素なら `stageNumber`、ほかは `min(stageNumber, (i + 1) × L)`）を加算量に掛けて足す。`attack`・`defense` は `Math.floor(Math.round(合計 × 100) / 100)`（小数の誤差で1ずれない）。
    * `grownMaxHp(baseMaxHp, bonus)` → `Math.floor(baseMaxHp × (100 + bonus.hpPercent) / 100)`。
* **HP**: `createEnemy(typeId, spec, bonus)` が `grownMaxHp(spec.maxHp, bonus)` を最大 HP・今の HP にする。
* **予告（`enemyIntent.js`。予告に足すのはここ1か所）**: `createIntent(spec, action, bonus, battleTurn, fatigue, random)`
    * 攻撃: `action.kind === 'attack'` なら `amount = action.amount + bonus.attack`。振りかぶり・吸い込む（`windup`）は 0 のまま。
    * 防御: 隙（`isOpeningAction`）なら乱数を呼ばず 0。そうでなければ `rollDefense(spec.defense, random)`（張らなければ `null`、張れば量。**必ず2回** `random()` を呼ぶのは今のまま）。`null` なら 0、量なら `量 + bonus.defense`（量が 0 でも足す）。これが `baseDefense`（加算後・疲弊の前）。`defense = fatiguedDefense(baseDefense, …)`。
    * `refreshIntent(intent, battleTurn, fatigue)` は中身そのままで移す。
    * 敵の種類・行動の決まりでは分岐しない。確率・周期・回復の量・燃える札の枚数は触らない。
* **`enemyDefense.js`**: `rollDefense`・`fatiguedDefense`・`isFatigued` を残す。
* **`Game`**: `stageBonus()`（`stageBonusOf(this.config.stageGrowth, this.stageNumber)`）と `intentOf(action)`（`createIntent(enemySpecOf(…), action, this.stageBonus(), this.battleTurn, this.config.fatigue, this.random)`）を持ち、`planIntent` と DEBUG の「次の行動」が `intentOf` を使う。
* 予告・シールドの数・攻防は今までどおり `intent.amount`・`intent.defense` だけを読むので、加算のための画面・演出の変更は要らない。
