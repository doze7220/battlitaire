# RES: 作業計画・作業レポート (Phase 06-01) : メニューの窓と設定
* 参照元REQ: `./_log/req/261122_1639_Phase06-01_メニューの窓と設定.md`

## 1. 作業目的
エンジンの UI 部品（`oz/ENGINE_API.md` 26章 `Ui`）で、タイトル画面とプレイ中（段取りの間）に**同じメニューの窓**を開けるようにし、その中に「設定」（BGM の音量・効果音の音量・攻防の演出の速さ）と「クレジット」（音の素材の出典）のタブを置く。設定はエンジンの `Storage`（22章）で保存し、次の起動でも残す。

* ルール層（`js/rules/`）は変更しない。数値も変えない。演出の速さを変えても、攻防の結果・決着・次の敵への進み方は変わらない。
* 座標はすべて論理座標（720×1280）。窓・部品・TURN の区画の大きさと位置は定数に置く（試遊で決め直す値）。
* 窓の見た目はエンジンの標準の見た目のまま（`look` は渡さない）。
* 次のサブフェイズで「DEBUG」タブを一番右に足せるよう、窓はタブの一覧を受け取って組み立てる形にする（今回 DEBUG タブそのものは作らない）。

### 要件1: メニューの窓
* **シーンの形（`MenuScene`）**
    * `constructor({ layer, tabs })`。`tabs` は「タブの一覧」`MenuTab[]`（`{ label: string, build: (tab) => void }`。`label` はタブの名前、`build` は `addTabs` が返したそのタブのオブジェクトに部品を足す関数）。配列は写して持つ。
    * `init()`: `Ui.createWindow({ title, width, height, onClose })`（`x`・`y` は渡さず画面の中央。`look`・`closeOnOutside`・`titleBarHeight`・`textSize` は渡さず既定のまま）→ `addTabs({ x, y, width, height, labels: tabs の label の並び })` → 返った配列の i 番目に `tabs[i].build(...)` を呼ぶ。開くたびに新しい `MenuScene` を作るので、窓も毎回新しく、タブは毎回先頭（「設定」）から。
    * `close()`: 閉じ済みの印（`closed`）を見て1回だけ `Engine.popScene()` する（同じフレームで閉じるボタンと Escape が重なっても2回外さないための印。窓の状態以外は持たない）。`onClose` と Escape の両方がこれを呼ぶ。
    * `onPointer(pointer)`: そのまま `this.window.onPointer(pointer)` に渡す。
    * `onKeyDown(code)`: `'Escape'` なら `close()`。ほかのキーは何もしない。
    * `draw(ctx, layer)`: `layer === this.layer` のときだけ `this.window.draw(ctx)`（レイヤーは `'main'` の1つだけ。メニューのシーンはスタックの最前面なので、背面の盤面・タイトルより手前に描かれる）。
    * `update` は持たない（窓は時間で動かない）。`Engine.addButton` は使わない。
* **同じ窓にする方法**: `js/main.js` に `createMenu()`（`new MenuScene({ layer: 'main', tabs: createMenuTabs() })`）を置き、タイトル画面と盤面の両方にこの関数を渡す（今の `createTitle`・`createHowTo` と同じ渡し方）。どちらから開いても同じ関数で作るので、タイトル・タブ・部品の並びは同じになる。
* **DEBUG タブを後から足せる作り**: 窓はタブの一覧だけを見て組み立てる（タブの数・名前・中身を `MenuScene` に書かない）。次のサブフェイズでは、`main.js` の `createMenu` で、デバッグスタートのときだけ `[...createMenuTabs(), DEBUG のタブ]` を渡せばよく、`MenuScene.js` と `menuTabs.js` の今のタブは書き直さずに済む。タブの列の幅は `addTabs` が `labels` の数で等分する（26章「タブの切り替わり方」）。今回は DEBUG のタブ・定数・操作は作らない。
* **大きさ（`js/view/menuLayout.js` の定数。試遊で決め直す値）**: 既定の大きさ（タイトルバー 88・部品 88・スライダー 132・文字 36）をそのまま使う。窓の内側（タイトルバーの下）の原点からの位置で決める。
    * 窓: 幅 640・高さ 696（タイトルバー 88 ＋ 内側 608）。画面の中央（左上は x 40・y 292 になる）。
    * 左右の余白 24、部品の幅 592。
    * タブの列: x 24・y 16・幅 592・高さ 88。
    * 中身の始まり: y 128（タブの列の下端 104 ＋ 間 24）。部品の間 16。
    * 「設定」タブ: BGM の音量のスライダー y 128・高さ 132 → 効果音の音量のスライダー y 276・高さ 132 → 攻防の演出の速さの項目名（文字の表示）y 424・高さ 72 → 選択肢の列 y 496・高さ 88（下端 584。内側の下の余白 24）。
    * 「クレジット」タブ: スクロールする領域 x 24・y 128・幅 592・高さ 456（下端 584）。領域の中の1行は x 0・幅 580（右端の 12 を位置の表示に空ける。26章）・高さ 72・行の間隔 80（行 i の y = 80 × i）。行が領域に収まらないほど増えたら、指で縦にずらして見られる。
    * 定数は1つの凍結したオブジェクト `MENU_LAYOUT`（`window`・`tabs`・`bgmSlider`・`seSlider`・`speedLabel`・`speedChoices`・`creditArea`・`creditLine`）にまとめ、値は上の数の元になる定数（余白・間・高さ）から計算して書く。
* **背面の動き**: `Engine.pushScene` で積むので、開いている間は背面の `update` が止まり、入力が届かない（6章）。閉じると `update` が再開し、続きから動く（8章。操作のフレームは時間が飛ばない）。

### 要件4: 「設定」タブ
* **値の表（`js/scenes/settingsStore.js` の定数。試遊で決め直す値）**
    * `VOLUME_RANGE = { min: 0, max: 1, step: 0.1 }`（スライダーの範囲と刻み。26章の決まりで `max - min` は `step` の整数倍）。
    * `BATTLE_SPEEDS`（凍結した配列。選択肢の列の並び順）: `{ id: 'normal', label: '普通', rate: 1 }`、`{ id: 'fast', label: '速い', rate: 1.5 }`。倍率と選択肢の文字はここ1か所。
    * `DEFAULT_BATTLE_SPEED = 'normal'`。
    * 音量の初期値は `js/audio/soundConfig.js` の `BGM_VOLUME`（0.5）・`SE_VOLUME`（0.7）を import して使う（ここに数を書き写さない）。
* **読み書きの口（`settingsStore.js` の関数）**: 
    * `bgmVolume()`・`seVolume()`: `Storage.get` の値を答える。範囲 0〜1 の有限の数でなければ初期値を答える（保存データが壊れていても `Sound` の音量に範囲外を渡して `RangeError` にしないため）。状態は変えない（スライダーの `read` から `draw` の中で呼ばれる）。
    * `battleSpeedId()`: 保存された識別子が `BATTLE_SPEEDS` にあればそれ、なければ `DEFAULT_BATTLE_SPEED`。状態は変えない。
    * `battleSpeedRate()`: `battleSpeedId()` の倍率。
    * `writeBgmVolume(v)`・`writeSeVolume(v)`: `Storage.set` で保存し、音量をその場で反映する（BGM は `bgmCues.js` の `setBgmVolume(v)`、効果音は `soundCues.js` の `setSeVolume(v)`）。
    * `writeBattleSpeed(id)`: `BATTLE_SPEEDS` にある識別子なら `Storage.set` で保存する（ない識別子は何もしない）。
    * `applySoundSettings()`: 起動時に1回、`bgmVolume()`・`seVolume()` を `setBgmVolume`・`setSeVolume` に渡す。
* **音の決まりを守る形**: `Sound` を呼ぶのは今のとおり `soundCues.js`・`bgmCues.js` の2つだけにする。`bgmCues.js` に `setBgmVolume(v)`（`Sound.bgmVolume = v`）、`soundCues.js` に `setSeVolume(v)`（`Sound.seVolume = v`）を足し、`settingsStore.js` はこれを呼ぶ（`settingsStore.js` は `Sound` を import しない）。`js/main.js` は起動の前の音量を直接 `Sound` に書かなくなり（`applySoundSettings()` を呼ぶ）、`Sound`・`SE_VOLUME`・`BGM_VOLUME` を import しなくなる。決まりは「`Sound` を呼ぶのは2つだけ」のまま、両ファイルの責務に「音量を `Sound` に渡すこと」を足す（開発資料の更新予定に記載）。
* **部品（`js/scenes/menuTabs.js` の「設定」タブの `build`）**
    * BGM の音量: `addSlider({ ...MENU_LAYOUT.bgmSlider, label: MENU_TEXT.bgmVolume, min, max, step（VOLUME_RANGE）, read: bgmVolume, write: writeBgmVolume, format: volumePercentText })`。動かすとその場で `Sound.bgmVolume` が変わるので、タイトルではタイトルの曲、プレイ中はステージの曲で確かめられる。
    * 効果音の音量: 同じ形（`MENU_LAYOUT.seSlider`・`MENU_TEXT.seVolume`・`seVolume`）。`write` は `writeSeVolume(v)` の後に**確かめの音**を鳴らす（`soundCues.js` に `playSeVolumeCheckSe()` を足し、既存の効果音 `place` を鳴らす。スライダーの `write` は値が変わったときだけ呼ばれる（26章）ので、刻みが変わるたびに1回鳴る）。
    * 攻防の演出の速さ: 項目名を `addValue({ ...MENU_LAYOUT.speedLabel, label: MENU_TEXT.battleSpeed, read: () => '' })`（値の文字は空）で出し、その下に `addChoices({ ...MENU_LAYOUT.speedChoices, choices: BATTLE_SPEEDS から { label, value: id }, read: battleSpeedId, write: writeBattleSpeed })`（`direction` は既定の横）。
    * 百分率の文字: `js/view/menuText.js` の `volumePercentText(v)` = `Math.round(v * 100) + '%'`（数でない値は呼ばれない前提だが、`Number.isFinite` でなければ `'--'`）。
* **演出の速さの効かせ方（`js/scenes/BattleShowScene.js`）**: `init` で `battleSpeedRate()` を1回読んで `this.speedRate` に持ち、`update(dt)` で `this.director.update(dt * this.speedRate)` とする。
    * 攻防の演出の管理（`battleDirector.js`）は `update(ms)` の `ms` を壁の時計に足し、ヒットストップの並びから演出の時計を求め、兵の動き・当たり・エフェクト・HP の表示値・揺れの拍子（壁の時計）・終わりと「次へ進んでよいか」（`endDelayMs` を含む）・音のきっかけ（`cuesInLastUpdate`）・HP が 0 になった時刻（`isKnockedOut`）をすべてこの時計で答える。そのため、シーンが足す時間に倍率を掛ければ、ヒットストップを含む演出の全体と、音のきっかけ・BGM を止める時刻・クリアと負けの音の時刻が同じ割合で早まり、絵と音がずれない。音の再生の長さは変わらない。
    * `battleDirector.js`・`hitStop.js`・`battleTimeline.js`・`battleAnimConfig.js` は変更しない（時間割の時刻・演出の設定の値は書き換えない）。
    * `Engine.timeScale` は使わない（画面全体の `update` に効き、段取りの間の動きに効いてしまうため。また 12章のとおりティック単位で段階的になる）。
    * 盤面のシーン（`BoardScene.update`）・段階の管理（`boardFlow.js`）・合図（`BannerShow`）は今のまま `dt` をそのまま足す。段取りの間の札・玉・兵の動き、ステージとターンの始まり、準備終了・BATTLE! の長さは変わらない。
    * 倍率は攻防ごとに `init` で読むので、次の攻防から効く（攻防の演出の途中はメニューを開けない）。
    * 攻防の結果は `BoardScene.startBattle` で `game.resolveBattle()` が先に決めており、演出の時計の速さは結果・決着・次の敵への進み方に関わらない。

## 5. 懸念事項・要確認ポイント
* 窓の標準の見た目での、文字の表示（`addValue`）の項目名と値の文字の並び方（左右の寄せ）は資料に書かれていない。攻防の演出の速さの項目名とクレジットの行は「項目名に文字・値は空文字」で出す計画なので、実機で文字が左に読めるかを目視で確かめてほしい（読みにくければ、試遊の後に `look` を使わない範囲で並べ方を見直す）。
* 効果音の音量のスライダーを動かすたびに確かめの音（`place`）が鳴る。ドラッグで刻みが続けて変わると続けて鳴るので、うるさく感じるかを試遊で確かめてほしい。
* (タスク2) 要件1の「窓の幅 640」は内側の幅も 640（左右余白 24 + 部品 592）として計算した。「選択肢の列 y 496」は項目名の下端にそのまま続ける値（間なし）に合わせた。

* TURN の区画の押せる範囲（x 300〜420・y 0〜88）は、HP ゲージの内側の端（各 10）の上に少し重なる。見た目の重なりはなく、HP ゲージは押せないので動作の問題はないが、押した感触を試遊で確かめてほしい。
