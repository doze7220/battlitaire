# RES: 作業計画・作業レポート (Phase 02-01) : 縦画面への組み直し
* 参照元REQ: `./_log/req/261111_2214_Phase02-01_縦画面への組み直し.md`

## 1. 作業目的
Phase 01 までの横長の画面（1280×720）を、縦長の画面（論理解像度 720×1280）に切り替え、スマホを優先して配置を組み直す。画面を上から「戦闘」「ソリティア」「UI」の3段に分け、最上段の高さは `js/view/layout.js` の値1つ（`BATTLE_H`、初期値 360）で変えられるようにする。押せるものは論理解像度でおよそ 80px 以上にし、タップだけで今の操作の流れのまま遊べるようにする。ゲームのルール（`js/rules/`）は変えない。カードの動き・兵の動き・音は作らない（02-02 以降）。

## 2. アーキテクチャ設計

### 共通の前提（全タスク共通）
* ルール層（`js/rules/`）は変更しない。描画・配置・シーンの側だけを変える。
* 盤面の座標・大きさはすべて `js/view/layout.js` に集め、当たり判定も同じ配置から `hitTest` で求める。描画のファイルに座標の数値を直書きしない（文字の大きさ・線の太さ・角の半径・余白などの見た目の値は、今と同じく各描画ファイルの定数でよい）。
* 配置は `createLayout` に渡される `screen`（`{ width, height }`）から計算する。`layout.js` に 720・1280 を書かない。解像度は `js/main.js` の `screen` だけで決まる。
* 画面の拡大縮小・中央寄せ・上下（左右）の帯はエンジンに任せる（`oz/ENGINE_API.md` 4章「表示は、ウィンドウに収まる最大の大きさに自動で合わせられる。縦横比は保たれ」、2章「中央寄せと黒い余白は、上の CSS で行う」）。`index.html` は変えない（今の CSS は canvas の幅・高さを指定していない）。入力は `Scene` の `onPointer` の論理座標（16章）で受ける。`js/` に `addEventListener`・`requestAnimationFrame`・`getContext` を書かない。
* 作らないもの: カードの動き、兵の動き、城・敵の絵（画像）、早送り・スキップ、効果音、画面の向きの検出・横向き用の別配置、解像度の自動切り替え。

### 要件1: 縦長の画面
* `js/main.js` の `screen` を `{ width: 720, height: 1280 }` にする。`Engine.start` の `width`・`height` は今どおり `screen` から渡す（ほかは変えない）。
* `BootScene`（タイトル）・`BattleResultScene`（結果の窓）・`BoardScene`（盤面）は、今どおり `screen` を受け取って使うので、解像度の値は `main.js` の1か所だけにある。
* `js/ui/virtualPadConfig.js` の「論理解像度 1280x720」のコメントだけを、「1280×720 のときに決めた配置のまま。縦画面では未調整（`virtualPad` は `false` で使わない）」の趣旨に直す。パッドの配置の数値は変えない。

### 要件2: 3段の配置（`js/view/layout.js`）
画面を上から3段に分ける。段の境目は次の式で決まる（`H` は `screen.height`、`W` は `screen.width`）。

| 段 | 上端 y | 高さ |
| --- | --- | --- |
| 戦闘（`sections.battle`） | 0 | `BATTLE_H`（初期値 360） |
| ソリティア（`sections.solitaire`） | `BATTLE_H` | `H − BATTLE_H − UI_H` |
| UI（`sections.ui`） | `H − UI_H` | `UI_H`（220。固定） |

* **最上段の高さの値**: `layout.js` に `const BATTLE_H = 360;` を1つだけ置く（JSDoc に「最上段（戦闘）の高さ。300〜480 の範囲で変えてよい。試遊で決め直す」と書く）。ほかの段の位置・大きさは、`BATTLE_H`・`UI_H` と `screen` から計算する。
* **UI の段の高さ** `UI_H = 220` は固定値（中身の行がおさまる高さ）。ソリティアの段は残りの高さを使う。

#### 最上段（戦闘）の配置 `BattleLayout`
サイドビューの見立てで、左に城、右に敵。地面の線より下に HP と予告の枠を置く。

| 名前 | 式（`BATTLE_H` 360・`W` 720 のときの値） |
| --- | --- |
| `area` | `{ x: 0, y: 0, w: W, h: BATTLE_H }` |
| `phase`（「フェーズ N」の枠） | 幅 `PHASE_BOX_W`(200)・高さ `BOX_H`(40)、`x = (W − 200) / 2`(260)、`y = BATTLE_TOP_PAD`(12) |
| `groundY`（地面の線の y） | `BATTLE_H − GROUND_OFFSET`(100) → 260 |
| `castle`（城の仮の図形の矩形） | `x = CASTLE_X`(40)、`w = CASTLE_W`(140)、`h = min(CASTLE_MAX_H(150), groundY − bodyTop)`、`y = groundY − h`。`bodyTop = phase.y + phase.h + BODY_GAP(16)` → 68。→ `{40, 110, 140, 150}` |
| `enemy`（敵の仮の図形の矩形。丸を内接させる） | `s = min(ENEMY_MAX_SIZE(120), groundY − bodyTop)`、`x = W − ENEMY_RIGHT(40) − s`、`y = groundY − s`、`w = h = s` → `{560, 140, 120, 120}` |
| `castleHp`（城の HP の枠） | `x = SIDE_MARGIN`(20)、`y = groundY + INFO_GAP`(8)、幅 `INFO_W`(240)、高さ `BOX_H`(40) → `{20, 268, 240, 40}` |
| `enemyHp`（敵の HP の枠） | `x = W − SIDE_MARGIN − INFO_W`(460)、`y = groundY + INFO_GAP` → `{460, 268, 240, 40}` |
| `intent`（敵の予告の枠） | `enemyHp` の真下: `y = enemyHp.y + BOX_H + INFO_GAP_Y`(4) → `{460, 312, 240, 40}`（下端 352 < 360） |

* 城の HP は城の下（左）、敵の HP と予告は敵の下（右）に並ぶので、どちらの数字か分かる。枠の文字は今どおり「城 HP 50 / 50」「敵 HP 50 / 50」「次の行動 攻撃 10」「フェーズ N」（24px）。240px の枠に収まる（最長の「次の行動 防御 15」でおよそ 190px＋左の余白 14px）。
* 02-03 で兵を足すため、`groundY`（足元の y）、`castle`（城の x・幅）、`enemy`（敵の x・幅）を `BattleLayout` から読めるようにしておく（今回はこれらを描画にだけ使う）。
* 最上段の描画（背景・地面の線・城と敵の仮の図形・フェーズ・HP・予告）は、新しいファイル `js/view/battleStageView.js` の `drawBattleStage` 1つにまとめる。今の `js/view/statusView.js`（状況の帯）は使われなくなるので削除する（ファイル名が「状況の帯」を指し、責務も変わるため、作り替えではなく置き換えとする）。
  * 背景: `area` を空の色で塗り、`groundY` から下を地面の色で塗り、`groundY` に横線を引く。
  * 城: `castle` の矩形を塗り、上辺に小さな凹凸（狭間）を3つ程度描く（凹凸の大きさは描画ファイルの見た目の定数で、`castle` の幅からの割合で決める）。
  * 敵: `enemy` の矩形に内接する丸を塗る。
  * 枠: 今の `statusView.js` の `drawBox`（角丸の半透明の枠＋左寄せの文字）と同じ描き方。予告の文字は今どおり `battleText.js` の `enemyActionText`（予告が `null` のときは「－」）。
  * 状態は読むだけ。`ctx.save()`／`ctx.restore()` を対で使う。

#### 中段（ソリティア）の配置
カードの大きさは横幅から計算する。上の行に「山札 `deckCount` 個・捨て札 1・手札の枠 `handSize` 個」を同じ大きさで並べ、その大きさのカードで列 `columnCount` 本を並べる（列は4本なので、上の行（初期値6枚）が並べば列も必ず並ぶ）。

| 名前 | 式（`W` 720・`deckCount` 4・`handSize` 1・`BATTLE_H` 360 のときの値） |
| --- | --- |
| 上の行の枚数 `n` | `deckCount + 1 + handSize` → 6 |
| カードの幅 `cardW` | `floor((W − SIDE_MARGIN×2 − ROW_GAP_X×(n−1)) / n)`（`SIDE_MARGIN` 20、`ROW_GAP_X` 16）→ `floor(600/6)` = 100 |
| カードの高さ `cardH` | `round(cardW × CARD_ASPECT)`（`CARD_ASPECT` 1.4。今の 90×126 と同じ比）→ 140 |
| 上の行の上端 `rowY` | `sections.solitaire.y + SOLITAIRE_PAD_TOP`(16) → 376 |
| 山札 `decks[i]` | `x = SIDE_MARGIN + (cardW + ROW_GAP_X) × i`、`y = rowY`、`cardW × cardH` → x = 20, 136, 252, 368 |
| 捨て札 `discard` | 山札の次の位置（i = deckCount）→ x = 484 |
| 手札の枠 `hand.slots[s]` | 捨て札の次から（i = deckCount + 1 + s）→ x = 600 |
| 手札の見出し `hand.title` | 中心 `x` = 手札の枠の並びの中央（650）、`y = rowY + cardH + LABEL_LINE_H / 2`（`LABEL_LINE_H` 32）→ 532。山札の「残り N」（`deckView.js` がカードの下 8px に 16px の文字で描く）と同じ行の高さに並ぶ |
| 列の上端 `columnTop` | `rowY + cardH + LABEL_LINE_H + ROW_GAP_Y`(12) → 560 |
| 放つボタンの上端 `releaseY` | `sections.ui.y − SOLITAIRE_PAD_BOTTOM(12) − RELEASE_H(80)` → 968 |
| 列の領域の高さ `areaH` | `releaseY − COLUMN_BOTTOM_GAP(16) − columnTop` → 392 |
| 列 `columns[i]` | 段の幅を `columnCount` 等分した区画の中央に置く: `pitch = (W − SIDE_MARGIN×2) / columnCount`(170)、`x = SIDE_MARGIN + pitch × i + (pitch − cardW) / 2` → x = 55, 225, 395, 565。`y = columnTop`、`w = cardW`、`h = areaH`、`step = COLUMN_STEP_DEFAULT`(36)、`cardW`、`cardH` |
| 放つボタン `releaseButtons[i]` | 列と同じ `x`・`w`、`y = releaseY`、`h = RELEASE_H`(80) → 100×80 |

* 山札・捨て札・手札は列より上、放つボタンは各列の下（同じ横位置）にある。上の行（下端 532＋文字の行 16 = 548）と列の上端（560）、列の領域の下端（952）と放つボタン（968）、放つボタンの下端（1048）と UI の段（1060）は重ならない。
* **手札の枠が増えたとき**: 上の行の枚数 `n` が増えるので、カードの大きさが全体で同じ比率で縮み、上の行・列とも横幅に収まる（Phase 01-03 の「縮めて収める」を、手札だけでなく盤面のカード全体の縮小として保つ）。縦はカードが小さくなる分だけ列の領域が広がるので崩れない。今の `createHandLayout` の「1行に2枠・行で縮める」作りは、上の行に並べる作りに置き換える。
* **長い列の詰め（要件7）**: `columnCardYs` は今のまま使う（列の領域の `y`・`h`・`step`・`cardH` から計算するので、新しい領域の高さに合わせて働く）。一番上のカードの下端は領域の下端（`columnTop + areaH`）を超えないので、放つボタン・最下段と重ならない。

#### 最下段（UI）の配置 `HudLayout`（作り替え）

| 名前 | 式（`W` 720・`H` 1280 のときの値） |
| --- | --- |
| `panel`（段の背景） | `sections.ui` → `{0, 1060, 720, 220}` |
| `gauges[i]`（ゲージの枠。`gaugeCount` 個を横1行） | `y = ui.y + UI_PAD_TOP`(16)、`h = GAUGE_H`(64)、`w = (W − SIDE_MARGIN×2 − UI_GAP_X(12)×(gaugeCount−1)) / gaugeCount`(161)、`x = SIDE_MARGIN + (w + UI_GAP_X) × i` → y 1076 |
| `actions`（「行動 残り / 最大」の枠） | `x = SIDE_MARGIN`、`y = gauges の下端 + UI_GAP_Y(12)`(1152)、`w = ACTIONS_W`(200)、`h = ACTION_END_H`(100) |

### 要件3: 最上段の高さを1つの値で変えられる
`BATTLE_H` だけを変えたときの収まり（`W` 720・`H` 1280・`handSize` 1）。**カードの大きさは横幅だけで決まり、`BATTLE_H` では縮めない。`BATTLE_H` の増減は、列の領域の高さ（`areaH`）が吸収する**（列が収まらないときは Phase 01-03 の長い列の詰めで収める）。最下段は固定（`UI_H` 220）。

| `BATTLE_H` | 地面 `groundY` | 城の高さ | 敵の大きさ | 上の行の上端 | 列の上端 | 列の領域 `areaH` | 詰めずに並ぶ枚数 | 放つボタン | UI の段 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 300 | 200 | 132 | 120 | 316 | 500 | 452 | 9 | 968〜1048 | 1060〜 |
| 360（初期値） | 260 | 150 | 120 | 376 | 560 | 392 | 8 | 968〜1048 | 1060〜 |
| 480 | 380 | 150 | 120 | 496 | 680 | 272 | 4 | 968〜1048 | 1060〜 |

* `areaH = 752 − BATTLE_H`（この解像度の場合）。列の領域がカード1枚の高さ（140）以上あれば崩れないので、`BATTLE_H` は 612 まで成り立つ（REQ の範囲 300〜480 は余裕を持って満たす）。
* 戦闘の段の中も `BATTLE_H` から計算する（地面は下から 100、城・敵の高さは地面とフェーズの枠の間に収まるよう `min` で縮む）。300 でも HP・予告の枠（地面の下 8〜92）は段の中に収まる。
* 押せるもの（カード 100×140、放つボタン 100×80、行動終了 468×100）の大きさは `BATTLE_H` で変わらない。

### 要件4: 指で押せる大きさ
* 山札・列のカード・手札の枠: 100×140（`handSize` 1）。放つボタン: 100×80。行動終了: 468×100。いずれも 80px 以上。
* 列の重なった下のカードの当たりは、見えている帯（ずらし幅 36、詰めた部分はそれ以下）だけ（Phase 01-03 のまま）。
* 手札の枠が 2 になると上の行は 7 枚で `cardW` = 83（`floor(584/7)`。80 以上）。3 以上では 80 を下回る（崩れはしないが押しにくくなる。5章に記す）。

### 要件5: タップだけですべての操作ができる
* 入力は今どおり `BoardScene.onPointer` の `'down'` → `layout.hitTest` → `boardSelection.applyTap`（行動を使い切ったときは行動終了だけ）で、結果の窓は `BattleResultScene.onPointer` の `'down'`。どれもホバーを使っていない。配置が変わるだけで、操作の流れは変えない。`boardSelection.js` は変更しない。

### 要件6: 結果の窓とタイトル
* 結果の窓（`js/view/resultLayout.js`）: 窓の幅を `min(PANEL_MAX_W(640), screen.width − PANEL_SIDE_MARGIN(24)×2)` にする（720 では 640 のまま。解像度を変えても画面の幅を超えない）。高さ 520 は 1280 に収まる。窓は今どおり画面の中央（y = 380〜900）。行（26px。最長「城が受けたダメージ 10」でおよそ 260px）と決着（72px「勝ち」「負け」）は 640 の幅に収まる。行は最大4〜5行で、決着の位置（窓の上端から 360）より上で終わる。`resultWindowView.js` は変えない。
* タイトル（`BootScene.js`）: 今の作りが `screen` の中央に「TAP SCREEN」を描くので、解像度が変われば縦画面の中央に出る。変更しない。

### 要件7: 長い列が段の中に収まる
* 要件2のとおり、`columnCardYs` を新しい列の領域（`columnTop`〜`columnTop + areaH`）に対して使うので、上から3枚は重ね幅を保ち、残りを領域の上端まで詰める。描画（`columnView.js`）と当たり（`hitTest`）は同じ `columnCardYs` を使い続ける。

### 要件8: PC でも崩れない
* 縦横比の保持と左右の帯はエンジンの表示の仕組みのまま（要件1）。クリックはポインタ入力として `onPointer` に届く（`oz/ENGINE_API.md` 16章）。ゲーム側の追加の作業はない。
