# RES: 作業計画・作業レポート (Phase 01-01) : 盤面と段取り
* 参照元REQ: `./_log/req/261110_2149_Phase01-01_盤面と段取り.md`

## 1. 作業目的
ソリティア風の盤面（山札4つ・列4本・捨て札・ゲージ4つ・残りの行動回数・各列の「放つ」ボタン）を表示し、1フェーズ分の段取り（置く・置けない札を捨てる・放つ）をタップ／クリックで行えるようにする。ゲームのルール（置けるかの判定、捨てられるかの判定、放ったときのゲージ計算、山札の補充、行動回数の増減）はルール層 `js/rules/` にだけ書き、画面はシーン `js/scenes/` と描画 `js/view/` に分ける。ルール層の操作は「何が起きたか」を返し、Phase 2 の演出がその結果を使えるようにする。攻防・城・敵・フェーズの繰り返し・演出・効果音は作らない。

## 2. アーキテクチャ設計

### 共通の前提（全タスク共通）
*   ルール層 `js/rules/` は `oz` も `js/` のほかのフォルダも import しない。Canvas・DOM・音・時間・`Math.random` に触れない。import してよいのは `js/rules/` の中のファイルだけ。
*   ルール層の数値（スート、数字の範囲、列の数、見える枚数、基本の行動回数、倍率の式の係数）は `js/rules/config.js` にだけ書く。ほかのファイル（`js/view/` を含む）に `4`・`7`・`5` などのルールの数値を直書きしない。画面の側で列の数・山札の数・列の最大枚数が必要なときは、ルール層の状態（`game.decks.length`・`game.columns.length`・`game.maxColumnLength`）から読む。
*   画面の座標・色・大きさ・フォント・表示する文字（絵文字、ゲージの名前）は `js/view/` に置く（調整値ではない）。
*   ファイル名: クラスを export するファイルはクラス名（`Game.js`、`BoardScene.js`）、関数や定数を export するファイルは camelCase（`config.js`、`cardView.js`）。
*   すべてのファイルの先頭行に、責務を JSDoc で3行以内に書く。すべての関数・クラス・メソッド・データ構造（`@typedef`）に JSDoc を書く。

### 要件1: 起動と盤面の表示
*   `js/main.js` の boot 画面の `next` を `() => new BoardScene({ screen, layer: 'main', random: Math.random })` に変え、`virtualPad` を `false` にする。乱数の関数（今回は `Math.random`、種の固定はしない）を作って渡すのは `js/main.js` の役目とし、ルール層は受け取った関数だけを使う。
*   盤面のシーン `js/scenes/BoardScene.js`（`Scene` を継承）が、`init()` でルール層のゲーム（`new Game({ random })`）と画面の配置（`createLayout(...)`）を作り、`draw` で `js/view/boardView.js` の `drawBoard` を呼ぶ。
*   画面の配置（1280×720 に収める。列は最大枚数でもはみ出さない）は `js/view/layout.js` が一手に持つ。配置の目安（実装時に微調整してよい。すべて `layout.js` 内の定数）:
    *   カード: 幅 90・高さ 126、角丸。
    *   山札: 上段に横に並べる。左端 x=80、間隔 130、y=50。
    *   捨て札: 山札の列の右（x=640 付近）、y=50。
    *   列: 山札と同じ x に並べる。列の領域の上端 y=230。カードの重ねのずらし幅は既定 36 とし、`maxColumnLength` 枚を重ねた高さが「列の領域の高さ（放つボタンの上まで）」を超えるときは、ずらし幅を縮めて収める。
    *   放つボタン: 各列の下、y=600、幅 90・高さ 44。
    *   右側のパネル（x=840〜1240）: ゲージ4つを縦に並べ（名前と数値）、その下に「行動 残り / 最大」、行動を使い切ったら「行動終了」を大きく出す。

### 要件2: カードと山札の表示
*   描画の部品は責務ごとにファイルを分ける:
    *   `js/view/suitStyle.js`: スートごとの絵文字（剣 🗡️・盾 🛡️・薬 🧪・力こぶ 💪）と色、ゲージの表示名（攻撃・防御・回復・力こぶ）の対応表。スートとゲージの識別子（`'sword'` など）はルール層の設定と同じ文字列をキーにする。
    *   `js/view/cardView.js`: 1枚のカードの表（角丸の枠・スートの絵文字・数字）、空き枠（点線の枠と短い文字）、強調の枠を描く関数。
    *   `js/view/deckView.js`: 山札（一番上の1枚を表で、その下に残りの枚数を数字で。空なら空き枠と「空」）と、捨て札（枠と枚数）を描く関数。選択中の枠、「捨てる」の表示（カードの上に重ねた帯の文字）もここ。
    *   `js/view/columnView.js`: 列（下から順に重ねたカード。空なら空き枠）、置ける列の強調、放つボタン（押せる／押せないの見た目を変える。押せないときは暗い色と薄い文字）を描く関数。
    *   `js/view/hudView.js`: ゲージ4つの名前と数値、残りの行動回数、「行動終了」を描く関数。
    *   `js/view/boardView.js`: 背景を塗り、上の部品を配置に従って順に呼ぶ（盤面全体の描画の取りまとめ）。
*   山札の「表で見えるカード」と「その下の残りの枚数」は、ルール層の問い合わせ（`game.visibleCards(d)`・`game.hiddenCount(d)`）で得る。見える枚数の設定は1なので、描画は `visibleCards` の先頭の1枚を表で描く。
*   描画の関数は、受け取った状態と表示用の値を読むだけで、何も書き換えない。`ctx` を変える処理は `ctx.save()`／`ctx.restore()` で囲む。

### 要件3: 置く（タップ2回）
*   「どの山札を選択中か」（`selectedDeck: number|null`）は `BoardScene` が持つ。ルール層の状態に混ぜない。
*   入力は `BoardScene.onPointer` の `'down'` だけで受ける（boot 画面から移った直後に `'down'` のない `'up'` が届くことがあるため。`oz/ENGINE_API.md` 16章）。`Engine.addButton` は使わない（押せない「放つ」も含め、当たり判定を `layout.js` の1か所にまとめるため）。
*   `layout.hitTest(x, y)` が `{ kind: 'deck', index } | { kind: 'column', index } | { kind: 'release', index } | null` を返す。列の当たり判定は、列の領域全体（カードがなくても）とする。
*   シーンの入力の流れ（判定はすべてルール層の問い合わせを使う）:
    *   `game.isOutOfActions()` なら、選択を解除して何もしない。
    *   山札: `index === selectedDeck` のとき、`game.canDiscard(index)` なら `game.discardTop(index)` を呼んで選択解除、そうでなければ選択解除。別の山札のとき、`game.canSelectDeck(index)` なら選択をその山札に替え、選べない（空の）山札なら選択解除。
    *   列: 選択中で、`game.placeableColumns(selectedDeck)` にその列が含まれるなら `game.place(selectedDeck, index)` を呼ぶ。いずれの場合も選択解除。
    *   放つボタン: `game.canRelease(index)` なら `game.release(index)` を呼び、選択解除。押せない放つボタンは何もしない（選択も変えない）。
    *   何もない所（`null`）: 選択解除。
*   強調表示する列は、`draw` のたびに `game.placeableColumns(selectedDeck)` の結果で決める（画面の側で数字の比較を書かない）。
*   操作の結果（戻り値）は、今回は `BoardScene` の `lastResult` に保持するだけとする（Phase 2 で `js/anim/` に渡す）。

### 要件4: 置けない札を捨てる（選んで捨てる）
*   `game.canDiscard(d)`: 行動が残っていて、山札 `d` が空でなく、その一番上のカードがどの列にも置けないとき `true`。
*   「捨てる」状態の表示は、`selectedDeck === d && game.canDiscard(d)` のときに `deckView` が出す。その判定は `boardView` に渡す表示用の値（後述の `BoardUi`）としてシーンが作る。

### 要件5: 放つ
*   ゲージの計算は純粋な関数 `computeRelease(cards, config)`（`js/rules/release.js`）で行う。列の下から順に同じスートが続く区切りに分け、区切りごとに「倍率 = `config.releaseMultiplier.base + config.releaseMultiplier.perCard × 区切りの枚数`」「加算量 = 区切りの数字の合計 × 倍率」を求め、スートに対応するゲージ（`config.suitGauge`）に足す。既定は `base: 0`・`perCard: 1`（倍率＝区切りの枚数）。
    *   確認用の例: 剣5・剣4・剣3 → 攻撃 36。剣5・盾4・剣3 → 攻撃 8・防御 4。剣5・剣4・盾3・剣2・剣1 → 攻撃 24・防御 3。
*   `game.release(c)` は、列のカードをすべて捨て札に移し、`computeRelease` の加算をゲージに足し、行動回数を1減らし、補充を行って結果を返す。
*   押せない表示は `game.canRelease(c)`（行動が残っていて列が空でない）の結果で決める。

### 要件6: 山札の補充
*   `refillEmptyDecks(decks, discard, random)`（`js/rules/piles.js`）: 空の山札ごとに、捨て札からその山のスートのカードをすべて取り出して混ぜ、その山札に入れる。補充が起きた山ごとに `{ deckIndex, suit, count }` を返す。
*   `Game` の各操作（置く・捨てる・放つ）の最後に必ず呼ぶ。これにより、空のままの山札も、のちに捨て札に同じスートが入った操作の直後に補充される。

### 要件7: 行動回数
*   `Game` が `actionsMax`（`config.baseActions`）と `actionsLeft` を持つ。置く・捨てる・放つの成功時に1減らす。
*   `actionsLeft === 0` のとき、`canSelectDeck`・`canDiscard`・`canRelease` は `false`、`placeableColumns` は空配列を返し、`place`・`discardTop`・`release` は何もせず `null` を返す。`isOutOfActions()` で問い合わせる。

### 要件8: 調整値と乱数
*   `js/rules/config.js` の `RULES`（凍結したオブジェクト）に集める:
    *   `suits`: `['sword', 'shield', 'potion', 'muscle']`（山札の並び順）
    *   `minRank: 1`・`maxRank: 7`
    *   `columnCount: 4`
    *   `visibleCount: 1`
    *   `baseActions: 5`
    *   `gauges`: `['attack', 'defense', 'heal', 'muscle']`（ゲージの並び順）
    *   `suitGauge`: `{ sword: 'attack', shield: 'defense', potion: 'heal', muscle: 'muscle' }`
    *   `releaseMultiplier`: `{ base: 0, perCard: 1 }`
*   ゲーム開始時に各山札を `shuffle(array, random)`（`js/rules/shuffle.js`、Fisher–Yates）で混ぜる。列と捨て札は空で始め、ゲージは0で始める。

### ルール層のデータ構造（JSDoc の `@typedef` で書く）
*   `Card`（`card.js`）: `{ id: number, suit: string, rank: number }`。後でフィールドを足せるようオブジェクトにする。
*   `Deck`（`piles.js`）: `{ suit: string, cards: Card[] }`。`cards[0]` が一番上。
*   捨て札: `Card[]`（`Game.discard`）。
*   列: `Card[]`（`Game.columns[c]`）。`[0]` が一番下、末尾が一番上。
*   ゲージ: `Object<string, number>`（`Game.gauges`。キーは `config.gauges` の順に作る）。
*   `Refill`（`piles.js`）: `{ deckIndex: number, suit: string, count: number }`。
*   `ReleaseSegment`（`release.js`）: `{ suit, gauge, cards: Card[], sum, count, multiplier, amount }`。`ReleaseCalc`: `{ segments: ReleaseSegment[], gains: Object<string, number> }`。
*   操作の結果（`Game.js`）:
    *   `PlaceResult`: `{ type: 'place', deckIndex, columnIndex, card, actionsLeft, refills: Refill[] }`
    *   `DiscardResult`: `{ type: 'discard', deckIndex, card, actionsLeft, refills: Refill[] }`
    *   `ReleaseResult`: `{ type: 'release', columnIndex, cards: Card[], segments: ReleaseSegment[], gains, actionsLeft, refills: Refill[] }`

### 画面の側のデータ構造
*   `Layout`（`layout.js`）: `decks[]`・`discard`・`columns[]`（各列の領域と `step`（ずらし幅））・`releaseButtons[]`・`hud`（ゲージ・行動回数・行動終了の位置）・`card`（幅と高さ）・`screen` と、`hitTest(x, y)`。
*   `BoardUi`（`boardView.js`）: シーンが `draw` のたびにルール層の問い合わせから作る表示用の値。`{ selectedDeck: number|null, discardMode: boolean, placeableColumns: number[], releasable: boolean[], outOfActions: boolean }`。

## 5. 懸念事項・要確認ポイント
* 計画時点の気づき: `js/` に、`PROJECT_ARCHITECTURE.md` 1章の構造にない空のフォルダ `js/effect/`・`js/entities/` がある。今回は触らない（削除もしない）。
* 計画時点の気づき: スートの絵文字（🗡️ は異体字セレクタ付き）は OS・ブラウザのフォントにより見え方が変わる。読みにくい場合は `js/view/suitStyle.js` の対応表だけを替える（替えた場合はここに記載する）。
* タスク2の注意点: `refillEmptyDecks` は捨て札に該当スートが無い空の山札を補充せず `Refill` も返さない（Game 側は毎操作の最後に呼ぶ前提）。`takeTop` は `shift()` のため `cards[0]` が一番上の前提。
* 計画時点の判断: 「押せない放つボタン」を押したときは、選択を変えない（REQ は「ボタン以外の場所」で解除とするため、ボタンは解除の対象外と解釈した）。空の山札をタップしたときは「選べない」ため選択を解除する。
