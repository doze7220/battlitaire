# RES: 作業計画・作業レポート (Phase 07-04a) : ★1の敵の追加（狼・猪・骸骨・スライムと並びの決まり）
* 参照元REQ: `./_log/req/261125_2154_Phase07-04a_★1の敵の追加.md`

## 1. 作業目的
★1の敵に、狼・猪・骸骨・スライムの4種を足し、敵の並びに「同じ敵・同じ動きを続けない」決まりを入れる。

* 行動の決まりを2つ足す（溜めて大攻撃＝狼・猪／攻撃か防御のどちらか＝骸骨・スライム）。狼と猪・骸骨とスライムの違いは、数値と表だけにする。
* ★1 のステージの並びを、種とステージの番号から直接求められるまま、同じ敵・同じ動きが隣り合わない形にする。
* 予告・見た目・動き（駆け寄る攻撃、骸骨の群れ、スライムのへこみと縮み）・音・DEBUG タブを、新しい敵に合わせる。
* ゴブリン・巨人・ドラゴンの数値・動き・見た目・乱数を呼ぶ順と回数は変えない。

### 要件1: 敵の種類と数値（ルール層）
* **設定（`config.js`）**: 並びは ゴブリン・狼・猪・骸骨・スライム・巨人・ドラゴン（DEBUG タブの並びになる）。4種とも `star: 1`。4種は `defense`（行動と別に毎ターン抽選する防御）を持たない。`EnemySpec.defense` を任意の項目にし、JSDoc に「行動と別に防御を抽選する敵だけが持つ」と書く。

| --- | --- | --- | --- |

| `boar` | 猪 | 44 | `type: 'buildup'`, attackRange 1〜2, heavyRange 13〜16, chargeChance 0.3, chargeTurns 2 |

| `slime` | スライム | 40 | `type: 'either'`, attackChance 0.4, attackRange 2〜3, guardRange 2〜4, bigGuardChance 0.2, bigGuardRange 5〜7 |

* **行動を作る関数（`enemyBehaviors.js`）**: 追加・export するのは次の4つ。ふつうの攻撃は今の `steadyAttackAction`（`attackRange` を読むだけ）を使い、JSDoc を「毎ターン攻撃の決まり・溜めて大攻撃・攻撃か防御の決まりで共通」に直す。
    * `chargeAction()`: `{ kind: 'windup', amount: 0, variant: 'charge' }`（乱数なし）
    * `heavyAction(behavior, random)`: `{ kind: 'attack', amount, variant: 'heavy' }`（乱数1回）
    * `guardAction(behavior, random)`: `{ kind: 'guard', amount: 0, guard }`（乱数1回）
    * `bigGuardAction(behavior, random)`: 同じ形に `variant: 'bigGuard'`（乱数1回）
* **決まり `buildup`**: 状態 `{ turnsToHeavy: number|null, chargeTurns: number }`。`turnsToHeavy` は「その予告のターンから大攻撃まであと何ターンか」（`null`＝溜めていない、0＝大攻撃のターン）、`chargeTurns` はその溜めの長さ（溜めていなければ 0）。初期値は `turnsToHeavy: null`・`chargeTurns: 0`。
    * `planNext`: `turnsToHeavy` が 2 以上 → 1 減らして `chargeAction`。1 → 0 にして `heavyAction`。0（直前が大攻撃）→ 溜めていない状態にして攻撃（溜める抽選はしない）。`null` → `random() < chargeChance` なら `turnsToHeavy`・`chargeTurns` とも設定の `chargeTurns` にして `chargeAction`、外れれば溜めていない状態のまま攻撃。
    * 乱数: 溜めていないターンは溜める抽選1回（外れれば量1回が続く）／溜めの続き 0 回／大攻撃 1 回／大攻撃の次 1 回。
    * `countdown`: `chargeTurns >= 2` かつ `turnsToHeavy >= 1` なら `turnsToHeavy`、そうでなければ `null`（狼・大攻撃のターン・溜めていないターンは添えない。猪の1ターン目「あと2」・2ターン目「あと1」。既存の `countdownText` のまま）。
    * `isState`: プレーンなオブジェクトで、`turnsToHeavy` が `null` か 0 以上の整数、`chargeTurns` が 0 以上の整数。`isOpening`: 常に真（防御 0。防御の乱数も呼ばない）。
* **決まり `either`**: 状態 `{}`。`planNext`: `random() < attackChance` なら攻撃（量1回）。外れたら `random() < bigGuardChance` なら `bigGuardAction`、外れれば `guardAction`（量1回）。`countdown` は `null`、`isState` はプレーンなオブジェクト、`isOpening` は `kind === 'attack'`。
* **予告（`enemyIntent.js` の `createIntent`）**: 行動が `guard`（加算の前の防御の量。`EnemyAction` の任意の項目）を持つときは、防御の抽選をせず `baseDefense = guard + bonus.defense`。持たないときは今のとおり（隙なら 0、そうでなければ `rollDefense`。`spec.defense` のない敵は抽選せず 0）。予告には `guard` を残さない（`const { guard, ...rest } = action`）。攻撃の加算は今のまま `kind === 'attack'` のときだけなので、防御だけのターンには乗らない。加算を足すのはここ1か所・疲弊は `fatiguedDefense` の1か所のまま（大防御も同じ道を通る）。`guard` を持たない行動の乱数の呼び方は今と同じ。
* **攻防（`battle.js`）**: `kind === 'guard'` は `enemyAttack = 0` で、出来事 `enemyGuard`（量 0）を1つ入れる（`enemyWindup` と同じ扱い）。`enemyDefend` 以降は今のまま。型と JSDoc を直す。`gameStats.js` は変えない（`rollAttackHeal` は `kind === 'attack'` だけなので対象外）。`Game.js` は処理を変えず、`planIntent` と `intentOf` の JSDoc の乱数の説明だけを直す（「隙でなければ防御の抽選で乱数を2回」が、行動が `guard` を持つときと `spec.defense` のない敵では合わなくなるため。防御の抽選は「行動が防御の量を持たず、敵が防御の設定を持ち、隙でないときだけ」とし、決まりごとの使い方は `enemyBehaviors.js` に従う、と書く）。
* **中断データ（`suspendData.js`）**: `SUSPEND_VERSION` を 2 に。`isIntentShape` の `kind` に `'guard'` を足す（知っている種類の凍結の並びにする）。`combatants.js` の型（`kind`・`variant`・`guard`・`behaviorState` の説明）を直す。
* **デバッグ（ルール層）**
    * `debugIntents.js`: `buildup` は ids `['attack', 'charge', 'heavy']`。`attack` → 溜めていない状態、`charge` → 溜めの1ターン目の状態、`heavy` → `turnsToHeavy: 0`・`chargeTurns` は設定の値。`chosen` は `variant` が `'heavy'`・`'charge'` ならそれ、なければ `'attack'`。`either` は ids `['attack', 'guard', 'bigGuard']`、状態 `{}`。`chosen` は `kind` が `'attack'` なら `'attack'`、`variant` が `'bigGuard'` なら `'bigGuard'`、ほかは `'guard'`。
    * `debugRuleItems.js`: `BEHAVIOR_ITEMS` に2つ足す（最大 HP の後に、下の順で並べる）。`defenseItems` は、その敵が `defense` を持つときだけ足す。「27 個」「3体共通」などの古い説明を直す。
        * `buildup`: 攻撃の幅・大攻撃の幅（`T.heavy`。種類 `amount`・名前 `heavyMin`／`heavyMax`）・溜める確率（`T.chargeChance`。種類 `chance`・時期 `nextIntent`）・溜めのターン数（`T.chargeTurns`。種類 `chargeTurns`・時期 `nextCharge`）。
        * `either`: 攻撃する確率（`T.attackChance`）・攻撃の幅・防御の幅（`T.guard`。種類 `defense`・名前 `defenseMin`／`defenseMax`）・大防御の確率（`T.bigGuardChance`）・大防御の幅（`T.bigGuard`。種類 `defense`・名前 `bigGuardMin`／`bigGuardMax`）。

### 要件2: 敵の並び
* **動き** は `behavior.type` の組。`enemyTypes.js` に `enemyMotionsOfStar(config, star)`（その★の敵を `behavior.type` ごとに、書いた順でまとめた配列の配列）を足す。決まりは★の値によらず同じ式で求め、動きが1つの★（今の★2・★3）では今のまま同じ敵が続く（★ごとの if は書かない）。
* **何番目か（`stageOrder.js`）**: `starPositionOfStage(stageStars, stageNumber)` は、そのステージが同じ★の中で何番目か（0 から）。倍数の最小公倍数を周期に、`floor(N / 周期) × 周期の中の数 + 端の数` で求める（前のステージの敵は計算しない）。★1 では 5・10 のステージを飛ばして数えるので、4 と 6 は続いた番号になる。
* **動きの並び（`motionOrder.js`）**: `motionIndexAt(seed, position, motionCount)`。動きの数 M ずつの組に分ける（組 b = floor(position / M)、組の中の s = position % M）。
    * 組の最後の動き `last(b)` = `seededIndex(seed, STREAM.last, M >= 3 ? b : 0, M)`（M が 2 なら種だけで決まる一定の値＝交互になる）。M が 1 なら答えは 0。
    * 組の最初の動き `first(b)` = `last(b)` と `last(b − 1)`（b が 0 ならなし）を除いた候補から `seededIndex(seed, STREAM.first, b, 候補の数)` で選ぶ。
    * 残りは `seededIndex(seed, STREAM.middle, …)` の並べ替えで真ん中に置く。
    * これで、組の中は M 個が1回ずつ（ステージ 1〜3 も）、組の境目でも続かず、隣の組の端だけを直接求めれば済む。
* **同じ動きの中の敵** は `seededIndex(seed, STREAM.member, stageNumber, 数)`。動きが隣り合わないので、同じ敵も隣り合わない。
* **`seededIndex.js`**: `seededIndex(seed, stream, number, count)`。今の `mix32` を使い、用途の鍵 `stream` を混ぜて、用途ごとに別の列にする。鍵の表 `STREAM` は同じファイルに凍結して持つ（混ぜ合わせの値で、ルールの数値ではない）。`stageOrder.js` の今の `mix32`・`seededIndex` はここへ移す。混ぜ方は `h = mix32(mix32(mix32(seed ^ 0x9e3779b9) + imul(stream, 0x9e3779b1)) + imul(number + 1, 0x85ebca77))`、値は `floor(h / 2^32 × count)`。
* 計画時の試し（一時スクリプト。削除済み）: 10 年分（月 1〜28 日）× ステージ 1〜500 で、隣り合う同じ敵・同じ動き 0 件、1〜3 の動きは3種1回ずつ、動きの数の比 1:1:1（差 0.03% 以内）、同じ動きの2種の比 1:1（差 0.1% 以内）、1〜3 の動きの順の6通りがほぼ等しい、続く日付で並びが同じ 0 件。M が 2・4・5 でも隣り合わない。
* 途中のタスクで★1 の動きの数が 2 のときは交互に、3 になるとステージ 1〜3 に1回ずつになる（数によらず式は同じ）。

#### 絵の敵の配置（`enemyFigures.js`）
* `layout.js` の `ENEMY_FIGURES`・`EnemyFigure`／`IntentSpot` の型・`enemyFigures` の組み立てを移し（式と巨人・ドラゴンの値は同じ）、`createEnemyFigures({ groundY, centerX, maxHeight, intentTop, badgeH, healTextRatio })` を export する。`layout.js` は呼ぶだけにし、`layout.js` の定数は引数で渡す。表に次の項目を足す。

#### 体の大きさ（`figureScale.js`。スライム）
* `bodyScale(minScale, hp, maxHp)` = `minScale + (1 − minScale) × (hp / maxHp を 0〜1 に収めた値)`（`minScale` が 1 ならちょうど 1）。足元（矩形の下端の中央）を軸に縮む。
* `scaledX(figure, x, scale)`（絵の中心から倍率をかけた x）・`scaledShieldArea(figure, scale)`（**中心だけ**足元から倍率をかけて動かし、幅・高さは変えない。マークが小さくならず、焼き付けの大きさも変わらない）・`scaledIntentY(figure, scale)`（`intent.y + rect.h × (1 − scale)`）。
* 描画: `enemyView.js` は表示中の HP から倍率を求め、`applyFootPose` に重ねる（段取りの間は `enemy.hp`・`enemy.maxHp`、攻防の間は `battleShowView.js` が `look.enemyHp` と `game.enemy.maxHp` を渡す）。`intentView.js` は札と数え下ろしの高さを `scaledIntentY` にする。
* 攻防: `BattleSnapshot` に `enemyMaxHp` を足し、`createEnemyBody` へ渡す。シールドの並び・シールドに当たる位置・駆け寄りの始めの位置は、攻防の前の HP の倍率（シールドがある間は HP が減らない）。体に当たる位置は、k 体目の兵が「その前の表示 HP（`state.enemyShown − k`）」の倍率の位置へ着く（`chargeTo` の `targetX` を、数か `(k) => x` の関数のどちらでも受けられるようにする）。当たりの光・「-1」は兵の終わりの位置から記録されるので付いてくる。

#### スライムのへこみ（`figureDent.js`）
* `dentAmount(times, clock, fallAt)` は、1回ぶんの和を 1 で頭打ちにした量に、倒れ始めの手前で消す倍率（下の「倒れるとき」）をかけたもの。1回ぶんは、当たりから `dentInMs` かけて 0→1、`dentOutMs` かけて 1→0（どちらも滑らかな `u²(3−2u)`）。続けて当たる間（今の間隔 80ms 以下）は 1 に張り付いたまま（震えない）、離れた1回は短くへこんで戻る。`applyDent(times, clock, fallAt, pose)` が、`pose.scaleY` に `1 − dentSquash × 量`、`pose.scaleX` に `1 + dentWiden × 量` をかける。
* 値は `BATTLE_ANIM` に `dentInMs: 60`・`dentOutMs: 220`・`dentSquash: 0.18`・`dentWiden: 0.08`。計画時の試し（戻り 180ms で計算）: 間隔 80ms 以下でへこみの量の揺れは 4% 以内（体の縦で約 0.7%）。戻りを 220ms にすると揺れはさらに小さい。
* 当たりの時刻は `enemyBody.js` の `hitEnemyBody` が（体に当たった兵だけ。シールドに当たった兵は入れない）記録する。重ねるのは `battleDirector.js` の `sampleLooks`（`sampleFigurePose` の後）。
* **倒れるとき**: 倒れ方は今の絵の敵と同じ（倒れる記録・時刻は変えない）。今の待機の伸び縮みと同じく、**倒れ始めた後（`clock >= fallAt`）はへこみを重ねない**（量はちょうど 0）。
    * 倒れ始めの時刻 `fallAt` は `max(最初の当たり + hpMs, 最後の当たり)` なので、続けて当たって倒すと最後の当たりと同じ時刻になる。倒れ始めで急に 0 にすると、へこんだ体（縦 0.82 倍）が一瞬で元の形に戻ってとぶ。そこで、倒れ始めの手前の `dentOutMs` の間、量に倍率 `u²(3−2u)`（`u = (fallAt − clock) / dentOutMs` を 0〜1 に収めた値）をかけ、`fallAt` でちょうど 0 になるようにする。これで、へこみは倒れる動きの頭に重ならず、体の形もとばない。倒れ始めと同じ時刻の当たりのへこみは出ない。
    * `fallAt` は、倒れない攻防では `null`（倍率 1）。`enemyBody.js` に、倒れ始めの時刻を返す `enemyFigureFallAt(body)`（群れ・倒れる記録のない絵は `null`）を足して読む。記録は時間割を組むときに入るので、時計だけから求められる。
    * 体の大きさ（縮み）は、HP の表示値が `fallAt` までに 0 になって止まるので、倒れる間は `minScale` のまま変わらない（とばない）。

## 5. 懸念事項・要確認ポイント
* 予告の札の高さは、背の低い3種（狼・猪・スライム）だけ、絵の上端から 30px 上にした（今までは「どの敵でも同じ高さ」。そのままだと体から約 100px 離れて見えるため）。巨人・ドラゴン・群れは変えない。
* 駆け寄りは、防御の兵を倒しきって城にも打撃が届くときだけ、城の前までもう一度詰める（防御の兵がいた所から離れた城を打つように見えるのを避けるため）。詰めない方がよければ、`dashSteps.js` で2つ目の `dash` を入れないだけで済む。
* スライムのシールドは、体が縮んでもマークの大きさを変えず、並べる範囲の中心だけを体に合わせて下げる（小さくすると数が読めないため）。半分まで縮んだときは、マークの並びが体とほぼ同じ幅になる。
* スライムのへこみは、体に当たった兵だけで起こす（シールドに当たった兵では起こさない）。80ms 以下で続けて当たる間はへこんだままで、最後の1体の後に戻る。倒すときは、倒れ始めの手前の 220ms でへこみが戻っていき、倒れ始めた後は重ねない（最後の一撃のへこみは出ない）。
* 防御だけのターンが疲弊で 0 になったときは「防御 0」の札になる（札が空にならないようにするため）。
* 動き A の「溜めのターン数」を DEBUG で変えても、今の溜めの残りは変わらず、次の溜めから効く（数え下ろしも、溜めに入ったときの長さで出す）。
* 敵の並びの種の混ぜ方が変わるので、今の版と同じ日付でも、★の中の選び方の値は変わる（今は★ごとに1種なので、出る敵は変わらない）。
* 駆け寄りの分だけ、狼・猪・スライムの攻撃のターンの攻防が約 1〜2 秒長くなる（`DASH_STYLES` の値で調整する）。
* 仮のスプライトの見分け・駆け寄りの重なり・へこみと縮みの見え方は、実際の画面での目視が必要。
* （タスク1）`EnemySpec.defense` を任意にしたので、`spec.defense` を直接読む他のファイル（`debugRuleItems.js` など）は、タスク4・敵を足すタスクで `defense` なしを扱うこと。いまの3種は全部持っているので動作は変わらない。
* （タスク2）`enemyTypeIdOfStage` は `config.enemies[*].behavior.type` を読むようになった（`enemyMotionsOfStar`）。敵の設定は必ず `behavior.type` を持つこと。
* （タスク4）敵が3種の今は敵の切り替えが2段になり、それより下の部品が1段ぶん（104px）下がる。新しい項目（`buildup`・`either` の項目、`chargeTurns` のスライダー）はまだ敵がいないため実物では確かめていない（タスク10・12で確かめる）。DEBUG タブの段の見た目は目視が必要。
