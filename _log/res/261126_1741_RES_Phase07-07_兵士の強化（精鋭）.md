## 1. 作業目的
3択の強化に枠「兵士」の強化を足し、放った兵に強い兵（精鋭）が混じるようにする。

* 兵士の強化: 「精鋭の確率」（剣・盾・ハンマーごと。1回 5〜10%・上限 50%・上限の手前は実際に増える分）と「精鋭の能力 +1」（剣・盾・ハンマーごと。上限なし。そのスートの確率が 0% の間は出ない）。精鋭1体のポイント = 1 + 能力（能力の初めの値は +1）。3択は4つの枠（城・兵士・カード・特別。重み 1・1・1・0.5）から3つを選ぶ形になる。
* 精鋭の抽選: 放った時点で、カードから出る剣・盾・ハンマーの兵と4スートそろいで足された剣・盾・ハンマーの兵を1人ずつ抽選する（金貨・自動兵士は対象外。確率 0 では乱数を呼ばない）。ゲージは「人数 + 精鋭の上振れ（精鋭の数 × 能力）」で、攻防の計算（`computeBattle` の合計の引き算）は変えない。
* 見た目と演出: 精鋭は体の円の内側を青く塗る（焼き付けも作る）。陣地にその区切り・4スートそろいの精鋭の数だけ青い兵が現れ、攻防ではふつうの兵が先・精鋭が後に当たり、精鋭は自分のポイントを1回の当たりで使う（敵に当たると「-2」など）。人数の表示は「人数 + 上振れ」をオレンジにし右下に小さく「+◯」を出し、枠を右へ広げる。山札の左下に「◯20%（+2）」を出す。
* 中断データ（版 5）・3択の選択肢の文字（9〜10% は金色）・「強化」タブ・DEBUG タブ（スライダーで精鋭が消える・ボタンの列・古い言い方）を合わせる。
* 敵・ステージの加算・疲弊・1ターンの流れ・3択の画面の流れ・ほかの枠の強化は変えない。**強化を取らないゲームでは、放つ量・攻防の結果・予告・乱数の呼び出し（3択の抽選の分を除く）が変更の前と同じ。**

* **強化の種類の識別子・スートの識別子で分岐する if は書かない。** 種類で引く表は `config.upgrades`・`UPGRADE_EFFECTS`（効き方で引く）・`UPGRADE_TEXTS` だけ。新しい効き方は `UPGRADE_EFFECTS` に2行を足し、足りない口（`eliteChance`・`elitePower`）は表と `EFFECT_DEFAULTS` に足す（今の行は既定を広げているので、同じ口を自動で持つ）。どのゲージの精鋭かは設定の `gauge` で表し、精鋭の能力が確率を取った後だけ出るのは設定の `requires`（強化の識別子）で表す。
* **強化で変わる値は `config.js` を書き換えない。** 確率・能力は `game.upgrades` から求め（`eliteStatusOf`）、引いた精鋭の数と上振れは新しい状態 `game.elites` に持つ。
* **ルールと画面の分離:** 精鋭の確率・能力・抽選・精鋭の数・上振れ・ゲージの値はルール層で決める。画面と演出は `game.eliteStatus()`・`game.eliteBoost()`・`release` の結果の `elites` を読んで見せるだけ（画面の側で確率から数を作らない）。演出の当たる順・「-N」・青は結果を変えない（ゲージ・HP・決着はルール層の値のまま）。
* **乱数:** 新しい抽選はプレイ用の乱数（`game.random`）だけ。精鋭の抽選は確率が 0 より大きいゲージの兵だけ1人1回で、確率 0 では呼ばない（強化を取らないゲームの乱数の並びは変わらない）。3択の値の抽選は効き方の `roll`（精鋭の確率は1回、精鋭の能力は呼ばない）。
* 数値はルールが `config.js`、配置が `js/view/` の定数（`layout.js`・`troopCountView.js`・`deckView.js`・`upgradeText.js`）、色が `eliteStyle.js` ほかの view の定数。動きの時間（`js/anim/` の設定）は足さない・変えない（精鋭はふつうの兵と同じ大きさ・同じ動き）。

#### 区切りの順（REQ の目安の順から変えた所）
REQ の目安の順（ルール層 → 中断データ → 文字 → 人数の表示 → 山札の角 → 見た目 → 陣地 → 攻防の演出 → DEBUG）のままでは、次の2つで途中のプレイが壊れるため、順を変える。
1. 強化の種類を一覧に足すと、3択・「強化」タブ・DEBUG タブがすぐ文字の表を引く（表にない識別子は Error）。→ **一覧に足す強化の文字の行はタスク1で一緒に足し**、金色の部分と文字の収まりだけをタスク7に残す。
2. ルール層で精鋭を引くとゲージが人数より大きくなり、攻防の時間割（待っていた兵の数がゲージと同じか確かめる・ポイントで消し合う）が Error になる。→ **攻防の演出の土台と当たり（タスク2・3a・3b。精鋭のいないゲームでは今と同じ時間割）を、抽選を入れる前に作り**、**ルール層の抽選と陣地への受け渡しを1つのタスク（タスク5）にまとめる**（抽選が入った時点で、陣地の精鋭と攻防への引き継ぎがそろう）。

この順で、どのタスクの終わりでも、強化を取らないゲーム・取ったゲームとも起動とプレイが壊れない（タスク1〜4の間は精鋭の強化を取っても精鋭が出ないだけ）。攻防の演出は「土台（名簿の精鋭・引き継ぎ・相打ち・人数の値）」（タスク2）、「防御・修理の側の当たり（打撃・修理）」（タスク3a）、「攻撃の側の当たり（敵・シールド・「-N」）」（タスク3b）の3つに分ける（REQ の「攻防の演出は大きいので、さらに分けられないか検討する」への答え）。3a・3b はどちらも精鋭のいない攻防を今と同じに保つので、どちらの終わりでも起動とプレイは壊れない。3b の `chargePoints` は 3a の `spendFromFront` を使うので、3a → 3b の順に行う。

* **`js/rules/upgradeEffects.js`**:
    * 型 `UpgradeEffect` に口を2つ: `eliteChance(spec, taken) → Object<string, number>`（ゲージ → 精鋭になる確率の百分率）・`elitePower(spec, taken) → Object<string, number>`（ゲージ → 精鋭の能力の足し分）。`EFFECT_DEFAULTS` に `eliteChance: () => ({})`・`elitePower: () => ({})`。
    * 型 `UpgradeTarget` に `eliteStatus: () => Object<string, import('./upgradeBoosts.js').EliteStatus>`（ゲームの問い合わせ。効き方の `status`・`preview` が読む）。
    * 行 `eliteChance`（`actionChance` と同じ形）: `canOffer: taken.amount < spec.maxPercent`・`isCapped: taken.amount >= spec.maxPercent`・`roll: Math.min(rollAmount(spec.range, random), spec.maxPercent - taken.amount)`（乱数1回）・`fixedValue: Math.min(spec.range.min, spec.maxPercent - taken.amount)`・`eliteChance: { [spec.gauge]: taken.amount }`・`preview: { before: taken.amount, after: taken.amount + value }`・`status: { shown: true, value: taken.amount, limit: game.eliteStatus()[spec.gauge].power }`（「強化」タブの1行に確率と能力を並べる）。取った記録の `amount` がそのまま確率の百分率。
