## 1. 作業目的
ステージの★（1〜3）を、ステージの番号の倍数（10 の倍数が★3、5 の倍数が★2）で決めるのをやめ、**ステージごとの抽選**で決める。強敵（★2・★3）の間隔を 2〜4 ステージほどに縮め、ときどき強敵が2連続する、間隔の読めない並びにする（狙い: ザコ（★1）が続きすぎて間延びするのをなくす）。

* 抽選は先に★3、外れたら★2、どちらも外れたら★1。★3の確率は★3が出た次のステージで 0%、その後1ステージごとに 8% 上がり、★3が出たら 0% に戻る。★2の確率は★2・★3が出た次のステージで 0%、その後1ステージごとに 30% 上がり（100% で頭打ち）、★2・★3が出たら 0% に戻る。ゲームの始まりは★2・★3が出た直後とみなす（ステージ 1 はかならず★1、ステージ 2 は★3 8%・★2 30%）。
* 抽選の乱数は日付の種から求める（プレイ用の乱数は使わない）。同じ日付なら、誰が何度始めても・DEBUG で途中のステージへ移っても・中断から再開しても、同じ並び。
* 同じ★の中の動き・敵の選び方（07-04a の「同じ敵・同じ動きを続けない」）はそのまま使い、何番目かは抽選で決まった★の並びから数える。最初に出る★2は巨人、★3はドラゴン（設定の「最初の1体」で決め、P8 で種類が増えても守られる）。
* 数値はすべて `config.js` に置き、★の識別子・敵の種類の識別子で分岐する if は書かない。
* DEBUG タブに先の 20 ステージの並びの一覧と、★3・★2の上がる量のスライダーを足す。
* **敵の数値・動き・見た目、ステージの加算と疲弊、攻防、強化、スコア、1ターンの流れ、ほかの機能は変えない。中断データの形と版（8）は変えない。**

### 要件1: ★の抽選（ルール。タスク1）
* **設定の形**（`config.js`。`stageStars` を置き換える。タスク1では `multiples` を残したまま `draws` を足し、タスク2で `multiples` を消す）:
  ```js
  stageStars: Object.freeze({
    base: 1,
    draws: Object.freeze([
      Object.freeze({ star: 3, risePercent: 8, resetBy: Object.freeze([3]), first: 'dragon' }),
      Object.freeze({ star: 2, risePercent: 30, resetBy: Object.freeze([3, 2]), first: 'giant' }),
    ]),
  }),
  ```
  * `base`: どの抽選にも外れたステージの★（1）。
  * `draws`: ★の抽選の並び（**書いた順に抽選し、最初に当たった★にする**）。1行は `star`（当たったときの★）・`risePercent`（1ステージごとに上がる確率の量。百分率の整数）・`resetBy`（この★の確率を 0% に戻す★の並び。出たステージの次が 0%）・`first`（任意。その★で最初に出る敵の種類の識別子。使うのはタスク2）。
  * 型 `StarDrawSpec`（`star`・`risePercent`・`resetBy`・`first?`）と `StageStarsSpec`（`base`・`draws`）の JSDoc。`Rules.stageStars` の説明を「ステージの★の抽選の決まり」に。先頭の説明の「ステージごとの★の決まり」を「ステージの★の抽選の決まり（上がる量・戻る★・最初の1体）」に直す。
  * ★の数の並び（★3・★2・★1）・上がる量・どの★で戻るか・最初の1体が設定だけで決まり、★の識別子で分岐する if は書かない（`draws` を順に回し、`resetBy.includes(star)` で戻すかを決める）。
* **抽選の決まり**（`starDraw.js`）:
  * 抽選ごとに「戻ってからのステージ数」`steps[i]`（始まりは全部 0。ゲームの始まりは★2・★3が出た直後とみなす）を持つ。
  * ステージ n の抽選: `draws` を書いた順に、確率 `chance = Math.min(PERCENT, risePercent × steps[i])`（整数）で、`seededIndex(seed, STREAM.star, (n − 1) × draws.length + i, PERCENT) < chance` なら当たり（★ = `draws[i].star`）。当たったらそこで止める（後の抽選は引かない）。どれも外れたら `base`。
  * 抽選の後、各 i について `steps[i] = draws[i].resetBy.includes(star) ? 0 : steps[i] + 1`。
  * `PERCENT = 100` は百分率の分母（100% で頭打ち。ルールの調整値ではない単位の定数）として `starDraw.js` に JSDoc 付きで置く。確率も抽選も整数どうしの比べで、浮動小数の誤差で並びが変わらない（`seededIndex` は今の作りのまま 0〜99 の整数を返す）。
  * これで、ステージ 1 は `steps` が 0 なのでかならず★1、ステージ 2 は★3 8%・★2 30%。★3は★3の次で 0%、★2は★2・★3の次で 0%、★2が出ても★3は戻らない（★2 → ★3 の2連続がありうる）。
  * 「同じ★の中の何番目か」（0 から）: ★ごとの出た数（`Map`）を数え、ステージ n の何番目かは n より前の同じ★のステージの数。間に別の★を挟んでも続けて数える（今と同じ）。
* **口**: `starDrawAt(stageStars, seed, stageNumber)` → `{ star, position }`。`stageNumber` が 1 以上の整数でなければ Error。ルール層の外のもの（`oz`・画面・`Math.random`・日付）は import も参照もしない。import は `seededIndex.js` だけ。
* **求め方と覚えておき方**（ステージ 1000 ほどまで重くならない速さ）:
  * ステージ 1 から順に抽選する（前のステージの結果で確率が変わるため）。1ステージは抽選 1〜2 回（`seededIndex`）と足し算だけ。
  * 求めた並び（★の並び・何番目かの並び・その先へ伸ばすための `steps` と★ごとの数）を **1つだけ** モジュールの中に覚える。鍵は種と決まりの値（`seed`・`base`・`draws` の `star`・`risePercent`・`resetBy`）をつないだ文字列で、呼ぶたびに今の値から作る。鍵が同じで、覚えた並びが足りなければ続きから伸ばし、足りていれば覚えた値を返す。鍵が違えば（別の種・DEBUG で上がる量を変えた）ステージ 1 から求め直す。
  * 覚えるのは計算の結果の写しだけで、答えは引数だけで決まる（同じ種・決まりの値・番号には、いつ・どの順で呼んでも同じ★と何番目かを返す）。覚えた配列は外へ渡さない（`{ star, position }` の値だけを返す）。このことをファイル先頭の責務と JSDoc に書く。覚えた並びは、DEBUG の一覧の `label` など描く中から呼ばれても伸びたり作り直されたりするが、計算結果の写し（キャッシュ）でありゲームの状態ではない。更新しても答えは引数だけで決まり変わらないので、憲法 3章「`draw` の中で状態を変更してはならない」には当たらない。
  * DEBUG の一覧は描くたびに 20 行を引くので、覚えておくことで1行は配列を引くだけになる。
* **用途の鍵**: `seededIndex.js` の `STREAM` に `star: 5`（★の抽選。混ぜ合わせの値でルールの数値ではない）を足し、型の JSDoc を直す。今の `member`・`last`・`first`・`middle` の値は変えない（★の中の動き・敵の選び方の列は今と同じ値を返す）。
