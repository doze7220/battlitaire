# RES: 作業計画・作業レポート (Phase 02-02) : カードの動き
* 参照元REQ: `./_log/req/261111_2313_Phase02-02_カードの動き.md`

## 1. 作業目的
02-01 までは、段取りの操作（置く・捨てる・手札に入れる・手札から置く・束を移す・放つ）の結果で、盤面が一瞬で切り替わる。今回は、その結果をカードの動きで見せる。カードが元の位置から先の位置へイージング付きで動き、山札の新しい一番上が裏から表へ返り、放ったときはカードが1枚ずつ捨て札へ飛びながらゲージの数字が数え上がる。動きの時間の値は `js/anim/` の設定のファイル1か所で変えられるようにし、動いている間は盤面のタップを受けない。

ルール層（`js/rules/`）は変えない。ルール層の操作は今までどおり一度に結果を決め、動きはその結果（`js/rules/planningResults.js` の型）と、操作の前後にシーンが読める状態だけから作る。動きの途中の盤面は「操作後のルール層の状態」＋「動きの見た目の値（隠すカード・飛んでいるカード・めくれ・ゲージの表示値）」で描く。攻防の演出・兵・効果音・早送り・スキップ・ドラッグ操作は作らない（02-03 以降）。

### 要件1: カードが元の位置から先の位置へ動いて見える
* **1枚の移動（`js/anim/cardTween.js`）**: 「カード・元の矩形・先の矩形・開始の遅れ（delay）・かかる時間（duration）・先の種類（`'column'|'hand'|'discard'`）」を持つデータ `CardTween` を作る関数と、動きの時計の値（ms）から見た目を求める関数を持つ。
    * `createCardTween({ card, from, to, delay, duration, dest })` → `CardTween`（`from`・`to` は `Rect`（`{x,y,w,h}`））。
    * `sampleCardTween(tween, clock)` → `{ x, y, w, h, arrived }`。`t = clamp01((clock − delay) / duration)`、位置は `from` から `to` への `easeOutCubic(t)` の補間。`clock < delay` のときは `from` にいる（`arrived: false`）。`clock ≥ delay + duration` で `arrived: true`。
    * `cardTweenEnd(tween)` → `delay + duration`。
* **操作ごとの元と先（`js/anim/planningMotion.js` が組み立てる）**。`n` は束の枚数、`L` は操作後の列の長さ、`B` は操作前の列の長さ。列のカードの矩形は `layout.columnCardRects(c, count)`（後述、長い列の詰めを含む）から取る。
    | 操作（`result.type`） | 元 | 先 | 先の種類 |
    | --- | --- | --- | --- |
    | `place` | `layout.decks[deckIndex]` | `columnCardRects(columnIndex, L)[L−1]` | `'column'` |
    | `discard` | `layout.decks[deckIndex]` | `layout.discard` | `'discard'` |
    | `hold` | `layout.decks[deckIndex]` | `layout.hand.slots[slotIndex]` | `'hand'` |
    | `placeFromHand` | `layout.hand.slots[slotIndex]` | `columnCardRects(columnIndex, L)[L−1]` | `'column'` |
    | `move` | `columnCardRects(fromColumn, B)[fromIndex + k]`（`B` は操作前の移し元の長さ） | `columnCardRects(toColumn, L)[L − n + k]` | `'column'` |
    | `release` | `columnCardRects(columnIndex, n)[k]`（操作前の長さは `n`） | `layout.discard` | `'discard'` |
    * `move` は束の各カード（下から `k = 0..n−1`）に、同じ delay（0）・duration の `CardTween` を1つずつ作る。元・先とも各カードの列の中の位置なので、重なりの形を保ったまま動き、着いた位置は操作後の列（詰めを含む）の位置と一致する。
    * 先が列のとき、先の矩形は「操作後の長さ `L`」で `columnCardRects` を求めるので、長い列の詰めがかかっても着いた瞬間に跳ばない。
    * 元の位置からはすぐ消える（操作後のルール層の状態にはもう無いため。動いているカードがそれに当たる）。
* **手前に描く・二重に見せない**: 動きの集まり（`boardAnimator.js`）が、着いていない `CardTween` について
    * `flying`: 描く矩形とカード（`CardTween` の並び順。束・列は下から順なので、上のカードが手前に重なる）。
    * `hiddenCardIds`: 先が `'column'`・`'hand'` のカードの ID の集合。列・手札の描画はこの ID のカードを描かない（列の中の位置の計算は、隠したカードも数に入れたまま `L` で行う）。
    * `discardPending`: 先が `'discard'` で着いていないカードの枚数。捨て札の描画は「`game.discard.length − discardPending`（0未満は0）」を枚数として出す。
    を作り、`view` に渡す。`boardView.js` は、ほかの盤面（最下段を含む）をすべて描いた後に `flying` を描く。
* 列が隠したカードだけになる（空の列に置いた）ときは、列の描画は空き枠を描く。手札の枠のカードが隠されているときは、空き枠として描く（入れられる枠の目印は今の `holdSlots` のまま。操作直後は選択がないので出ない）。

### 要件2: 山札のめくれ
* **めくれ（`js/anim/deckFlip.js`）**: 「山札の番号・delay・duration」を持つ `DeckFlip` と、時計から見た目を求める関数。
    * `createDeckFlip({ deckIndex, delay, duration })` → `DeckFlip`。
    * `sampleDeckFlip(flip, clock)` → `{ scaleX, faceUp }`、または終わっていれば `null`。`t = clamp01((clock − delay) / duration)`。`t < 0.5` は裏（`faceUp: false`、`scaleX = 1 − 2t`）、`t ≥ 0.5` は表（`faceUp: true`、`scaleX = 2t − 1`）。`clock < delay` は裏で `scaleX = 1`。`clock ≥ delay + duration` は `null`（普通の表の描画に戻る）。
    * `deckFlipEnd(flip)` → `delay + duration`。
* **いつめくるか（`planningMotion.js`）**: 次の山札の番号の集合（重複は1つにまとめる）に、delay 0 のめくれを作る。ただし操作後にその山札の見えるカードが1枚以上あるものだけ（山札が空のままならめくれない）。
    * `place`・`discard`・`hold` の `deckIndex`。
    * 結果の `refills`（`place`・`discard`・`hold`・`release` が持つ）の各 `deckIndex`。
* **描き方**: `cardView.js` に `drawCardBack`（裏の見た目）と `drawCardFlip(ctx, x, y, w, h, card, scaleX, faceUp)`（カードの中心を軸に横だけ `scaleX` で縮めて、裏か表を描く。`ctx.save()`／`translate`／`scale`／`restore`）を足す。`deckView.js` の `drawDeck` は、表示用の状態に `flip`（`{ scaleX, faceUp }` か `null`）を受け取り、`flip` があれば一番上のカードを `drawCardFlip` で描く。

### 要件3: 放つ
* `release` の束（`result.cards`、下から順 `k = 0..n−1`）を、**一番上のカードから**順に捨て札へ飛ばす（上から取るほうが、重なったカードの見え方として自然なため）。カード `k` の delay は `(n − 1 − k) × stagger`。
* ずらしの間隔 `stagger` は、枚数に応じて詰める: `n ≤ 1` なら 0、それ以外は `min(RELEASE_STAGGER_MS, (RELEASE_TOTAL_MAX_MS − CARD_MOVE_MS) / (n − 1))`（0未満にならないよう `max(0, …)`）。束が長くても全体（最後のカードが着くまで）が `RELEASE_TOTAL_MAX_MS` 以内に収まる。
* まだ飛び立っていないカードは、元の列の位置に見えたまま（`sampleCardTween` は `clock < delay` で `from` を返す）。操作後の列は空なので、元の列は空き枠の上にこれらのカードが重なって見える。
* **ゲージの数え上げ（`js/anim/gaugeCount.js`）**: 「ゲージの識別子・始めの値・終わりの値・delay・duration」を持つ `GaugeCount` と、時計から表示する整数を求める関数。
    * `createGaugeCount({ gauge, from, to, delay, duration })` → `GaugeCount`。
    * `sampleGaugeCount(count, clock)` → 整数。`t = clamp01((clock − delay) / duration)`、`t ≥ 1` なら `to`、それ以外は `from + Math.floor((to − from) × t)`（線形。整数で1ずつ増えて見える）。
    * `gaugeCountEnd(count)` → `delay + duration`。
* `planningMotion.js` は、`result.gains` のうち値が 0 より大きいゲージごとに、`from` = 操作前のゲージの値（シーンが操作前に読んだもの）、`to` = 操作後のゲージの値、delay 0、duration = `(n − 1) × stagger + CARD_MOVE_MS`（最後のカードが捨て札に着く時刻）の `GaugeCount` を作る。加算のないゲージは作らない（表示は変わらない）。
* `gaugeView.js` の `drawGauges` は、表示値の差し替え（`Object<string, number>`。ゲージの識別子 → 表示する値）を受け取り、あればその値を、なければ `gauges` の値を出す。

### 要件4: 速さは1か所で変えられる
* `js/anim/animConfig.js` に、凍結したオブジェクト `ANIM_TIMING` として次をまとめる（単位はミリ秒、JSDoc に「試遊で決め直す」と書く）。ほかのファイルにこれらの時間の数値を書かない。
    | 名前 | 初期値 | 意味 |
    | --- | --- | --- |
    | `cardMoveMs` | 250 | カード1枚が動く時間 |
    | `deckFlipMs` | 200 | 山札のめくれの時間 |
    | `releaseStaggerMs` | 80 | 放つときのずらしの間隔（上限） |
    | `releaseTotalMaxMs` | 1000 | 放つ束の全体の時間の上限（ずらしの間隔をこれに収まるよう詰める） |
* 補間は `js/anim/easing.js`（`clamp01`・`lerp`・`easeOutCubic`）に置く。
* 時間の進め方は「共通の前提」のとおり `update(dt)` で `dt` を足す（`timeScale` は `update` の呼ばれる回数で反映される）。

### 要件5: 動いている間はタップを受けない
* `js/anim/boardAnimator.js` の `BoardAnimator`（動きの集まりの管理）が、進行中の `CardTween`・`DeckFlip`・`GaugeCount` と時計を持ち、`isBusy()`（時計がすべての動きの終わり `endTime` より前なら `true`）を答える。
* `BoardScene.onPointer` は、最初に `this.animator.isBusy()` なら何もせず戻る（`'down'` も含め、山札・列・手札・放つ・行動終了のすべてを無視。選択も変えない）。
* 選択の目印は今までどおり `boardUiFor` から描く（動いている間も意味は同じ。操作の直後は選択が `null` になっているので、多くの場合は出ない）。

### 要件6: ゲームの結果は変わらない
* `BoardScene` は、行動が残っているときのタップで `applyTap` を呼ぶ**前に** `snapshotBoard(game)`（`planningMotion.js`）で操作前の値（列ごとの長さ・ゲージの値・山札ごとの見えるカードの枚数）を写し取り、`applyTap` の後に結果が `null` でなければ、操作後の `snapshotBoard(game)` と合わせて `buildPlanningMotion(result, before, after, this.layout)` を呼び、返った動きを `this.animator.start(motion)` に渡す。ルール層の操作は今までどおり `applyTap` の中で即座に呼ばれ、遅らせない。
* `snapshotBoard(game)` は `game` を読むだけ（`game.columns[c].length`、`{ ...game.gauges }`、`game.visibleCards(d).length`）で、ルール層を import しない（引数で受け取る）。
* 描画は「操作後のルール層の状態」＋ `animator.view()` の見た目の値で行う。`view()` は状態を変えない（`draw` から呼ぶため）。
* 動きがあってもなくても、ルール層の状態と操作の結果は同じ（演出はルール層に何も書き込まず、操作を呼ばない）。

### 画面の側のデータ構造（JSDoc の `@typedef`）
* `js/anim/planningMotion.js`:
    * `BoardSnapshot` = `{ columnLengths: number[], gauges: Object<string, number>, deckVisibleCounts: number[] }`。
    * `Motion` = `{ tweens: CardTween[], flips: DeckFlip[], counts: GaugeCount[] }`。
* `js/anim/boardAnimator.js`:
    * `FlyingCard` = `{ card, x, y, w, h }`。
    * `FlipLook` = `{ scaleX: number, faceUp: boolean }`。
    * `BoardAnimView` = `{ flying: FlyingCard[], hiddenCardIds: Set<number>, discardPending: number, deckFlips: Map<number, FlipLook>, gaugeValues: Object<string, number> }`。動きがないときは、空の配列・空の集合・0・空の Map・空のオブジェクト。
* `js/view/layout.js`: `Layout` に `columnCardRects: function(number, number): Rect[]` を足す（列の番号と枚数から、下から順の各カードの矩形。`columnCardYs` を使い、x・幅・高さは列の配置から）。

### `BoardAnimator`（`js/anim/boardAnimator.js`）
* フィールド: `clock`（ms）、`endTime`（ms）、`motion`（`Motion` か `null`）。
* `start(motion)`: 時計を0に戻し、`motion` を持ち、`endTime` を `cardTweenEnd`・`deckFlipEnd`・`gaugeCountEnd` の最大にする（動きが1つもなければ 0）。進行中の動きがあれば置き換える（タップを受けないので、普通は起きない）。
* `update(ms)`: `clock += ms`。`clock ≥ endTime` になったら `motion` を `null` にする。
* `isBusy()`: `motion !== null && clock < endTime`。
* `view()`: 上の `BoardAnimView` を作って返す（状態は変えない）。着いていない `CardTween` だけを `flying`・`hiddenCardIds`・`discardPending` に入れる。めくれは `sampleDeckFlip` が `null` でないものだけ `deckFlips` に入れる。数え上げは `gaugeValues[gauge] = sampleGaugeCount(...)`。

### 描画の側の変更
* `cardView.js`: `drawCardBack(ctx, x, y, w, h)`（角丸・濃い色の地・内側の枠。見た目の定数）、`drawCardFlip(ctx, x, y, w, h, card, scaleX, faceUp)`（要件2）。`scaleX` が 0 のときは何も描かない。
* `deckView.js`: `DeckViewState` に `flip`（`FlipLook|null`）を足す。`drawDiscard(ctx, rect, count, pending = 0)` とし、出す枚数を `Math.max(0, count − pending)` にする。
* `columnView.js`: `drawColumn(ctx, columnLayout, cards, highlighted, runFrom, hiddenIds = new Set())`。`hiddenIds` に含まれるカードは描かない（位置は全体の枚数で計算）。全部隠れているなら空き枠を描く（強調は今と同じ扱い）。
* `handView.js`: `HandViewState` に `hiddenIds`（`Set<number>`）を足し、隠すカードの枠は空き枠として描く。
* `gaugeView.js`: `drawGauges(ctx, gaugeRects, gauges, shownValues = {})`（要件3）。
* `boardView.js`: `drawBoard(ctx, layout, game, ui, anim)`。`anim`（`BoardAnimView`）を各部品に渡す（`gaugeValues` → `drawGauges`、`deckFlips.get(d) ?? null` → `drawDeck`、`discardPending` → `drawDiscard`、`hiddenCardIds` → `drawColumn`・`drawHand`）。最下段（`drawHud`）の後に、`anim.flying` を順に `drawCardFace` で描く（ほかのカードより手前）。

### シーンの変更（`js/scenes/BoardScene.js`）
* `init` で `this.animator = new BoardAnimator()` を作る（コンストラクタでも `null` で宣言し JSDoc を書く）。

### 参照する責務
*   `js/scenes/`: シーン（`Scene` の継承）。入力を受けてルール層の操作を呼ぶこと、`anim` の時間を進めること、`view` を呼んで描くこと、シーンの切り替え、ボタンの登録。ルールの判定や計算を書くこと（ルール層を呼ぶ）、細かい描画の処理（`view` に置く）は責務違反。
*   `js/view/`: カード・山札・列・ゲージ・城・敵・兵などの描き方、画面の配置（座標と大きさ）と、座標から「何に当たるか」を求めること。ゲームの状態を変えること、ルールの判定、時間で進む動き（`anim` に置く）は責務違反。

## 5. 懸念事項・要確認ポイント
* 計画時点の判断（`timeScale` の反映）: `oz/ENGINE_API.md` 11章で `dt` は一定・`timeScale` の影響を受けないが、12章で `update` の呼ばれる回数が `timeScale` に従う（`0` で呼ばれない、小さくするとティック単位で段階的）ので、`update(dt)` ごとに `dt` を時計に足す方法を選んだ。`dt × timeScale` は二重に効くため使わない。`draw` の `time.gameTime` は `draw` の中で状態を変えられないため使わない。REQ の「`dt` ではなく」の意図が「`dt` に `timeScale` を掛けて使え」であった場合は指示がほしい。
* 計画時点の判断（ルール層は変えずに足りるか）: 動きに必要な情報は、操作の結果（`deckIndex`・`slotIndex`・`columnIndex`・`fromColumn`・`fromIndex`・`toColumn`・`cards`・`gains`・`refills`）と、シーンが操作の前後に読める値（列の長さ・ゲージの値・山札の見える枚数）で足りる。ルール層の変更は不要と判断した。
* 計画時点の判断（`anim` が配置を使う方法）: `js/anim/` から `js/view/layout.js` を import せず、`createLayout` が返す `Layout` に `columnCardRects` のメソッドを足し、シーンが `Layout` を `buildPlanningMotion` に渡す（`hitTest` と同じ形）。`anim` → `view` の import の向きを作らないため。
* 計画時点の判断（放つ順）: 放つときは一番上のカードから順に飛ばす。ずらしの間隔は 80ms を上限に、全体が 1000ms に収まるよう枚数に応じて詰める（例: 10枚なら (1000−250)/9 ≈ 83 → 80ms のまま 970ms、13枚なら 62.5ms）。
* 計画時点の判断（めくれの開始）: めくれは操作と同時（delay 0）に始める。カードが山札から離れるのとめくれが重なって見える。離れてから返したい場合は `planningMotion.js` で delay を足す（その値も `animConfig.js` に置く）。
* 起こりうる見た目のずれ（補充と捨てる）: ある山札の最後の1枚を捨てたとき、ルール層は捨て札からそのスートのカード（捨てたばかりのカードを含む）を混ぜて同じ山札に戻す。このとき、捨て札へ飛ぶカードと、補充されて山札の一番上でめくれるカードが同じカードになることがある（ルール層の結果どおりで、ゲームの結果には影響しない）。また、捨て札の枚数は `game.discard.length − discardPending` を0で止めて出すので、補充で捨て札から抜けた分と重なると、動いている間の枚数が実際とずれて見えることがある（動きが終わればルール層の値に戻る）。
* 起こりうる見た目のずれ（列の詰め直し）: 先の列が長い列の詰めにかかる場合、先の列にもとからあるカードは操作の瞬間に詰めの位置へ移る（動かない）。移し元の列の残りのカードも、操作の瞬間に操作後の位置へ移る。要件（着くカードが跳ばない）は満たすが、もとからあるカードも滑らかに動かしたい場合は、別の指示がほしい。
* 計画時点の判断（イージング）: 移動は `easeOutCubic`（出だしが速く、着く直前に減速）。数え上げは線形、めくれは線形で横幅を縮めて広げる。
* 目視確認推奨（実装後）: 5種の操作と放つ（1枚・長い束）の動き、長い列（9枚以上）への置く・移すで着いた瞬間に跳ばないこと、山札が尽きて補充されたときのめくれ、空の山札がめくれないこと、ゲージの数え上げが最後のカードの着くころに終わること、動いている間のタップ（行動終了を含む）が無視されること、`animConfig.js` の値を変えて速さが変わること。
