# RES: 作業計画・作業レポート (Phase 02-04) : 効果音
* 参照元REQ: `./_log/req/261113_2136_Phase02-04_効果音.md`

## 1. 作業目的
02-03 までで、段取りの操作はカードの動きで、攻防は兵の動きで見えるが、音はまったく鳴らない。今回は、段取りの操作（めくる・置く・捨てる・放つ・行動終了）と攻防の出来事（相殺・城へのダメージ・敵へのダメージ・修理・勝ち・負け）に効果音（SE）を付け、放った束では1枚ごとに「連鎖」の音をずらして鳴らす。音のファイルは、外部パッケージを使わない Node.js の生成スクリプト（`tools/`）で仮の合成音（WAV 16bit モノラル）として作り、`assets/sounds/` に置く。音の名前とパスの一覧と SE の音量は設定の1か所にまとめ、盤面のシーンに入る前に `Assets.load` で読み込む。BGM・ミュート・連鎖の音程の上昇は作らない。音を鳴らしても鳴らさなくても、ルール層の状態・操作の結果・演出の進み方は変わらない。

## 2. アーキテクチャ設計

### 共通の前提（全タスク共通）
*   ルール層（`js/rules/`）は変更しない。どの操作が成り立ったか・何枚放ったかは、ルール層の操作の戻り値（`PlanningResult`・`BattleResult`）と、シーンが持つ選択の状態の変化から読む。
*   `Sound`（`Sound.playSe`・`Sound.seVolume`）と `Assets.load` だけで音を扱う（`oz/ENGINE_API.md` 20〜21章）。`Sound` を import してよいのは `js/main.js`（音量の設定のみ）と `js/scenes/` の音の補助モジュール `js/scenes/soundCues.js` だけとする。シーン（`BoardScene`・`BattleShowScene`）は `soundCues.js` の関数を呼ぶ。`js/anim/`・`js/view/`・`js/rules/` は `Sound` を import しない。
*   `js/` に `addEventListener`・`requestAnimationFrame`・`getContext`・`setTimeout`・`setInterval`・`AudioContext`・`Audio`・`performance.now`・`Date.now` を書かない。音を鳴らす時刻は、`anim` の時計（`update(dt)` の `dt` を足したもの）だけで決める。
*   `Sound.playSe` は `update`・`onPointer` の中でだけ呼ぶ（`draw`・`init`・`destroy` では呼ばない）。`Sound.playSe` に一覧にない名前・ロードの終わっていない名前を渡すとエラーでループが止まる（`oz/ENGINE_API.md` 15・21章）ので、使う名前は必ず設定の一覧（`SOUND_FILES`）にあるものだけにし、ロードは盤面のシーンに入る前に完了させる（要件5）。
*   カードの動き・兵の動きの見た目と速さは変えない（`animConfig.js`・`battleAnimConfig.js`・`battleTimeline.js` など、許可のない `anim` のファイルは変更しない）。

### 音の一覧（要件4・要件5）
音の名前は `Sound.playSe` に渡す名前で、ファイルは `assets/sounds/<名前>.wav`（ページからのパスは `./assets/sounds/<名前>.wav`）とする。全部で12個。

| 名前 | 用途 | 合成の例（仮の音。種類ごとに聞き分けられればよい） | 長さの目安 |
| --- | --- | --- | --- |
| `flip` | めくる（山札を選んだ） | 高めのノイズの短い「シュッ」（急な減衰） | 約 0.06〜0.08 秒 |
| `place` | 置く（置く・手札に入れる・手札から置く・束を移す） | 低めの正弦波（約 150Hz）＋短いクリックの「コトッ」 | 約 0.08〜0.1 秒 |
| `discard` | 捨てる | 矩形波の下がる音（約 400Hz→200Hz） | 約 0.15 秒 |
| `release` | 放つ | 正弦波の上がる音（約 300Hz→900Hz） | 約 0.25 秒 |
| `chain` | 連鎖（放ったカード1枚ごと） | 高めの正弦波の短い「ピッ」（約 1200Hz） | 約 0.06 秒 |
| `turnEnd` | 行動終了（攻防に入った） | 矩形波の2音（約 523Hz→784Hz） | 約 0.3 秒 |
| `block` | 相殺（`block`・`enemyBlock`） | ノイズ＋矩形波（約 200Hz）の金属的な「ガキン」 | 約 0.15 秒 |
| `castleHit` | 城へのダメージ | 低い正弦波（約 80Hz）＋ノイズの「ドン」 | 約 0.35 秒 |
| `enemyHit` | 敵へのダメージ | 矩形波の下がる音（約 300Hz→150Hz）＋ノイズ | 約 0.2 秒 |
| `heal` | 修理 | 正弦波の上がる3音（約 523・659・784Hz） | 約 0.4 秒 |
| `win` | 勝ち | 正弦波（または三角波）の長調の上がる4音（約 523・659・784・1047Hz）、最後を伸ばす | 約 1.2 秒（2 秒以下） |
| `lose` | 負け | 正弦波の短調の下がる3音（約 392・311・262Hz）、最後を伸ばす | 約 1.5 秒（2 秒以下） |

*   勝ち・負け以外は 1 秒以下、勝ち・負けは 2 秒以下（要件4）。
*   各音は、頭の数ミリ秒で立ち上げ（クリック音を防ぐ）、終わりに向けて減衰させる。最大振幅は 0.8 程度に収める（割れない）。

### 要件1: 段取りの操作で鳴る（操作と音の対応）
鳴らすのはタップを受けた時点（`BoardScene.onPointer` の中）。1回のタップで鳴る操作の音は1つ（放つのときだけ、それに加えて要件3の連鎖の音が時間で鳴る）。

| タップの結果（シーンから見えるもの） | 鳴らす音 |
| --- | --- |
| `applyTap` が操作を呼ばず（`step.result === null`）、選択が山札（`step.selection.kind === 'deck'`）になった（前の選択が同じ山札でない） | `flip`（めくる） |
| `step.result.type === 'place'`（めくったカードを列に置いた。補充が起きても同じ） | `place` |
| `step.result.type === 'hold'`（手札に入れた） | `place` |
| `step.result.type === 'placeFromHand'`（手札から列に置いた） | `place` |
| `step.result.type === 'move'`（束を移し替えた） | `place` |
| `step.result.type === 'discard'`（置けずに捨て札へ捨てた） | `discard` |
| `step.result.type === 'release'`（束を放った） | `release`（＋要件3の `chain` を枚数分、時間で） |
| 行動を使い切った状態で「行動終了」を押し、`game.resolveBattle()` が `null` でない結果を返した | `turnEnd` |
| それ以外（何も当たらない・置けない場所・選択を外しただけ・手札や束を選んだだけ・動いている間のタップ・押せない「行動終了」） | 鳴らさない |

*   「めくる」は、ルール層の状態を変える操作ではなく、シーンが持つ選択の状態が「山札の選択」に変わったことで判断する（このゲームでは山札の一番上はすでに見えていて、ルール層に「めくる」操作はない。山札を選べるかは `boardSelection.js` が `game.canSelectDeck` で判定済み）。REQ の「山札の一番上をめくった（選んだ）とき」に当たる。5章に記す。
*   判定はシーンの補助モジュール `js/scenes/soundCues.js` の純粋関数 `planningSeName(prevSelection, step)` に置き（名前か `null` を返す）、`BoardScene` はタップの前の選択を覚えておき、`applyTap` の後にこれを呼んで、名前があれば `Sound.playSe` で鳴らす（実際の呼び出しは `soundCues.js` の `playSe` を通す）。ルールの判定はせず、`applyTap` の戻り値と選択を見るだけ。
*   「行動終了」の音は、`BoardScene.onPointer` の行動終了の分岐で、`resolveBattle()` が `null` でない結果を返したとき、`Engine.pushScene` の前に鳴らす。

### 要件2: 攻防の出来事で鳴る（段と音の対応・鳴らす時点）
攻防の段（`battleSteps.js` の `BattleStep`）のうち、音を合わせるのは次の5種類。並びにない出来事（量が0）は段が作られないので鳴らない。1つの段で1回だけ鳴らす。

| 段の種類（出来事） | 鳴らす音 | 鳴らす時点（段の開始 `start` からの時刻） | 理由 |
| --- | --- | --- | --- |
| `block`（出来事 `block`） | `block` | `start`（ぶつかった時点） | 直前の段（`enemyMarch`）で敵兵がぶつかる位置まで進み、この段の頭でぶつかり始めるため |
| `enemyBlock`（出来事 `enemyBlock`） | `block` | `start`（ぶつかった時点） | 直前の段（`march`）で兵士がぶつかる位置まで進み、この段の頭でぶつかり始めるため |
| `castleHit`（出来事 `castleDamage`） | `castleHit` | `start + BATTLE_ANIM.hitMoveMs`（当たった時点） | `battleTimeline.js` の `addHit` で、兵が `hitMoveMs` かけて城に着いて消え、HP の表示が減り始める時刻 |
| `enemyHit`（出来事 `enemyDamage`） | `enemyHit` | `start + BATTLE_ANIM.hitMoveMs`（当たった時点） | 同上（敵に着く時刻） |
| `heal`（出来事 `heal`） | `heal` | `start + BATTLE_ANIM.formMs`（大工が現れ終わって直し始める時点） | `battleTimeline.js` の `addHeal` で、HP の表示が増え始める時刻 |

*   勝ち・負け（出来事 `win`・`lose`）は段にならない（`buildBattleSteps` はそこで読むのをやめる）。決着の表示は `battleShowView.js` で「演出が終わった（`look.finished`）かつ `result.outcome !== null`」のときに出るので、`BattleShowScene` が `update` の中で「`director.isFinished()` かつ `result.outcome !== null` かつ まだ鳴らしていない」ときに1回だけ、`outcome` が `'win'` なら `win`、`'lose'` なら `lose` を鳴らす（シーンのフィールド `outcomeSePlayed` で1回に限る）。
*   **音を合わせる時点（以下「きっかけ」）を作る場所**: 新しい `js/anim/battleCues.js` の純粋関数 `buildBattleCues(timedSteps)` が、時間割の段（`TimedStep[]`）から上の表の5種類だけを取り出し、`{ time, type }`（`type` は段の種類の文字列）の並び（時刻の昇順）を作る。時刻の式は表のとおりで、時間は `BATTLE_ANIM` から読む（数値を直書きしない）。`battleTimeline.js` は変更しない（許可がないため）。そのため、きっかけの時刻の式は `battleTimeline.js` の `addHit`・`addHeal` の時刻と同じ式を `battleCues.js` に書く（5章に記す）。
*   **きっかけを答える場所**: `BattleDirector` に次を足す。
    *   フィールド `cues`（`buildBattleCues(timeline.steps)` の結果。コンストラクタで作る）、`prevClock`（直前の `update` の前の時計。初期値 0）。
    *   `update(ms)`: `this.prevClock = this.clock;` の後に、今までどおり `this.clock += ms;`。
    *   `skip()`: 今までの処理の後に `this.prevClock = this.clock;`（飛ばした段のきっかけを、次の問い合わせで出さない）。
    *   `cuesInLastUpdate()`: `prevClock < cue.time <= clock` のきっかけの `type` を、時刻の順に配列で返す（状態は変えない）。早送りで1回の `update` が長くなっても、区間に入るきっかけは全部返すので取りこぼさない。同じきっかけが2つの区間に入ることはないので、1回だけ鳴る。きっかけの時刻はどれも 0 より大きい（`block`・`enemyBlock` の前には必ず `enemyMarch`・`march` の段があり、`castleHit`・`enemyHit`・`heal` は `start` に正の時間を足すため）。
*   **鳴らす場所**: `BattleShowScene.update(dt)` で `this.director.update(dt)` の直後に、`cuesInLastUpdate()` の各 `type` を `soundCues.js` の `playBattleCueSe(type)` に渡す（`type` → 音の名前の対応は `soundCues.js` が持つ）。その後に決着の音を調べる。今の `update` のほかの処理（等速に戻す、次のフェーズへ進めて戻る）は変えない。
*   **早送り**: `Engine.timeScale` で `update` が多く呼ばれるだけなので、きっかけは等速と同じ順に、詰まって鳴る。音を速くする処理は書かない。
*   **スキップ**: `skip()` で `prevClock` を `clock` に合わせるので、飛ばした段のきっかけは鳴らない。スキップで終わりに移ると、次の `update` で `isFinished()` が真になるので、決着していれば勝ち・負けの音は鳴る。
*   **責務の線引き（`anim` に音の名前を持たせない）**: `anim` は「いつ・何が起きたか」を、自分の言葉（段の種類の文字列、連鎖の何枚目か）で答えるだけにし、音の名前（`'block'` などの `SOUND_FILES` の名前）は持たない。理由: `anim` の責務は見た目の値と時間を作ることで、どの音を鳴らすかは見せ方の別の判断であるため。また、音の名前を `anim` に持たせると、音の差し替え・対応の変更で `anim` を直すことになり、「音の対応は1か所（`soundCues.js`）」が崩れるため。段の種類 `block` と音の名前 `block` が同じ文字列なのは偶然とし、対応表は `soundCues.js` に明示的に書く。

### 要件3: 放った束の連鎖の音
*   **ずらし方**: 放ったカードが1枚ずつ捨て札に**着いた時点**で、`chain` を1回ずつ鳴らす。放つ動き（`planningMotion.js` の `release`）では、カード `k`（列の下から `k` 番目、0 始まり）が `delay = (n - 1 - k) * stagger` から `ANIM_TIMING.cardMoveMs` かけて捨て札へ動くので、着く時刻は `delay + cardMoveMs` である。上のカードから順に着くので、着く時刻の早い順に「1枚目、2枚目、…」と数える。`release` の音はタップの時点で鳴り、1枚目の `chain` は `cardMoveMs` 後に鳴る（重ならない）。
*   **何枚目かが分かる作り**: 連鎖のきっかけは「何枚目か」（1 始まりの序数）として返し、`soundCues.js` の `playChainSe(ordinal)` が受け取る。今回は `ordinal` を使わず、どの枚も同じ `chain` を鳴らす（音程を変える処理・音程違いの名前は作らない）。`playChainSe` の JSDoc に「`ordinal` は将来、エンジンに音程の指定が入ったときに音程を上げるために使う。今は使わない」と書く。
*   **きっかけを作る場所**: `planningMotion.js` の `Motion` に `chainTimes: number[]`（連鎖のきっかけの時刻（ms）、昇順）を足す。`buildPlanningMotion` は最初に `chainTimes: []` で作り、`release` のときだけ、各カードの着く時刻 `(n - 1 - k) * stagger + move` を入れて昇順に並べる。ほかの操作では空のまま。カードの動きの値（`tweens`・`flips`・`counts`）は変えない。
*   **きっかけを答える場所**: `BoardAnimator` に次を足す。
    *   フィールド `prevClock`（直前の `update` の前の時計。初期値 0）、`chainTimes`（`start` で `motion.chainTimes` を写す。初期値 `[]`）。
    *   `start(motion)`: 今までの処理に加え、`this.prevClock = 0; this.chainTimes = [...(motion.chainTimes ?? [])];`。
    *   `update(ms)`: `this.prevClock = this.clock;` の後に、今までどおり時計を進め、終わったら動きを捨てる（`chainTimes` は捨てない。最後のカードの着く時刻は動きの終わりの時刻と同じなので、動きを捨てた同じ `update` でも答えられるようにするため）。
    *   `chainCuesInLastUpdate()`: `prevClock < chainTimes[i] <= clock` の `i` について、序数 `i + 1` を昇順に配列で返す（状態は変えない）。
*   **鳴らす場所**: `BoardScene.update(dt)` で `this.animator.update(dt)` の直後に、`chainCuesInLastUpdate()` の各序数を `playChainSe(ordinal)` に渡す。
*   動いている間（`isBusy()`）はタップを無視するので、連鎖の途中で次の動きが始まることはない（最後の連鎖の時刻は動きの終わりの時刻と同じ）。

### 要件4: 仮の音の生成（`tools/makeSounds.mjs`）
*   新しいフォルダ `tools/` に `makeSounds.mjs` を置く。拡張子を `.mjs` にするのは、`package.json` がないため、Node.js に ES Modules として読ませるため。ゲームの実行時には読まない（`index.html`・`js/` から import しない）。
*   Node.js の組み込みモジュール（`node:fs`・`node:path`・`node:url`）だけを使う（外部パッケージを使わない。`npm install` をしない）。
*   先頭に責務定義（3行以内）と、実行のしかたのコメント（例: リポジトリの最上位で `node tools/makeSounds.mjs`。書き出し先は `assets/sounds/`。同じ名前のファイルは上書きする。ゲームの実行時には使わない）を書く。
*   書き出し先は、スクリプト自身の位置（`import.meta.url` → `fileURLToPath`）から `../assets/sounds/` を求める（どこから実行しても同じ場所に書く）。フォルダがなければ作る（`mkdirSync(..., { recursive: true })`）。
*   作り:
    *   定数: 標本化周波数 `SAMPLE_RATE`（22050）、最大振幅 `PEAK`（0.8）、立ち上げの時間 `ATTACK_SEC`（0.005）など。名前付きの定数にし、JSDoc を書く。
    *   波形の小さな関数（モジュール内）: 正弦波・矩形波・三角波（位相から値）、ノイズ（**種を固定した簡単な疑似乱数**（線形合同法など）。何度実行しても同じファイルになり、差分が出ないようにするため。`Math.random` は使わない）。
    *   音の組み立ての小さな関数: 長さ（秒）と「時刻 → 値」の関数から `Float32Array` を作る、周波数を時間で動かす（位相を足していく）、減衰（指数または直線）、音を並べる（何秒目から足す）、最大振幅に合わせる。
    *   WAV の書き出し: 44 バイトのヘッダー（`RIFF`・`WAVE`・`fmt `（PCM=1、チャンネル 1、標本化周波数、16bit）・`data`）と、`-1〜1` を 16bit の整数（`Math.round(v * 32767)`、範囲に収める）にした本体を `Buffer` に書いて `writeFileSync` する。
    *   音の作り方の表 `RECIPES`（名前 → 標本を作る関数）。名前と中身は「音の一覧」の表のとおり。1回の実行で全部を書き出し、書き出したファイル名と長さ（秒）を `console.log` で1行ずつ出す。
    *   長さの上限（勝ち・負け以外 1 秒、勝ち・負け 2 秒）を超える音があれば、書き出さずにエラー（`throw`）にする。
*   ゲーム側の設定（`soundConfig.js`）を import しない（`package.json` がなく、`.js` の ES Modules の扱いが Node.js の版に左右されるため）。名前の一致は、タスクの中で実装AIが確かめる（書き出したファイルの数・名前が `SOUND_FILES` の一覧と一致すること）。
*   書き出した `assets/sounds/*.wav` はコミットの対象（コミットはオーケストレータが行う）。

### 要件5: 音の読み込みと設定（`js/audio/soundConfig.js`・`js/main.js`）
*   **設定のファイル**: 新しいフォルダ `js/audio/` に `soundConfig.js` を置く。新しいフォルダを作る理由: 音の名前とパスの一覧・音量は、ルール層（`js/rules/` は音に触れない）・シーン（`js/scenes/` はシーンとその入力の補助）・描画（`js/view/`）・演出（`js/anim/` は音を扱わない）のどの責務にも入らず、起動（`js/main.js`）とシーンの音の補助（`js/scenes/soundCues.js`）の両方から読まれる、音の設定の置き場所だから。
    *   `SOUND_FILES`: 凍結したオブジェクト。名前 → ページ（`index.html`）からの相対パス（`'./assets/sounds/flip.wav'` など。「音の一覧」の12個）。`Assets.load` の `sounds` にそのまま渡す。本番の音に差し替えるときは、同じ名前のファイルを置き換えるか、ここのパスを書き換える。
    *   `SE_VOLUME`: `Sound.seVolume` の初期値（`0`〜`1`。初期値 `0.7`。試遊で決め直す）。
    *   `oz` も `js/` のほかのファイルも import しない（値だけを持つ）。先頭に責務定義、定数に JSDoc を書く。
*   **読み込む場所**: `js/main.js` で、`Engine.start` の前に `Sound.seVolume = SE_VOLUME;` を設定し、`await Assets.load({ sounds: SOUND_FILES });`（モジュールの最上位の `await`）でロードを済ませてから `Engine.start(config)` を呼ぶ。
    *   理由: `Assets`・`Sound` は `Engine.start` の前から使える（`oz/ENGINE_API.md` 20・21章）。ロードを先に済ませれば、タイトル（「TAP SCREEN」）を押して盤面に入ったときに、ロードの終わっていない名前で `Sound.playSe` がエラーになる（ループが止まる）ことがない。タイトルは最初の入力を受けるだけの画面で、そこでは音を鳴らさず、次の画面（盤面）から鳴らすので、「タッチの最初の押下」の遅れの影響も受けない（21章「最初の入力まで」）。`BootScene.js` を変えずに済み、タイトルの見た目と操作は変わらない。
    *   読み込みに失敗した音は、`Assets.load` が警告を出して続行し、`Sound.playSe` はエラーにならず鳴らないだけ（エンジンの仕様どおり）。入力の前に音声をロードすると Chrome が黄色の警告を出すことがあるが、動作に影響しない（21章）。
    *   `config.scene`（`createTitle()`）・`virtualPad` ほか、今の `Engine.start` の設定は変えない。先頭の責務定義に「起動の前の音の読み込みと SE の音量の設定」を足す。

### 要件6: ゲームの結果は変わらない
*   音の判定は、ルール層の操作の戻り値・選択・`anim` の時計を読むだけで、ルール層の状態・選択・`anim` の時計・`Engine.timeScale`・シーンの操作を変えない（`BattleShowScene` の `outcomeSePlayed` は音を1回に限るためだけのフィールドで、演出の進み方に使わない）。
*   `BoardAnimator`・`BattleDirector` に足す `prevClock` は、きっかけの区間を答えるためだけに使い、`isBusy`・`isFinished`・`isReadyToLeave`・`view` の答えを変えない。

## 5. 懸念事項・要確認ポイント
*   **連鎖の音程の上昇（保留）**: DIR の「連続の枚数が増えるほど音程が上がる」は、`oz/ENGINE_API.md` 21章の `Sound.playSe` に音程（再生速度）の指定がないため作らない（REQ 要件3）。連鎖の音は `playChainSe(ordinal)` で何枚目かを受け取る形にしてあり、エンジンに音程の指定が入ったら、ここで `ordinal` から音程を決めればよい。OZ Engine への連絡票は発注者の判断で出す。
*   **「めくる」の判断**: このゲームのルール層には「めくる」操作がなく、山札の一番上は最初から見えている。REQ の「山札の一番上をめくった（選んだ）とき」に従い、ルール層の状態の変化ではなく、シーンの選択が山札の選択に変わったとき（`boardSelection.js` が `game.canSelectDeck` で選べると判定したとき）に `flip` を鳴らす。別の山札を選び直したときも鳴る。選んだ山札をもう一度押して捨てたときは `discard` だけが鳴る。
*   **攻防のきっかけの時刻の二重の式**: `battleTimeline.js` は変更の許可がないため、当たり（`start + hitMoveMs`）・修理（`start + formMs`）の時刻の式を `battleCues.js` にも書く。`battleTimeline.js` の `addHit`・`addHeal` の時刻を変えるときは、`battleCues.js` も合わせて直す必要がある（このことは `battleCues.js` の JSDoc に書く。`battleTimeline.js` は変更しないので、そちらには書かない）。
*   **起動の前のロード**: `js/main.js` で `Engine.start` の前に `await Assets.load(...)` するため、ロードが終わるまで（ローカルの小さな WAV 12個なので短い）タイトルが出ず、ページは空のままになる。タイトルの見た目と操作は変わらない。入力の前に音声をロードするので、Chrome がコンソールに黄色の警告を出すことがあるが、エンジンの資料のとおり動作に影響しない。
*   **最初の盤面のタップ**: タイトルで最初の入力を済ませてから盤面に入るので、盤面の最初のタップからすぐ鳴るはず（`oz/ENGINE_API.md` 21章）。テストプレイで、Android の Chrome と iPhone の Safari で最初の操作の音が鳴ることを確かめてほしい。
*   **早送りでの重なり**: 3倍速では、攻防の音・決着の音が詰まって重なる（REQ のとおり、音を速くしない）。放つ束が長いと連鎖の音が 80ms ごとに続く（全体の上限は `releaseTotalMaxMs`）。聞こえ方はテストプレイで確かめてほしい。
*   **音量と聞き分け**: 仮の音の音色・長さ・`SE_VOLUME`（0.7）は仮の値。テストプレイで聞き分けられるか、大きすぎないかを確かめてほしい。
