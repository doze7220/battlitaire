# RES: 作業計画・作業レポート (Phase 04-01) : クオータービューとスプライトの差し替え
* 参照元REQ: `./_log/req/261117_0015_Phase04-01_クオータービューとスプライトの差し替え.md`

## 1. 作業目的
戦闘の段（最上段）を斜め上から見下ろしたクオータービューの見た目にし、仮の図形（空と地面の塗り・城の四角・巨人とドラゴンの玉・人形の兵・五角形のシールドマーク）を、発注者が OZ Vector Editor で作ったスプライト（`assets/sprites/`）に差し替える。城は戦闘の段の左端から約 1/3 に移し、城の左側を空ける。盤面のカードのスートの絵文字をスートのスプライトに差し替え、画面に出る名前を「回復」→「修理」、「力こぶ」→「金貨」にそろえる。ルール・攻防の流れ・兵の動き・時間割・音は変えず、描く絵と置き場所（`js/view/` の中）だけを変える。

## 2. アーキテクチャ設計
### 要件5: スプライトの扱い（新しいモジュール `js/view/spriteView.js`）
*   **責務**: スプライトJSの import と、位置・大きさを合わせて `draw(ctx)` を呼ぶことを一手に持つ。`assets/sprites/` を import してよいのはこのモジュールだけ。後で Canvas のキャッシュに替えるときは、このモジュールの中身だけを差し替える（呼ぶ側の関数の形は変えない）。
*   **識別子の表** `SPRITE_IDS`（凍結。呼ぶ側はこの定数で絵を指す。文字列を直書きしない）:
    | キー（＝値） | ファイル |
    | --- | --- |
    | `background` | `assets/sprites/background.js` |
    | `castle` | `assets/sprites/unit_castle.js` |
    | `giant` | `assets/sprites/unit_giant.js` |
    | `dragon` | `assets/sprites/unit_dragon.js` |
    | `soldier` | `assets/sprites/unit_solder.js`（ファイル名は `solder` のまま） |
    | `goblin` | `assets/sprites/unit_goblin.js` |
    | `sword` | `assets/sprites/suit_sword.js` |
    | `shield` | `assets/sprites/suit_shield.js` |
    | `hammer` | `assets/sprites/suit_hammer.js` |
    | `gold` | `assets/sprites/suit_gold.js` |
    `effect_fire.js` は今回 import しない。
*   **絵の範囲の表**（凍結した定数。REQ 要件5の表の値をそのまま書く。スプライトの `bounds` は実行時に読まない）: 識別子 → `{ sprite, minX, maxX, minY, maxY }`（`sprite` は import した既定の export）。
*   **公開する関数**:
    *   `spriteFitRect(id, centerX, footY, height)` → `Rect`: 絵の高さを `height` にしたとき（縦横比は絵の範囲から）の、絵の範囲の矩形。横は絵の範囲の中央を `centerX` に、下端（`maxY`）を `footY` にそろえる。`js/view/layout.js` が城・敵の絵の矩形を求めるのに使う（座標は layout が持ち、縦横比だけをここから得る）。
    *   `drawSpriteFit(ctx, id, rect)`: 縦横比を保ったまま、絵の範囲が `rect` に収まる最大の倍率 `s = min(rect.w / 範囲の幅, rect.h / 範囲の高さ)` で、横は中央、縦は下端（足元）をそろえて描く。`ctx.save()` → `translate(左端 − minX·s, rect の下端 − maxY·s)` → `scale(s, s)` → `sprite.draw(ctx)` → `ctx.restore()`。背景・城・巨人・ドラゴン・兵に使う。
    *   `drawSpriteCentered(ctx, id, cx, cy, size)`: 絵の範囲の長い方の辺が `size` になる倍率で、絵の範囲の中心を (cx, cy) にそろえて描く（`save`／`translate`／`scale`／`draw`／`restore`）。カードのスートの絵・シールドマークに使う。
    *   未知の識別子はどの関数でも `Error` を投げる（内部の引き出し関数1つにまとめる）。
*   背景は `drawSpriteFit(ctx, SPRITE_IDS.background, area)`（area は 720×360）で、倍率 1・基準点 (360, 260) にぴったり重なる。
*   スプライトは回さない（`rotate` を使わない）。描いた向きのまま（巨人・ドラゴンは左向き）。

### 要件1・2・3: 戦闘の段の配置（`js/view/layout.js` の `createBattleLayout`）
*   **layout は `spriteView.js` から `SPRITE_IDS`・`spriteFitRect` だけを import する**（絵の縦横比を得るため。描画はしない）。`BATTLE_H = 360`・地面の基準 `groundY = BATTLE_H − GROUND_OFFSET`（= 260。兵・城・敵の足元）・`bodyTop`・枠（phase・castleHp・enemyHp・intent・countdown）の位置は今のまま。
*   **城**（定数を新設、旧定数 `CASTLE_X`・`CASTLE_W`・`CASTLE_MAX_H` は消す）:
    *   `CASTLE_CX = 240`（城の絵の中心の x。段の左端から約 1/3。試遊で動かす1か所）
    *   `CASTLE_H = 190`（城の絵の高さ。大きさを変える1か所）
    *   `castle = spriteFitRect(SPRITE_IDS.castle, CASTLE_CX, groundY, Math.min(CASTLE_H, groundY − bodyTop))`（目安: 幅 約 93、x 約 194〜286、上端 70。フェーズの枠の下端 52 と重ならない）。`BattleLayout.castle` は「城の絵の矩形」になる。
*   **敵の中心と群れの矩形**（旧定数 `ENEMY_RIGHT` は消し、`ENEMY_CX` を新設）:
    *   `ENEMY_CX = 620`（敵の中心の x。ゴブリンの群れの矩形と、巨人・ドラゴンの絵の中心）
    *   `enemy`（群れの矩形）は `{ x: ENEMY_CX − enemySize/2, y: groundY − enemySize, w: enemySize, h: enemySize }`（`enemySize` は今の `ENEMY_MAX_SIZE` の式のまま。今と同じ 560〜680）。ゴブリンの群れの並び（`hordeSlots`）・絵を持たない敵のシールドマークの並べ先（`shieldRects` の既定）・兵の当たる位置の基準は、今どおりこの矩形。
*   **敵の絵（巨人・ドラゴン）**: 敵の種類の識別子ごとの凍結した表 `ENEMY_FIGURES` を layout に置く（敵ごとの大きさ・シールドマークの並べ先の割合を1か所で変えられる）。旧定数 `BIG_ENEMY_MAX_SIZE` は消す。
    ```
    giant:  { sprite: SPRITE_IDS.giant,  height: 200, shield: { cx: 0.41, cy: 0.39, w: 0.7, h: 0.3 } }
    dragon: { sprite: SPRITE_IDS.dragon, height: 200, shield: { cx: 0.47, cy: 0.49, w: 0.6, h: 0.3 } }
    ```
    *   `shield` は絵の矩形に対する割合で、`cx`・`cy` はシールドマークを並べる矩形の中心（絵の基準点＝体の中ほどの位置に当たる値: 巨人 113/273・153/396、ドラゴン 150/318・196/396 の近似）、`w`・`h` はその幅・高さ。
    *   各敵について `rect = spriteFitRect(sprite, ENEMY_CX, groundY, Math.min(height, groundY − (countdown.y + countdown.h)))`（目安: 巨人 幅 約 138・x 約 551〜689、ドラゴン 幅 約 161・x 約 540〜700。上端 60 で数え下ろしの枠の下端 52 と重ならない）、`shieldArea = { x: rect.x + rect.w·cx − rect.w·w/2, y: rect.y + rect.h·cy − rect.h·h/2, w: rect.w·w, h: rect.h·h }`、`healText = { x: rect.x + rect.w/2, y: rect.y + rect.h · ENEMY_HEAL_TEXT_RATIO }`。
    *   `BattleLayout.enemyFigures`: 敵の種類の識別子 → `EnemyFigure`（凍結）。新しい typedef `EnemyFigure` = `{ sprite: string, rect: Rect, shieldArea: Rect, healText: { x, y } }`。
*   **敵の回復の量の位置**: 新しい定数 `ENEMY_HEAL_TEXT_RATIO = 0.15`（文字の中心 y の、絵（群れの矩形）の上端からの距離の、高さに対する割合）。絵を持つ敵は `enemyFigures[typeId].healText`、絵を持たない敵は `BattleLayout.enemyHealText = { x: enemy の中心 x, y: enemy.y + enemy.h · ENEMY_HEAL_TEXT_RATIO }`。
*   **兵の配置（`TroopLayout`）**: 形（項目）は変えない（`js/anim/` は変えない）。値は新しい城の矩形から求め直す。
    *   `fieldL = castle.x + castle.w + FIELD_GAP`、`F = enemy.x − FIELD_GAP − fieldL`（式は今のまま。城が右へ動くので F は 約 364 → 約 250 に縮む）。
    *   `castleHitX`・`carpenterX` = 城の絵の中心 x（`castle.x + castle.w/2`）、`armorHitX` = `enemy.x`、`enemyHitX` = `enemy.x + enemy.w/2`（式は今のまま。敵ごとの作り直しは後のサブフェイズ）。
    *   `smallW`・`smallH`・`bigW`・`bigH`・`spacing`・`groundY`・`backFootY` の式と定数（`SMALL_UNIT_RATIO`・`BIG_UNIT_RATIO`・`UNIT_ASPECT`・`BACK_ROW_RATIO`・`UNIT_SPACING`）は変えない。兵の丸の見た目の直径は `drawSpriteFit` で兵の矩形（幅 w × 高さ h）に収めるので幅 w（小 約 21px、大 約 38px）になり、縮小の倍率はこれらの配置の定数だけで決まる。
*   **使われなくなる項目を消す**（後の片付けタスク）: `BattleLayout.groundY`（背景の塗りと地面の線にだけ使っていた。兵の足元は `troops.groundY` のまま）・`enemyBig`・`enemyBigInner`。
*   **JSDoc**: `BattleLayout` の「サイドビューの見立てで」を「クオータービュー（斜め上から見下ろした地面。地面は回さず、左に城、右に敵。城の左側は後で自軍の兵が並ぶ場所として空けておく）」に直す。ファイル先頭の責務の「大きな敵の玉とそれに内接する矩形」を「城の絵の矩形・敵の絵（巨人・ドラゴン）の矩形とシールドマークを並べる矩形」に直す。
