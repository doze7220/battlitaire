## 5. 懸念事項・要確認ポイント
* **（解決済み）`campSlot` の置き場所**: 初めの計画は `js/view/layout.js` から `js/anim/campSlots.js` を実行時に import する案（view → anim の初めての実行時の import）だったが、計画の監査を受けた発注者の判断で「描画の側へ移す」に決まった。`campSlots.js` を `git mv` で `js/view/` へ移し（タスク2）、`layout.js` は同じフォルダから import する。代わりに `js/anim/troopRoster.js`・`js/anim/enemyAttacks.js` → `js/view/campSlots.js` が、anim → view の初めての実行時の import になる（今の anim → view は JSDoc の型の参照だけ。2章の「import の向き」）。`campSlots.js` は何も import しない純粋関数なので循環の import は生じず、`js/anim/` の責務の表にも anim → view を禁じる決まりはない。
* **当たるゴブリンの位置**: 「番号の大きい方から消える」を保つため、攻撃の兵が当たるのは番号の大きいゴブリンから。R2 列では番号の大きいゴブリンが群れの左（手前）とは限らないので、攻撃の兵がほかのゴブリンの前を通って、群れの中ほど・右のゴブリンに当たることがある（今の格子では左の列から当たっていた）。足元の y の順に描くので重なりの前後は自然になるはずだが、見た目は試遊で確かめてほしい。
* **攻防の間のゴブリンの描く順**: R2 列の足元はいつも `groundY` より上なので、攻防の間は全員が「城・敵の絵より奥の兵」の側で描かれる（今は一番手前の行が手前の側だった）。ゴブリンには絵がなく城とも重ならないので見た目は変わらない見込み。
* **群れの矩形 `enemy` の作り直し**: 群れの兵の体が入る矩形（x 568〜702・y 121〜335）に変えるので、敵の回復の量の位置（絵のない敵。x 635・y 約 153）・シールドの既定の並べ先・シールドに当たる位置が動く。ゴブリンは回復も常時防御力も持たないので、今の遊びでは見えない。
* **攻防の演出中のラベル**: 背面の盤面のシーンもラベルを描き、その上に演出のシーンがもう一度描く。帯の側にかかる文字の縁は2回重なるので、少し太く見えるかもしれない（目視で確かめてほしい）。
* **敵を倒したときの案内の暗幕**: ラベルはこの暗幕（戦闘の段だけを覆う）より手前に描くので、案内の間もラベルは暗くならない。
