# RES: 作業計画・作業レポート (Phase 07-03) : 中断と再開
* 参照元REQ: `./_log/req/261125_2058_Phase07-03_中断と再開.md`

## 1. 作業目的
ゲームの途中でブラウザを閉じても、タイトルの「再開」から、閉じたターンの始まりに戻って続けられるようにする。

* 各ターンの始まりで、ルールの状態（プレイ用の乱数の状態を含む）を中断データとして上書きで保存する。
* プレイ用の乱数を、状態を取り出し・戻せる乱数に替える（抽選を呼ぶ順と回数は変えない）。
* タイトルに、中断データがあるときだけ「再開」のボタンを出す。
* 負けの結果が画面に出た時に中断データを消す。デバッグ（`?debug`）では、保存も消去も「再開」もない。

### 要件1: 保存の時と中身
* **中断データの形（`js/rules/suspendData.js`）**: 1つのプレーンなオブジェクト。`version` と、次の項目の表 `FIELDS`（凍結。項目名 → `{ save(game), check(value, config), load(game, value) }`）の全項目を持つ。後のサブフェイズで状態が増えたら、`FIELDS` に1行足す（形が変わるので `SUSPEND_VERSION` を上げる）。

| 項目 | 中身 | 確かめ（`check`） |
| --- | --- | --- |
| `rng` | `game.rng.state()`（4つの整数） | `isRngState` |
| `seed` | 敵の並びの種 | 整数 |
| `stageNumber`・`phase`・`battleTurn` | ステージの番号・通しのターン・戦闘のターン | 1 以上の整数 |
| `actionsMax`・`actionsLeft` | そのターンの行動の回数・残り | 0 以上の整数 |
| `decks` | `[{ suit, cards }]`（並びの順） | 数が `config.suits` と同じ・各 `suit` が同じ順・札はその山札のスート |
| `discard`・`columns`・`hand` | 捨て札・列・手札（`null` は空き枠） | 配列・列の数 `columnCount`・手札の枠の数 `handSize` |
| `gauges` | ゲージの識別子 → 値 | `config.gauges` の全部が 0 以上の整数 |
| `castle` | `{ hp, maxHp }` | 整数で 1 ≤ hp ≤ maxHp |
| `enemy` | `{ typeId, hp, maxHp, intent, behaviorState }`（名前は設定から引くので持たない） | `typeId` が `enemyTypeIds(config)` にある・整数で 1 ≤ hp ≤ maxHp・予告の形・`isBehaviorState` |
| `stats` | 結果の集計の5つ | `createGameStats()` の全部の名前が 0 以上の整数 |

* 札1枚は `{ id, suit, rank }`。全部の札（山札・捨て札・列・手札）を集めた確かめ（`hasAllCards`）: `createDecks(config, () => 0)` で作った札と、枚数・id・スート・数字がちょうど一致する（欠け・重なり・知らない札を見つける。id の決め方を書き写さない）。`actionsLeft <= actionsMax` も項目どうしの確かめとして見る。
* 予告の形: `kind` が `'attack'` か `'windup'`、`amount`・`baseDefense`・`defense` が 0 以上の整数、`variant` は無いか文字列、`burn` は無いか整数で 0 ≤ min ≤ max。
* 保存しないもの: `stage`（いつも `'planning'`）・`outcome`（いつも `null`）・`config`・画面の状態。疲弊は `battleTurn` から決まる（予告の `defense` は保存した値のまま）。
* 参照を共有しない: `save` の結果と `load` に渡す値は `structuredClone` で写す。
* **公開する口**:
    * `SUSPEND_VERSION`（1。版番号はここ1か所）
    * `toSuspendData(game)` → `SuspendData`。ターンの始まり（抽選が決まった後・操作の前）に呼ぶ。`game` は変えない。
    * `readSuspendData(raw, config = RULES)` → `SuspendData|null`。版番号・形・今の設定との合い方を確かめ、合わなければ `null`。どんな値でも例外を投げない（`null`・配列・数・文字列・入れ子の欠けを含む）。
    * `restoreGame(data, config = RULES)` → `Game`。`readSuspendData` を通ったデータだけを渡す。`new Game({ rng: createRng(data.rng), seed: data.seed, config })` を作り（ここで起きる抽選の結果は捨てる）、`FIELDS` の `load` で全項目を上書きする（乱数の状態も `rng.setState` で保存したものに戻る）。敵の `name` は `enemySpecOf(config, typeId).name`。
* **敵の決まりの状態の確かめ**: `enemyBehaviors.js` の表 `BEHAVIORS` の各行に `isState(state)` を足す。`steady`: プレーンなオブジェクト。`cycle`: `countdown` が 0 以上の整数。`inhale`: `lastVariant` が `'claw'`・`'inhale'`・`'breath'` のどれか。口は `isBehaviorState(behavior, state)`（決まりの種類で分岐する if を `suspendData.js` に書かない）。
* **保存の口（`js/scenes/suspendStore.js`）**:
    * `SUSPEND_DEFAULTS`（`{ suspend: null }`。凍結。`Storage.open` の `defaults` に足す名前）
    * `saveSuspend(game)`: デバッグなら何もしない。`Storage.set('suspend', toSuspendData(game))`。
    * `loadSuspend()`: デバッグなら `null`（書かない）。`Storage.get('suspend')` を `readSuspendData` に通す。保存があるのに `null` になったら `clearSuspend()` してから `null` を返す（その中断データだけを捨てる）。
    * `clearSuspend()`: デバッグなら何もしない。`Storage.set('suspend', null)`。
    * 保存の名前 `'suspend'` は1つの定数にする。`Engine.debug` は `Engine.start` の後だけ読めるので、この口はシーンからだけ呼ぶ。
* **保存を呼ぶ所**（次の2つだけ）:
    * `BoardScene.init`: 新しいゲームを作った直後（再開の盤面では呼ばない）。
    * `BattleShowScene` の新しいメソッド `goToNextPhase()`: `this.game.startNextPhase()` → `saveSuspend(this.game)` → `Engine.popScene()`。今の2か所（自動で進む `update`・「タップで次へ」の `onPointer`）を、条件はそのままこれに置き換える。
* **`Storage.open`**: `main.js` の1か所で `Storage.open({ ...SETTINGS_STORAGE, defaults: { ...SETTINGS_STORAGE.defaults, ...SUSPEND_DEFAULTS } })`。`key`・`version` は今のまま（前の保存の設定が残る）。

### 要件2: プレイ用の乱数
* `js/rules/rng.js`。計算は sfc32（32 ビット整数4つの状態。1回の呼び出しで1回進む）。出る値は `t / 2^32`（0 以上 1 未満）。
```
t = (a + b + counter) の 32 ビット; counter += 1
a = b ^ (b >>> 9);  b = c + (c << 3);  c = rotl(c, 21) + t    （すべて 32 ビット符号なし）
```
* 公開する口:
    * `rngStateOfSeed(seed)`: 0 以上 2^53 未満の整数から始めの状態 `[a, b, c, counter]` を作る。`a = seed >>> 0`、`b = Math.floor(seed / 2^32)`、`c = 0`、`counter = 1` とし、20回進めて混ぜる。範囲外・整数でない値は Error。
    * `isRngState(value)`: 長さ 4 の配列で、全部が 0 以上 2^32 未満の整数か。
    * `createRng(state)`: `Rng` を作る（形が違えば Error）。`Rng` は `next()`（`this` に依らない関数。`game.random` としてそのまま渡せる）・`state()`（写し）・`setState(state)`（写して持つ。形が違えば Error）。型は typedef `Rng`・`RngState`。
* `js/scenes/playRng.js`: `newPlayRng()` = `createRng(rngStateOfSeed(Math.floor(Math.random() * 2 ** 53)))`。`Math.random` は1回だけ呼ぶ。
* `Game`: オプション `random` を `rng`（`Rng`。必須。`rng.next` が関数でなければ Error）に替え、`this.rng = rng`、`this.random = rng.next`（ルール層の今までの使い方 `this.random`・`game.random` はそのまま）。`createDecks(config, this.random)` など、抽選を呼ぶ順と回数は変えない。
* `BoardScene` のオプション `random` を `rng` に替える。`main.js` の `createBoard` が `newPlayRng()` を1回呼び、ふつうの盤面・`createDebugBoard(seed, rng)` の両方へ渡す。`seed`（敵の並び）は今のまま別に持つ。
* 計画時の試し（一時スクリプト。削除済み）: 100 万回の値で、平均 0.4995〜0.5001、100 区間の χ²（自由度 99）78〜115、続く値の相関 0.003 未満。始めの値が 1・2^20・2^32・2^52 だけ違う組の出力のちがうビットは平均 15.9〜16.0（同じ値 0 回）。続く 10 万個の種の1つ目の値の χ² 91.5。

### 要件5: 中断データが消える時
* `BattleShowScene.update` の、負けの音・敵を倒した音を鳴らす1回だけの所（`isFinished()` かつ `!outcomeSePlayed`）で、`this.result.outcome !== null` なら `clearSuspend()` を呼ぶ。印 `outcomeSePlayed` の名前は変えず、JSDoc を「音を鳴らす・中断データを消すのを1回に限る」に直す。
* 「はじめる」は確かめずに新しい盤面を作り、`BoardScene.init` の `saveSuspend` が上書きする。敵を倒したときは消さない。

### 要件6: 版番号と壊れたデータ
* 版番号は `SUSPEND_VERSION` だけ。`SETTINGS_STORAGE.version` は上げない。
* 合わないデータは `readSuspendData` が `null` を返し、`loadSuspend` がその中断データだけを捨てる（`?debug` では捨てずに `null` を返すだけ）。
* 敵の HP・攻撃・防御・確率・行動の回数などの数値だけが変わったときは、保存した値から続ける（`check` は設定の数値と比べない）。後の抽選は今の `RULES` を使う。種とステージの番号から決まる敵の種類との一致は確かめない（敵の種類が足されて並びが変わっても、今の敵は保存した種類で続ける）。
* 札の数字の範囲・スートが変わり、全部の札の組が今の設定と合わないときは「山札の数が合わない」として捨てる。
