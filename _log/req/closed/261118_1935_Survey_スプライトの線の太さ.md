## 【調査の背景】
OZ Vector Editor で描いたスプライト（`assets/sprites/`）を、ゲームの中で大きさを変えて表示すると、見た目（特に線の太さ）がエディタでの印象と変わる。発注者が望むのは、**線の太さも絵と同じ割合で変わること**（2px の線は、2倍で 4px、0.5倍で 1px）。なぜ違って見えるのかを突き止める。発注者はコードを読まないため、結論は画面の見え方の言葉でも書くこと。

## 【調査要件】
*   **要件1: スプライトの大きさを変えている箇所と、その変え方**
    *  `js/` の中で、スプライトの `draw(ctx)` を呼ぶ箇所（`js/view/spriteView.js` の `drawSpriteFit`・`drawSpriteCentered`・`drawTroopFigure`）と、それらを呼ぶ箇所をすべて挙げる。
    *  それぞれで、大きさを `ctx.scale` で変えているか、それ以外（線の太さの割り戻し、`setTransform`、画像に焼いてから描く など）で変えているかを、ファイルと行で示す。
    *  スプライトJS（`assets/sprites/*.js`）の `draw` の中で、線の太さ（`lineWidth`）・線の端と角（`lineCap`・`lineJoin`）・塗りと線の描く順・変換の扱いがどうなっているか（今の `ctx` の変換に従って線も太さが変わる作りか）を示す。
*   **要件2: 縦と横で違う倍率を掛けている箇所**
    *  縦と横で違う倍率になる `ctx.scale` がある箇所（`drawTroopFigure` の `scaleX`・`scaleY` など）を挙げ、その倍率がどこから来て、どんな場面でどれだけの値になるか（設定の値・式）を示す。
    *  そのとき、縦の線と横の線の太さがどれだけ違って描かれるかを数字で示す。
*   **要件3: 線の太さが 1px を下回る箇所**
    *  要件1の各箇所について、実際の倍率（絵の範囲と描く大きさから求めた値）を求め、スプライトの中の線の太さ（`strokeWidth`。今のスプライトには 1・2・6 がある）が、表示したときに **論理座標（720×1280）で何 px**、**実際の画素で何 px** になるかを表にする。実際の画素は、Canvas の画素数が「表示サイズ × min(devicePixelRatio, 2)」であることから、devicePixelRatio が 1 と 2 の場合、およびスマホ縦画面とPCの代表的な表示サイズの場合について求める（表示サイズの前提は RES に書く）。
    *  兵の数で大きさが変わるもの（兵・持ち物）は、最大と最小の大きさの両方を求める。
    *  1px を下回るものに印を付ける。
*   **要件4: エディタとゲームの見え方の比較（発注者に画面で確かめてもらう）**
    *  OZ Vector Editor（ローカル `D:\ozlab\ozvectoreditor`、**読むだけで変更しない**）が、表示の拡大・縮小のときにスプライトの線をどう描くか（線の太さが表示の倍率に合わせて変わるか、画面の上で一定の太さか。devicePixelRatio の扱い）を、エディタのコードと `PROJECT_ARCHITECTURE.md` 2章「スプライト（書き出し形式）」から、ファイルと行で示す。
    *  発注者が比べるための **一時ページ** を作ってよい。決まりは次のとおり。
        *  **プロジェクトのフォルダ（`D:\ozlab\battlitaire`）と、エディタのフォルダ（`D:\ozlab\ozvectoreditor`）の外**（実装セッションの作業用の一時フォルダ）に置く。スプライトJSは写しを置いて読み込んでよい（元のファイルは書き換えない）。ページの見せ方（静的サーバーの立て方など）は実装セッションが決めてよい。
        *  1つのスプライト（線の太さが分かりやすいもの。例: `suit_sword.js` と兵 `unit_solder.js`）を、**等倍・2倍・0.5倍**、および **ゲームの中で実際に描いている大きさ**（要件3で求めた倍率）で並べる。ゲームと同じ描き方（`ctx.scale` で大きさを変えて `draw(ctx)` を呼ぶ、Canvas の画素数は表示サイズ × min(devicePixelRatio, 2)）で描く。縦横で倍率の違う例（要件2）も1つ並べる。
        *  発注者に、エディタ（表示 100%・200%・50%）と一時ページ、および実際のゲームの画面を見比べてもらい、どこがどう違って見えるかを聞き取る。何をどこで見ればよいかは、発注者が迷わない言葉で伝える。
        *  確認が済んだら一時ページ（と写し）を消す。RES には、ページの作り（何をどの倍率で並べたか）と、発注者の見え方の報告を書く。
*   **要件5: 原因の候補ごとの判定**
    *  要件1〜4を踏まえて、原因の候補ごとに「当たっている／当たっていない／一部当たっている」と、その根拠（ファイルと行、要件3の数字、発注者の見え方の報告）を表にまとめる。候補には少なくとも次を含め、調査で見つかった他の候補も足す。
        *  エディタの表示の拡大・縮小では線の太さが変わらない（または変わり方がゲームと違う）ため、エディタで見た印象とゲームの比例した見え方が食い違う。
        *  ゲーム側で線の太さが絵と同じ割合で変わっていない（`ctx.scale` 以外の描き方・割り戻しがある）。
        *  縦と横の倍率が違うため、線の向きで太さが変わる。
        *  縮小で線が 1px（論理座標または実際の画素）を下回り、細くなる代わりに薄く・ぼやけて見える。
        *  devicePixelRatio の上限 2 や表示サイズの違いで、エディタとゲームで実際の画素の線の太さが違う。
        *  塗りと線の描く順・線の端と角の形で、見える線の太さが変わる。
    *  原因が **エンジン（`oz/`）の不足**（`oz/ENGINE_API.md` にない機能が要る、または書かれたとおりに動かない）にあると判断した場合は、`PROJECT_CONSTITUTION.md` の「エンジンの不足への対応」に従い、ゲーム側の回避策は書かず、OZ Engine への連絡票の **案** を RES に添える（連絡票のファイル `D:\ozlab\ozengine-web\_doc\BRIDGE_FROM_BATTLITAIRE.md` には書かない。書くのは発注者の承認の後）。案の書き方は OZ Engine のリポジトリの `_doc/newgame/NEW_GAME_GUIDE.md` 10章（読むだけ）に合わせる。
    *  原因が OZ Vector Editor 側にあると判断した場合も、エディタのリポジトリは変えず、何がどう違うかを RES に書く。

## 【関連する責務】
* `js/view/spriteView.js` : スプライトJSの import と識別子の表（`SPRITE_IDS`）・絵の範囲の表を持ち、位置と大きさを合わせて `draw(ctx)` を呼ぶ（足元をそろえて矩形に収める `drawSpriteFit`・中心にそろえる `drawSpriteCentered`・体と持ち物を重ねて描く `drawTroopFigure`。足元を軸にした伸び縮みを受ける）。絵の縦横比から矩形を求める（`spriteFitRect`）。`assets/sprites/` を import するのはここだけ。
* スプライトの決まり: `assets/sprites/` のスプライトは `js/view/spriteView.js` だけが import し、回さずに描いた向きのまま描く。絵の範囲は `spriteView.js` の凍結した表に持ち、`bounds` は実行時に読まない。`effect_hit.js`（ヒットマーク）は手で書いた仮のスプライト。
* `oz/ENGINE_API.md` 4章・13章: Canvas の画素数は論理解像度と一致せず、表示の大きさ（CSS の画素数）× `devicePixelRatio`（上限 2）になる。`draw` に渡す `ctx` には論理座標で描けるように拡大の変換がエンジンによって設定されている。`setTransform`・`resetTransform` で変換を初期化すると論理座標が崩れる。
* `oz/ENGINE_API.md` 23章: スプライトJSは OZ Vector Editor が書き出す。座標の単位は px で、エディタの px はそのままゲームの px になる。配置（位置・回転・拡大縮小）は、呼ぶ側が `ctx` の変換（`translate`・`rotate`・`scale`）で行ってから `draw` を呼ぶ。`draw(ctx)` は `ctx` の状態を元に戻して終わる。
