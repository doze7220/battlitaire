## 【実装要件】
段取りの終わり方を「行動を使い切ると『準備終了』が出て、タップで攻防」に変え、攻防・フェーズ・ステージの始まりを演出で見せる。あわせて、遊び方の文章を新しい画面と流れに合わせる。

* **ルールは変えない**（ルール層 `js/rules/` は変更しない）。演出の途中のどの時点でも、ルールの結果は変わらない。
* 始まりの演出は短く、繰り返し見ても待たされない長さにする。長さはすべて設定の値にまとめ、試遊（後のサブフェイズ）で決め直す値と書く。
* タイトルからクリア・負けまで、通しで遊べること。スマホの縦画面を優先し、PC でも同じように遊べること。

### 今の流れ（05-01 の後）
* 行動を使い切ると、札・玉・兵が全部着いてから、間を置かずに自動で攻防に入る（`BoardScene` の `update` の最後で `startBattle()`）。使い切ってから攻防に入るまでの盤面のタップは無視し、選択を外す。
* 攻防に入る瞬間に「行動終了」の効果音（`turnEnd`）が鳴る。
* 攻防の演出の後は、次のどれかになる。
  * 決着も敵の撃破もなければ、少し間を置いて自動で次のフェーズへ進む。
  * 途中の敵を倒したら、「○○を倒した！」「次は○○」「タップで次へ」を出し、タップで次の敵のフェーズへ進む。
  * 決着したら、結果の板を出し、タップでタイトルへ戻る。
* タイトルの「はじめる」でスタートの音が鳴る。盤面のシーンでは、待ち時間（`BGM_TIMING.startToStageMs`）の後と、敵が入れ替わったところでステージの曲が流れる。
* 行動が残っているのに、できる操作が何もない状態は、今のルールでは起きない（山札が空になっても捨て札から補充され、列・手札に札が残る）。そのため、その場合の扱いは作らない。

*   **要件1: ロゴのスプライト（仮の書き出し）**
    *  始まりの演出に出すロゴは、すべて `assets/sprites/` のスプライトで描く（発注者の決定）。次の **17 個のスプライト JS** を新しく作る（このサブフェイズでは、手で書いた仮のスプライトを置いてよい。発注者の決定）。
        *  決まった言葉のロゴ（4つ）:
            *  「準備終了」`logo_ready.js`
            *  「BATTLE!」`logo_battle.js`
            *  「PHASE」`logo_phase.js`
            *  「STAGE」`logo_stage.js`
        *  敵の名前のロゴ（3つ。敵の種類の識別子ごと）: `logo_name_goblins.js`・`logo_name_giant.js`・`logo_name_dragon.js`
        *  数字（10個）: `digit_0.js`〜`digit_9.js`。フェーズの番号・ステージの番号を、この数字の絵を並べて描く（2桁以上も描ける）。
    *  **仮の中身**（発注者の決定）:
        *  エディタには文字の道具がないので、**直線だけで描いた太いブロック体の英字・数字**で仮に描く。
            *  英字は `READY`・`BATTLE!`・`PHASE`・`STAGE`・`GOBLINS`・`GIANT`・`DRAGON`。
            *  数字は `0`〜`9`。
        *  ロゴ（数字以外）の後ろには、色の付いた板を敷く。
        *  漢字の「準備終了」と敵の日本語の名前は、後で発注者がエディタで描いて同じ名前で差し替える。
        *  遠くからでも読める、はっきりした色と太さにする（色・形の細部は計画で決める）。
    *  **エディタでの描き方の約束**（計画で値を決め、開発資料に書く）:
        *  ロゴも数字も、原点 (0, 0) を絵の中心にして描く。
        *  ゲームは、エディタの px をそのままゲームの px として描く（倍率 1）。演出で拡大縮小するときは、その倍率をかける。
        *  数字は、決まった大きさの枠の中に描く（たとえば幅 W×高さ H。値は計画で決める）。ゲームは、その枠の幅を間隔として左から並べ、並べた全体の中心を置く位置に合わせる。
        *  ロゴの大きさの目安は計画で決める。画面の幅 720 に収まり、スマホで読める大きさにする。
        *  敵の名前のロゴと敵の種類の識別子の対応は、`js/view/` の表1か所に持つ。表にない敵の種類では、名前のロゴを描かない（エラーにしない）。
    *  **ファイルの形**:
        *  既存のスプライト（`card_back.js` など）と同じ形にする。`oz-vector-editor-sprite`・`formatVersion` 2 のスプライトデータ（`bounds`・`elements`・`source`）と、同じ `draw(ctx)` を持つ既定の export。他のファイルには依存しない。
        *  `source`（作業データ）も持たせ、**エディタの「開く」でそのまま開いて図形を編集できる**ようにする。`elements` と `source` の図形は同じ内容にする。
        *  `bounds` は、エディタの定義（線の太さの半分を含む）に合わせて求める。
    *  スプライトの import と描画は、今の決まりどおり `js/view/spriteView.js` に集める。17 個の import で `spriteView.js` が肥大化するなら、表の持ち方を計画で工夫する（ただし `assets/sprites/` を import するのは `spriteView.js` だけ、の決まりは守る）。
    *  画面の最上部の「PHASE」とフェーズの番号（05-01 で作った文字の表示）は、今回は変えない（文字のまま）。
*   **要件2: 準備終了**
    *  段取りを途中で終える操作はない。行動（金貨で増えた分を含む）を使い切り、札の移動・山札のめくれ・列の詰め直し・玉に変わる前の札・玉・兵の動きが**全部終わってから**、画面の中央に「準備終了」のロゴを出す（今の「全部着いてから自動で攻防」の待ち方をそのまま使い、自動で攻防に入る代わりにロゴを出す）。
    *  ロゴは、ぽんと拡大しながら出る。出きったら、そのまま出し続ける。出方の長さは設定の値にする（目安 300ms）。
    *  ロゴが出た瞬間に、効果音を鳴らす（要件6）。
    *  ロゴが出きった後、**画面のどこかをタップ**（PC ではクリック）すると攻防が始まる（要件3）。
    *  出ている途中のタップと、行動を使い切ってからロゴが出るまでのタップは無視する（選択も外す。今と同じ）。
    *  ロゴの下の盤面は、今のまま見えていてよい（暗くするかは計画で決めてよい。決めたら RES に書く）。
*   **要件3: 攻防の始まりの合図（BATTLE!）**
    *  「準備終了」が出ているときのタップで、攻防に入る。
        *  「準備終了」を消す。
        *  戦闘の段の中央に「BATTLE!」のロゴを出し、効果音を鳴らす（要件6）。
    *  「BATTLE!」を出している間（目安 700ms。設定の値）は、攻防の演出の兵の動きを始めない。消えた後に、今と同じ攻防の演出が始まる。
    *  攻防の演出の時間割・音のきっかけは変えない（始まる時刻が「BATTLE!」の分だけ後ろにずれるだけ）。
    *  ルール層の攻防の解決（`resolveBattle`）と、攻防の演出のシーンを積む時刻は、計画で決めてよい（タップの瞬間でも、「BATTLE!」の後でもよい）。どちらにしても、次の2つを守る。
        *  攻防の前の値の写しと、待っていた兵の数の引き継ぎは、今と同じ値になる。
        *  画面の HP・人数の表示が、演出より先にルール層の結果を見せない。
    *  「BATTLE!」の間のタップは無視する。
*   **要件4: フェーズの始まり**
    *  毎フェーズの始まりに、戦闘の段の中央付近に、次の2つを目立つ形で出す（目安 1000ms。設定の値）。
        *  「PHASE」のロゴと、フェーズの番号（数字の絵）
        *  その敵の次の行動の予告の文字。今の予告の枠と同じ文字（`enemyActionText`）で、巨人の数え下ろしがあれば「攻撃まで あとN」も添える。文字は縁取りした大きめの文字でよい。
    *  フェーズの始まりとは、次の3つの場面のこと。
        *  ゲームの最初のフェーズ（ステージの始まり（要件5）の後）
        *  攻防の演出の後に自動で次のフェーズへ進んだとき
        *  敵を倒した後の次の敵の最初のフェーズ（ステージの始まりの後）
    *  **フェーズの始まりの演出が終わるまで、盤面のタップを無視する**（発注者の決定）。
    *  予告の枠・数え下ろしの枠（戦闘の段の右下・右上）は、今のまま出ていてよい（作り直しは後のサブフェイズ）。
*   **要件5: ステージの始まり**
    *  敵が替わるとき（ゲームの最初のゴブリンの軍勢を含む）に、ステージの始まりの演出を出す（目安 1500ms。設定の値）。
        *  新しい敵が、戦闘の段の右の画面の外から、いつもの位置へ入ってくる。巨人・ドラゴンは絵が、ゴブリンの軍勢は群れが入ってくる。入り終わった後は、今の待機の動きに戻る。
        *  戦闘の段の中央付近に、「STAGE」のロゴとステージの番号（数字の絵。1 から数える。ルール層の敵の番号 `enemyIndex` + 1）、その下に敵の名前のロゴを出す。
    *  ステージの始まりが終わったら、続けてフェーズの始まり（要件4）を出す。
    *  **ステージの始まりの演出が終わるまで、盤面のタップを無視する**（発注者の決定）。
    *  敵が入ってくる前は、その敵を戦闘の段に描かない（ゲームの最初は、盤面のシーンに入ってから敵が入ってくるまで、敵のいない戦闘の段が見えていてよい）。
    *  敵の入り方（動き・時間）は `js/anim/` に置き、敵の絵の描き方（`enemyView.js` など）は位置のずれを受け取るだけにする。
*   **要件6: 音**
    *  「準備終了」が出た瞬間と、「BATTLE!」が出た瞬間の**両方で**、効果音を鳴らす（発注者の決定）。
    *  後で発注者がそれぞれ別の音に差し替えられるように、`js/audio/soundConfig.js` の効果音の一覧に、**新しい名前を2つ**足す（名前は計画で決める）。今は、どちらも今の「行動終了」の音のファイル（`./assets/sounds/turnEnd.wav`）を指す。新しい音のファイルは作らない。
        *  エンジンで、同じファイルを2つ以上の名前で読み込めるかは、`oz/ENGINE_API.md` で確かめる。読み込めないと分かったら、計画で別の方法を決めて RES に書く。
    *  鳴らすのは、今の決まりどおり `js/scenes/soundCues.js` の中だけ。
    *  今の「攻防に入る瞬間の行動終了の音」は、上の2つに置き換わる（同じ音が二重に鳴らないようにする）。使われなくなる名前・関数は片付ける。
    *  **ステージの曲は、ステージの始まりの演出と同じ時刻に流し始める**。
        *  ゲームの最初: 今と同じく、スタートの音の待ち時間（`BGM_TIMING.startToStageMs`）の後に、ステージの曲とステージの始まりの演出を一緒に始める。待っている間も盤面のタップは無視する。
        *  敵を倒した後: タップでステージの始まりに入った時刻に、新しい敵の曲を流す。
        *  ほかの音のきっかけ（HP が 0 になった瞬間に BGM を止める、クリア・負けの音、攻防の中の音、段取りの操作の音）は変えない。
*   **要件7: 敵を倒した後のつなぎ**
    *  途中の敵を倒した後の案内は、「○○を倒した！」と「タップで次へ」だけにする。**「次は○○」は消す**（発注者の決定。次の敵の名前はステージの始まりで出す）。
    *  タップで次の敵に入れ替わり（今の `startNextPhase` → 攻防の演出のシーンを外す）、ステージの始まり（要件5）→ フェーズの始まり（要件4）と続く。
    *  使われなくなる文字の関数（`nextEnemyText` など）は `js/view/` から片付ける（ルール層の値はそのまま残してよい）。
*   **要件8: 遊び方の文章**
    *  `js/view/howToText.js` の文章を、新しい画面（05-01）と流れ（今回）に合わせて直す。少なくとも次を直す。
        *  「行動終了」を押すと攻防になる → 行動を使い切ると「準備終了」が出て、タップで攻防になる。
        *  残りの回数は右下の「行動終了」ボタンに出る → 戦闘の段と盤面の間の行動のゲージ（5つのブロック）で残りが分かり、金貨で増えた分は金色で出る。
        *  攻防の間の早送り・スキップ → 消す。
        *  城と敵の HP は画面の一番上のゲージ、金貨はその下のゲージ（10 ごとに赤い丸）で分かる。
        *  攻撃・防御・修理の量は、戦闘の段の兵と左上の人数で分かる（「ゲージ」の言い方を合わせる）。
    *  数字（行動の回数・換算など）は、今の `js/rules/config.js` の値を文字で書く（今の決まりのまま）。
    *  ページの数・見出しは、内容に合わせて直してよい。

## 【計画書に必ず含めるべきタスクごとの作業】
AIが作成する計画書（RES）のタスクリストには、個別の実装タスクの後に、以下の作業を必ず含めること。
*   コード修正完了後、JSDocコメントの記載漏れがないことを確認する。
*   タスク完了後、作業レポート（本RESファイル）の詳細作業内容を記載し完成させる。
*   開発資料（`PROJECT_ARCHITECTURE.md`）の記載に影響が出る場合は、資料本体は修正せず、その旨を『開発資料の更新予定』欄に追記する。

## 【計画書に必ず含めるべき固定タスク】
AIが作成する計画書（RES）のタスクリストには、全実装タスクの後に、以下のタスクを必ず含めること。
*   各タスクで記録した『開発資料の更新予定』を確認し、開発資料（`PROJECT_ARCHITECTURE.md`）へ反映する。開発資料に影響を与えない場合は、このタスクは不要とする。反映する内容は次のとおり。
    *   3章の処理の流れ: 準備終了 → タップ → BATTLE! → 攻防、フェーズ・ステージの始まり、タップを無視する間、ステージの曲の始まり
    *   ロゴ・数字のスプライト: 17 個のファイルと、エディタで描くときの約束（原点が中心、倍率 1、数字の枠の大きさ）
    *   スプライトの一覧
    *   効果音の一覧（新しい2つの名前）
    *   4章の責務の表（新しく作る・責務の変わったファイル）
    *   ※ 実装AIによる開発資料の書き換えは、本ワークフローにおいて原則禁止であるが、**この最終タスクのみ明示的な例外とする**。後続タスクが存在せず、資料の変更によって他タスクの前提が動く危険がないためである。個別の実装タスク内で資料を書き換えてはならない。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : `PROJECT_CONSTITUTION.md` の絶対禁止事項に反する設計をしてはならない。
    *   描画（`js/view/`）は状態を変えず、ルール層（`js/rules/`）を実行時に import しない。
    *   時間で進む動き（ロゴの出方・敵の入り方・演出の長さの時計）は `js/anim/` に置く。`js/anim/` は描画も状態の変更もしない。
    *   配置（座標と大きさ）は `js/view/layout.js` に置く。
    *   シーンはルールの判定や計算を書かず、ルール層の問い合わせを使う。
    *   シーンの切り替えは、今のエンジンの `Engine.pushScene`・`Engine.popScene`・`Engine.changeScene` だけで作る。
*   **スプライトの扱い** :
