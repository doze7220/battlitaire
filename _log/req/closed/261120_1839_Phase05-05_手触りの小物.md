## 【実装要件】
試遊で見つかっている小さな引っかかりを片付ける。放った直後の待ち、兵の重なり、使われなくなった早送り・スキップの仕組み、兵の動きと突撃の当たりがほぼ同時にそろってしまうこと、の4つである。

* **ルールは変えない**（ルール層 `js/rules/` は変更しない）。
* タイトルからクリア・負けまで、通しで遊べること。スマホの縦画面を優先し、PC でも同じように遊べること。

*   **要件1: 放った直後の待ちを短くする**
    *  今は、放った直後、札が下から順に全部玉に変わるまで、盤面のタップを受け付けない。待ちは最大で約 0.8 秒（`orbStartDelayMs` 120 + `orbConvertMaxMs` 700）。
    *  札が玉に変わる**ずらしを詰めて**、待ちを**最大で約 0.4 秒**にする（発注者の決定）。
    *  直すのは `js/anim/animConfig.js` の設定の値だけにする（`orbConvertStaggerMs`・`orbConvertMaxMs` など。どの値をいくつにするかは計画で決める）。玉に変わる仕組み・タップを無視する仕組みは変えない。
    *  連鎖の音（札が1枚玉に変わるたびに鳴る、だんだん高くなる音）は、今のとおり玉に変わる時刻に合わせて鳴る（間隔が詰まるだけ）。連鎖の音の音程の決まりは変えない。
    *  玉が上る・合体する・式・飛ぶ・弾ける時間は変えない。
*   **要件2: 兵を縦にばらけさせる**
    *  今は、陣地の足元の範囲が、地面の線の上 96px〜下 2px（高さ約 98px）しかない。兵が多いと、小さな兵が重なって見づらい。
    *  陣地の**縦の範囲を今より広く取り**、兵が縦にばらけて並ぶようにする（発注者の決定）。
        *  目安は、今の 1.5〜2 倍程度。地面の線より下（手前）にも広げてよい。
        *  値は `js/view/layout.js` の定数（`CAMP_FOOT_ABOVE`・`CAMP_FOOT_BELOW` など）で決め、試遊で決め直す値と書く。
    *  守ること:
        *  兵の足元は、戦闘の段の地面の中（段の下端 y 360 より上。下の行動のゲージの帯にかからない）に収める。
        *  兵が空（上 60px）に入らない。
        *  人数の表示の枠（05-04 で最上部のゲージの下へ下げた）と重ならない。
        *  城の絵・敵の絵と兵が前後に重なるときの見え方が不自然にならないようにする。手前（足元の y が大きい）の兵ほど手前に描く、など。今の描く順を確かめ、必要なら計画で直す。
    *  攻撃・防御・修理・敵の側の陣地（`TROOP_CAMPS_X` の4つ）に同じ考え方を当てる。横の範囲（x）は変えない。
    *  ゴブリンの群れ（敵の絵の代わりの群れ。`hordeSlots`）の並びは変えない。
    *  攻防の演出で、兵が陣地から出ていく・当たる・帰る動きが、広げた縦の範囲でもおかしく見えないようにする。たとえば、地面の線より手前の兵が敵や城に当たるときの高さ・位置。
        *  時間割（いつ動くか）は、要件4・5 のばらつき・ずらしのほかは変えない。
        *  動きの位置の計算で陣地の y を前提にしている所があれば、計画で洗い出す。
*   **要件3: 使われなくなった早送り・スキップを片付ける**
    *  05-01 で早送り・スキップのボタンをなくしたが、演出の内側に仕組みが残っている。どれも今は呼ばれていない。これを消す。
        *  `js/anim/battleDirector.js` の `skip()`・`skipped`（`isReadyToLeave()` の「スキップならすぐ」の分岐を含む）・`wallTimeAt` の import と、JSDoc・コメントの「スキップ」の記述
        *  `js/anim/hitStop.js` の `wallTimeAt`（ほかに使う所がなければ）
        *  `js/anim/battleAnimConfig.js` の `fastScale` と、「早送り」の記述
    *  消す前に、`js/` 全体を grep して、ほかに使う所がないことを確かめる。
    *  見た目・音・演出の時間は変えない（使われていないものを消すだけ）。

*   **要件4: 兵の動きにばらつきを入れる**（発注者の追加）
    *  今は、兵が出る・進む・跳ぶ動きの時刻が、ほぼそろっている。
        *  攻防で前から順に出る遅れは、1体 12ms・広がり全体で最大 300ms（`moveStaggerMs`・`moveStaggerMaxMs`）。進む時間（`marchMs`）は全員同じ。
        *  段取りの間に陣地へ跳ぶ遅れは、1体 10ms・最大 300ms（`landStaggerMs`・`landStaggerMaxMs`）。
    *  兵1体ごとに、**動き出す時刻と動きの速さに、もう少し大きなずれ（タイムラグ）を入れて**、群れがばらけて見えるようにする。
        *  対象は、攻防の演出で兵が陣地から出ていく・進む・帰る動きと、段取りの間に兵が陣地へ跳ぶ動き。
        *  ずれは、乱数ではなく、兵の番号などから決まる値で作る（同じ入力なら毎回同じ動きになる。今の `campSlot` と同じ考え方）。
        *  ずれの大きさ（広がりの上限・速さのばらつきの幅）は設定の値（`js/anim/battleAnimConfig.js` など）にし、試遊で決め直す値と書く。
        *  目安: 動き出しの広がりは今の 2〜3 倍程度。速さのばらつきは ±15% 程度。
    *  ばらつきを入れても、攻防の結果は変わらない（見せ方の時刻が変わるだけ）。
*   **要件5: 突撃の当たりをばらけさせる**（発注者の追加）
    *  今は、攻撃の兵が敵へ突撃して当たる時刻がほぼ同時で、ダメージの数字（「-1」）がほぼ同じタイミングで一度に出てしまう。
    *  攻撃の兵が敵に当たる時刻を、**1体ずつ少しずつずらし**、ダメージの数字・ヒットマーク・当たりの音が、ぱらぱらと続けて出るようにする。
        *  参考: 敵の側の打撃（防御の兵・城に当たる）は、すでに1つずつ間隔を空けて当たっている（`strikeStaggerMs` 90・`strikeStaggerMaxMs` 1200）。これと同じくらいの感触を目安にする。
        *  当たりの間隔・広がりの上限は設定の値にし、試遊で決め直す値と書く。兵が多いときに演出が長くなりすぎないよう、広がり全体に上限を設ける。
    *  次のものは、どれも**ずらした当たりの時刻に合わせて**出る。今と同じく、時間割（`battleTimeline.js`）が記録した当たりの時刻から作られていることを確かめ、ずれないようにする。
        *  敵の HP の表示値（最上部のゲージと数字）の減り
        *  ダメージの数字・ヒットマーク・白い光・粒・ヒットストップ
        *  当たりの音
        *  シールドで止められる兵（敵の防御・常時防御力で相殺される当たり）
    *  当たりの合計の数・攻防の結果は変わらない。
    *  攻撃の兵と敵の兵がぶつかる相打ち（`clash`）、修理の兵の動き、敵の攻撃の時刻も、ずらしを入れてよい。入れるかどうかは計画で決め、RES に書く。決める基準は、全体の流れと音のきっかけが崩れないこと。
    *  ばらつき・ずらしで、攻防の演出全体の長さが少し延びてよい。どれくらい延びるかの見積もりを RES に書く。

### 今回は扱わないもの（発注者の決定）

    *   4章の責務の表のうち、`battleDirector.js`・`hitStop.js`・`battleAnimConfig.js` の行（スキップ・早送りの記述を消す）

    *   ※ 実装AIによる開発資料の書き換えは、本ワークフローにおいて原則禁止であるが、**この最終タスクのみ明示的な例外とする**。後続タスクが存在せず、資料の変更によって他タスクの前提が動く危険がないためである。個別の実装タスク内で資料を書き換えてはならない。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : `PROJECT_CONSTITUTION.md` の絶対禁止事項に反する設計をしてはならない。
    *   描画（`js/view/`）は状態を変えず、ルール層（`js/rules/`）を実行時に import しない。
    *   配置（座標と大きさ）は `js/view/layout.js` に置く。
    *   時間で進む動きは `js/anim/` に置く。`js/anim/` は描画も状態の変更もしない。
    *   演出の時間の数値は、`js/anim/animConfig.js`・`js/anim/battleAnimConfig.js` などの設定のファイルにだけ書く。
*   **ルールと演出を変えない** :
    *   `js/rules/` は変更しない。
    *   要件の外の動きは変えない。次のものがそれにあたる。
        *   攻防の演出の時間割（要件4・5のばらつき・ずらしは除く）
        *   音のきっかけの種類（鳴る時刻が当たりに合わせて動くのは除く。連鎖の音の間隔が詰まるのも除く）
        *   カードの動き、合図の演出、最上部のゲージ・予告・人数の表示
    *   乱数（`Math.random` や、ルール層の乱数）を演出に使わない。ばらつきは番号などから決まる値で作る。
*   **1ファイル1責務** : 変えるファイルの責務を広げない。描く順を直す場合も、責務に合うファイルで直す。
*   **先回り実装の禁止** : 次のものは作らない（05-06 か未定）。
    *   合図の長さの変更、演出を飛ばす操作
    *   放った列以外を玉に変わる途中でも触れるようにすること
    *   兵の大きさ・数の上限の変更
    *   兵の重なりを避ける並べ直しの仕組み（今の決まった並び（`campSlot`）のまま、範囲を広げるだけ）
    *   ヒットマークの絵
    *   効果音の差し替え、起動時のロードの表示
*   **エンジンの使い方** :
    *   `oz` は `import { … } from 'oz'` でだけ使う。
    *   `js/` に `addEventListener`・`requestAnimationFrame`・`getContext`・`setTimeout`・`setInterval`・`performance.now()`・`Date.now()` を書かない。
*   **変更してよい範囲** :
    *   変更してよいもの: `js/anim/`・`js/view/`・`js/scenes/` の中のファイル。どのファイルを変えるかは計画に明記すること。
    *   変更しないもの: `js/rules/`・`js/audio/`・`oz/`・`index.html`・`js/main.js`・`js/ui/`・`assets/`。
    *   これら以外の変更が必要だと分かった場合は、計画の中で理由を書いて対象に加えないこと。RESの懸念事項に記して、発注者の判断を仰ぐこと。
*   **テストプレイで確かめること（計画の最後に、発注者が見る点として書くこと）**
    *  列の札を放つと、札が玉に変わり終わるのが今より早く（最大でおよそ 0.4 秒）、すぐ次の操作ができる。連鎖の音は、玉に変わるのに合わせて鳴る。
    *  兵が陣地で、今より縦にばらけて並ぶ。兵がたくさんいても、重なりが今より少ない。
        *  兵が空・行動のゲージの帯・人数の表示にはみ出さない。
        *  城や敵の絵との前後の重なりが自然に見える。
    *  攻防の演出で、兵が出ていく・当たる・帰る動きが自然に見える（手前の兵も、奥の兵も）。
    *  兵が出る・進む・陣地へ跳ぶ動きが、そろわずにばらけて見える。
    *  攻撃の兵が敵に当たるのが少しずつずれていて、ダメージの数字・ヒットマーク・当たりの音がぱらぱらと続けて出る。敵の HP のゲージと数字も、当たるたびに減る。
    *  攻防の結果（HP の増減・決着）は今と同じ。演出が長くなりすぎていない。
    *  スマホの縦画面と PC で、タイトルからクリア・負けまで通しで遊べる。
