## 【実装要件】
いまのドラゴンは、03-01 で入れた仮の行動（攻撃・防御のスタンスの重みによる抽選）と仮の玉で出ている。今回は、ドラゴンを「爪攻撃でブレスチャージを溜め、満ちたら確率でブレスを撃ち、ブレスで盤面の列の札を燃やす」最後の敵に作り変える。ゴブリンの軍勢・巨人の行動と見た目は変えない。

*   **要件1: ドラゴンの行動の決まり（爪・ブレス・ブレスチャージ）**
    *  ドラゴンの行動は「爪攻撃」と「ブレス攻撃」の2種類だけで、防御のスタンスは取らない。どちらも、ほかの行動と同じく1フェーズ前に予告される。常時防御力はいまどおり働く。
    *  ドラゴンはブレスチャージ（溜まった数）を持つ。爪攻撃を1回撃つ（その爪攻撃の攻防が行われる）ごとにチャージが 1 溜まる。チャージは満ちる数を超えない。ドラゴンが出たときのチャージは 0。
    *  チャージが満ちる数に届いていない間は、毎フェーズ爪攻撃を予告する。チャージが満ちた後は、毎フェーズ一定の確率でブレスを予告し、予告しなければ爪攻撃を予告する（満ちたまま増えない）。ブレスを撃つとチャージは 0 に戻る。
    *  初期値（仮。03-05 で調整する。`js/rules/config.js` のドラゴンの設定に置き、そこを書き換えるだけで変えられる）: 爪の攻撃力 10、ブレスの攻撃力 35、満ちる数 4、満ちた後にブレスを予告する確率 50%、燃やす札の枚数 4〜6 枚（最小と最大）、常時防御力 15（いまのまま）、最大 HP 120（いまのまま）。ドラゴンの仮の行動の設定（重みつきの攻撃・防御のスタンス）は、この決まりの設定に置き換える。
    *  ドラゴンの行動の決まりは、`js/rules/enemyBehaviors.js` の表に新しい決まりの種類として足す（決まりの状態の初期値と次の行動の決め方）。ゴブリンの軍勢の重みによる抽選・巨人の周期の決まりは変えない。乱数は外から渡されたもの（`Game` の `random`）だけを使う。
*   **要件2: ブレスチャージと予告の表示**
    *  戦闘の段に、ドラゴンと戦っている間は常に、ブレスチャージが「ブレス 1/4」のような形（溜まった数／満ちる数）で出る。満ちているときは、満ちていることが分かる見た目（色を変える等）にしてよい。巨人の数え下ろしと同じ位置・枠を使ってよい。文字が枠からはみ出さないこと。位置は `js/view/layout.js` から求める。
    *  予告の枠は、爪攻撃なら「爪」、ブレスなら「ブレス」と、攻撃の種類が分かる表示に量をつけて出す（例:「爪 10」「ブレス 35」）。ブレスの予告は、爪より目立つ見た目にしてよい。
    *  チャージの表示は、爪攻撃の攻防の演出の中で爪が城に当たったときに 1 増えて見え、ブレスが城に当たったときに 0 に戻って見える（演出の前に先に変わって見えないこと）。
    *  ゴブリンの軍勢・巨人と戦っている間は、ブレスチャージは出ない（巨人の数え下ろしはいまどおり）。
*   **要件3: ブレスで札を燃やす（ルール）**
    *  ブレスの攻防では、城へのダメージに加えて、盤面の列の札を燃やす。燃やす枚数は、設定の最小〜最大の範囲から外から渡された乱数で決める。
    *  1枚ごとに、**札が1枚以上ある列の中から**ランダムに1本を選び、その列の一番上（上に乗っている側）の1枚を燃やす。これを枚数分くり返す（同じ列が続けて選ばれてよい）。列の途中の札は燃えない。燃やしている途中で、列の札がすべてなくなったら、残りの枚数は燃やさずにそこで止まる。
    *  燃えた札はすぐ捨て札へ移る。燃やすのは列の札だけで、山札・手札・捨て札は燃やさない。
    *  ブレスで城の HP が 0 になったときは、そこでゲームオーバーとして決着し、札は燃えない。
    *  燃やす順番は、ブレスが城に当たった後、自軍の攻撃より前とする。燃えたことは、このフェーズの自軍の攻撃（段取りで溜めたゲージ）の量を変えない。
    *  ルール層の攻防は、いまどおり「行動終了」の時点で一度に結果を決める。燃えた札（どの列の、どの札が、どの順で燃えたか）は、攻防の出来事の並びに独立した出来事として入る（燃えた札がなければ入らない）。
    *  「ブレスで札を燃やす」を、ドラゴン専用の分岐として `js/rules/battle.js` や `js/rules/Game.js` に直書きせず、03-02 の攻撃の直後の回復（`attackHeal`）と同じく、行動の決まり・行動の設定から読み取る形にすること。
*   **要件4: 札が燃える見せ方**
    *  攻防の演出で、ブレスの城への被害の段の後、自軍の突撃の前に、札が燃える段が入る。燃える札は、燃える順に1枚ずつ赤く光って（明滅して）から、捨て札の位置へ飛んでいく。捨て札の枚数は、札が着くごとに1枚ずつ増えて見える。
    *  燃える段に入るまで、燃える札は列の元の位置にそのまま見えていること（「行動終了」を押した時点で列から消えて見えないこと）。燃えて飛んだ後は列から消え、その下の札が列の一番上として見える。
    *  効果音は、1枚燃えるごとに、いまの「捨てる」の音を当ててよい（`js/audio/` は変えない）。
    *  早送り・スキップでも、いまの段と同じように扱われる（スキップしたら、燃えた後の盤面になる）。
*   **要件5: ドラゴンの見た目**
    *  戦闘の段のドラゴンは、大きな赤い玉（仮の図形）で描かれる。大きさは巨人の玉と同じでよい。常時防御力のシールドマーク（15個）は、いまどおり玉に重ねて見え、はみ出さない（大きな玉に合わせて並べ直してよい）。
*   **要件6: ほかは変えない**
    *  上に書いたこと以外の、段取り（カードの操作と動き）・攻防の演出（兵の動き・早送り・スキップ・速さ）・敵の入れ替わり・決着・音の挙動は変えない。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : `PROJECT_CONSTITUTION.md` の絶対禁止事項に反する設計をしてはならない。ドラゴンの行動の決まり・ブレスチャージの状態・燃やす枚数と燃やす札の選び方と列・捨て札の変更はルール層（`js/rules/`）に置き、画面・エンジンに触れない。描画の側（`js/view/`）・演出（`js/anim/`）・シーン（`js/scenes/`）は、ルール層の状態（ブレスチャージを含む）と攻防の結果を読むだけで、書き換えない。ブレスチャージの値は、描画の側で計算し直すのではなく、ルール層から読める形にする。
*   **行動の決まりの拡張性** : ドラゴンの決まりは `js/rules/enemyBehaviors.js` の表に、既存の決まり（`weighted`・`cycle`）を壊さずに足す。行動に付く効果（ブレスで燃やす）は、行動の設定の任意の項目から読み取る形にし、`battle.js`・`Game.js` で敵の種類で分岐しない。予告の種類（爪・ブレス）の増やし方は、`js/rules/battle.js` の攻撃の扱い（城へのダメージ）を種類ごとに重複させない形にすること（例: 攻撃の系統として扱う、など。計画で決めてよい）。
*   **演出中の盤面の見え方** : 攻防の演出中も盤面（列・捨て札の枚数）は描かれている。ルール層の列・捨て札は「行動終了」の時点で燃えた後の状態になるため、燃える段までの盤面の見え方（燃える札を元の位置に見せ、捨て札の枚数を燃える前の値で見せる）は、03-02 で HP を攻防の前の値の写しから見せたのと同じ考え方で、演出の側が攻防の前の写しと出来事から作る。ルール層の状態を巻き戻したり、演出のために書き換えたりしない。
*   **配置は `layout.js` から読む** : ブレスチャージの表示の位置、ドラゴンの玉の大きさ、燃える札が飛ぶ先（捨て札の位置）は、`js/view/layout.js` の配置から求める（必要なら `layout.js` に足す）。描画・演出・シーンのファイルに座標の数値を直書きしない。
*   **時刻の式の二重化に注意** : 攻防の当たり・修理の時刻の式が `js/anim/battleCues.js` と `js/anim/battleTimeline.js` の2か所にある（`_doc/COWORK_STATUS.md`、03-01・03-02 RES 5章）。燃える段とチャージの表示の変わる時刻を足すときは、両方を合わせて直す計画にする（または1か所にまとめる計画にしてもよい。その場合は理由を書く）。
*   **先回り実装の禁止** : 結果の画面と集計、タイトル画面（TITLE）の分離、最高記録の保存、敵の絵、敵ごとの演出の変化、特殊行動（毒・呪いカード・山札の封じ等）、BGM、炎の粒などの凝った演出は作らない。
*   **エンジンの使い方** : 動きは `Scene` の `update(dt)` で進め、`draw` の中でシーンの状態を変えない（`oz/ENGINE_API.md`）。シーンの操作と `Engine.timeScale` の変更は `update`・`onPointer` の中で行う。`js/` に `addEventListener`・`requestAnimationFrame`・`getContext`・`setTimeout`・`setInterval` を書かない。必要な機能がエンジンにないときは、回避策を書かずにRESに記録して作業を止める。
*   **変更してよい範囲** : 変更・追加してよいのは `js/rules/`・`js/anim/`・`js/view/`・`js/scenes/` の中のファイルとする（どのファイルを変えるかは計画に明記すること）。`oz/`・`index.html`・`js/main.js`・`js/ui/`・`js/audio/`・`assets/` は変更しない。変更が必要だと分かった場合は、計画の中で理由を書いて対象に加えるのではなく、RESの懸念事項に記して発注者の判断を仰ぐこと。
*   **1ファイル1責務** : 行動の決まり、攻防の計算、札を燃やすこと、敵の進行を、1つのファイルに詰め込みすぎない（`js/rules/Game.js`・`js/rules/battle.js` を肥大化させない）。新しいファイルを作る場合は、先頭に責務定義を書く。
