## 【実装要件】
初めて遊ぶ人が、ゲームの外でルールの説明を受けなくても遊べるように、タイトル画面から開く「遊び方」の画面を足す。数ページをめくって読む形で、文字だけ（図は入れない）。**ゲームのルール・設定の値は変えない。**

*   **要件1: タイトル画面に「遊び方」ボタンを置く**
    *  タイトル画面の「はじめる」ボタンの下に「遊び方」ボタンを置く。「はじめる」と同じ幅で、「はじめる」より控えめな見た目（塗りを薄くする・縁だけにする、など。計画で決める）にする。押せる範囲の高さは 80 以上とする。
    *  押し方は「はじめる」と同じく、**このシーンで押して、ボタンの中で離したとき** に開く（前の画面で押した指を離しただけでは開かない）。
    *  Enter・Space は今のまま「はじめる」（盤面へ進む）。「遊び方」にキーを割り当てるかは計画で決めてよい（割り当てるなら Enter・Space 以外）。
    *  遊び方はタイトル画面からだけ開く。プレイ中（盤面・攻防の演出）には開く口を作らない。
*   **要件2: 遊び方の画面（ページをめくる）**
    *  1ページ＝1つの話題。ページは下の【遊び方の文章】の7ページで、この順に並べる。
    *  各ページに、見出し（ページの題）・本文・今のページ番号（例: 「2 / 7」）を出す。
    *  画面の下に「まえへ」「つぎへ」「タイトルへ」のボタンを置く。最初のページでは「まえへ」、最後のページでは「つぎへ」を、押せない見た目（薄くする）にし、押しても何も起きない。「タイトルへ」はどのページでも押せて、タイトル画面へ戻る。ボタンは押して離したときに働く（タイトル画面と同じ）。押せる範囲の高さは 80 以上とする。
    *  PC 向けに、キーの ← と → でページを移り、Escape でタイトル画面へ戻る。
    *  遊び方を開くと、毎回1ページ目から始まる。
    *  効果音は鳴らさない（タイトル画面も鳴らしていないため）。
*   **要件3: スマホの縦画面で読める文字の大きさ**
    *  論理解像度 720×1280 の画面で、本文の文字は **32px 以上**、見出しはそれより大きく（44px 前後）する。行の間隔は文字の大きさの 1.4〜1.6 倍程度。左右の余白は 40px 前後。
    *  本文は、画面の幅に収まるように自動で折り返す（文字の幅を測って、1文字単位で折り返してよい）。行頭に「、」「。」「）」「」」が来ないようにする（前の行の末尾に付ける）。文章の中の改行（段落の区切り・箇条の区切り）は、そのまま改行として扱う。
    *  どのページも、見出しからボタンの上までの範囲に収まること。収まらないページがあった場合は、文字を 32px 未満に縮めたり、文章を勝手に削ったりせず、行の間隔を詰めてよい範囲（1.4 倍まで）で詰め、それでも収まらなければ、どのページがどれだけはみ出すかを RES の懸念事項に書いて発注者の判断を仰ぐ。
    *  背景・色はタイトル画面の暗い背景に合わせる。
*   **要件4: 文章は1か所にまとめる**
    *  遊び方の文章（ページの見出しと本文）は、新しい1つのファイル（`js/view/titleText.js` と同じ作りの、凍結した定数だけを持つファイル）にまとめる。発注者が後で文章を直すときは、このファイルだけを書き換えれば済むようにする（ページを1つ足す・消す・並べ替えることも、このファイルの中だけで済むこと。ページ数は数えて出す）。
    *  文章の中の数字（1〜7、行動 5 回、最大 +6、金貨 5 ごと・最大 +2、城の HP 50 など）は、今の `js/rules/config.js` の値に合わせて **文字として書く**（設定の値から組み立てない）。設定の値を変えたときは、この文章も手で直す必要があることを、文章のファイルの先頭の責務のコメントに一言書き、`PROJECT_ARCHITECTURE.md` にも書く（開発資料の更新予定に挙げる）。
    *  「遊び方」「まえへ」「つぎへ」「タイトルへ」などのボタンの文字も、画面に出す文字としてどこに置くか計画で決める（タイトル画面の「遊び方」は `js/view/titleText.js` に足すのが自然）。
*   **要件5: 今と同じく使えること**
    *  タイトル画面の「はじめる」・Enter・Space で今と同じく盤面へ進み、タイトルからクリア・負けまで通しで遊べる。決着の後はタイトル画面へ戻り、そこからまた遊び方を開ける。

## 【計画書に必ず含めるべき固定タスク】
AIが作成する計画書（RES）のタスクリストには、全実装タスクの後に、以下のタスクを必ず含めること。
*   各タスクで記録した『開発資料の更新予定』を確認し、開発資料（`PROJECT_ARCHITECTURE.md`）へ反映する（画面の流れに遊び方の画面を足すこと、タイトル画面の説明、遊び方の文章のファイルと「設定を変えたら文章も直す」こと、新しく作る・責務の変わったファイルの表など）。開発資料に影響を与えない場合は、このタスクは不要とする。
    *   ※ 実装AIによる開発資料の書き換えは、本ワークフローにおいて原則禁止であるが、**この最終タスクのみ明示的な例外とする**。後続タスクが存在せず、資料の変更によって他タスクの前提が動く危険がないためである。個別の実装タスク内で資料を書き換えてはならない。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : `PROJECT_CONSTITUTION.md` の絶対禁止事項に反する設計をしてはならない。遊び方の画面は新しいシーン（`js/scenes/`）にし、今のページの番号はシーンが持つ。描画（ページの見出し・本文の折り返し・ボタン）は `js/view/` に置き、状態を変えない。配置（ボタンの矩形・本文の範囲）と当たり判定は `js/view/layout.js` の今の作り（`createTitleLayout` と同じ形）に合わせる。当たり判定は `Engine.addButton` を使わず、配置の当たり判定で行う（今のタイトル画面と同じ）。
*   **画面の切り替え** : タイトル画面 → 遊び方 → タイトル画面の切り替えは、今の作り（`js/main.js` がシーンを作る関数を持ち、互いに渡す）に合わせる。遊び方の画面を作る関数をタイトル画面に渡し、遊び方の画面にはタイトル画面を作る関数を渡す。BOOT・盤面の流れは変えない。
*   **ルールを変えない** : `js/rules/` は読むだけで変更しない。ルールの判定や計算を画面の側に書き写さない（遊び方の文章は文字として持つだけ）。
*   **先回り実装の禁止** : 図・スプライト・アニメーション・ページをめくる動き・効果音・BGM・プレイ中のメニュー・スクロール・言語の切り替え・「初回だけ自動で開く」などは作らない。タイトル画面の作り直し（P5 で扱う）もしない（「遊び方」ボタンを足すのに必要な配置の変更だけにする）。
*   **エンジンの使い方** : 入力は `Scene` の `onPointer`・`onKeyDown` で受け、シーンの切り替えは `oz/ENGINE_API.md` に書かれた方法で行う。`draw` の中でシーンの状態を変えない。`js/` に `addEventListener`・`requestAnimationFrame`・`getContext`・`setTimeout`・`setInterval`・`performance.now()`・`Date.now()`・`Math.random` を書かない。`ctx` の状態を変える描画は `save`／`restore` で囲む。
*   **変更してよい範囲** : 変更してよいのは `js/main.js`・`js/scenes/TitleScene.js`・`js/view/titleView.js`・`js/view/titleText.js`・`js/view/layout.js` と、新しく作るファイル（`js/scenes/` の遊び方のシーン、`js/view/` の遊び方の描画・遊び方の文章）とする（どのファイルを変えるかは計画に明記すること）。`js/rules/`・`js/anim/`・`js/audio/`・`js/ui/`・`oz/`・`index.html`・`assets/`・`_doc/` は変更しない。これら以外の変更が必要だと分かった場合は、計画の中で理由を書いて対象に加えるのではなく、RESの懸念事項に記して発注者の判断を仰ぐこと。
*   **1ファイル1責務** : `js/view/layout.js` を肥大化させない（遊び方の配置は `createTitleLayout` と同じくらいの大きさの関数1つに収める。収まらなければ別のファイルに分ける）。文章のファイルは文字の定数だけを持ち、描画・折り返しの処理を書かない。
*   **テストプレイで確かめること（計画の最後に、発注者が見る点として書くこと）**
    *  タイトル画面の「はじめる」の下に「遊び方」ボタンがあり、押して離すと遊び方の1ページ目が開く。「はじめる」・Enter・Space は今と同じく盤面へ進む。
    *  7ページを「まえへ」「つぎへ」（PC では ← →）で行き来でき、ページ番号が「1 / 7」〜「7 / 7」と出る。最初のページの「まえへ」、最後のページの「つぎへ」は薄く、押しても何も起きない。
    *  「タイトルへ」（PC では Escape）でタイトル画面へ戻り、もう一度開くと1ページ目から始まる。
    *  スマホの縦画面で、本文が無理なく読める大きさで、どのページも画面に収まり、文字がはみ出したり重なったりしない。行頭に「、」「。」が来ない。
    *  文章が【遊び方の文章】のとおりに出る。
    *  タイトルからクリア・負けまで今と同じく通しで遊べ、決着の後のタイトル画面から、また遊び方を開ける。
