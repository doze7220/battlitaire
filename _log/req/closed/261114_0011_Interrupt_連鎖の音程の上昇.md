## 【実装要件】
### 1. 連鎖の音を、何枚目かに応じて高くする
* `js/scenes/soundCues.js` の `playChainSe(ordinal)` で、`ordinal`（何枚目か。1 始まり）から再生速度 `rate` を決め、`Sound.playSe(CHAIN_SE, { rate })` で鳴らす（`oz/ENGINE_API.md` 21章。`rate` は音程と長さが一緒に変わる。半音は `2 ** (半音の数 / 12)`）。
* 上がり方: 1枚目は元の高さ（`rate` = 1）。2枚目から1枚ごとに「1段の半音の数」ずつ高くする。上げ幅は「上限の半音の数」で頭打ちにし、それより後の枚は上限の高さのまま鳴らす。
  * 式: `半音の数 = min((ordinal - 1) * 1段の半音の数, 上限の半音の数)`、`rate = 2 ** (半音の数 / 12)`。
* `ordinal` から `rate` を決める部分は、`Sound` を呼ばない純粋関数（例: `chainSeRate(ordinal)`）に分け、`playChainSe` はそれを使って鳴らすだけにする（`planningSeName` と `playPlanningSe` の分け方と同じ）。
* `ordinal` が 1 未満・整数でない・数値でないなど、ありえない値で来たときは、エラーにせず元の高さ（`rate` = 1）で鳴らす（`Sound.playSe` の `RangeError` でループが止まらないようにするため。いまの呼び出し元は必ず 1 以上の整数を渡す）。
* `playChainSe` の JSDoc の「今は使わない」の説明を、今の作りに合わせて直す。`void ordinal;` は消す。

### 2. 上がり方の調整値を設定のファイルにまとめる
* `js/audio/soundConfig.js` に、連鎖の音程の調整値を凍結したオブジェクトで足す（名前は実装AIに任せる。例: `CHAIN_PITCH`）。
  * 1段の半音の数: 初期値 `2`（1枚ごとに全音ずつ上がる）。
  * 上限の半音の数: 初期値 `12`（1オクターブ上で頭打ち。7枚目以降は同じ高さ）。
  * どちらも JSDoc に意味と「試遊で決め直す」ことを書く。
* `soundCues.js` は、この調整値を `soundConfig.js` から import して使う。`soundConfig.js` は今までどおり値だけを持ち、何も import しない。先頭の責務定義に、連鎖の音程の調整値を持つことを足す（3行以内）。

### 範囲外（やらないこと）
* 連鎖の音のファイル（`assets/sounds/chain.wav`）・生成スクリプト（`tools/makeSounds.mjs`）の変更。音程違いのファイルを作ること。
* 連鎖の鳴る時刻・回数の変更（`js/anim/`・`js/scenes/BoardScene.js` は変えない）。
* ほかの効果音の音程の変更、音量の変更。
* ルール層（`js/rules/`）の変更。

## 【関連する責務】
* `js/scenes/soundCues.js`: 段取りの操作・連鎖・行動終了・攻防のきっかけ・決着から鳴らす効果音を決め、`Sound.playSe` で鳴らす（シーンから呼ばれる音の補助。`Scene` を継承しない）。`Sound.playSe` はこのファイルの関数の中でだけ呼ぶ。連鎖の音の名前は定数 `CHAIN_SE`（`'chain'`）。
* `js/audio/soundConfig.js`: 効果音の名前とパスの一覧（`SOUND_FILES`）と SE の音量の初期値（`SE_VOLUME`）を凍結して持つ。値だけを持ち、`oz` も `js/` のほかのファイルも import しない。音を鳴らさない。
* `js/scenes/BoardScene.js`: `update(dt)` で `BoardAnimator` を進めた直後に、`chainCuesInLastUpdate()` が返す序数（1 始まり、昇順。放つ操作1回ごとに 1 から数え直す）ごとに `playChainSe(ordinal)` を呼ぶ。今回このファイルは変えない。
* 放った束の連鎖（02-04 RES 要件3）: 放ったカードが1枚ずつ捨て札に着いた時点で、連鎖の音を1回ずつ鳴らす。着く時刻の早い順に「1枚目、2枚目、…」と数える。
* 演出・音はルール層の状態を変えず、ゲームの結果は変わらない。
