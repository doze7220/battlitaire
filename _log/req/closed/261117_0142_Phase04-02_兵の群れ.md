## 【実装要件】
攻防の演出で、自軍の兵を **1人＝1体** で描き、役割ごとの陣地に並べ、相打ちやダメージの後に **ぽこんと跳ねてから画面の下へ落ちて消える** ようにする。**ルールは変えない。** 攻防の出来事の並び（ルール層が出した結果）を、演出の時間に合わせて見せ方だけを作り変える。演出の途中・早送り・スキップのどれでも、ルールの結果は変わらない。

用語: 自軍の兵は3種類。**防御の兵**（いまの守備兵。盾）、**攻撃の兵**（いまの兵士。剣）、**修理の兵**（いまの大工。ハンマー）。数はそれぞれ攻撃・防御・修理（識別子 `heal`）のゲージの量と同じ。

*   **要件1: 1人＝1体**
    *  自軍の兵の数は、ゲージの量と同じにする。「大きな1体で10人分」のまとめ方（`BATTLE_ANIM.unitSize`・`splitUnits`・大きなユニットの描き方）はやめ、すべて1体ずつ描く。端数が減ったときに、大きな兵が割れて小さな兵に変わって見えないようにするため。
    *  兵の数に上限は設けない（ゲージが 200 を超えても全部描く）。たくさん出したときの重さの確認は、後の Phase のデバッグモードで行うので、今回は数を増やして確かめる仕掛けは作らない。
    *  敵の側の兵（敵兵・敵の守り）も同じく1体ずつにする（大きなユニットを使わない）。敵の側の見せ方の作り直しは後のサブフェイズで行うので、今回は今の流れのまま、1体ずつ描く・相打ちで跳ねて落ちる（要件5）ことだけをそろえる。
*   **要件2: 兵の見た目**
    *  兵は丸い体（`unit_solder.js`、白い丸）に、役割のスートの絵を縮小して持たせる。攻撃の兵は剣（`suit_sword.js`）、防御の兵は盾（`suit_shield.js`）、修理の兵はハンマー（`suit_hammer.js`）だけを持つ。武器は体の前（右）寄りに、体より小さく重ねる（大きさ・位置は定数で調整できること）。
    *  敵の側の兵は今の緑の丸（`unit_goblin.js`）のままでよい（持ち物なし）。
    *  兵の大きさは定数1か所で変えられること。初期値は、いまの小さな兵（直径約 21px）より少し大きい、直径 24px 前後を目安にする（試遊で決め直す）。
    *  スプライトを描く処理は `js/view/spriteView.js` に集めたまま（兵の体と武器を重ねて描く関数を足すなど）。ほかの描画モジュールにスプライトの import を散らさない。
*   **要件3: 陣地**
    *  陣地は、右（敵の側）から順に「防御 → 城 → 攻撃 → 修理」と並べる。
        *  防御の兵は城の前（右）にいて、敵の攻撃を受ける。
        *  攻撃の兵は城の後ろ（左）にいて、突撃のときに城の後ろから敵へ向かって出ていく。
        *  修理の兵は、攻撃の兵のさらに後ろ（左）にいる。
    *  陣地は戦闘の段の地面の上で、奥行き（y）にも広がる範囲にする（クオータービューなので、横一列ではなく、陣地の矩形の中に散らばって並ぶ）。陣地の矩形は `js/view/layout.js` の定数で決め、試遊で動かせること。初期値の目安（城の中心は x 約 240）: 修理 x 約 20〜100、攻撃 x 約 100〜190、防御 x 約 300〜400。y は地面の上の、城の足元の前後（下の HP の枠に大きくかからない範囲）。
    *  兵どうしは重なってよい。**奥（y が小さい）の兵から先に描き**、手前の兵が奥の兵の上に見えるようにする。
    *  兵の位置は **何番目の兵か** で決まる（陣地の中の決まった並び。乱数を使うなら、何番目かから決まる値にし、毎フレーム・毎回の呼び出しで変わらないこと）。毎フレームちらつかない。1体が消えても、ほかの兵は並び替わらない。
    *  城と敵の間の場は、04-01 で約 250px に狭くなっている。防御の兵の陣地と、敵兵とぶつかる位置が重なりすぎないよう、配置を計画で決めること。
*   **要件4: 移動の見せ方**
    *  兵は歩く動きを持たず、**揺れながら**（左右に体を傾ける）、または **弾みながら**（小さく跳ねる）移動する。どちらにするかは試遊で決めるので、演出の設定（`js/anim/battleAnimConfig.js`）の値1つで切り替えられるようにし、両方を作る。初期値は「弾む」。揺れ・弾みの大きさと速さも設定の値にする。
    *  群れが進むとき、兵は陣地の中の並び（相対位置）を保ったまま進む。少しずつ遅れて出るなど、まとまりすぎない見せ方は計画で決めてよい。
*   **要件5: 跳ねて落ちる消え方**
    *  兵は、**相打ちになったとき**（防御の兵と敵兵、攻撃の兵と敵の守り、攻撃の兵と常時防御力のシールドマーク）と、**相手にダメージを与えた後**（敵兵が城に当たった後、攻撃の兵が敵に当たった後）に、ぽこんと上へ跳ねてから画面の下へ落ちて消える。相打ちは1対1で、ぶつかった兵どうしが1体ずつ消える。
    *  落ちていく兵は **戦闘の段の中だけ** に描く（段の矩形で切り抜く）。下のソリティアの段には描かない。
    *  跳ねる高さ・落ちる速さ・ずらしの間隔は演出の設定の値にする。
*   **要件6: 修理の兵と、使われなかった兵**
    *  修理の兵は、修理の段で、陣地から城へ弾みながら（要件4の動き）向かい、1体ずつ城に入って消える。消えるのに合わせて城の HP の表示が増える（増え方の合計はいまどおりルールの回復の量。最大 HP で頭打ちになった分の兵も、同じく城に入って消えてよい）。
    *  使われなかった兵（敵が攻撃しなかったフェーズの防御の兵、相打ちで余った防御の兵など）は、フェーズの演出の終わりに **走って城へ帰って消える**（城の位置へ移動して消える。跳ねて落ちない）。
    *  いまの「余った兵が薄れて消える」（`fadeMs`・`fadeLeftover`）は、自軍の兵については上の消え方に置き換える。
*   **要件7: 人数の表示**
    *  戦闘の段の上端（左上。フェーズの枠と数え下ろしの枠に重ならない位置）に、攻撃・防御・修理の兵の人数をまとめて表示する。各人数の前に、その役割のスートの絵（剣・盾・ハンマー）を小さく出す。
    *  攻防の間、兵が消えるたびに数がその場で減る（落ち始めた時点、または城に入った時点で 1 減る）。スキップすると最後の値になる。
    *  数は、ルールが出した結果を演出の時間に合わせて見せるもので、ルールの値は変えない。
    *  表示は攻防の演出の間に出す。段取りの間に出すかどうかは、出してもよい（同じ値をゲージの行が出している。二重に見えるかは試遊で確かめる）。
*   **要件8: 今と同じく使えること**
    *  早送り・スキップは今と同じく使え、結果は変わらない。音のきっかけ（相殺・当たり・修理・敵の回復・燃える札）の鳴る時点は、新しい見せ方の対応する瞬間（ぶつかった瞬間・当たった瞬間・城に入った瞬間など）に合わせる。
    *  兵が戦闘の段に現れるのは、今と同じく「行動終了」の後（攻防の演出の始め）でよい。札を放つたびに兵が増える見せ方は後のサブフェイズで作る。
    *  常時防御力の段・敵の回復の段・札が燃える段・敵を倒したときの案内・決着の表示は、今の流れのまま動くこと。
*   **要件9: 時刻の式の一本化**
    *  いま、攻防の当たり・修理・常時防御力での相殺・敵の回復の時刻の式が `js/anim/battleCues.js` と `js/anim/battleTimeline.js` の2か所にある（片方を変えたら、もう片方も合わせて直す必要がある）。攻防の演出の時間割を作り直すので、音のきっかけの時刻は **時間割を作るときに記録したものを読む** 形などにして、式を1か所にまとめること（燃える段の `burnCardOffsets` のように）。
*   **要件10: 片付け（触るファイルのついで）**
    *  `js/view/battleShowView.js` の途中の敵を倒したときの案内「タップで次へ」（`DEFEAT_HINT_TEXT`）を、ファイルの中の定数から、文字のまとめ（`js/view/battleText.js`）へ移す。
    *  `js/view/battleShowView.js` と `js/view/battleStageView.js` の先頭の責務定義を、実際にしていることに合わせて直す（今回の変更の後の内容で。例: `battleStageView.js` の「爪・ブレスの種類を目立たせる」は、実際に目立たせるのはブレスだけ）。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : `PROJECT_CONSTITUTION.md` の絶対禁止事項に反する設計をしてはならない。時間で進む動き（兵1体ごとの位置・跳ねて落ちる動き・人数の表示値）は `js/anim/` に置き、ルール層の操作の結果から作る。描画（`js/view/`）は `anim` が作った見た目の値を受けて描くだけで、時間を進めない・状態を変えない。配置（陣地の矩形・兵の大きさ・人数の表示の位置）は `js/view/layout.js` に置く。調整できる時間・高さ・切り替えの値は `js/anim/battleAnimConfig.js` に置く。
*   **ルールを変えない** : ルール層（`js/rules/`）は変更しない。出来事の並び・量・順番はそのまま読む。兵の数・消える数・HP の変化の合計は、ルールの結果と一致させる。
*   **重さへの配慮** : 兵1体ごとの見た目を毎フレーム作り直すときに、1体ごとに大きな配列やオブジェクトをむやみに作らない設計にする（数百体でも動く前提）。並び（何番目の兵がどこにいるか）は攻防の始めに1回だけ求め、毎フレームは時計から位置を計算するだけにするなど、計画で工夫を書くこと。ただし、重さを測る仕掛け・数を増やす仕掛けは作らない。
*   **スプライトの扱い** : `assets/sprites/` を変更しない。スプライトの `draw` 以外のキーを実行時に読まない。スプライトを描く処理は `js/view/spriteView.js` に集める。`ctx` の変換・切り抜きは必ず `save`／`restore` で囲む。
*   **先回り実装の禁止** : 放つ → 光の玉 → 兵（段取りの間に兵が待つこと）、敵ごとの攻防の見せ方（ゴブリンの数と HP の連動・シールドが剥がれる・ヒットマーク・ブレスの炎・巨人とドラゴンが倒れて落ちる）、敵ごとの当たる位置の作り直し、エフェクト（ヒットストップ・白い光・ダメージの数字・粒・揺れ・待っている兵の呼吸・踏み込みの加速・ための動き）、デバッグモード、兵が多すぎるときのまとめ方、ゲージの行の作り替えは作らない。これらは後のサブフェイズ・Phase で扱う。
*   **使われなくなったものの片付け** : 大きなユニットへの換算（`unitSize`・`splitUnits` など）、大きなユニットの配置の項目（`bigW`・`bigH`・`backFootY` など）、自軍の兵の薄れて消える処理など、作り変えで使われなくなる関数・設定・項目は、残さずに消す（呼び出し元と JSDoc も合わせる）。ただし、作り変えと無関係な箇所の「ついでの整理」はしない（要件10の2件は例外として行う）。
*   **エンジンの使い方** : 動きは `Scene` の `update(dt)` で進め、`draw` の中でシーンの状態を変えない（`oz/ENGINE_API.md`）。`js/` に `addEventListener`・`requestAnimationFrame`・`getContext`・`setTimeout`・`setInterval`・`performance.now()`・`Date.now()`・`Math.random`（演出の並びに使う乱数を含む）を書かない。
*   **変更してよい範囲** : 変更してよいのは `js/anim/`・`js/view/`・`js/scenes/` の中のファイル（新しいファイルを含む）とする（どのファイルを変えるかは計画に明記すること）。`js/rules/`・`js/audio/`・`oz/`・`index.html`・`js/main.js`・`js/ui/`・`assets/` は変更しない。これら以外の変更が必要だと分かった場合は、計画の中で理由を書いて対象に加えるのではなく、RESの懸念事項に記して発注者の判断を仰ぐこと。
*   **1ファイル1責務** : `js/anim/battleTimeline.js`・`js/anim/battleDirector.js`・`js/view/layout.js` を肥大化させない。兵1体ごとの並び・動き・跳ねて落ちる動きなど、新しい責務は新しいモジュールに分ける。
*   **テストプレイで確かめること（計画の最後に、発注者が見る点として書くこと）**
    *  攻防の演出で、自軍の兵が1人＝1体で、丸い体に剣・盾・ハンマーを持って描かれている。大きな兵が出ない。
    *  陣地が右から「防御 → 城 → 攻撃 → 修理」と並び、兵が奥から手前の順に重なって見える。兵が消えても、ほかの兵が並び替わらず、ちらつかない。
    *  兵が弾みながら（設定を切り替えれば揺れながら）移動する。
    *  相打ちと、城・敵に当たった後に、兵がぽこんと跳ねて画面の下へ落ちる。落ちる兵がソリティアの段に描かれない。
    *  修理の兵が城へ弾みながら向かって消え、城の HP が増える。使われなかった防御の兵が、終わりに城へ走って帰って消える。
    *  戦闘の段の左上に攻撃・防御・修理の人数が出て、兵が消えるたびに減る。スキップすると最後の値になる。
    *  音が、ぶつかった・当たった・城に入った瞬間に合って鳴る。早送り・スキップが今と同じく使え、結果（城と敵の HP、決着）が変わらない。
    *  常時防御力の段・敵の回復・ブレスで札が燃える段・敵を倒したときの案内・決着の表示が今の流れのまま動き、タイトルからクリア・負けまで通しで遊べる。
