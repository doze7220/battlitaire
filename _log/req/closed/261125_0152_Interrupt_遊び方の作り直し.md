## 【実装要件】
タイトル画面から開く「遊び方」（今は文字だけの8ページ）を、**短く、楽しい雰囲気** に作り直す。ページを4つに減らし、語りかける口調の文章に替え、大事な言葉に色を付け、各ページにゲームの絵を添える。画面を見れば分かること（置ける列の印、手札の枠、行動の減り方など）は説明しない。**ゲームのルール・設定の値は変えない。** 画面の流れ（タイトル → 遊び方 → タイトル）、ページのめくり方（「まえへ」「つぎへ」「タイトルへ」のボタン、← →・Escape、開くたびに1ページ目から、効果音なし）、背景の色、見出し・ページ番号・区切り線・ボタンの見た目は今のままとする。

*   **要件1: ページは4つ。文章は下の【遊び方の文章】のとおり**
    *  ページは【遊び方の文章】の4ページで、この順に並べる。ページ番号は「1 / 4」〜「4 / 4」と出る（ページ数は今と同じく数えて出す）。
    *  文章は【遊び方の文章】の文字を変えずに写す（下の要件2・3の印は、文章のファイルの中でそのまま使うか、計画で決めた同じ働きの書き方に置き換える）。
    *  文章の中の数字（1〜7、5、+2）は、今と同じく `js/rules/config.js` の今の値を **文字として書いたもの** で、設定の値から組み立てない。文章のファイルの先頭の責務のコメントにある「設定の値を変えたらこの文章も手で直す」の一言は残す。

*   **要件2: 文の途中で改行しない。折り返しは区切りのよい位置でだけ行う**
    *  1つの段落は、文の途中に改行を入れず、幅に合わせて自動で折り返す。段落と段落の間は、行の間隔より少し広く空ける（半行ほど。計画で決める）。
    *  折り返してよい位置は、次の2つだけとする。
        *  句読点などの後（「、」「。」「！」「？」「）」の直後）。
        *  文章の中に書いた **折り返してよい位置の印 `|`**（画面には出さない）。【遊び方の文章】では、言葉の切れ目に `|` を入れてある。
    *  言葉の途中（例: 「アクションポイント」「ソリティア」「ゴブリン」の途中）では折り返さない。ただし、折り返してよい位置の間の文字の並びが、それだけで1行の幅を超えるときに限り、今と同じ1文字単位の折り返しに戻してよい（今の文章では起きない見込み）。
    *  行頭禁止の文字（今の「、」「。」「）」「」」に「！」「？」を足す）は、今と同じく行頭に来ないようにする。
    *  文章を直す人が、どこに `|` を入れればよいか分かるよう、文章のファイルの先頭のコメント（3行以内の責務の後の説明）か、ページの並びの定数の JSDoc に、印の書き方を書く。

*   **要件3: 大事な言葉に色を付ける**
    *  文章の中の `{種類:言葉}` の部分は、`{`・`}`・`種類:` を画面に出さず、言葉だけをその種類の色で描く（太字にするかは計画で決める。本文の文字の大きさは変えない）。
    *  種類と色は次のとおり。色の値は、絵柄の色は `js/view/suitStyle.js` の `SUIT_LOOKS` と同じ値にする（値を書き写すか import するかは計画で決める。`suitStyle.js` は変更しない）。
        *  `key`: 大事な言葉。見出しと同じ黄色（`howToView.js` の `HEADING_COLOR` `'#ffe680'`）。
        *  `sword`: 剣・攻撃。剣の色（`'#d9534f'`）。
        *  `shield`: 盾・防御。盾の色（`'#4a90d9'`）。
        *  `hammer`: ハンマー・修理。ハンマーの色（`'#4cae4c'`）。
        *  `gold`: 金貨。金貨の色（`'#e0a030'`）。
    *  色を付けた言葉の途中では折り返さない（`{…}` の中に `|` は入れない）。色を付けた言葉の前後は、`|` があるときだけ折り返せる（句読点の後は要件2のとおり）。

*   **要件4: 各ページに絵を添える**
    *  絵はゲームで使っているスプライト（城・兵・ゴブリン・巨人・ドラゴン・カード・予告の絵・BATTLE! のロゴ）を、今ある描く口（`spriteView.js`・`cardView.js`・`troopView.js` の export）で描く。新しいスプライトは作らない。`assets/` は変更しない。
    *  1〜3ページ目は、見出しの区切り線と本文の間に、横長の絵の区画を1つ置く（高さは計画で決める。目安 260〜320px）。4ページ目は、敵ごとの段を3つ縦に並べ、各段の左に敵の絵、右に敵の名前と説明の文を置く。
    *  ページごとの絵の中身:
        *  1ページ目: 左に城と、その前に兵3体（攻撃・防御・修理を1体ずつ）。右に向かい合うドラゴン。
        *  2ページ目: 盤面の列と同じように重ねた、剣の 5・4・3 の札（カードの描き方は盤面と同じ `drawCardFace`）。
        *  3ページ目: 上に BATTLE! のロゴ。下に、左の兵3体（攻撃・防御・修理）と右の巨人、巨人の頭の上に攻撃の予告の札（予告の絵と数字。盤面の予告の札に似た見た目でよい）。
        *  4ページ目: ゴブリンの軍勢の段はゴブリン3体ほど、巨人の段は巨人、ドラゴンの段はドラゴン。敵の名前は本文より目立つ書き方（太字・`key` の色など。計画で決める）にする。
    *  絵は動かさない（止まった絵でよい）。兵の焼き付け（キャンバスキャッシュ）は使わず、直接描く。`drawTroop` が焼き付けのない状態でも直接描けることを、計画の時点でコードで確かめる。焼き付けの資源の作成・破棄に遊び方の画面から触らない。
    *  ページの文章と絵を結びつける情報（どのページにどの絵を出すか、4ページ目の段の並び）は、文章のファイルの側に、絵の識別子（文字列）として持たせてよい。絵の組み立て（どのスプライトをどこにどの大きさで描くか）は、文章のファイルにも `howToView.js` にも書かず、`js/view/` の新しいファイル（例: 遊び方の絵だけを描くファイル）に分ける。

*   **要件5: スマホの縦画面で読める大きさのまま、どのページも画面に収める**
    *  本文の文字は今の 34px のまま（32px 未満にしない）、行の間隔は今の 1.5 倍（詰めるなら 1.4 倍まで）。左右の余白は今の 40px。
    *  どのページも、見出しの区切り線からボタンの上までの範囲に、絵と文章が重ならずに収まること。収まらないときは、絵の区画の高さ・絵の大きさを詰める。それでも収まらなければ、文字を縮めたり文章を削ったりせず、どのページがどれだけはみ出すかを RES の懸念事項に書いて発注者の判断を仰ぐ。

*   **要件6: 今と同じく使えること**
    *  タイトル画面の「はじめる」・Enter・Space で今と同じく盤面へ進み、タイトルからクリア・負けまで通しで遊べる。決着の後のタイトル画面から、また遊び方を開ける。

## 【計画書に必ず含めるべきタスクごとの作業】
AIが作成する計画書（RES）のタスクリストには、個別の実装タスクの後に、以下の作業を必ず含めること。
*   コード修正完了後、JSDocコメントの記載漏れがないことを確認する。
*   タスク完了後、作業レポート（本RESファイル）の詳細作業内容を記載し完成させる。
*   開発資料（`PROJECT_ARCHITECTURE.md`）の記載に影響が出る場合は、資料本体は修正せず、その旨を『開発資料の更新予定』欄に追記する。

## 【計画書に必ず含めるべき固定タスク】
AIが作成する計画書（RES）のタスクリストには、全実装タスクの後に、以下のタスクを必ず含めること。
*   各タスクで記録した『開発資料の更新予定』を確認し、開発資料（`PROJECT_ARCHITECTURE.md`）へ反映する（画面の流れの「8ページ」を4ページにすること、`howToText.js`・`howToView.js` の行の説明（折り返しの印・色の印・絵の識別子）、新しく作るファイルの行など）。開発資料に影響を与えない場合は、このタスクは不要とする。
    *   ※ 実装AIによる開発資料の書き換えは、本ワークフローにおいて原則禁止であるが、**この最終タスクのみ明示的な例外とする**。後続タスクが存在せず、資料の変更によって他タスクの前提が動く危険がないためである。個別の実装タスク内で資料を書き換えてはならない。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : `PROJECT_CONSTITUTION.md` の絶対禁止事項に反する設計をしてはならない。今のページの番号は今と同じくシーン（`HowToScene`）が持ち、描画（文章の折り返し・色付け・絵）は `js/view/` に置いて状態を変えない。配置（絵の区画・本文の範囲・4ページ目の段）は `js/view/layout.js` の `createHowToLayout` の作りに合わせる。
*   **1ファイル1責務** : 文章のファイル（`howToText.js`）は文字の定数（と絵の識別子の文字列）だけを持ち、描画・折り返しの処理を書かない。`howToView.js` が大きくなりすぎるなら、印の読み取りと折り返し（文章を「色の付いた言葉の並び」に分け、行に割り付ける処理）や絵の組み立てを `js/view/` の別のファイルに分ける。`js/view/layout.js` を肥大化させない（遊び方の配置は `createHowToLayout` の中に収め、収まらなければ別のファイルに分ける）。
*   **ルールを変えない** : `js/rules/` は読むだけで変更しない。ルールの判定や計算を画面の側に書き写さない（遊び方の文章と絵の数字は文字・飾りとして持つだけ）。
*   **先回り実装の禁止** : 絵の動き（アニメーション）・ページをめくる動き・効果音・BGM・スクロール・言語の切り替え・「初回だけ自動で開く」・プレイ中に遊び方を開く口・新しいスプライトは作らない。タイトル画面は変えない。
*   **エンジンの使い方** : 入力は今と同じく `Scene` の `onPointer`・`onKeyDown` で受ける。`draw` の中でシーンの状態を変えない。`js/` に `addEventListener`・`requestAnimationFrame`・`getContext`・`setTimeout`・`setInterval`・`performance.now()`・`Date.now()`・`Math.random` を書かない。`ctx` の状態を変える描画は `save`／`restore` で囲む。外部ライブラリは使わない。
*   **変更してよい範囲** : 変更してよいのは `js/view/howToText.js`・`js/view/howToView.js`・`js/view/layout.js`（遊び方の配置の部分）・`js/scenes/HowToScene.js`（必要なときだけ）と、`js/view/` に新しく作るファイルとする（どのファイルを変えるかは計画に明記すること）。`js/view/spriteView.js`・`js/view/cardView.js`・`js/view/troopView.js`・`js/view/suitStyle.js`・`js/view/intentView.js` は読んで export を呼ぶだけで変更しない。`js/rules/`・`js/anim/`・`js/audio/`・`js/ui/`・`js/main.js`・`js/scenes/TitleScene.js`・`js/view/titleView.js`・`js/view/titleText.js`・`oz/`・`index.html`・`assets/`・`_doc/` は変更しない。これら以外の変更が必要だと分かった場合（使いたい描く口が export されていない、など）は、計画の中で理由を書いて対象に加えるのではなく、RESの懸念事項に記して発注者の判断を仰ぐこと。
*   **テストプレイで確かめること（計画の最後に、発注者が見る点として書くこと）**
    *  タイトル画面の「遊び方」で1ページ目が開き、4ページを「まえへ」「つぎへ」（PC では ← →）で行き来でき、ページ番号が「1 / 4」〜「4 / 4」と出る。最初のページの「まえへ」、最後のページの「つぎへ」は薄く、押しても何も起きない。「タイトルへ」（PC では Escape）で戻り、もう一度開くと1ページ目から始まる。
    *  文章が【遊び方の文章】のとおりに出て、`|`・`{`・`}`・`key:` などの印が画面に出ない。色を付けた言葉が、種類ごとの色で出る。
    *  行が、句読点の後か言葉の切れ目でだけ折り返され、「アクションポイント」「ソリティア」などの言葉の途中で切れない。行頭に「、」「。」「！」が来ない。段落の間が少し空いている。
    *  各ページに【実装要件】要件4の絵が出て、文章と重ならない。4ページ目は、敵の絵の右に名前と説明が並ぶ。
    *  スマホの縦画面で、本文が無理なく読める大きさで、どのページも画面に収まる。
    *  タイトルからクリア・負けまで今と同じく通しで遊べ、決着の後のタイトル画面から、また遊び方を開ける。盤面の兵の見た目（焼き付けで描く・描かない）が今と変わらない。
