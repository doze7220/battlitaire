## 【実装要件】
いまは起動すると「TAP SCREEN」の画面（BOOT）が出て、タップで盤面へ進む。決着すると戦闘の段に「クリア」「負け」が出て、タップで BOOT へ戻る。今回は、BOOT と別にタイトル画面（TITLE）を置き、決着の表示を広げて結果（集計）を見せ、そこからタイトル画面へ戻って新しいゲームを始められるようにする。

*   **要件1: BOOT とタイトル画面（TITLE）を分ける**
    *  起動すると、いまの「TAP SCREEN」の画面（BOOT）が出る。BOOT の見た目と、入力の受け方（このシーンで押して離したとき、または Escape 以外のキーで進む）は変えない。BOOT は最初の入力を受けて音を鳴らせるようにする役目だけを持ち、進む先はタイトル画面（TITLE）になる。
    *  タイトル画面（TITLE）は BOOT とは別のシーン（新しいファイル）にする。暗い背景の上に、ゲーム名「バトリティア」を大きく出し、その下に「はじめる」ボタンを出す。ボタンは押せる大きさ（一辺 80px 以上）で、文字がボタンからはみ出さないこと。配置（ゲーム名とボタンの位置・大きさ）は `js/view/layout.js` から求める（必要なら `layout.js` に足す）。
    *  「はじめる」ボタンを押すと、新しいゲーム（城の HP・敵の進行・盤面・集計がすべて初期状態）の盤面へ進む。ボタンの外を押しても進まない。PC では Enter または Space キーでも始められる。前の画面で押した入力（BOOT を進めたときの離す・決着の表示を閉じたタップ）で、タイトル画面がそのまま進んでしまわないこと（いまの BOOT の「このシーンで押したか」と同じ考え方）。
    *  将来タイトル画面で BGM を鳴らすための分離であり、BGM はこの Phase では入れない。
*   **要件2: 結果の集計（ルール層）**
    *  1回のゲームを通して、次の4つをルール層で数える。新しいゲームを始めると 0 から数え直す。
        *  **かかったフェーズ数**: そのゲームで「行動終了」を押して攻防を行った回数（決着したフェーズを含む）。
        *  **敵に与えた総ダメージ**: すべての敵について、実際に減った敵の HP の合計。防御（常時防御力・防御のスタンス）で減った分は含めず、敵の HP を超えた分（とどめの余り）も含めない。
        *  **城が受けた総ダメージ**: 実際に減った城の HP の合計。防いだ分・城の HP を超えた分は含めない。
        *  **回復の合計**: 城の修理で実際に増えた城の HP の合計。最大 HP で頭打ちになった分は含めない。巨人など敵の回復は数えない。
    *  集計は、描画の側で出来事の並びから数え直すのではなく、ルール層が持ち、そこから読める形にする（攻防の結果を決める「行動終了」の時点で数える）。数え方の置き場所（`Game.js` に持たせるか、別のファイルに分けるか）は計画で決めてよいが、`Game.js`・`battle.js` を肥大化させないこと。
*   **要件3: 決着の表示を広げて結果を見せる**
    *  ゲームクリア（ドラゴンを倒した）とゲームオーバー（城の HP が 0）のとき、攻防の演出の終わりに出る決着の表示を広げ、「クリア」か「負け」かに加えて、要件2の4つの数字を、それぞれ何の数字か分かる見出しつきで出す（例:「かかったフェーズ数 12」「敵に与えた総ダメージ 380」「城が受けた総ダメージ 95」「回復の合計 40」）。見出しの言葉は分かりやすければ変えてよい。
    *  決着の表示は別のシーンにはせず、いまの決着の表示（暗幕と大きな「クリア」「負け」）を広げる形にする。戦闘の段に収まらなければ、暗幕と表示を画面全体に広げてよい。文字が暗幕・画面からはみ出さず、下の盤面と重なって読みにくくならないこと。配置は `js/view/layout.js` から求める。
    *  案内の文字は「タップでタイトルへ」のように、タップでタイトル画面へ戻ることが分かる言葉にする。
    *  決着の表示が出る時点・決着の効果音・途中の敵を倒したときの案内（次の敵の案内）はいまのまま変えない。
*   **要件4: 結果からタイトル画面へ戻る**
    *  決着の表示をタップすると、タイトル画面（TITLE）へ戻る。BOOT へは戻らない。そこから「はじめる」で新しいゲームを始められる。
    *  何度くり返しても、前のゲームの状態（城の HP・敵・盤面・集計・早送りの速さ）が新しいゲームに持ち越されないこと。
*   **要件5: ほかは変えない**
    *  上に書いたこと以外の、段取り（カードの操作と動き）・攻防の演出（兵の動き・早送り・スキップ・速さ・燃える段）・敵の入れ替わりと行動・音の挙動は変えない。

## 【計画書に必ず含めるべきタスクごとの作業】
AIが作成する計画書（RES）のタスクリストには、個別の実装タスクの後に、以下の作業を必ず含めること。
*   コード修正完了後、JSDocコメントの記載漏れがないことを確認する。
*   タスク完了後、作業レポート（本RESファイル）の詳細作業内容を記載し完成させる。
*   開発資料（`PROJECT_ARCHITECTURE.md`）の記載に影響が出る場合は、資料本体は修正せず、その旨を『開発資料の更新予定』欄に追記する。

## 【計画書に必ず含めるべき固定タスク】
AIが作成する計画書（RES）のタスクリストには、全実装タスクの後に、以下のタスクを必ず含めること。
*   各タスクで記録した『開発資料の更新予定』を確認し、開発資料（`PROJECT_ARCHITECTURE.md`）へ反映する（シーンの流れ（BOOT → TITLE → 盤面 → 決着 → TITLE）、タイトル画面、結果の集計、決着の表示、作成済みのファイルの表の更新など）。開発資料に影響を与えない場合は、このタスクは不要とする。
    *   ※ 実装AIによる開発資料の書き換えは、本ワークフローにおいて原則禁止であるが、**この最終タスクのみ明示的な例外とする**。後続タスクが存在せず、資料の変更によって他タスクの前提が動く危険がないためである。個別の実装タスク内で資料を書き換えてはならない。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : `PROJECT_CONSTITUTION.md` の絶対禁止事項に反する設計をしてはならない。結果の集計はルール層（`js/rules/`）に置き、画面・エンジンに触れない。描画の側（`js/view/`）・シーン（`js/scenes/`）は集計を読むだけで、書き換えない。
*   **シーンの流れ** : シーンの組み立て（BOOT の進む先が TITLE、TITLE の進む先が新しい盤面、決着の後の戻り先が TITLE）は、いまと同じく `js/main.js` でシーンを作る関数を渡す形でつなぐ。各シーンのファイルの中で、ほかのシーンのクラスを直接 import して作らない形を保つ（いまの BOOT・盤面・攻防の演出と同じ考え方）。
*   **配置は `layout.js` から読む** : タイトル画面のゲーム名・ボタン、広げた決着の表示の位置・大きさは、`js/view/layout.js` の配置から求める（必要なら `layout.js` に足す）。描画・シーンのファイルに座標の数値を直書きしない。表示する文字は、いまの決着の文字と同じく文字のまとめ（`js/view/battleText.js` など）に置く。
*   **先回り実装の禁止** : 最高記録の保存（`Storage`）、BGM、タイトル画面のメニュー（設定・遊び方など）、結果の画面の演出（数字が数え上がる等）、敵の絵、敵の数値の調整（03-05）は作らない。
*   **エンジンの使い方** : 動きは `Scene` の `update(dt)` で進め、`draw` の中でシーンの状態を変えない（`oz/ENGINE_API.md`）。シーンの操作と `Engine.timeScale` の変更は `update`・`onPointer`・`onKeyDown` の中で行う。`js/` に `addEventListener`・`requestAnimationFrame`・`getContext`・`setTimeout`・`setInterval` を書かない。必要な機能がエンジンにないときは、回避策を書かずにRESに記録して作業を止める。
*   **変更してよい範囲** : 変更・追加してよいのは `js/main.js` と、`js/rules/`・`js/view/`・`js/scenes/` の中のファイルとする（どのファイルを変えるかは計画に明記すること）。`oz/`・`index.html`・`js/anim/`・`js/ui/`・`js/audio/`・`assets/` は変更しない。変更が必要だと分かった場合は、計画の中で理由を書いて対象に加えるのではなく、RESの懸念事項に記して発注者の判断を仰ぐこと。
*   **1ファイル1責務** : 集計、タイトル画面、決着の表示を、1つのファイルに詰め込みすぎない（`js/rules/Game.js`・`js/view/battleShowView.js` を肥大化させない）。新しいファイルを作る場合は、先頭に責務定義を書く。
