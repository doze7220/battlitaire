## 【実装要件】
デバッグの入口を、URL の `?debug` の1つにまとめる。タイトル画面の「デバッグスタート」のボタンと、`js/main.js` の定数 `DEBUG_TOOLS_ENABLED` を消す。デバッグのときは画面の右下に「DEBUG MODE」と出し、何も保存しない。

* 今のゲームのコードには、URL の `?debug` を読む所はない（現場設計で確かめた。入口は定数だけ）。
* 座標はすべて論理座標（画面 720×1280）で書く。
* この REQ では、URL に `?debug` を付けて開いたとき（下の要件1の決まり）を「デバッグ」、それ以外を「ふつう」と書く。
* ふつうに開いたときの遊び・見た目・設定の保存は、「デバッグスタート」のボタンがなくなることのほかは、今と変えない。

*   **要件1: `?debug` の読み方**
    *  URL のクエリに `debug` があれば、デバッグとする（`?debug`・`?debug=1` など。ほかのクエリと一緒でもよい）。ただし `?debug=0` は、付いていないのと同じ（ふつう）とする。
    *  URL を読むのは、起動のときの1か所だけにする。結果を `Engine.start` の起動設定 `debug` に渡す。ほかの所は `Engine.debug` を読み、URL は読まない。
    *  `Engine.debug` は `Engine.start` の後でしか読めない（3章）。起動の前に行う準備（`Storage.open`・保存された音量の反映・`Assets.load`・最初のシーンの constructor）の中で読まない。
*   **要件2: デバッグのゲーム**
    *  デバッグのときは、タイトルの「はじめる」（Enter・Space も）から始めたゲームが、いまの「デバッグスタート」のゲームと同じになる。
        *  盤面の TURN の区画から開くメニューの窓の一番右に DEBUG タブが出る。
        *  ルールの値は、`config.js` の `RULES` ではなく、その写し（`debugRules`）を使う。写しは最初のゲームで作り、ページを読み込み直すまで持つ（DEBUG タブで変えた値は、次のゲームにも残る）。
    *  タイトル画面の「設定」から開くメニューの窓には、デバッグでも DEBUG タブは出さない（今と同じ。ゲームが始まっていないため）。
    *  ふつうのときは、DEBUG タブ・FPS の表示・「DEBUG MODE」の表示は出ず、デバッグの操作はどこからも呼べない。ルールの値はいつも `RULES`。
    *  DEBUG タブの中身（兵の数・敵・次の行動・HP・FPS・焼き付け・ルールの値）の動きは変えない。
    *  遊び方の画面の中身は、`?debug` の有無で変えない。
*   **要件3: 「デバッグスタート」と定数を消す**
    *  タイトル画面の「デバッグスタート」のボタン（配置・当たり・文字・描画・シーンの受け口）と、`js/main.js` の定数 `DEBUG_TOOLS_ENABLED` を消す。デバッグでもふつうでも、タイトル画面のボタンは「はじめる」「遊び方」「設定」の3つで、位置・大きさは今と同じ。
    *  コードの JSDoc・責務の説明に残る「デバッグスタート」の言い方（`js/rules/` の `debugRules.js` など、`js/scenes/BoardScene.js` など）も、今の動きに合わせて直す（動きは変えない）。どのファイルを直すかを、計画で全部挙げる。
*   **要件4: 「DEBUG MODE」の表示**
    *  デバッグのときは、画面の右下に、赤く小さい文字で **2行**（上の行「DEBUG」、下の行「MODE」）を横書きで出す。文字は太字で 14px ほど（14px を下回らない）。背景が明るくても暗くても読めるよう、細い縁取りなどを付けてよい。
    *  位置は、盤面の一番右の放つボタンの右の余白（x 665〜720）に収め、画面の下端に寄せる（おおよそ x 666〜714、y 1244〜1276）。どの画面でも同じ位置・同じ見た目にする。放つボタン・遊び方のボタン（y 1140〜1240）・メニューの窓・TURN の区画・FPS の表示（左下）と重ならないこと。
    *  BOOT（「TAP SCREEN」）・タイトル・遊び方・盤面・攻防の演出・結果の表示・メニューの窓を開いている間の、全部の画面で出ている。いちばん手前に描く（窓の背後の暗い幕や結果の幕に隠れない・暗くならない）。
    *  押しても何も起きない（下の画面の入力を妨げない）。
    *  ふつうのときは何も描かない。
    *  全部の画面の上に出す方法は計画で決める（例: 手前のレイヤーを1つ足し、いちばん下に積まれるシーンがそのレイヤーに描く。10章）。エンジンには「DEBUG MODE」の表示はないので、ゲーム側で描く。描く処理・文字・位置は1か所に置き、シーンごとに書き写さない。
*   **要件5: FPS の表示**
    *  デバッグで開いても、FPS の表示は消えた状態で始まる（エンジンは `debug` が真だと左上に出した状態で始めるので、起動の直後に消す。14章「代入の効き方と場所」に従う）。一瞬でも左上に見えないのがよい。
    *  今までどおり、DEBUG タブの「FPS を表示」で出し入れでき、左下に出る。
*   **要件6: デバッグのときは保存しない**
    *  デバッグのときは、何も保存しない（`Storage.set` を呼ばない）。
    *  デバッグで開いたときも、保存された設定（BGM と効果音の音量・攻防の演出の速さ）を読み込んで使う。
    *  デバッグで設定を変えると、その場で効き、ページを閉じる（読み込み直す）まで残る（メニューを開き直しても、次のゲームでも、変えた値のまま）。保存された値は書き換わらない。`?debug` を外して開き直すと、元の設定に戻っている。
    *  ふつうのときは、今までどおり保存する（同じ `key`・`version`・名前。今の保存された設定をそのまま使える）。

## 【テストプレイで確かめること（実装セッションが発注者に依頼するときに示す）】
1. `?debug` なしで開く: タイトルのボタンが3つだけ。ゲームのメニューに DEBUG タブがない。「DEBUG MODE」・FPS が出ない。設定を変えて開き直すと残っている。`?debug=0` でも同じ。
2. `?debug` で開く: 最初の画面から右下に「DEBUG」「MODE」の2行が赤く出る。タイトル・遊び方の全ページ・盤面・メニューの窓・攻防の演出・結果の表示で出ていて、ほかの物と重ならず、隠れない。PC とスマホで読める。
3. `?debug` で開く: FPS は初めは出ていない。「はじめる」→ TURN の区画 → 一番右に DEBUG タブ。操作が今までどおり効く。「FPS を表示」で左下に出る。DEBUG タブで変えたルールの値が、次の「はじめる」のゲームでも残り、ページを読み込み直すと戻る。
4. 設定: `?debug` なしで音量などを決めておく → `?debug` で開くとその値で始まる → 変えるとその場で効き、メニューを開き直しても残る → `?debug` を外して開き直すと、初めに決めた値に戻っている。
5. 攻防の演出・決着・音まで、ふつうとデバッグの両方で通しで遊べる（261125 のエンジンの載せ替えの後、攻防の演出・決着・音・スマホはまだ確かめていない）。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **入口は1つ**: デバッグかどうかの持ち主は `Engine.debug` だけにする。ゲーム側に、同じ意味の定数・変数を別に持たない（起動設定に渡すための、起動のときの値を除く）。
*   **ルール層**: `js/rules/` は `oz` も URL も読まない（憲法 3章）。デバッグのゲームかどうかは、いままでどおり、盤面へルールの値の写しと DEBUG タブ付きのメニューを渡すことで伝える。ルール層で直してよいのは JSDoc・責務の説明だけ。
*   **URL**: URL はブラウザの `location` から読むだけ。書き換えない（履歴・クエリの変更をしない）。`window` にプロパティを足さない。DOM の要素を足さない。
*   **設定の値の持ち主**: 設定の値を読み書きするのは、いままでどおり `settingsStore.js` の口だけ。デバッグのときに保存しない仕組みもここに置き、メニューのタブ（`menuTabs.js`）や盤面に、デバッグかどうかの分岐を散らさない。`key`・`version`・`defaults` の形は変えない。
*   **描画**: `draw` の中では状態を変えない。`Engine.fpsVisible` への代入は、14章で許された場所でだけ行う。`ctx` の状態は `save`・`restore` で囲む。`js/` に `requestAnimationFrame`・`addEventListener`・`getContext` を書かない。
*   **レイヤーを足す場合**: 既存の `'main'` に描くものの順序・見た目を変えない。
*   **エンジンの使い方**: エンジンは `import { … } from 'oz'` でだけ使い、`oz/` は編集しない。`oz/src/` は読まない。必要な機能が `oz/ENGINE_API.md` にない、または書かれたとおりに動かないときは、ゲーム側に回避策を書かず、作業を止めて RES に記録する（憲法 3章「エンジンの不足への対応」）。
*   **今回やらないこと**:
    *   DEBUG タブの項目を足す・並べ替える・動きを変えること。「焼き付けで描く」の初めの状態を変えること。
    *   スロー・一時停止など時間の操作、開発用のキー（FPS のキーなど）、エンジンの土台にある開発用パネルの雛形・名前の置き場所の取り込み。
    *   ふつうのときにデバッグ用のファイルを読み込まないようにすること（動的 `import`）。静的 `import` のままでよい。
    *   公開のページで `?debug` を使えなくすること（誰でも開けてよい）。
    *   タイトル画面の作り直し、設定・クレジットの中身の変更、ルールの数値の変更。
