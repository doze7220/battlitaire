## 【実装要件】
戦闘の段に残る表示（敵の予告・巨人の数え下ろし・兵の人数）を、背景・兵・敵・最上部のゲージと重ならず、スマホで読める形に整える。

* **ルールは変えない**（ルール層 `js/rules/` は変更しない）。
* 城と敵の HP は最上部のゲージ（05-01）で読むので、戦闘の段には出さない。敵の回復の「+20」など、その場で出る数字は今のまま残す。
* タイトルからクリア・負けまで、通しで遊べること。スマホの縦画面を優先し、PC でも同じように遊べること。

### 今の表示（05-03 の後）
* 敵の予告: 戦闘の段の右下の枠（x 360〜700・y 312〜352）に「次の行動 攻撃 4」のような文字で出している。ブレスのときは枠を赤くして目立たせる。
* 巨人の数え下ろし: 段の右上の枠（x 480〜700・y 12〜52）に「攻撃まで あとN」「攻撃！」の文字で出している。上半分が、敵の HP ゲージと HP の数字に重なっている。
* 人数の表示: 段の左上の枠（x 20〜250・y 12〜52）に、攻撃・防御・修理の絵と人数を横に並べている。城の HP ゲージ（y 8〜28）と金貨のゲージ（y 32〜42）に上下を覆われて読みにくい。
* 巨人・ドラゴンの絵は高さ 200px で、頭のてっぺんが空のゲージのすぐ下まで来ている（頭の上に余白はない）。
* 予告の種類（ルール層の `enemy.intent`）は次の6つ。
  * 攻撃（`kind: 'attack'`。量あり。ゴブリン・巨人）
  * 防御（`kind: 'defend'`。量あり。ゴブリン）
  * 振りかぶり（`kind: 'windup'`。量なし。巨人の攻撃の前のフェーズ）
  * 爪（`kind: 'attack'`・`variant: 'claw'`。量あり。ドラゴン）
  * 吸い込む（`kind: 'windup'`・`variant: 'inhale'`。量なし。ドラゴン）
  * ブレス（`kind: 'attack'`・`variant: 'breath'`。量あり、札を燃やす。ドラゴン）
* 巨人の「攻撃の後の回復」は攻防のときの抽選で決まり、予告には入らない。そのため、予告には出さない（今の「+20」の表示のまま）。

*   **要件1: 予告の絵（仮のスプライト）**
    *  予告専用の仮のスプライト JS を、`assets/sprites/` に **6 つ**新しく作る（このサブフェイズでは、手で書いた仮のスプライトを置いてよい。発注者の決定）。名前は `intent_attack.js`・`intent_defend.js`・`intent_windup.js`・`intent_claw.js`・`intent_inhale.js`・`intent_breath.js`。
    *  仮の中身は、6 つの違いが見て分かる簡単な図形にする。
        *  例: 攻撃＝赤い拳か刃、防御＝青い盾、振りかぶり＝上向きの矢印と棍棒、爪＝3本の斜めの線、吸い込む＝内向きの渦か矢印、ブレス＝赤と黄の炎。
        *  味方の兵の剣・盾の絵（`suit_sword`・`suit_shield`）と見分けやすい色と形にする。
        *  後で発注者がエディタで描き直して、同じ名前で差し替える。
    *  **エディタでの描き方の約束**（計画で値を決め、開発資料に書く）:
        *  原点 (0, 0) を絵の中心にし、決まった大きさの枠（たとえば 幅 48 × 高さ 48）の中に描く。
        *  ゲームは、エディタの px をそのままゲームの px として描く（倍率 1）。
    *  **ファイルの形**:
        *  既存のスプライト（`logo_battle.js` など）と同じ形にする。`oz-vector-editor-sprite`・`formatVersion` 2 のスプライトデータ（`bounds`・`elements`・`source`）と、同じ `draw(ctx)` を持つ既定の export。他のファイルには依存しない。
        *  `source`（作業データ）も持たせ、エディタの「開く」でそのまま開いて図形を編集できるようにする。`elements` と `source` の図形は同じ内容にする。
        *  `bounds` は、エディタの定義（線の太さの半分を含む）に合わせて求める。
    *  スプライトの import と描画は、今の決まりどおり `js/view/spriteView.js` に集める。
    *  予告の種類（`kind`・`variant`）と絵の対応は、`js/view/` の表1か所に持つ。
        *  `variant` があれば `variant` を、なければ `kind` を使う。
        *  表にない種類では、絵の代わりに「？」の文字を出す（エラーにしない）。
*   **要件2: 予告を敵の頭の上に出す**
    *  右下の予告の枠をなくし、敵の次の行動の予告を、**敵の頭の上に重ねて**出す（発注者の決定）。
        *  敵の絵の大きさ（巨人・ドラゴンの高さ 200px）・位置は変えない。頭の上の方に重なって、頭の一部が隠れてよい。
        *  ゴブリンの軍勢は、群れの上の方に重ねる。
    *  中身は、予告の絵（要件1）と、量の数字。
        *  数字は、縁取りした太字の文字（目安 28px 以上。スマホで読める大きさ）。
        *  量のない行動（振りかぶり・吸い込む）は、絵だけ。
    *  敵の絵の上でも読めるようにする（縁取り・半透明の板など。見た目は計画で決める）。
    *  **ブレス**のときは、今と同じく目立たせる（赤い板・光るなど。見た目は計画で決める）。札を燃やす攻撃だと分かることが大事。
    *  最上部のゲージ（05-01。y 8〜58）とは重ならないようにする。重なるなら、予告の方を下げる。
    *  置く位置（敵ごとの頭の上の位置）は `js/view/layout.js` に置く（敵の種類ごとの表 `ENEMY_FIGURES` に足すなど。値は試遊で決め直す値と書く）。
    *  **段取りの間**は、ルール層の今の予告（`game.enemy.intent`）を出す。
    *  **攻防の演出中**は、今と同じく、その攻防の敵の行動（`result.enemyAction`）を出す。
    *  敵の絵の動きとの関係:
        *  ステージの始まり（05-03）で敵が入ってくる間は、予告も敵と一緒に動くか、入り終わってから出す。どちらにするかは計画で決める。入ってくる前の敵の位置に、予告だけが浮かんで見えないようにする。
        *  攻防の演出で敵が倒れて落ちるとき（敵の絵が見えなくなるとき）は、予告も消す。
        *  待機の伸び縮み・ための姿勢・揺れで予告が一緒に揺れるかは、計画で決めてよい（読めることを優先する）。
    *  予告は、05-03 のフェーズの始まりの演出（「PHASE N」と予告の文字）とは別に、いつも出ている（フェーズの始まりの演出は今のまま変えない）。
*   **要件3: 巨人の数え下ろし**
    *  右上の数え下ろしの枠をなくし、**予告の絵の下に、今と同じ文字**（「攻撃まで あとN」、攻撃するフェーズは「攻撃！」。`countdownText`）を小さめに出す（発注者の決定）。
    *  縁取りした文字で、スマホで読める大きさにする（目安 20px 以上）。
    *  数え下ろしのない敵（ゴブリン・ドラゴン）では出さない。
    *  段取りの間・攻防の演出中で、今と同じ値（`game.attackCountdown()`）を使う。
*   **要件4: 人数の表示**
    *  攻撃・防御・修理の人数の表示は、**今の横に並んだ枠のまま**、最上部のゲージ（城の HP ゲージ・金貨のゲージ・金貨のバッジ。y 8〜58）より**下へ下げる**（発注者の決定）。
    *  城の絵とも重ならないようにする。重なるなら、枠の幅・中の間隔を詰めるか、位置をずらして避ける（位置・大きさは計画で決める）。
    *  陣地で待つ兵（段取りの間に陣地に並ぶ兵。陣地の足元の範囲は地面の線の上 96px〜下 2px）と、なるべく重ならないようにする。
    *  中身（絵・人数の文字・色）と、段取りの間と攻防の演出中に出す値は、今のまま。
    *  位置・大きさは `js/view/layout.js` の定数で変えられるようにし、試遊で決め直す値と書く。
*   **要件5: 資料とスプライトの表の食い違いを合わせる**（前のサブフェイズからの持ち越し）
    *  `PROJECT_ARCHITECTURE.md` のスプライトの決まりは「回さずに描いた向きのまま描く」。一方で、次の2つは絵を傾けて描いている（向きを変える回転ではない）。
        *  兵の揺れ（`js/view/spriteView.js` の `drawTroopFigure` の `tilt`）
        *  巨人・ドラゴンのための動き（`js/view/enemyView.js` の `applyFootPose`）
    *  上の件で、資料の書き方を実装に合わせる。「向きを変えるための回転はしない。揺れ・ための動きで足元を軸に少し傾けるのはよい」という趣旨にする。
    *  `spriteView.js` の絵の範囲の表は、兵（`soldier`）とゴブリン（`goblin`）だけ、スプライトの `bounds` と値が違う（表は 198×196、`bounds` は 202×200）。これを、表かスプライトのどちらかに合わせる。
        *  どちらに合わせるかは計画で決める。今の見た目をなるべく変えない方を優先する。
        *  スプライトのファイルは変更しない（表を合わせるか、違いの理由を資料に書くか）。
        *  決めた理由を RES に書く。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : `PROJECT_CONSTITUTION.md` の絶対禁止事項に反する設計をしてはならない。
    *   描画（`js/view/`）は状態を変えず、ルール層（`js/rules/`）を実行時に import しない。

    *   時間で進む動きは `js/anim/` に置く。`js/anim/` は描画も状態の変更もしない。
*   **スプライトの扱い** :
    *   新しく作ってよいのは、要件1の 6 つのファイルだけ。`assets/sprites/` の既存のファイルは変更しない。
    *   スプライトの `draw` 以外のキーは、実行時に読まない。
    *   `assets/sprites/` を import するのは `js/view/spriteView.js` だけにする。
    *   `ctx` の変換の設定は、必ず `save`／`restore` で囲む。
*   **ルールと演出を変えない** :
    *   `js/rules/` は変更しない。
    *   次のものは変えない: 攻防の演出の時間割・兵の動き・エフェクト、敵の絵の大きさと位置、陣地の位置、音のきっかけ、05-03 のフェーズ・ステージの始まりの演出、最上部のゲージ。
*   **1ファイル1責務** : `js/view/battleStageView.js`・`js/view/layout.js`・`js/view/spriteView.js`・`js/view/boardView.js`・`js/view/battleShowView.js` を肥大化させない。予告（絵・量・ブレスの目立たせ・数え下ろし）の描画は、責務に合うモジュールに分ける（新しいファイルにするかは計画で決め、ファイル先頭の責務定義を合わせる）。
*   **先回り実装の禁止** : 次のものは作らない（後のサブフェイズか未定）。
    *   予告の出方のアニメーション（ぽんと出る・揺れるなど）
    *   予告の数字のスプライト化（05-03 の数字の絵は使わない。文字で出す）
    *   人数の表示の作り直し（陣地ごとに出すなど。今回は位置を下げるだけ）
    *   巨人の回復の予告
    *   フェーズの始まりの演出の変更
    *   敵の絵の大きさの調整
    *   ヒットマークの絵
    *   使われなくなった anim 側の早送り・スキップの片付け
*   **エンジンの使い方** :
    *   `oz` は `import { … } from 'oz'` でだけ使う。
    *   `js/` に `addEventListener`・`requestAnimationFrame`・`getContext`・`setTimeout`・`setInterval`・`performance.now()`・`Date.now()` を書かない。
*   **変更してよい範囲** :
    *   変更してよいもの: `js/view/` の中のファイル（新しいファイルを含む）と、要件1の 6 つの新しいスプライトのファイル。`js/anim/`・`js/scenes/` は、予告を敵の入りに合わせるために必要な最小の変更だけ（理由を計画に書く）。どのファイルを変えるかは計画に明記すること。
    *   変更しないもの: `js/rules/`・`js/audio/`・`oz/`・`index.html`・`js/main.js`・`js/ui/`、`assets/` の既存のファイル。
    *   これら以外の変更が必要だと分かった場合は、計画の中で理由を書いて対象に加えないこと。RESの懸念事項に記して、発注者の判断を仰ぐこと。
*   **テストプレイで確かめること（計画の最後に、発注者が見る点として書くこと）**
    *  戦闘の段の右下の予告の枠と、右上の数え下ろしの枠がない。
    *  敵の頭の上（ゴブリンは群れの上）に、予告の絵と量の数字が出ている。
        *  攻撃・防御・振りかぶり・爪・吸い込む・ブレスの違いが、絵で見て分かる（仮の絵）。
        *  振りかぶり・吸い込むは絵だけ。ブレスのときは目立つ。
        *  最上部のゲージと重ならず、スマホで読める。
    *  巨人のときは、予告の絵の下に「攻撃まで あとN」（攻撃するフェーズは「攻撃！」）が出る。
    *  攻防の演出中も予告が出ていて、敵が倒れて落ちるときは消える。ステージの始まりで敵が入ってくるとき、予告だけが先に浮かんで見えない。
    *  攻撃・防御・修理の人数の枠が、最上部のゲージより下にあり、城の絵・ゲージと重ならずに読める。段取りの間に放った兵が着くと増え、攻防で兵が消えると減る（今と同じ）。
    *  6 つの予告の絵のスプライトを、OZ Vector Editor の「開く」で開いて編集できる。
    *  兵・ゴブリンの大きさが、今と見た目で変わらない（要件5で表を合わせた場合も）。
    *  スマホの縦画面と PC で、タイトルからクリア・負けまで通しで遊べる。
