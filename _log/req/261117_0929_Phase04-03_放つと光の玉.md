## 【実装要件】
札を放つと、列の札が **光の玉** になって戦闘の段まで飛び、**兵に変わって陣地で待つ** ようにする。兵は段取りの間に放つたびに増え、「行動終了」で攻防が始まると、待っていた兵がそのまま戦う。**ルールは変えない。** ルール層は放った時点で結果（ゲージの量）を確定している。玉と兵は、その結果を時間をかけて見せるだけにする。

用語: **区切り** は、放った列の中で同じスートが続く束（倍率がかかる単位。`ReleaseResult.segments` の1項目）。自軍の兵は3種類で、**攻撃の兵**（剣・陣地 attack）、**防御の兵**（盾・陣地 defense）、**修理の兵**（ハンマー・陣地 heal）。数はそれぞれ攻撃・防御・修理（識別子 `heal`）のゲージの量と同じ。金貨（識別子 `muscle`）は兵にならない。

*   **要件1: 札が玉になって列の上で合体する**
    *  放つと、列の札が **下から順に** 光の玉に変わり、列の真上（列の一番上の札の少し上あたり）へ上っていく。札は捨て札へ飛ばない（ルール上は捨て札に移っているので、捨て札の山の見た目は放った時点で増えてよい）。
    *  区切りごとに、玉が1つの大きな玉に合体する。合体したところで、その区切りの計算を **「12 ×3 = 36」**（合計 ×倍率 = 加算量）の形で玉のそばに出す。1枚だけの区切りも同じ形で出す。1列に区切りが複数あれば、区切りごとに別々の大きな玉になる（下の区切りから順）。
    *  玉の色は区切りのスートで見分けられること（剣・盾・ハンマー・金貨。いまのスートの色の決まり `js/view/suitStyle.js` を使ってよい）。
    *  連鎖の音（1枚ごとに高くなる、いまの `playChainSe`）は、札が1枚ずつ玉に変わる瞬間に合わせて鳴らす（いまは捨て札に着く瞬間）。
*   **要件2: 大きな玉が飛んで、弾けて兵になる**
    *  合体した大きな玉は、戦闘の段のその種類の陣地（攻撃・防御・修理）まで飛び、着いたところで弾ける。
    *  弾けた所から、区切りの加算量と同じ数の兵が四方へ飛び出し、陣地の自分の家（`campSlot` の位置。すでに待っている兵の続きの番号）へ跳んで着く。跳び方は 04-02 の兵の移動の見せ方（`BATTLE_ANIM.moveStyle` の弾む／揺れる）に合わせてよい。
    *  兵は戦闘の段の中だけに描く（04-02 と同じく段の矩形で切り抜く）。
*   **要件3: 金貨の玉**
    *  金貨の区切りの大きな玉は、兵にならず、ゲージの行の金貨の数字の枠へ飛ぶ。着くと金貨の数字が増える。
*   **要件4: ゲージの数字と兵の数**
    *  攻撃・防御・修理のゲージの数字は、玉が弾けてから兵が家に着くまでの間に数え上がり、兵が全員着いた時点で兵の数と一致する（いまは放った直後から数え上がっている）。金貨は要件3のとおり玉が着いてから増える。
    *  玉が飛んでいる間、ゲージの数字はまだ着いていない分を引いた値を出す。全部が着いた後の値はルール層の値と一致する。
*   **要件5: 段取りの間、兵は陣地で待つ**
    *  段取りの間、着いた兵は陣地の家に立って待っている（待っている間の呼吸などの動きは作らない）。放つたびに兵が増える。
    *  人数の表示（戦闘の段の左上）は、今と同じく攻防の演出の間だけ出す。段取りの間は出さない。
    *  攻防が始まると、待っていた兵が **同じ位置からそのまま** 戦う。攻防の始めに自軍の兵が消えて出し直されたり、ちらついたり、位置が飛んだりしないこと（いまの `form` の段で自軍の兵が薄く現れる見せ方は、待っている兵がいるので要らなくなる。敵の守りが現れる見せ方は今のまま）。
    *  攻防が終わって次のフェーズになると、今と同じく兵はいない状態から始まる（攻撃・防御・修理のゲージは次のフェーズで 0 から）。
*   **要件6: 玉が飛んでいる間も操作できる**
    *  玉が飛んでいる間・兵が跳んでいる間も、次の操作（めくる・置く・捨てる・手札・束の移し替え・放つ）ができる。玉と兵の動きはタップを止めない（札の移動・山札のめくれは今と同じくタップを止めてよい）。
    *  続けて放てば、前の玉が飛んでいる間に次の玉が出る。いくつ重なっても、それぞれが最後まで飛んで兵・金貨になる。
    *  「行動終了」を押したときに飛んでいる玉・跳んでいる兵があれば、全部が着いて兵が家に立ってから攻防が始まる。待っている間はほかの操作を受け付けない。攻防の結果は、待たずに始めた場合と変わらないこと。
*   **要件7: 調整できること**
    *  玉が上る時間・合体にかかる時間・式を出しておく時間・飛ぶ時間・兵が家へ跳ぶ時間・ずらしは、設定の値として1か所にまとめる（段取りの動きの設定 `js/anim/animConfig.js`、兵の動きは `js/anim/battleAnimConfig.js` のように、既存の置き場所に合わせる）。初期値は目安でよく、試遊で決め直す。飛ぶ道筋（まっすぐか、弧を描くか）も計画で決めてよい。
*   **要件8: 今と同じく使えること**
    *  めくる・置く・捨てる・手札・束の移し替えの見せ方と音は今のまま。放つ音・連鎖の音は要件1のとおり。新しい効果音は足さない。
    *  攻防の演出（04-02 の兵の動き・相打ち・跳ねて落ちる・修理の兵・使われなかった兵・人数の表示・早送り・スキップ）は今のまま動き、結果は変わらない。
    *  タイトルからクリア・負けまで通しで遊べる。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : `PROJECT_CONSTITUTION.md` の絶対禁止事項に反する設計をしてはならない。時間で進む動き（玉・合体・兵が家へ跳ぶ動き・ゲージの表示値）は `js/anim/` に置き、ルール層の操作の結果（`ReleaseResult` の `segments`・`gains`）から作る。描画（`js/view/`）は `anim` が作った見た目の値を受けて描くだけで、時間を進めない・状態を変えない。配置（合体する位置・玉の大きさ・飛ぶ先）は `js/view/layout.js` の矩形から求める。文字の形（「12 ×3 = 36」）は文字のまとめ（`js/view/battleText.js` など、いまの文字の置き場所）に置く。
*   **ルールを変えない** : ルール層（`js/rules/`）は変更しない。放った時点のルールの結果をそのまま読む。玉が着いた後の兵の数・ゲージの数字は、ルール層の値と一致させる。「行動終了」で待つ場合も、攻防の結果を変えない。
*   **段取りと攻防の受け渡し** : 段取りの間に待っている兵の並び（種類ごとの数と家の番号）は、攻防の演出が始まるときに引き継ぐ。引き継ぎの形（段取り用の入れ物を作って攻防の名簿に渡す、名簿を途中から伸ばす、など）は計画で決めること。家の位置は今と同じく `campSlot` で番号から決め、攻防の間に兵が消えても並び替わらないこと（04-02 のまま）。
*   **重さへの配慮** : 兵の数に上限はない（1回の放つで 196 体になりうる）。毎フレーム兵1体ごとに大きなオブジェクトを作らない（04-02 の型付き配列の作りに合わせる）。重さを測る仕掛け・数を増やす仕掛けは作らない。
*   **スプライトの扱い** : `assets/sprites/` を変更しない。スプライトの `draw` 以外のキーを実行時に読まない。スプライトを描く処理は `js/view/spriteView.js` に集める。`ctx` の変換・切り抜き・合成の設定は必ず `save`／`restore` で囲む。
*   **先回り実装の禁止** : 敵ごとの攻防の見せ方（ゴブリンの数と HP の連動・シールドが剥がれる・ヒットマーク・ブレスの炎・巨人とドラゴンが倒れて落ちる）、敵の側の余った兵の消え方の作り直し、敵ごとの当たる位置の作り直し、エフェクト（ヒットストップ・白い光・ダメージの数字・粒・揺れ・待っている兵の呼吸・踏み込みの加速・ための動き）、玉が着いたときの新しい効果音、デバッグモード、兵が多すぎるときのまとめ方、ゲージの行の作り替えは作らない。これらは後のサブフェイズ・Phase で扱う。
*   **使われなくなったものの片付け** : 放った札が捨て札へ飛ぶ動き・攻防の始めに自軍の兵を出し直す処理など、作り変えで使われなくなる関数・設定・項目は、残さずに消す（呼び出し元と JSDoc も合わせる）。作り変えと無関係な箇所の「ついでの整理」はしない。
*   **エンジンの使い方** : 動きは `Scene` の `update(dt)` で進め、`draw` の中でシーンの状態を変えない（`oz/ENGINE_API.md`）。`js/` に `addEventListener`・`requestAnimationFrame`・`getContext`・`setTimeout`・`setInterval`・`performance.now()`・`Date.now()`・`Math.random`（演出の並びに使う乱数を含む）を書かない。
*   **変更してよい範囲** : 変更してよいのは `js/anim/`・`js/view/`・`js/scenes/` の中のファイル（新しいファイルを含む）とする（どのファイルを変えるかは計画に明記すること）。`js/rules/`・`js/audio/`・`oz/`・`index.html`・`js/main.js`・`js/ui/`・`assets/` は変更しない。これら以外の変更が必要だと分かった場合は、計画の中で理由を書いて対象に加えるのではなく、RESの懸念事項に記して発注者の判断を仰ぐこと。
*   **1ファイル1責務** : `js/scenes/BoardScene.js`・`js/anim/boardAnimator.js`・`js/anim/battleTimeline.js`・`js/anim/battleDirector.js`・`js/view/layout.js` を肥大化させない。玉の動き・合体・段取りの間の兵など、新しい責務は新しいモジュールに分ける。
*   **テストプレイで確かめること（計画の最後に、発注者が見る点として書くこと）**
    *  放つと、列の札が下から順に光の玉になって列の上に上り、区切りごとに1つに合体して「12 ×3 = 36」のような式が出る。連鎖の音が玉に変わるのに合わせて鳴る。
    *  大きな玉が戦闘の段の陣地へ飛んで弾け、兵が飛び出して陣地の家へ跳んで並ぶ。剣は攻撃の陣地、盾は防御の陣地、ハンマーは修理の陣地に行く。
    *  金貨の玉はゲージの行の金貨の数字へ飛び、着くと数字が増える。
    *  ゲージの数字が兵が着くのに合わせて増え、着いた後は兵の数と一致する。
    *  玉が飛んでいる間もめくる・置く・放つなどの操作ができ、続けて放つと玉が重なって飛ぶ。
    *  段取りの間、兵が陣地で待ち、放つたびに増える。人数の表示は段取りの間には出ない。
    *  玉が飛んでいる間に「行動終了」を押すと、全部が着いてから攻防が始まる。攻防の始めに兵が消えたりちらついたりせず、待っていた兵がそのまま戦う。
    *  攻防の演出（相打ち・跳ねて落ちる・修理の兵・使われなかった兵・人数の表示・早送り・スキップ）が今のまま動き、タイトルからクリア・負けまで通しで遊べる。
