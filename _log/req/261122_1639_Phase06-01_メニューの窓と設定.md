## 【実装要件】
エンジンの UI 部品（`oz/ENGINE_API.md` 26章）で、タイトル画面とプレイ中（段取りの間）に同じメニューの窓を開けるようにし、その中に「設定」（BGM と効果音の音量・攻防の演出の速さ）と「クレジット」（音の素材の出典）を入れる。設定は保存し、次の起動でも残す。

* **ルールは変えない**（ルール層 `js/rules/` は変更しない。数値も変えない）。演出の速さを変えても、攻防の結果・決着・次の敵への進み方は変わらない（憲法 3章「演出の途中や早送り・スキップで、ゲームの結果が変わってはならない」）。
* 座標はすべて論理座標（画面 720×1280）で書く。窓・部品の大きさや位置は定数に置き、試遊で決め直す値と書く。
* タイトルからクリア・負けまで、通しで遊べること。スマホの縦画面を優先し、PC でも同じように遊べること（タップ（クリック）だけで使え、ホバーに頼らない）。

*   **要件1: メニューの窓**
    *  窓はエンジンの `Ui.createWindow` で作る。タイトル画面から開いても、盤面から開いても、**同じ窓**（同じタイトル・同じタブ・同じ部品の並び）である。
    *  窓は、窓だけを持つシーンとして `Engine.pushScene` で積む（開いている間は背面のシーンに入力が届かず、背面の `update` が止まる。背面の動き（兵の待機・玉など）が止まって見えるのはそれでよい）。閉じるときは `Engine.popScene` で外す。開くたびに新しい窓を作る（タブは毎回「設定」から始まる）。
    *  窓の中に、タブの列（`addTabs`）で「設定」「クレジット」の2つのタブを置き、押して切り替える。
    *  **後から DEBUG タブを一番右に足せる作りにしておく**（次のサブフェイズで、デバッグスタートから始めたときだけ、タブの列の一番右に「DEBUG」を足す）。タブの名前と中身を組み立てる部分を、タブの一覧を受け取って作る形にするなど、タブを足すときに窓の作りを書き直さずに済むようにする。ただし今回は DEBUG タブそのもの・デバッグの定数・デバッグの操作は作らない。
    *  閉じ方は、タイトルバーの閉じるボタン、窓の外のタップ（`closeOnOutside` の既定のまま）、PC の Escape キー。閉じると、開く前の画面にそのまま戻る。
    *  見た目は、エンジンの**標準の見た目**のまま（`look` は渡さない。発注者の決定。ゲームの絵柄に合わせるかは後の試遊で決める）。
    *  大きさ: 画面の中央に置き、スマホの縦画面で文字が読め、スライダーを指で動かせる大きさにする（26章「既定の大きさ」の既定の値（タイトルバー 88・部品 88・スライダー 132・文字 36）は、短い辺 720 のこのゲームにそのまま合う）。窓の幅・高さと部品の並びは計画で決め、定数に置く。
    *  土台から残した `js/scenes/MenuScene.js`（使っていない）は、作り変えて使うか、消して新しいファイルにするかを計画で決める。消す・名前を変える場合は RES に書き、開発資料の「土台から残したファイル」の記述も直す予定に入れる。
*   **要件2: タイトル画面の「設定」**
    *  タイトル画面に「設定」ボタンを足す。置き場所は「遊び方」ボタンの下で、見た目は「遊び方」ボタンと同じ縁だけのボタンにする（文字は「設定」）。
    *  押して同じボタンの中で離したとき（今の「はじめる」「遊び方」と同じ押し方）に、メニューの窓が開く。キーは割り当てない（「遊び方」と同じ）。
    *  メニューを開いている間・閉じた後も、タイトルの曲は途切れず、頭に戻らない。閉じた後は、タイトル画面の「はじめる」「遊び方」「設定」が今までどおり使える。
    *  ボタンの文字は `js/view/titleText.js` に置く。タイトル画面の配置（`createTitleLayout`）と当たり判定（`titleHitTest`）に「設定」を足す。
*   **要件3: 盤面の TURN の区画**
    *  画面の最上部の中央の「TURN」とターンの番号を、**区画（枠）で囲んだボタン**の見た目にする。押せることが見て分かるようにする。
        *  区画は、左右の HP ゲージ・HP の数字・金貨のゲージ・「GOLD」のラベルと重ならない。枠の色・太さ・塗り・大きさは計画で決め、定数に置く（試遊で決め直す値）。
        *  区画は、段取りの間も攻防の演出の間も同じ場所に出す（攻防の演出中も最上部のゲージは描かれている）。押せない間の見た目は、押せる間と同じでよい（変えるかは後の試遊で決める）。
        *  押せる範囲は、指で押しやすい大きさ（目安として縦横 80 前後）を保つ。見た目の区画より広くてよい。
    *  **押せる間（発注者の決定）**: 段取りの間なら**いつでも**押せる。押すとメニューの窓が開く。
        *  「段取りの間」は、ステージの始まり・ターンの始まりの合図が終わってから、「準備終了」が出るまでの間。札・玉・兵が動いている途中でも押せ、行動を使い切ってから準備終了が出るまでの間も押せる。
        *  開いている間は背面の動きが止まり、閉じると続きから動く（札・玉・兵の動き、準備終了が出るまでの待ちも、閉じてから続く）。
    *  **押しても何も起きない間**: スタートの待ち・ステージの始まり・ターンの始まりの合図の間、「準備終了」が出ている間、BATTLE! の間、攻防の演出の間（演出のシーンが最前面にあるので、盤面の入力は届かない）、決着や敵を倒した後の案内の間。
        *  「準備終了」の「画面のどこかをタップで攻防へ」は今のまま（TURN の区画の上をタップしても BATTLE! が始まる）。
    *  TURN の区画を押したときは、盤面の操作（めくる・置く・選択）をしない。選んでいた山札・手札・束の選択はそのまま残してよい（閉じた後に続けられる）。
    *  プレイ中に開いて閉じても、盤面・行動の残り・兵・ゲージ・敵の予告は変わらない。
    *  盤面のタップの処理の順（`BoardScene.onPointer`。札が動いている間の無視 → `flow.tap` → 行動を使い切っていれば戻る → 盤面の操作）の中で、TURN の区画の判定をどこに入れるかは計画で決める。上の「押せる間」「押しても何も起きない間」を満たすこと（札が動いている間の無視より前に判定しないと、動いている途中に開けない点に注意）。「段取りの間か」の判定は、段階の管理（`boardFlow.js`）の状態から答える形にし、シーンに判定を書き散らさない。
*   **要件4: 「設定」タブ**
    *  **BGM の音量**と**効果音の音量**のスライダーを1つずつ置く（`addSlider`）。
        *  範囲は 0〜1、刻みは 0.1。値の文字は百分率（例: 「50%」）。
        *  動かすと、その場で音量が変わる（`Sound.bgmVolume`・`Sound.seVolume`）。タイトル画面で開けばタイトルの曲で、プレイ中に開けばステージの曲で、すぐ確かめられる。効果音の音量を動かしたときに確かめの音を鳴らすかは計画で決めてよい（鳴らすなら既存の効果音を使い、`soundCues.js` 経由で鳴らす）。
        *  初期値は、今の `js/audio/soundConfig.js` の `BGM_VOLUME`（0.5）・`SE_VOLUME`（0.7）を使う（試遊で決め直す値のまま）。
    *  **攻防の演出の速さ**を、選択肢の列（`addChoices`。横に並べる）で選ぶ。
        *  選択肢は「普通」「速い」の2つ（発注者の決定）。「普通」は今の速さ（1倍）、「速い」は今の **1.5 倍**の速さ。初期値は「普通」。
        *  倍率の値（1 と 1.5）と選択肢の文字は、設定の値として1か所に置く（試遊で決め直す値）。
        *  **次の攻防から効く**。攻防の演出の途中ではメニューを開けないので、演出の途中で速さが変わることはない。
        *  速くするのは攻防の演出（`BattleShowScene` が見せる演出）だけ。段取りの間の札・玉・兵の動き、ステージ・ターンの始まり、準備終了・BATTLE! の合図の長さは変えない。
        *  「速い」では、攻防の演出の全体（兵の動き・当たり・ヒットストップ・エフェクト・HP の減り・演出の終わりから次のターンまでの間）が同じ割合で速くなる。演出の時計で鳴らしている音のきっかけ（当たりの音・敵の攻撃の音）と、HP が 0 になった瞬間に BGM を止める時刻・クリアや負けの音の時刻も、演出と同じ割合で早まり、絵と音がずれない。音の再生の長さそのもの（mp3 の長さ）は変わらない。
        *  実現の仕方は計画で決める。参考: 攻防の演出の管理（`battleDirector.js`）は、`update` で足す壁の時計からヒットストップの並びで演出の時計を求めている。シーンが足す時間に倍率を掛ければ、ヒットストップも同じ割合で縮む。エンジンの `Engine.timeScale`（12章）は画面全体の `update` に効くので、使うなら段取りの間の動きに効かないことを確かめること。どちらでも、時間割の時刻（`battleTimeline.js` などの段の時刻）は書き換えない。
*   **要件5: 「クレジット」タブ**
    *  音の素材の出典を、文字（`addValue` など）で並べる。文面は仮に次の2行とする（発注者の決定。正式な文面は後で発注者が書き換える）。
        *  「BGM: 魔王魂」
        *  「効果音: Springin' Sound Stock」
    *  文面は1か所の定数（文字だけのファイル。`titleText.js` のような形）にまとめ、発注者がそこだけを書き換えれば変わるようにする。行を足せる形にする。
    *  押しても何も起きない。
*   **要件6: 設定の保存**
    *  BGM の音量・効果音の音量・攻防の演出の速さを、エンジンの `Storage`（22章）で保存する。ブラウザを閉じて開き直しても残る。
        *  `Storage.open` は `js/main.js` で起動時に1回だけ呼ぶ（開発資料の `js/main.js` の責務「起動時に1回だけ行う準備（`Storage.open` など）」）。`key`・`version`・`defaults` は計画で決める。`defaults` の音量は `soundConfig.js` の初期値を使う。
        *  起動時に、保存された音量を `Sound.bgmVolume`・`Sound.seVolume` に反映してから音を鳴らす（保存値と実際の音量が食い違わないようにする。26章の「値を変える部品の使い方の例」の注意）。
        *  部品は値を保存しないので、スライダー・選択肢の列の `write` の中で `Storage.set` を呼ぶ（26章「値のつなぎ方」）。`read` は `draw` の中から呼ばれるので、状態を変えない。
    *  設定の値を読み書きする口（今の値を答える・新しい値を書いて保存する・起動時に反映する）を1か所にまとめ、窓の部品・攻防の演出のシーンはその口を呼ぶ形にする。置き場所は計画で決める（ルール層ではない。演出の速さはルールではない）。
    *  **音の決まりを守る**: 今の決まりは「`Sound` を呼ぶのは `js/scenes/soundCues.js`・`js/scenes/bgmCues.js` の中だけ（起動の前の音量の設定は `js/main.js`）」。メニューから音量を変える処理をどこで `Sound` に渡すかは、この決まりに沿う形を計画で決める。決まりを広げる場合は、開発資料の責務の表（`js/scenes/` の行）を直す予定として RES に書く。

## 【計画書に必ず含めるべき固定タスク】
AIが作成する計画書（RES）のタスクリストには、全実装タスクの後に、以下のタスクを必ず含めること。
*   各タスクで記録した『開発資料の更新予定』を確認し、開発資料（`PROJECT_ARCHITECTURE.md`）へ反映する。開発資料に影響を与えない場合は、このタスクは不要とする。
    *   ※ 実装AIによる開発資料の書き換えは、本ワークフローにおいて原則禁止であるが、**この最終タスクのみ明示的な例外とする**。後続タスクが存在せず、資料の変更によって他タスクの前提が動く危険がないためである。個別の実装タスク内で資料を書き換えてはならない。
    *   開発資料の冒頭の「ゲームはまだこれらを使っていない」（UI 部品（26章））の記述と、`js/main.js` の記述（`Storage` を使っていない前提の部分）、3章の画面の流れ（タイトル画面のボタン・盤面からメニューを開けること）も、実際に合わせて直す。エンジンの使い方は書き写さず、章の番号と機能の名前だけを挙げる。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持**: 描画層（`js/view/`）にデータ・状態を持たせない。窓の開閉・タブの組み立てはシーン（`js/scenes/`）が行い、`Ui` の窓はシーンが持つ（26章「シーンへの置き方」）。設定の値の持ち主を1か所にし、窓・タイトル・盤面・攻防の演出にばらばらに値を持たせない。
*   **ルール層に触れない**: `js/rules/` は変更しない。メニューを開閉しても、ルール層の状態を変える操作を呼ばない。
*   **エンジンの使い方**: エンジンは `import { … } from 'oz'` でだけ使い、`oz/` は編集しない。`oz/src/` は読まない。必要な機能が `oz/ENGINE_API.md` にない、または書かれたとおりに動かないときは、ゲーム側に回避策を書かず、作業を止めて RES に記録する（憲法 3章「エンジンの不足への対応」）。
*   **入力の扱い**: `Engine.addButton` を窓と重なる位置に登録しない（26章「注意」。窓に入力が届かなくなる）。窓のシーンは受けたポインタをそのまま窓の `onPointer` に渡す。タイトル画面・盤面の当たり判定は今のとおり `js/view/layout.js` の配置で行う。
*   **時間**: 時間は `update(dt)` の `dt` と `draw` の `time` だけを使う。`draw` の中で状態を変えない（`read`・`format`・`label`・`enabled` の中も同じ）。
*   **今回やらないこと**:
    *   DEBUG タブ、デバッグを有効にする定数、デバッグスタート、デバッグの操作、FPS の表示（次のサブフェイズ以降で行う）。
    *   キャンバスキャッシュ（`oz/ENGINE_API.md` 25章）を使うこと。
    *   「設定」「クレジット」以外のタブ（更新履歴など）。設定の中身も、音量2つと演出の速さだけにする。
    *   スロー・一時停止など時間の操作。演出の速さを「普通」「速い」以外にすること。演出の設定の値（`js/anim/battleAnimConfig.js` などの速さ・大きさ・エフェクト）を変えること。
