## 【実装要件】
兵・ゴブリン・持ち物・シールドなど、たくさん描くスプライトを、キャンバスキャッシュ（`oz/ENGINE_API.md` 25章）で焼き付けて描けるようにする。DEBUG タブのチェックボックスで、焼き付けで描くか、元のスプライトを直接描くかを切り替えられるようにし、兵が多いときの重さ（FPS）を、焼き付けありとなしで測って RES に残す。

* 座標はすべて論理座標（画面 720×1280）で書く。
* タイトルからクリア・負けまで、通しで遊べること（デバッグの定数が ON でも OFF でも）。スマホの縦画面を優先し、PC でも同じように使えること。
* 絵の位置・大きさ・動き（傾き・伸び縮み・濃さ・奥と手前の描き分け）は、今と変えない。

*   **要件1: 焼き付けで描くもの**
    *  次のものを、焼き付けで描く。
        *  兵の群れで描くすべての種類（`js/view/troopView.js` の `drawTroop`）: 攻撃・防御・修理の兵（体＋持ち物）、敵兵・敵の守り・ゴブリン、シールド、炎。段取りの間に陣地で待つ兵と、攻防の演出中の兵の両方。
        *  段取りの間のゴブリンの軍勢の群れ（`js/view/enemyView.js`）と、巨人・ドラゴン・ゴブリンの軍勢の常時防御力のシールドマーク。
    *  上のもの以外（カード・山札・城・巨人・ドラゴンの絵・背景・ロゴ・数字・予告の絵・ヒットマーク・玉・人数の表示のアイコンなど）は、今のまま直接描く。測った結果、上のもの以外が重いと分かった場合は、焼き付けの対象を広げずに RES の「5. 懸念事項」に書く。
    *  焼き付けの単位（体と持ち物を1枚にまとめるか別々にするか）、倍率（焼き付ける大きさ。兵は `TROOP_SIZE` の一定の大きさ。シールドマークは数によって大きさが変わる）、色違い・大きさ違いの持ち方は計画で決める。決め方は 25章の注意（`scale` と大きく違う倍率で描くと、拡大ではぼやけ、縮小では細い線が淡くなる）に従い、今の描く大きさで、元のスプライトを直接描いたときと同じに見えるようにする。攻防の演出中の伸び縮み・傾きは、焼き付けたものに `ctx` の変換を掛けて描いてよい（大きく見た目が変わるなら懸念事項に書く）。
    *  焼き付ける範囲には、線の太さを含める（スプライトの `bounds` を使うか、表の範囲に線の太さを足すかは計画で決める）。絵の外側（線のふち）が切れないこと。描く位置・大きさの基準は、今の `SPRITE_TABLE` の範囲のまま（見た目を変えない）。
    *  焼き付けは `Engine.start` の後に作る。作る場所・持ち主・手放す時期（シーンの `init`・`destroy` で作り・手放すか、起動の後に1回だけ作ってページの間持ち続けるか）は計画で決める。持ち続ける場合も、数と大きさを抑え、iPhone の Safari の Canvas のメモリの上限（25章の注意）に当たらない量にする。
    *  ウィンドウの大きさや画面の向きを変えても、絵がぼやけたり崩れたりしない（25章「自動の焼き直し」）。
*   **要件2: 焼き付けの入り切り（DEBUG タブ）**
    *  DEBUG タブの「FPS を表示」のチェックボックスと FPS の値の近く（ルールの値の並びより上）に、チェックボックス「焼き付けで描く」（文字は計画で決めてよい。`js/view/debugText.js` に置く）を1つ足す。
    *  入れると焼き付けで描き、外すと元のスプライトを直接描く。切り替えはすぐ（次のフレームから）効く。段取りの間でも、攻防の演出中（メニューの窓は開けないので、次に段取りに戻ったときも同じ設定）でも、同じ設定で描く。
    *  初めは「入れた」状態（焼き付けで描く）。デバッグの定数が OFF のとき、「はじめる」のゲーム、タイトル画面などは、いつも焼き付けで描く。
    *  入り切りの状態は保存しない（`Storage` に書かない）。ページを読み込み直すと「入れた」状態に戻る。
    *  入り切りの状態はルールの状態ではない（描き方の設定）。ルール層には置かない。状態を変えるのはチェックボックスの `write` の中だけ（`read` は状態を変えない）。
    *  どちらで描いても、見た目は同じに見える。
*   **要件3: 重さの計測（テストプレイで発注者が測る）**
    *  測る端末は **Android のスマホ（Chrome）**。焼き付けあり・なしの両方で、次の4つの場面の FPS を測る（FPS は DEBUG タブの「FPS を表示」で画面の隅に出し、メニューの窓を閉じて見る）。
        1.  兵 189 体（DEBUG タブの兵の数のスライダーを攻撃・防御・修理とも 63）で、段取りの間（兵が陣地で待っている間）。
        2.  兵 189 体で、攻防の演出中。
        3.  ゴブリンの軍勢 300 体（DEBUG タブのルールの値でゴブリンの軍勢の最大 HP を 300 にし、敵の HP を満タンにする）で、段取りの間。
        4.  ゴブリンの軍勢 300 体で、攻防の演出中。
    *  実装セッションは、テストプレイの依頼のときに、上の測り方を手順として発注者に示し、発注者から受け取った結果（端末の名前・場面・焼き付けあり／なし・FPS（ふだんの値と、いちばん下がったときの値））を、RES に表で残す（「5. 懸念事項」の前に見出しを立てるか、「5. 懸念事項」の中に書く）。
    *  目標は、焼き付けありのとき、上の場面で 60fps 付近が出ること。**届かなかったときは、今回は結果を RES に残して報告するまでとし、描く数を減らすなどのほかの対策は入れない**（発注者が結果を見てから決める）。
    *  PC では、焼き付けあり・なしで見た目が同じこと、ウィンドウの大きさを変えても絵がぼやけないことを確かめる（FPS の記録は任意）。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **描き分けは1か所で**: 焼き付けで描くか直接描くかの描き分けは、スプライトを描く1か所（`js/view/spriteView.js`、または計画で決めた描画層の1か所）で行う。呼ぶ側（`troopView.js`・`enemyView.js` など）に、焼き付けかどうかの分岐を散らさない。キャッシュの入り切りは、エンジンの口ではなく、ゲーム側の描き分けで作る（発注者の決定）。
*   **描画層の決まり**: 描画層（`js/view/`）は、ゲームの状態（ルールの状態・演出の進み）を持たない・変えない。ルール層・anim を実行時に import しない。`assets/sprites/` を import するのは `js/view/spriteView.js` だけのまま。焼き付け（画像）と入り切りの設定を描画層に置く場合は、ゲームの状態ではない「描き方の資源・設定」であることを JSDoc に書き、`draw` の中で作り直し・入り切りを変えない（25章の自動の焼き直しはエンジンが行うのでよい）。
*   **焼き付けの作り・手放し**: `CanvasCache.create` は `Engine.start` の後に呼ぶ。シーンで作るなら `init` で作り `destroy` で `dispose()` する（継承するクラスでは `super.init()`・`super.destroy()` を呼ぶ。25章「作れる時期」）。手放した後の焼き付けを描かない。
*   **見た目を変えない**: `SPRITE_TABLE` の範囲・`TROOP_SIZE`・持ち物の大きさとずれの割合・シールドマークの並べ方は変えない。スプライト（`assets/sprites/`）は変えない。
*   **窓と入力**: 窓（`Ui`）はシーンが持つ。`read`・`format`・`label`・`enabled` は `draw` の中から呼ばれるので、状態を変えない。値を変えるのは `write`・`onPress` の中だけ。
*   **エンジンの使い方**: エンジンは `import { … } from 'oz'` でだけ使い、`oz/` は編集しない。`oz/src/` は読まない。必要な機能が `oz/ENGINE_API.md` にない、または書かれたとおりに動かないときは、ゲーム側に回避策を書かず、作業を止めて RES に記録する（憲法 3章「エンジンの不足への対応」）。
*   **時間**: 時間は `update(dt)` の `dt` と `draw` の `time` だけを使う。`draw` の中で状態を変えない。
*   **今回やらないこと**:
    *   要件1に挙げたもの以外を焼き付けで描くこと。
    *   60fps に届かないときの、ほかの対策（描く兵の数を減らす、描き方を変えるなど）。
    *   兵の大きさ（`TROOP_SIZE`）・スプライトの範囲の表・スプライトそのものを変えること（範囲の表と `bounds` の違いの解消を含む）。
    *   デバッグの定数を OFF にすること（後のサブフェイズ）。
    *   06-02・06-03 で作った DEBUG タブの項目（兵の数・敵・次の行動・HP・FPS・ルールの値）の動きを変えること（チェックボックスを足すための配置のずれは除く）。
