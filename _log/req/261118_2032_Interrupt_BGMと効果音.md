## 【実装要件】
発注者が用意した音のファイルで、BGM（タイトル・ステージごと）を入れ、効果音の一部を差し替え・追加する。**ゲームのルール・設定の値（`js/rules/`）と、攻防の演出の時刻・見た目は変えない。** ここに書いていない効果音は、今の仮の合成音のまま変えない。

エンジンの確認結果（`oz/ENGINE_API.md` 21章）: `Sound.playBgm` はループで流れ、別の曲ならクロスフェード、同じ曲なら何もしない。`Sound.stopBgm` で止められ（フェードアウトつき）、フェードアウト中の曲の名前を `playBgm` すると頭から流れ直す。音は実時間で進み `Engine.timeScale` の影響を受けない。mp3 は `Assets.load` の `sounds` で読める（例が mp3）。**エンジンへの追加の依頼は要らない。**

*   **要件1: 音のファイルを `assets/` へ写す**
    *  次の表のとおり、元のファイルを **ASCII の名前で** `assets/` へコピーする（元のファイルは動かさない・消さない）。BGM は新しいフォルダ `assets/bgm/`、効果音は今の `assets/sounds/` に置く。
    *  元のフォルダ: BGM は `D:\ozlab\_attic\assets\魔王魂\`、効果音は `D:\ozlab\_attic\assets\Springin' Sound Stock\`（フォルダ名に `'` を含む）。

*   **要件2: 音の一覧と音量**
    *  音の名前とパスの一覧（`js/audio/soundConfig.js`）に、BGM 3曲と追加の効果音4つ（スタート・巨人の攻撃・ドラゴンの爪・ブレス）を足し、`win`・`lose` のパスを mp3 に替える。BGM と効果音は、エンジンの一覧では区別しない（ENGINE_API 21章）ので、同じ `Assets.load` の `sounds` に入れてよい（一覧を分けるかは計画で決める）。
    *  BGM の音量の初期値を `js/audio/soundConfig.js` に足し（初期値 0.5。試遊で決め直す）、`js/main.js` で起動の前に `Sound.bgmVolume` に設定する（SE の音量と同じやり方）。**音量・消音を切り替える画面や操作は作らない。**
    *  BGM の切り替え・止め方のフェードの長さ、スタートの音の後にステージの曲を始めるまでの待ち時間など、調整したくなる値は `js/audio/soundConfig.js` に名前を付けて持つ（試遊で決め直す値として）。
    *  読み込みは今と同じく、`Engine.start` の前に `Assets.load` で済ませる（読み込みの終わっていない名前で `playBgm` するとエラーになるため）。BGM の分だけ起動の前に画面が空の時間が延びるが、ロードの画面は作らない（懸念事項に書くだけ）。
*   **要件3: タイトルの BGM**
    *  タイトル画面（TITLE）が出たら、タイトルの曲をループで流す（BOOT を離れた後なので、TITLE の `init` で鳴らしてよい。ENGINE_API 21章「最初の入力まで」）。BOOT では鳴らさない。
    *  タイトル → 遊び方 → タイトルと行き来しても、タイトルの曲は止まらず、頭に戻らずに流れ続ける（遊び方の画面でも流れたまま。遊び方の画面は今のまま効果音を鳴らさない）。
    *  決着の後にタイトル画面へ戻ったときは、タイトルの曲を頭から流す（決着で BGM は止まっているため）。
*   **要件4: ゲームスタート**
    *  タイトルの「はじめる」（Enter・Space も同じ）で盤面へ進むとき、タイトルの曲を短いフェードアウト（初期値 300ms）で止め、同時にゲームスタートの音（`start`）を鳴らす。
    *  ステージ（ゴブリン）の曲は、**スタートの音が鳴り終わってから**鳴らし始める（スタートの音と重ねない）。待ち時間は設定値（初期値はスタートの音の長さに合わせて 1200ms 前後）。待っている間も盤面の操作は今のまま受け付ける。待ち時間は盤面のシーンの `update` の `dt` で数えてよい（段取りの間は `Engine.timeScale` が 1 のため）。`js/` に `setTimeout`・`performance.now()`・`Date.now()` を書かない。
*   **要件5: ステージの BGM**
    *  ステージは敵1体ごと（ゴブリンの軍勢・巨人・ドラゴン）。曲は、ゴブリン・巨人のステージが `stage`、ドラゴンのステージが `dragon`。
    *  各ステージの曲は、**そのステージが始まったところで頭から鳴り始め**、ステージの間はループで流れ続ける。フェーズが変わっても、攻防の演出を積んでも、早送り・スキップしても途切れない・頭に戻らない（音は実時間で進み、`timeScale` の影響を受けない）。
    *  ステージが始まったところ:
        *  最初のステージ（ゴブリン）: 新しいゲームの盤面に入り、要件4の待ち時間が過ぎたところ。
        *  2つ目以降（巨人・ドラゴン）: 前の敵を倒した後の案内（「タップで次へ」）をタップして、次の敵との最初のフェーズに入ったところ。
    *  **巨人のステージはゴブリンと同じ曲だが、巨人のステージが始まったところで頭から流し直す**（エンジンでは、同じ曲の `playBgm` は何もしない。要件6でゴブリンを倒したときに BGM は止まっているので、止まった後・フェードアウト中のどちらでも頭から流れる。ENGINE_API 21章）。
    *  どの曲を流すかは、敵の種類の識別子（`game.enemy.typeId`。`goblins`・`giant`・`dragon`）から引く表（`js/audio/soundConfig.js` に置く。`js/rules/` は import しない）で決める。ステージが始まったかどうか（敵が入れ替わったか）の見分け方は計画で決める（ルール層は変えない。`js/rules/` の問い合わせを読むだけ）。
*   **要件6: 敵を倒したとき・決着したときの BGM と音（ゴブリン・巨人・ドラゴンで同じ形）**
    *  **BGM を止める時刻:** 攻防の演出の中で、**敵の HP が 0 になった瞬間**（ゴブリンの軍勢は最後の1体が弾かれて HP が 0 になったとき、巨人・ドラゴンはシールドの後の当たりで HP が 0 になったとき）に BGM を止めて無音にする（短いフェードアウト。初期値 300ms）。負けは、**城の HP が 0 になった瞬間**に同じく止める。ゴブリン・巨人を倒したときも、ドラゴンを倒した（クリア）ときも、負けたときも同じ形にする。
    *  **音と表示:** 敵が倒れて消え、演出が終わって、敵を倒した後の案内（ゴブリン・巨人）・結果の板（クリア）が出るのと同時に、クリアの音（`win`）を鳴らす。負けは、結果の板が出るのと同時に負けの音（`lose`）を鳴らす。案内・結果の板が出る時刻は今のまま（演出の終わり）で変えない。**ゴブリン・巨人を倒したときにもクリアの音を鳴らす**（今は鳴らしていない）。音は1回の攻防で1回だけ。
    *  BGM が止まってから案内・結果の板が出るまでの間も、当たり・修理などの今の効果音は今のまま鳴る。
    *  HP が 0 になった瞬間を、演出の時計の上でどう見つけるか（音のきっかけの種類を足す、HP の変化の記録から求める、など）は計画で決める。ただし時刻の式を新しく書き写さず、時間割が持つ記録から読むこと。
*   **要件7: 攻撃の効果音（巨人の攻撃・ドラゴンの爪・ブレス）**
    *  巨人の攻撃の攻防では `giantAttack`、ドラゴンの爪の攻防では `dragonClaw`、ドラゴンのブレスの攻防では `dragonBreath` を、**敵の攻撃の段の始まりに1回だけ**鳴らす。
        *  巨人の攻撃・ドラゴンの爪（飛ぶもののない打撃）: 敵の攻撃の最初の段（`strikeBlock`、防御の兵がいなければ `strikeCastle`）の始まり（撃つ瞬間。大きな一撃なら段が光る時刻）。この時刻には1発目の当たりの音（相殺の音・城に当たる音）も鳴るが、**両方鳴らす**（今の当たりの音は1発目も含めて今のまま）。
        *  ブレス: 炎が口から出始める時刻（`enemyMarch` の段の始まり）。その後の相打ち（相殺の音）・城に当たる音、同時に始まる札が燃える段の音は今のまま。
    *  ゴブリンの攻撃・敵の防御・振りかぶり・吸い込む（ための段）では、新しい音は鳴らさない。
    *  どの敵のどの攻撃でどの音を鳴らすかは、表で持つ（敵の種類の識別子・行動の中の種類（`variant`）は既存の見せ方の表 `js/anim/enemyShows.js` と同じ引き方）。`js/anim/` は音の名前を持たず「いつ・どの攻撃が始まったか」のきっかけだけを答え、音の名前への対応は `js/scenes/soundCues.js` が持つ（今の `BATTLE_CUE_SE` と同じ分担）。
*   **要件8: 早送り・スキップのとき**
    *  早送り: 効果音は今と同じく演出の時計のきっかけで鳴る（早送りの分だけ間隔が詰まる）。BGM は実時間で進むので、早送りの影響を受けない（速くならない・音程が変わらない）。
    *  スキップ: 今と同じく、飛ばした分のきっかけの効果音（攻撃の音を含む）は鳴らさない。BGM はそのまま流れ続ける。ただし、決着する・敵を倒す攻防で、**HP が 0 になる瞬間より前にスキップした**ときは、スキップした時点で BGM を止める（要件6）。クリアの音・負けの音は今と同じく案内・結果の板が出るときに1回だけ鳴る。
*   **要件9: 今と同じく使えること**
    *  タイトルからクリア・負けまで通しで遊べ、決着の後のタイトル画面から何度でも新しいゲームを始められる（そのたびに要件3〜6のとおりに鳴る）。BGM が二重に鳴ったり、止まらずに残ったりしない。
    *  音の読み込みに失敗した名前があっても、エラーにならず遊べる（エンジンの決まり。ENGINE_API 20章・21章）。

*   タスク完了後、作業レポート（本RESファイル）の詳細作業内容を記載し完成させる。
*   開発資料（`PROJECT_ARCHITECTURE.md`）の記載に影響が出る場合は、資料本体は修正せず、その旨を『開発資料の更新予定』欄に追記する。

## 【計画書に必ず含めるべき固定タスク】
AIが作成する計画書（RES）のタスクリストには、全実装タスクの後に、以下のタスクを必ず含めること。
*   各タスクで記録した『開発資料の更新予定』を確認し、開発資料（`PROJECT_ARCHITECTURE.md`）へ反映する（フォルダ構造の `assets/bgm/` と `assets/sounds/` の説明、処理フローの「TITLE と遊び方の画面も今は音を鳴らさない（BGM は後の Phase）」の書き直し、BGM の流れ（タイトル・スタート・ステージ・敵を倒したとき・決着）、`soundCues.js`・`soundConfig.js`・`main.js` と、新しく作る・責務の変わったファイルの表など）。開発資料に影響を与えない場合は、このタスクは不要とする。
    *   ※ 実装AIによる開発資料の書き換えは、本ワークフローにおいて原則禁止であるが、**この最終タスクのみ明示的な例外とする**。後続タスクが存在せず、資料の変更によって他タスクの前提が動く危険がないためである。個別の実装タスク内で資料を書き換えてはならない。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : `PROJECT_CONSTITUTION.md` の絶対禁止事項に反する設計をしてはならない。`Sound`（`playSe`・`playBgm`・`stopBgm`）を呼ぶのは `js/scenes/soundCues.js` の中だけにする（今の `Sound.playSe` と同じ決まりを BGM にも広げる。音量の設定は今のまま `js/main.js`）。シーンは `soundCues.js` の関数を呼ぶ。`js/audio/` は値（音の名前とパス・音量・フェードの長さ・待ち時間・敵の種類 → 曲の名前の表）だけを持ち、`oz` も `js/` のほかのフォルダも import しない。`js/anim/` は音の名前を持たず、`Sound` を import しない（きっかけの時刻と種類を答えるだけ）。`js/view/` は `Sound` を import しない。
*   **時刻の式を増やさない** : 攻撃の音・HP が 0 になる瞬間のきっかけは、時間割（`js/anim/battleTimeline.js`）が持つ段の始まりの時刻・HP の変化の記録から読む。打撃・相打ち・落ちる時刻の式を別の場所に書き写さない。攻防の演出の時刻・長さ・見た目は変えない。
*   **ルールを変えない** : `js/rules/` は読むだけで変更しない。敵の種類・行動の中の種類はルール層の値（`typeId`・`variant`）を読むだけにする。
*   **BGM の状態** : どの曲が流れているかの状態は、エンジンが持つ（同じ曲の `playBgm` は何もしない）。ゲームの側で必要な状態（スタートの後の待ち時間の残り、いまのステージの敵を見分けるための値、決着の BGM を止め済みか、など）は、それを使うシーンが持つ。ルール層の状態には入れない。`draw` の中で音を鳴らさない・止めない。
*   **エンジンの使い方** : 音は `oz/ENGINE_API.md` 20章・21章に書かれた方法だけで扱う。`js/` に `AudioContext`・`Audio`・`addEventListener`・`requestAnimationFrame`・`setTimeout`・`setInterval`・`performance.now()`・`Date.now()`・`Math.random` を書かない。エンジンの機能が足りないと分かった場合は、回避策を作らず、RES の懸念事項に書いて発注者の判断を仰ぐこと。
*   **先回り実装の禁止** : 音量・消音の切り替えの画面や操作、設定の保存（`Storage`）、ロードの画面、ここに書いていない効果音の差し替え・追加、ゴブリンの攻撃の音、ための段の音、BGM の音程・速さの変化、曲の切り替えの演出（画面の暗転など）、遊び方の画面の音は作らない。音のファイルの加工（切り詰め・形式の変換・ループ位置の調整）もしない。

*   **懸念事項に書くこと（作らずに記録する）**
    *  BGM の分だけ起動の前に画面が空の時間が延びること（BGM は合わせて約 10MB。ロードの画面は作らない）。
    *  BGM はデコードした後のメモリが大きいこと（タイトルの曲は約 5 分）。スマホで重い・鳴らないなどの様子があれば発注者に伝える。
    *  mp3 はファイルの頭と終わりにわずかな無音を持つことがあり、ループのつなぎ目で一瞬途切れて聞こえる場合があること（ファイルの加工・エンジンの回避策はしない）。
*   **テストプレイで確かめること（計画の最後に、発注者が見る点として書くこと）**
    *  BOOT（TAP SCREEN）では音が鳴らず、タイトル画面でタイトルの曲が流れる。遊び方を開いて戻っても、曲が途切れず頭に戻らない。
    *  「はじめる」（Enter・Space）で、タイトルの曲が短く消えてスタートの音が鳴り、鳴り終わってからゴブリンのステージの曲が始まる。その間も盤面を操作できる。
    *  ステージの曲がフェーズをまたいでも、攻防の演出・早送り・スキップでも途切れず、曲の終わりまで来たら頭に戻ってくり返す。早送りで BGM が速くならない。
    *  ゴブリンの最後の1体が弾かれて HP が 0 になった瞬間に BGM が止まり、演出が終わって案内が出るのと同時にクリアの音が鳴る。タップで巨人のステージに入ると、同じ曲が頭から流れる。
    *  巨人の攻撃で、撃つ瞬間に巨人の攻撃の音が鳴る（当たりの音も鳴る）。巨人を倒したときもゴブリンと同じく、HP 0 で BGM が止まり、案内と同時にクリアの音。タップでドラゴンのステージに入ると、ドラゴンの曲が流れる。
    *  ドラゴンの爪で爪の音、ブレスで炎が口から出るときにブレスの音が鳴る（相打ち・城に当たる音・札が燃える音は今のまま）。
    *  ドラゴンの HP が 0 になった瞬間に BGM が止まり、結果の板が出るのと同時にクリアの音が鳴る。負けは、城の HP が 0 になった瞬間に BGM が止まり、結果の板と同時に負けの音が鳴る。
    *  決着の攻防を、HP が 0 になる前にスキップすると、スキップした時点で BGM が止まり、結果の板と同時にクリア・負けの音が鳴る。
    *  結果の板のタップでタイトルへ戻ると、タイトルの曲が頭から流れ、もう一度遊んでも同じように鳴る。BGM が二重に鳴ったり、残ったりしない。
    *  BGM と効果音の音量の釣り合い（BGM の初期値 0.5・SE 0.7）。
