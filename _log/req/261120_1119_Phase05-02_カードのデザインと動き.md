## 【実装要件】
カードの表の枠と裏の模様を、`assets/sprites/` のスプライトで描く。あわせて、カードの動きの粗い所を2つ直す（長い列の詰め直し、山札のめくれの時刻）。

* スプライトは次の順で作る。
  1. 今回、実装側で、今の見た目と同じ仮のスプライト JS を書き出す。OZ Vector Editor で開いて調整できる形にする。
  2. 後で発注者がエディタで調整し、書き出したファイルを同じ名前で差し替える。
  3. 差し替えた後も、ゲーム側のコードを変えずに描ける。
* **ルールは変えない**（ルール層 `js/rules/` は変更しない）。
* タイトルからクリア・負けまで、通しで遊べること。スマホの縦画面を優先し、PC でも同じように遊べること。

*   **要件1: カードのスプライト（仮の書き出し）**
    *  次の5つのスプライト JS を、`assets/sprites/` に新しく作る（このサブフェイズでは、手で書いた仮のスプライトを置いてよい。発注者の決定）。
        *  カードの表の枠: スートごとに1つで、計4つ。`card_front_sword.js`・`card_front_shield.js`・`card_front_hammer.js`・`card_front_gold.js`。スートの識別子とスプライトの名前の対応は、今のスートの絵と同じにする（`sword` → sword、`shield` → shield、`potion` → hammer、`muscle` → gold）。
        *  カードの裏: `card_back.js`（1つ）。
    *  **エディタでの描き方の約束**:
        *  原点 (0, 0) をカードの中心にする。カードの外形は、**幅 100 × 高さ 140**（x −50〜50、y −70〜70）の実寸で描く。いまのゲームのカードと同じ大きさで、エディタで太さ 2px の線は、ゲームでも 2px に見える。
        *  ゲームは、この 100×140 の範囲をカードの矩形（`layout.card` の幅×高さ）に合わせて拡大縮小して描く。この範囲の外にはみ出した部分も、同じ倍率でそのまま描く。
        *  倍率の元にする 100×140 は、`js/view/` の定数1か所に持つ。スプライトの `bounds` は実行時に読まない（線の太さの分だけ広がるため）。
        *  この約束は、開発資料にも書く（発注者がエディタで描くときの決まりとして）。
    *  **仮の中身は、今の見た目をそのまま写す**。テストプレイで、カードの見た目が今と変わらないことを確かめる。
        *  表の枠（4つとも同じ中身）: 角丸の地（`#fdfaf0`）と縁（`#333333`、太さ 2、角の半径 8）。
        *  裏: 角丸の地（`#2f4a8a`）と縁（`#333333`、太さ 2、角の半径 8）、内側の角丸の枠（`#9fb4e6`、太さ 2、内側へ 6、角の半径 4。塗りなし）。
        *  エディタには角丸の矩形がないため、角の丸みは短い直線を並べた閉じたパスで近似してよい（近似の細かさは計画で決める）。
    *  **ファイルの形**:
        *  既存のスプライト（`effect_hit.js` など）と同じ形にする。`oz-vector-editor-sprite`・`formatVersion` 2 のスプライトデータ（`bounds`・`elements`・`source`）と、同じ `draw(ctx)` を持つ既定の export。他のファイルには依存しない。
        *  `source`（作業データ）も持たせ、**エディタの「開く」でそのまま開いて図形を編集できる**ようにする。`elements` と `source` の図形は同じ内容にする。
        *  `bounds` は、エディタの定義（線の太さの半分を含む）に合わせて求める。
    *  スプライトの import と描画は、今の決まりどおり `js/view/spriteView.js` に集める。
*   **要件2: カードをスプライトで描く**
    *  カードの表は、スートの表の枠のスプライトを描き、その上に、今と同じく左上の数字（スートの色）と中央のスートの絵を重ねて描く。数字・スートの絵の位置・大きさ・色は変えない。
    *  カードの裏は、裏のスプライトで描く。
    *  めくれ（横幅を縮めた表裏）・玉に変わる前の札・手札・列・山札・動いているカードなど、表と裏を描くすべての所が、スプライトで描かれる（今の `drawCardFace`・`drawCardBack` を通る所）。
    *  次のものはスプライトにせず、今のままコードで描く。
        *  カードに重ねる色（燃える札の明滅などの `drawCardTint`）と、強調の枠（`drawHighlight`）。角の半径 8 の角丸のままでよい。
        *  空き枠（点線）と、捨て札の枠。
    *  未知のスートのカードでもエラーにせず、どれか1つの表の枠で描く（どれにするかは計画で決める）。
*   **要件3: 長い列の詰め直しを滑らかにする**
    *  長い列は、領域に収まらなくなると詰まり、短くなると広がる（`columnCardYs`）。このとき、列にもとからあったカードも、新しい位置へ滑らかに動いて移るようにする。今は一瞬で移る。
    *  **動き始める時刻**（発注者の決定）: もとからあるカードは、**動くカードが着いてから**動き始める。
        *  置く（山札から・手札から）、束の移し替えの場合: 動くカードが列に着いてから。
        *  束の移し替えで元の列が短くなった場合: 動いた札が先の列に着いてから。
        *  放つで列が短くなった場合: 放った札が全部玉に変わってから。
    *  動く時間は、演出の時間の設定（`js/anim/animConfig.js`）に新しい値として置き、試遊で決め直す値と書く。目安 200ms。
    *  動いている間、盤面のタップは今のカードの移動の間と同じく無視する。
    *  詰め直しが起きない操作（列が領域に収まったまま）では、今と同じ動きのままにする。
    *  攻防の演出中に、ブレスで札が燃えて列が短くなる場合は、今回は扱わない（今のままでよい）。
*   **要件4: 山札のめくれの時刻**
    *  今は、上のカードが山札を離れる瞬間に、下のカードがめくれ始める。これを、**抜けたカードが半分ほど離れた頃**（目安 120ms 後。発注者の決定）にめくれ始めるようにする。
    *  待っている間は、下のカードは裏のまま見えている。
    *  待ちの時間は、演出の時間の設定（`js/anim/animConfig.js`）に新しい値として置き、試遊で決め直す値と書く。
    *  対象は、山札からカードが抜けるすべての操作（置く・捨てる・手札に入れる）と、山札が空になって捨て札から補充されたときのめくれ。
    *  めくれが終わるまで盤面のタップを無視するのは、今のとおりでよい（待ちの分だけ延びる）。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : `PROJECT_CONSTITUTION.md` の絶対禁止事項に反する設計をしてはならない。
    *   描画（`js/view/`）は状態を変えず、ルール層（`js/rules/`）を実行時に import しない。
    *   時間で進む動きは `js/anim/` に置く。`js/anim/` は描画も状態の変更もしない。
    *   配置（座標と大きさ）は `js/view/layout.js` に置く。
*   **スプライトの扱い** :
    *   新しく作ってよいのは、要件1の5つのファイルだけ。`assets/sprites/` の既存のファイルは変更しない。
    *   スプライトの `draw` 以外のキーは、実行時に読まない。
    *   `assets/sprites/` を import するのは `js/view/spriteView.js` だけにする。
    *   `ctx` の変換の設定は、必ず `save`／`restore` で囲む。
*   **ルールと演出を変えない** :
    *   `js/rules/` は変更しない。
    *   今回の要件の外の動きは変えない。放つ演出（玉・兵）、攻防の演出、カードの移動の時間（`cardMoveMs`）、めくれそのものの時間（`deckFlipMs`）、効果音のきっかけがそれにあたる。
*   **1ファイル1責務** : `js/view/cardView.js`・`js/view/spriteView.js`・`js/anim/planningMotion.js`・`js/anim/boardAnimator.js`・`js/scenes/BoardScene.js` を肥大化させない。列の詰め直しの動きが大きくなるなら、責務に合うモジュールに分ける（分けるかどうかは計画で決め、ファイル先頭の責務定義を合わせる）。
*   **先回り実装の禁止** : 次のものは作らない（後のサブフェイズか未定）。
    *   カードの数字やスートの絵の作り直し
    *   山札の下に裏のカードを重ねて見せる表示
    *   空き枠・捨て札の枠のスプライト化
    *   攻防の演出中の燃える札の詰め直しの動き
    *   「準備終了」・始まりの演出
    *   放った直後のタップを受けない時間の短縮
    *   ヒットマークの絵
    *   遊び方の文章（`js/view/howToText.js`）の書き換え
*   **エンジンの使い方** :
    *   `oz` は `import { … } from 'oz'` でだけ使う。
    *   `js/` に `addEventListener`・`requestAnimationFrame`・`getContext`・`setTimeout`・`setInterval`・`performance.now()`・`Date.now()` を書かない。
*   **変更してよい範囲** :
    *   変更してよいもの: `js/view/`・`js/anim/`・`js/scenes/` の中のファイル（新しいファイルを含む）と、要件1の5つの新しいスプライトのファイル。どのファイルを変えるかは計画に明記すること。
    *   変更しないもの: `js/rules/`・`js/audio/`・`oz/`・`index.html`・`js/main.js`・`js/ui/`、`assets/` の既存のファイル。
    *   これら以外の変更が必要だと分かった場合は、計画の中で理由を書いて対象に加えないこと。RESの懸念事項に記して、発注者の判断を仰ぐこと。
*   **テストプレイで確かめること（計画の最後に、発注者が見る点として書くこと）**
    *  カードの表（列・山札・手札・動いているカード・玉に変わる前の札）と裏（めくれの途中）が、今と同じ見た目で描かれている。数字とスートの絵の位置・大きさ・色も今と同じ。
    *  `assets/sprites/` の `card_front_sword.js`・`card_front_shield.js`・`card_front_hammer.js`・`card_front_gold.js`・`card_back.js` を、OZ Vector Editor の「開く」で開ける。原点を中心に 幅100×高さ140 のカードの形が見え、図形を選んで編集できる。
    *  （任意。確かめられるなら）エディタで色などを変えて同じ名前で書き出し、差し替えて再読み込みすると、ゲームのカードに反映される（ゲーム側のコードの変更なし）。
    *  山札から置く・捨てる・手札に入れると、抜けたカードが半分ほど離れた頃に、下のカードが裏から表へめくれる。
    *  列が詰まる長さ（14枚以上）で置く・移すと、動くカードが着いた後に、もとからあったカードが詰まった位置へ滑らかに動く。
    *  長い列から移す・放つと、残ったカードが広がった位置へ滑らかに動く（移すときは動いた札が着いた後、放つときは札が全部玉に変わった後）。
    *  これらの動きの間はタップを無視し、終わった後は普通に操作できる。
    *  スマホの縦画面と PC で、タイトルからクリア・負けまで通しで遊べる。
