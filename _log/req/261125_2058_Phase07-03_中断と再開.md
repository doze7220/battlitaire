## 【実装要件】
ゲームの途中でブラウザを閉じても、タイトルの「再開」から、閉じたターンの始まりに戻って続けられるようにする。

* 座標はすべて論理座標（画面 720×1280）で書く。画面の呼び名は TURN・ターン（内部の名前は phase）。
* ゲームのルール・数値・乱数を呼ぶ順と回数・演出は変えない（要件2 でプレイ用の乱数の作り方だけを替える）。

### 今の作り（現場設計で確かめたこと）
* エンジンの `Storage` は、`Storage.open` を1回しか呼べず、1つの `key` に全部の名前が1つの JSON で入る。`open` の `version` を上げると、設定を含む全部が既定値に戻る。`defaults` に名前を足すだけなら版番号は上げなくてよい（増えた名前は既定値になる）。
* 設定の保存は `settingsStore.js` の `SETTINGS_STORAGE`（`key` は `'battlitaire'`、`version` は 1）。デバッグ（`Engine.debug`）のときは保存しない（`writeValue`）。`Engine.debug` は `Engine.start` の後だけ読める。
* プレイ用の乱数は `main.js` が `Math.random` を盤面のシーンに渡し、`Game` が全部の抽選に使う。`Math.random` は状態を取り出せない。エンジンに乱数の機能はない。画面・演出（`js/view/`・`js/anim/`）は乱数を使っていない。
* 敵の並びの種（`Game.seed`。始めた日付の整数）は、`main.js` の `createBoard` が「はじめる」のときに1回だけ読む。敵の種類は種とステージの番号だけで求まる。
* ターンの始まり: 最初のターンは `new Game` の終わりで予告が決まる。2ターン目からは、攻防の演出のシーンが `game.startNextPhase()` を呼んだ時点で、ゲージ・行動の回数・敵の入れ替わり・予告まで全部決まる（敵を倒したときは「タップで次へ」のタップで呼ぶ）。どちらも、その後に画面の「ステージの始まり」「TURN N と予告」が出る。
* `boardFlow.js` は、スタートの待ち（`stageWaitMs`）の後にステージの始まり（曲も同時に始まる）→ フェーズの始まり、の順に出す。ステージの始まりを出す前の敵は描かない（`entranceLook`）。
* いまは、遊んでいる途中でタイトルへ戻る操作はない（負けてから戻るだけ）。途中でやめるのは、ページを閉じる・読み込み直すこと。

*   **要件1: 保存の時と中身**
    *  各ターンの始まり（予告など、そのターンの始まりの抽選がすべて決まった時）に、中断データを上書きで保存する。はじめてのターンも、敵を倒した後の最初のターンも含む。
    *  ターンの途中（札を置く・放つなど）では保存しない。途中で閉じると、そのターンの始まりからになる。攻防の演出の途中や、敵を倒した後の「タップで次へ」の前に閉じたときも、そのターンの始まりからになる。
    *  中断データに持つもの（ルールの状態）: 山札・捨て札・列・手札（並びの順と、カードの id・スート・数字）／城の HP・最大 HP／全部のゲージ（金貨を含む）／行動の回数（そのターンの回数と残り）／敵の種類・HP・最大 HP・予告（防御の量、疲弊の前の量、行動の中の種類、燃やす枚数の範囲を含む）・行動の決まりの状態（数え下ろし・前の行動の種類）／敵の並びの種（始めた日付）・ステージの番号・通しのターンの番号・戦闘のターンの番号（疲弊はこれから決まる）／結果の集計（倒した敵の数などの5つ）／プレイ用の乱数の状態／中断データの版番号。
    *  持たないもの: 出ている兵、玉・兵・エフェクト・演出の途中、カードの動きの位置、選択の状態、設定、デバッグの状態、ルールの設定の値（`config.js`）。
    *  中断データの形（状態 → 保存できるデータ、データ → 状態）を作る所は、ルール層の1か所にする。後のサブフェイズで状態が増えたとき、ここに足せばよい形にする。`Storage` の読み書きは画面の側（`js/scenes/`）の1か所にする。
*   **要件2: プレイ用の乱数**
    *  プレイ用の乱数を、状態を取り出し・戻せる乱数に替える。純粋な計算としてルール層に置き（`Math.random`・日付は読まない）、始めの状態は「はじめる」のたびに画面の側で `Math.random` から1回だけ作る（今までどおり、日付によらず毎回ちがう）。
    *  偏りのない、十分にばらつく計算にする（一時スクリプトで、出る値の偏り・続く値の関係・始めの状態が近いときの似かたを確かめる）。
    *  敵の並びの種（`seed`）とは別のまま。
*   **要件3: タイトルの「再開」**（発注者の決定）
    *  中断データがあるときだけ、「はじめる」の上に「再開」のボタンを出す。ゲーム名と「はじめる」の間に置き、ほかのボタンとゲーム名は動かさない。
    *  ボタンの中に「再開」と、その下に「STAGE 6・TURN 3」のように、どこからか（ステージの番号と、戦闘のターンの番号）を出す。3桁でもはみ出さない。
    *  見た目は、押してほしいボタンと分かる、塗りのあるボタンにする（「はじめる」と同じ系統）。「はじめる」との見分けがつくこと。押し方は今のボタンと同じ（このシーンで押して離す）。
    *  キーボードの Enter・Space は、中断データがあれば「再開」、なければ今までどおり「はじめる」。
    *  中断データがないときのタイトルは、今とまったく同じ。
*   **要件4: 「再開」の動き**
    *  押すと、「はじめる」と同じくタイトルの曲を止めてスタートの音を鳴らし、盤面へ進む。スタートの待ちの時間も同じ。
    *  戦闘の1ターン目（TURN 1）からの再開（発注者の決定）: ふつうにステージへ入ったときと同じで、敵が入ってきて「STAGE N」と名前 → 「TURN 1」と予告。
    *  2ターン目以降（TURN 2〜）からの再開: 「STAGE N」は出さず、敵は初めから立っている。スタートの待ちの後に、ステージの曲を始めると同時に「TURN N」と予告を出す。待ちの間・表示の間は、今と同じく盤面を触らせない。
    *  盤面・手札・捨て札・金貨・城と敵の HP・予告・敵の Lv・疲弊・行動の回数・倒した敵の数が、保存したときと同じである。
    *  同じ手順で遊べば、同じ札が出て、同じ結果になる（閉じて開き直しても、引き直しにならない）。
    *  日付が変わってから再開したときは、始めた日の敵の並びで続ける（今日の日付を読み直さない）。
    *  再開しても中断データは消えない。次のターンの始まりで上書きされる。再開の直後に閉じても、もう一度再開できる。
*   **要件5: 中断データが消える時**
    *  負けの結果が画面に出た時に消える（発注者の決定: 負けるターンの攻防の演出の途中で閉じたときは、そのターンの始まりから再開できる）。負けの音・結果の板を出すのと同じ時（1回だけ）に消す。
    *  「はじめる」を押すと、確かめずに新しいゲームが始まり、中断データは新しいゲームの最初のターンのもので上書きされる（発注者の決定: 確認の窓は作らない）。
    *  敵を倒しても消えない。音量・演出の速さの設定は、中断データの保存・破棄と関係なく残る。
*   **要件6: 版番号と壊れたデータ**
    *  中断データは、設定の保存とは別の版番号を持つ（初めは 1。1か所の定数）。`SETTINGS_STORAGE` の `version` は上げない（設定が消えるため）。すでに設定を保存してある端末で開いても、設定が残ること。
    *  版番号が合わないとき、形が壊れているとき、今の設定にない敵の種類や、山札・列・手札の数が今の設定と合わないときは、その中断データだけを捨てて「再開」を出さない（エラーで止まらない）。
    *  ルールの設定の数値（敵の HP など）だけが変わったときは、捨てずに保存した値から続け、後の抽選から新しい設定の値を使う。
*   **要件7: デバッグ**
    *  デバッグ（`?debug`）では、中断データを保存せず、消さず、「再開」も出さない。「はじめる」・負けの結果を含む。ふつうに遊んだ中断データは、デバッグで開いて遊んでも、そのまま残る。
    *  デバッグのゲームも、要件2 の新しい乱数を使う（操作・見え方は今と同じ）。DEBUG タブに項目は足さない。
*   **要件8: 確かめ**
    *  一時スクリプトで次を確かめ、結果を RES に書く。
        *  ランダムな操作で多数の局を進め、どのターンの始まりで保存し、JSON にして戻しても、戻したゲームと続けたゲームが、同じ操作で最後まで同じ状態・同じ結果になる（ゴブリン・巨人・ドラゴンのどのターンでも。ブレスで札が燃えた後・捨て札の補充の後を含む）。
        *  保存したデータが `Storage.set` に渡せる値だけでできている（`undefined`・`NaN` などがない）。保存した後にゲームを進めても、保存したデータの中身が変わらない（参照の共有がない）。
        *  版番号違い・欠け・種類違い・数違いのデータで、例外にならず「なし」になる。
        *  前の版の設定だけの保存データを読んで、設定がそのまま残る。デバッグの印のときに書き込みが0回である。

## 【テストプレイで確かめること（実装セッションが発注者に依頼するときに示す）】
特に断りがなければ、`?debug` を付けずに開く。「閉じて開き直す」は、ページの読み込み直しでよい。
1. 中断データがないとき、タイトルは今までと同じで「再開」がない。「はじめる」を押してすぐ閉じて開き直すと、「再開」と「STAGE 1・TURN 1」が出る。
2. 何ターンか遊び、途中（札を置いた後など）で閉じて開き直し、「再開」を押すと、そのターンの始まりから続く。盤面・手札・金貨・城と敵の HP・予告・Lv が、そのターンの始まりと同じ。
3. 再開の後、閉じる前と同じ手順で遊ぶと、同じ札がめくれ、同じ結果になる。
4. TURN 1 からの再開では「STAGE N」と名前が出る。TURN 2 からの再開では、敵が初めから立っていて「TURN N」と予告から始まり、曲が流れる。
5. 再開の直後に閉じても、もう一度「再開」できる。
6. 攻防の演出の途中・敵を倒して「タップで次へ」が出ている所で閉じると、どちらもそのターンの始まりから再開できる。「タップで次へ」をタップした後なら、次のステージの TURN 1 から再開できる。
7. 中断データがあるときに「はじめる」を押すと、新しいゲームが始まり、開き直すと新しいゲームの所から再開になる。
8. 負ける。負けの結果が出た後にタイトルへ戻ると「再開」がない。負けるターンの演出の途中で閉じると、そのターンの始まりから再開できる。
9. 「再開」のボタンが見やすく、文字がはみ出さない。PC では Enter・Space で再開できる。
10. 音量・演出の速さを変えてから、再開・はじめる・負けを行っても、設定が残っている。
11. `?debug` では「再開」が出ない。`?debug` で遊んで負けた後に、`?debug` を外して開くと、元の中断データから「再開」できる。
12. タイトルから負けまで、途中の中断と再開を含めて、PC とスマホで通しで遊べる。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **タスクの分け方**: 乱数（ルール層）→ 中断データの形と戻し方（ルール層）→ 保存の口 → ターンの始まりでの保存・負けでの消去 → 再開した盤面の流れ → タイトルの「再開」のように、各タスクの終わりで起動とプレイが壊れない順・大きさに分ける。やむを得ず途中で壊れる区切りがあれば、計画に明記する。
*   **ルールと画面の分離**: ルール層は `oz` も画面のモジュールも import せず、`Storage`・`Math.random`・日付を読まない。画面はルール層の状態を直接組み立てず、ルール層の口を呼ぶ。
*   **アーキテクチャの維持**: `Game.js` に責務を足しすぎない（憲法 3章。合わない処理は新しいファイルに分ける）。敵の種類・行動の決まりの識別子で分岐する if を足さない。設定の保存（`settingsStore.js`）と中断データの扱いを1つの責務に混ぜない。`Storage.open` を呼ぶのは今までどおり1か所・1回だけ。
*   **デバッグの写し**: デバッグのゲームが使うルールの値の写し（`debugRules.js`）の仕組みは変えない。
*   **描画**: `draw` の中では状態を変えない。`Storage` を毎ティック・毎描画で読まない。`ctx` の状態は `save`・`restore` で囲む。`js/` に `requestAnimationFrame`・`addEventListener`・`getContext` を書かない。`localStorage` を直接触らない。
*   **エンジンの使い方**: エンジンは `import { … } from 'oz'` でだけ使い、`oz/` は編集しない。`oz/src/` は読まない。必要な機能が `oz/ENGINE_API.md` にない、または書かれたとおりに動かないときは、ゲーム側に回避策を書かず、作業を止めて RES に記録する（憲法 3章「エンジンの不足への対応」）。
*   **今回やらないこと**:
    *   「はじめる」の前の確認の窓・表示（発注者の決定）。
    *   遊んでいる途中でタイトルへ戻る操作、メニューの窓の変更、中断データを消すボタン。
    *   複数の中断データ、端末の間の引き継ぎ、ページを閉じる瞬間の保存。複数のタブで同時に開いたときの調整。
    *   新しい敵、3択・強化、スコア・今日のベスト・自己ベスト。
    *   ルール・数値・演出・BGM・効果音の変更、新しいスプライト、遊び方の文章の変更。
    *   `README.md`・`_doc/` の資料の書き換え。
