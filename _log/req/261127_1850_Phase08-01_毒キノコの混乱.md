## 【実装要件】
★2の敵「毒キノコ」（名前は仮。識別子は `mushroom` を初期案とし、計画で決めてよい）を足す。毒キノコは、2〜3 ターンに1回「混乱」を予告し、ターンの始めに選んだ列（印の列）の束を、そのターンの攻防の前に、行動（AP）を使わずにひとりでに放たせる。放たれた兵は自軍のまま戦う。
* **狙い**: 「予告された束を、出撃の前に組み直せ」。混乱のターンの敵の行動は「厚い守り」か「強い攻撃」のどちらかで、予告を読んで答えが変わる。
  * 厚い守りなら、ひとりでに放たれる剣は守りに吸われて無駄になる。印の列から剣の束を他の列へ移す、先に自分で放つ、などで組み直す。
  * 強い攻撃なら、印の列に盾を積み増して、AP を使わずに出せる束として使う。
* ★2は巨人と毒キノコの2種になる。

**決まりごと**
* **数値の置き場所**: 数値はすべて設定に置く（ルールは `js/rules/config.js`、動き・時間は `js/anim/battleAnimConfig.js`・`js/anim/animConfig.js`、大きさ・位置は配置の定数など）。下の値は初期値で、発注者が試すたびに見て変える。
* **座標**: すべて論理座標（画面 720×1280）で書く。
* **呼び名**: 画面の呼び名は TURN・ターン（内部の名前は phase）。「束」は列のカード全部（放つ・移す単位と同じ）。
* **変えないもの**:
  * ほかの8種の敵（ゴブリン・オーガ・狼・猪の親子・骸骨・スライム・巨人・ドラゴン）: 数値・動き・見た目・予告・乱数を呼ぶ順と回数・攻防の計算と出来事・時間割。
  * 自軍の数値、放つ計算（束の補正・4スートそろい・札の +◯・精鋭）、1ターンの流れ（毒キノコの混乱のターンを除く）。
  * ★の抽選（`stageStars`）・★1の並びの決まり・最初の★2が巨人であること・ステージの加算・激昂の決まり。
  * スコアの項目・強化・精鋭の仕組み。

### 今の作り（現場設計で確かめたこと）
* **★2の敵**: 巨人（`config.js` の `enemies.giant`。★2・最大 HP 60・防御の設定 `defense`（75%・2〜6）・行動の決まり `cycle`（4 ターンごとに攻撃 18〜22・攻撃の直後の回復））だけ。`stageStars.draws` の★2の行の `first` が `giant`。
* **同じ★の中の敵の選び方**: `stageOrder.js` の `enemyTypeIdOfStage`。動きの組（`enemyTypes.js` の `motionKeyOf` = `spec.motion ?? spec.behavior.type`）ごとに `motionOrder.js` で並べる。毒キノコの行動の決まりが新しい種類なら、★2の動きは2つになり、巨人と毒キノコが交互に近い形で出る。
  * 最初の1体（`first`）は「同じ動きを続けない」の数に入らないので、★2の2番目のステージがまた巨人になることがある。これは 08-02（くじ袋での出し分け。別の REQ）で置き換わるので、今回は直さない。
  * 設定に★2の敵を足すと、同じ日付でも★2のステージに出る敵が変わる。これは構わない。★1の並び・★の抽選の結果（どのステージが何★か）は変わらない。
* **予告**: 予告（`EnemyIntent`）は攻撃の側（`kind`＝`attack`・`windup`・`guard`。量 `amount`）と防御の側（`defense`）を持つ。防御の量は、行動が `guard` を持てばそれに加算を足した値、そうでなく敵が防御の設定を持ち隙でなければ設定から抽選、それ以外は 0（`enemyIntent.js`・`enemyDefense.js`）。スライムの子スライムの予告（`minions`）のように、任意の項目を足す前例がある（`enemySplit.js` の `intentWithMinions`）。
* **予告の札**: 攻撃の側と防御の側の札を並べる（`intentView.js`・`intentParts.js`）。スライムは攻撃の札の右に子スライムの札を並べる。ターンの始まりの文字は `battleText.js`（例: 「攻撃 4 +子スライム 8」）。
* **予告を決める時**: `Game.planIntent`（コンストラクタと `advancePhase`）。行動の決まり（`enemyBehaviors.js` の `planBehaviorAction`）は列の状態を知らない。
* **放つ**: `Game.release(c)` が列のカードをすべて取り、`computeRelease`（束の補正・4スートそろい・札の +◯）→ 戦闘の記録・結果の記録 → 精鋭の抽選（`drawElites`）→ ゲージ → 捨て札 → 行動 −1 → 山札の補充、の順で行う。`canRelease` は段取り中・行動が残っている・列が空でないとき。
* **攻防に入るまで**: 行動を使い切り、盤面の動き（玉など）が全部止まると `boardFlow.js` が「準備終了」を出す（`canResolveBattle` は段取り中で行動 0）。タップで「BATTLE!」、消えると `BoardScene.startBattle` が `resolveBattle` を呼んで攻防の演出へ進む。
* **列の表示**: 列は4本（`columnCount`）。各列の下に放つ矢印（`layout.js` の `releaseButtons`。高さ 80）がある。
* **中断データ**: 版 9（`suspendData.js` の `SUSPEND_VERSION`）。ターンの始まりに保存し、予告の形は `INTENT_KINDS` などで確かめる。
* **DEBUG タブ**: 敵の切り替えの一覧は設定の `enemies` から作られる（毒キノコは行を足せば出る）。敵の次の行動（`debugIntents.js`）・ルールの値のスライダー（`debugRuleItems.js`。敵の最大 HP は2刻み）がある。

### 要件1: 毒キノコの数値と行動（発注者の決定。ステージの加算の前。★2）
* **名前・★**: 「毒キノコ」・★2。
* **HP**: 56（DEBUG のスライダーが2刻みなので偶数）。
* **ふつうのターン**: 攻撃 3〜5 を行い、防御は 75% で張る（量 2〜4）。張るかと量は、巨人などと同じく敵の種類の防御の設定から抽選してよい。
* **混乱のターン**: 混乱を予告し、あわせて次のどちらかを行う（半々。確率は設定）。
  * **厚い守り**: 攻撃しない。防御 8〜10。
  * **強い攻撃**: 攻撃 8〜10。防御しない（防御 0）。
* **混乱の間隔**: 混乱のターンの次の混乱は、2 ターン後か 3 ターン後（ランダム。例: 3 ターン目に混乱したら、次は 5 か 6 ターン目）。最初の混乱は、その戦闘の 2 ターン目か 3 ターン目（ランダム）。次の混乱までの数え下ろしは画面に出さない。間隔と最初の混乱のターンは設定に置く。
* **加算と激昂**: ステージの加算は、攻撃（ふつう・強い攻撃）と防御（ふつう・厚い守り）に、ほかの敵と同じく足す。激昂の倍率は、攻撃の量（ふつう・強い攻撃）にほかの敵と同じくかける。毒キノコだけの特別な扱いはしない（混乱の間隔・印の列の選び方は激昂で変わらない）。
* **並び**: ★2として★2のステージに出る。並びの仕組みは今のまま（上の「今の作り」）。設定の `motion` で巨人と同じ組に入れることはしない（入れると巨人と同じ動きとして数えられ、交互にならない）。

### 要件2: 混乱の印の列（ルール層で決める）
* **選ぶ時**: 混乱を予告するターンの始め（予告を決めるとき）に、印の列を1つ選ぶ。選んだ列は、そのターンの間は変わらない（プレイヤーが束を動かしても、列が空になっても、印は同じ列に残る）。
* **選び方**:
  1. 束の枚数がいちばん多い列。
  2. 枚数が同じなら、束の数値の合計が高い列（合計は、放つ計算の区切りの合計と同じく、札の数字に強化の「+◯」を足したもの）。
  3. それも同じなら、左の列。
  * 列がすべて空なら、いちばん左の列に印が付く（プレイヤーはそこへ札を置ける）。
* **持ち方**: 印の列は予告の一部として持つ（例: 予告の任意の項目。持ち方は計画で決める）。ふつうのターン・ほかの敵の予告は持たない。
* **乱数**: 印の列を選ぶときに乱数を呼ばない。混乱するか・厚い守りか強い攻撃か・次の混乱までの間隔は、行動の決まりの抽選で決めてよい（乱数を呼ぶ順と回数は計画で決めて RES に書く）。
* 列の状態を知らない行動の決まりと、列を知るゲームのどちらで選ぶかは計画で決める（行動の決まりに列を渡すか、ゲームが予告に印を足すか）。

### 要件3: 印の列の束がひとりでに放たれる（ルール層で決める）
* **放たれる時（発注者の決定）**: 行動を使い切り、盤面の動きが全部止まった後、「準備終了」が出る前。
  * 印の列に束があれば、その束が放たれて光の玉になり、陣地へ飛んで兵（金貨は金貨のゲージ）になる。全部着いてから「準備終了」が出る。以後の「準備終了 → タップ → BATTLE! → 攻防」は今のまま。
  * 印の列に束がなければ、混乱は空振りになり、何も放たれず、そのまま「準備終了」が出る。
* **放ち方**: 自分で放つのと同じ計算にする（束の補正・4スートそろい・札の +◯・精鋭の抽選・戦闘の記録のコンボ・結果の記録の一番長いコンボ・山札の補充）。違うのは、行動（AP）を使わないことだけ。
* **1ターンに1回だけ**: ルール層で、混乱の予告があるターンは、ひとりでに放つ操作が済むまで攻防に入れないようにする（画面の側が呼び忘れても、混乱が抜けたまま攻防に進まない）。空振りでも「済んだ」ことになる。
* **プレイヤーの操作**: 印の列の束は、混乱の前に、自分で放つ（AP 1）ことも、他の列へ移す（AP 1。今の束の移し替え）こともできる。印の列へ札を置いて積み増すこともできる。印があっても、ほかの操作は今のまま。
* 印の列の兵がひとりでに放たれた結果は、ルール層の操作の結果（今の放つの結果と同じ形でよい）として返し、演出はそれを読むだけにする。

### 要件7: 確かめ（一時スクリプトで行い、結果を RES に書く）
* **予告**: 毒キノコを多数のターン進め、混乱の間隔が 2〜3 ターン・最初の混乱が 2〜3 ターン目になる。混乱のターンは厚い守り（攻撃 0・防御 8〜10＋加算）か強い攻撃（攻撃 8〜10＋加算×激昂・防御 0）、ふつうのターンは攻撃 3〜5（＋加算×激昂）と防御（75%・2〜4＋加算）。
* **印の列**: 枚数・合計・左の順に選ばれる（同数・同合計・全部空の場合を含む）。ターンの途中で束を動かしても、印の列は変わらない。
* **ひとりでに放つ**: 同じ列を自分で放ったときと、ゲージ・精鋭・戦闘の記録・結果の記録・捨て札・山札が同じになり、行動の数だけが違う。空振りでは何も変わらない。済むまで攻防に入れず、済んだ後は1回で攻防に入れる。
* **変わっていないこと**: 同じ乱数の状態から比べて、ほかの8種の予告・乱数の呼び出し・攻防の出来事が変更の前と同じ。★1の並びと、各ステージの★（10 年分の種 × ステージ 1〜500 ほど）が変更の前と同じ。最初の★2は巨人。
* **中断データ**: 混乱のターン・ふつうのターンで保存して戻し、同じ操作で同じ結果（印の列・ひとりでに放たれる兵）になる。

## 【テストプレイで確かめること（実装セッションが発注者に依頼するときに示す）】
1. **出たとき**: `?debug` で毒キノコに切り替えると、毒キノコ（仮の絵）が出る。ふつうのターンは攻撃 3〜5 と防御を予告する。
2. **混乱の予告**: 2 か 3 ターン目に、予告の札に「混乱」の札が並び、束のいちばん多い列が紫に染まり、渦巻きの印が出る。ターンの始まりの文字にも混乱が出る。
3. **厚い守りか強い攻撃**: 混乱のターンは、攻撃せずに厚い守り（防御 8〜10）か、防御なしの強い攻撃（攻撃 8〜10）のどちらか。
4. **ひとりでに放たれる**: 行動を使い切ると、印の列の束が「混乱！」の文字とともに光の玉になって陣地へ飛び、全部着いてから「準備終了」が出る。補正・4スートそろい・精鋭は自分で放つときと同じ。
5. **組み直せる**: 印の列の束を他の列へ移したり、先に自分で放ったりできる。印は同じ列に残る。印の列を空にして行動を使い切ると、何も放たれずに「準備終了」が出る。印の列に札を置いて積み増すと、その分も放たれる。
6. **狙いどおりか**: 厚い守りの予告なら剣を逃がし、強い攻撃の予告なら盾を積む、と予告を読んで段取りが変わるか。強敵として楽しいか・強すぎないか。
7. **倒したとき**: 「〜を倒した！」で★2の強敵の点が付く。3択の次の敵・結果の画面の倒した敵の絵に、毒キノコの絵が出る。
8. **激昂**: 16 ターン目からの激昂で、攻撃の量（ふつう・強い攻撃）に倍率がかかる。
9. **DEBUG**: 次の行動の「ふつう」「混乱＋厚い守り」「混乱＋強い攻撃」と、ルールの値のスライダーと「元に戻す」が効く。
10. **中断と再開**: 混乱の印が出ているターンで閉じて「再開」しても、同じ列に印があり、行動を使い切ると同じように放たれる。
11. **ほかの敵と通しのプレイ**:
    * ほかの敵の見た目と動きは前と変わらない。最初の★2は巨人のまま。強敵のステージに毒キノコも出る（巨人が2回続けて出ることはある）。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **タスクの分け方**: 各タスクの終わりで、起動とプレイが壊れない順・大きさに分ける。
    *   順の例: ルール層（印の列の選び方・ひとりでに放つ操作・攻防に入れる条件。まだ毒キノコは設定にない）→ 盤面の流れと放つ演出（「準備終了」の前にひとりでに放つ。ほかの敵の流れが変わらないことを確かめる）→ 印の列と混乱の札の見た目 → 中断データ → 毒キノコの設定・絵・演出の表 → DEBUG タブ。
    *   毒キノコを設定に足すのは、見せる表と中断データがそろってからにする（途中で Error にならないように。設定に足すと★2のステージに出始める）。
    *   やむを得ず途中で壊れる区切りがあれば、計画に明記する。
*   **ルールと画面の分離**:
    *   印の列の選び方・ひとりでに放つ計算・攻防に入れる条件は、ルール層で決める。演出は結果と状態を読むだけにする。
    *   ひとりでに放つ計算は、`Game.release` と同じ計算の道を通す（式を写して別に持たない）。
    *   ルール層は `oz` も画面のモジュールも import せず、`Math.random`・日付を読まない。
*   **アーキテクチャの維持**:
    *   敵の種類の識別子で分岐する if を足さない（設定・表で分ける）。混乱するかは行動の決まり・予告の項目で決まり、印の種類の見た目は表で引く。
    *   1つのモジュールに責務を足しすぎない（憲法 3章。合わない処理は新しいファイルに分ける）。`Game.js`・`battle.js`・`layout.js`・`BoardScene.js`・`boardFlow.js`・`enemyBehaviors.js` は大きいので、足す処理は分けて置けないか先に検討する。
    *   ほかの敵の予告と攻防の計算は、今の結果と同じになるようにする。
*   **動きの時間**:
    *   動きの時間は `dt`・演出の時計だけで決め、状態は時計から求められる形にする（今の演出と同じ）。
    *   ひとりでに放つ玉の動きは、自分で放つ玉と同じ動き・同じ設定を使う。
*   **描画**:
    *   `draw` の中では状態を変えない。`ctx` の状態は `save`・`restore` で囲む。
    *   `js/` に `requestAnimationFrame`・`addEventListener`・`getContext` を書かない。
*   **エンジンの使い方**:
    *   エンジンは `import { … } from 'oz'` でだけ使い、`oz/` は編集しない。`oz/src/` は読まない。
    *   必要な機能が `oz/ENGINE_API.md` にない、または書かれたとおりに動かないときは、ゲーム側に回避策を書かず、作業を止めて RES に記録する（憲法 3章「エンジンの不足への対応」）。
*   **ついでに直すもの（持ち越し事項）**:
