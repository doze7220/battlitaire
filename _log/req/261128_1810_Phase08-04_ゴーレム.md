## 【実装要件】
★2の敵「ゴーレム」（識別子は `golem` を初期案とし、計画で決めてよい）を足す。ゴーレムは数ターンに1回防御を取り、**その防御はターンをまたいで残って積み重なる**。溜まった防御を攻撃に足す「体当たり」で防御を使い切り、その後は防御 0 の隙になる。
* **狙い**: 「溜めさせるな、削り続けろ」。剣で溜まった防御を削り続けるほど、体当たりが弱くなる。削らずに放っておくと、守りが厚くなり、体当たりも重くなる。
* ★2は巨人・毒キノコ・ネクロマンサー・ゴーレムの4種になり、くじ袋（08-02）に入る。

**決まりごと**
* **数値の置き場所**: 数値はすべて設定に置く（ルールは `js/rules/config.js`、動き・時間は `js/anim/battleAnimConfig.js`、大きさ・位置は配置の定数など）。下の値は初期値で、発注者が試すたびに見て変える。
* **座標**: すべて論理座標（画面 720×1280）で書く。
* **呼び名**: 画面の呼び名は TURN・ターン（内部の名前は phase）。行動の画面の呼び名は「防御を取る」「身をかがめる」「体当たり」（コードの呼び名は計画で決める）。
* **変えないもの**:
  * ほかの10種の敵（ゴブリン・オーガ・狼・猪の親子・骸骨・スライム・巨人・毒キノコ・ネクロマンサー・ドラゴン）: 数値・動き・見た目・予告・乱数を呼ぶ順と回数・攻防の計算と出来事・時間割。ほかの敵の防御は、今のままそのターンの終わりに消える。
  * 自軍の数値、放つ計算、精鋭の抽選、1ターンの流れ。
  * ★の抽選・★1の並び・くじ袋の決まり（敵を足すと★2の袋の並びが変わるのは構わない）・ステージの加算・激昂の決まり。
  * スコアの項目・強化の仕組み。

### 今の作り（現場設計で確かめたこと）
* **攻防の計算**: `battle.js` の `computeBattle` が合計の引き算で求める。順は、敵の攻撃 → 盾の兵との相殺（`block`）→ 城の被害（`castleDamage`）→ 敵の回復 → 敵の防御での相殺（`enemyBlock`。自軍の攻撃と敵の防御の小さい方）→ 敵への攻撃（`enemyDamage`）→ 倒した → 修理。敵の攻撃が先。**敵の防御の余りは消える**（関数の説明にも「敵の防御の余りも消える」とある）。
* **敵の防御**: 予告の `defense` 1つ（07-01）。予告を作るとき（`enemyIntent.js` の `createIntent`）に、行動が防御の量 `guard` を持てばそれに防御の加算を足し、持たなければ隙でない行動だけ敵の設定の `defense`（張る確率と量の幅）で抽選する。予告・シールドの数・攻防は同じ `intent.defense` を読む。ターンをまたいで残る防御は今はない。
* **シールドの印**: 段取りの間、絵の敵の体の前に `intent.defense` の数だけシールドの印を格子に並べる（`enemyView.js`・`layout.js` の `shieldRects`）。焼き付けは数 1〜30 まで（`troopView.js` の `SHIELD_BAKE_MAX_COUNT`）で、超える数は直接描く。攻防の演出では、自軍の剣がシールドに当たると印が剥がれる（`DEFENSE_SHOWS` の `figure` → `shieldBlock`）。
* **予告の札**: 攻撃の側と防御の側が1枚の札にまとまる（`intentView.js`・`intentParts.js`）。子・亡者の札と列の印の札は、その札の右に足される。量のない行動（振りかぶり `windup`）は絵だけ、または `BADGE_LABELS` の文字（「怒り」）。`EMPHASIZED_VARIANTS` の中の種類（ブレス・大攻撃・大突進）は赤い札で目立たせる。ターンの始まりの文字は `battleText.js`（例「攻撃 3 ／ 防御 2」）。
* **似た動き**: 狼の「溜める → 大攻撃」（行動の決まり `buildup`。溜めは `windup` の中の種類 `charge`。演出は `ENEMY_SHOWS` の `charge`（ための動き）と `heavy`（大きな一撃））。猪の親子の突進は駆け寄りの見せ方 `dashStraight`。
* **激昂**: 予告の `amount` は倍率の後の量、`baseAmount` は倍率の前の量（DEBUG でターンの番号を変えると数え直す。`enemyIntent.js` の `refreshIntent`）。
* **くじ袋**: ★2・★3の敵は `config.js` の `enemies` に1行足せば袋に入る（`stageStars.draws` の `order: 'bag'`）。
* **中断データ**: 版 10（`suspendData.js` の `SUSPEND_VERSION`）。行動の決まりの状態（`behaviorState`）は決まりごとの形の確かめ（`enemyBehaviors.js` の `isState`）で確かめて保存している。
* **攻撃の始まりの音**: 攻防の最初の段に付く。ネクロマンサーは、敵自身の攻撃の前に亡者の段があるため音なしにした（08-03）。

### 要件1: ゴーレムの数値と行動（発注者の決定。ステージの加算の前。★2）
* **名前・★**: 「ゴーレム」・★2。
* **HP**: 48（DEBUG のスライダーが2刻みなので偶数）。
* **行動の型**（どのターンも、次の4つのどれか1つ）:
  * **防御を取る**: 攻撃しない。溜めた防御に 4〜6（＋ステージの防御の加算）を足す。足した後の溜めの全部が、そのターンの防御になる。
  * **攻撃**: 攻撃 3〜5（＋ステージの攻撃の加算）。新しい防御は足さない（溜めた防御は、そのままそのターンの防御になる）。
  * **身をかがめる（兆し）**: 攻撃しない・新しい防御も足さない（溜めた防御は、そのままそのターンの防御になる）。次のターンは必ず体当たり。
  * **体当たり**: 攻撃 3〜5（＋ステージの攻撃の加算）に、その時点の溜めた防御の全部を足した量で攻撃する。溜めた防御は 0 になり、そのターンの防御は 0（隙）。
* **並び方**:
  * 「防御を取る」は 2〜3 ターンに1回（前の「防御を取る」から次までのターン数を毎回抽選。間のターンは攻撃）。その戦闘の最初の「防御を取る」は 1〜2 ターン目（抽選）。
  * 「防御を取る」を 2〜3 回（抽選）行った後、次の「防御を取る」の番の代わりに「身をかがめる」になり、その次のターンが体当たり。
  * 体当たりの次のターンから、戦闘の始まりと同じ数え方で始め直す（最初の「防御を取る」は 1〜2 ターン後）。
  * 例: 1 防御を取る（溜め 5）→ 2 攻撃 4 → 3 防御を取る（溜め 9）→ 4 攻撃 3 → 5 身をかがめる → 6 体当たり（攻撃 4 ＋溜め）→ 7 …。
  * 間隔・回数の幅は設定に置く。数え方（何を状態に持つか）は計画で決める。
* **加算と激昂（発注者の決定）**:
  * ステージの防御の加算は、「防御を取る」1回ごとに足す（溜めに足す量に足す）。ステージの攻撃の加算は、攻撃と体当たりの攻撃 3〜5 の分に足す。
  * 激昂の倍率は、攻撃と体当たりの **攻撃 3〜5（＋加算）の分にだけ** かける。体当たりに足す溜めた防御の分には、激昂の倍率をかけない。DEBUG でターンの番号を変えたときに数え直せる形で持つ（今の `baseAmount` と同じ考え方）。

### 要件2: 溜めた防御（ターンをまたいで残る。結果はルール層で決める）
* 溜めた防御は、ゴーレムの状態として持つ（ほかの敵は持たない、または 0）。置き場所（敵の状態・行動の決まりの状態など）は計画で決める。
* **減り方**: そのターンの攻防で自軍の剣が敵の防御に当たった分（`enemyBlock` の量）だけ減り、残りは次のターンへ持ち越す。ほかの敵の防御は今のまま、そのターンの終わりに消える（持ち越すかどうかは設定・決まりで分け、敵の識別子で分岐しない）。
* **体当たりで 0**: 体当たりのターンの予告で、溜めた防御の全部が攻撃に移り、溜めは 0・そのターンの防御も 0 になる。
* **ゴーレムを倒したとき**: 戦闘が終わるので、溜めは次の敵に残らない。城が落ちた攻防の扱いは計画で決める（今の作りに合わせる）。
* **体当たりの威力の決まる時（発注者の決定）**: 「身をかがめる」のターンの攻防で剣が溜めを削った分だけ、体当たりの威力が下がる。威力は、**体当たりのターンの予告を作る時点**の溜め（＝身をかがめるのターンの攻防の後に残った溜め）に、攻撃 3〜5（＋加算×激昂）を足した量で決まる。体当たりのターンは敵の攻撃が先なので、そのターンに放つ剣では威力を削れない。
* 溜めの量に上限は付けない。

### 要件3: 予告と画面に出る溜め
* **予告の札**（攻撃の側と防御の側が1枚の札にまとまる今の作りを使う）:
  * 防御を取る: 防御の側に、足した後の溜めの合計（そのターンの防御）を出す。今回足した量（例「+5」）も分かるようにする（見せ方は計画で決める）。
  * 攻撃: 攻撃の側に攻撃の量、防御の側に溜めの合計（溜めが 0 なら防御の側を出さない。今と同じ）。
  * 身をかがめる: 振りかぶりの絵（量なし）と、防御の側に溜めの合計。体当たりが来ることが分かる文字か絵を出す（「身をかがめる」。見せ方は計画で決める）。
  * 体当たり: 攻撃の側に威力（攻撃＋溜め）を1つの数字で出し、赤い札で目立たせる（ブレス・大攻撃と同じ）。防御の側は出さない。
* **ターンの始まりの文字**: 同じ中身が分かるようにする（例: 「防御を取る +5 ／ 防御 9」「攻撃 4 ／ 防御 9」「身をかがめる ／ 防御 9」「体当たり 13」）。
* **体の前の溜め（発注者の決定）**: ゴーレムの体の前に、溜めの量のシールドの印を並べる。印は 10 個で止める（それより多くても 10 個）。その横に、溜めの量の数字をいつも出す（溜めが 0 なら印も数字も出さない）。数字の位置・大きさ・色は計画で決める（HP のゲージ・予告の札・人数の枠と重ならない）。ほかの敵のシールドの印は今のまま（数字なし・上限なし）。印の上限と数字を出すかは、敵の種類ごとの表か設定で分ける。
* 攻防の演出の中で、剣が当たって溜めが減るのが見えるようにする（印が剥がれ、数字が減る。演出の数字はルール層の出来事の量から求め、数え直さない）。

### 要件7: 確かめ（一時スクリプトで行い、結果を RES に書く）

  * 身をかがめるのターンに削った分だけ、体当たりの威力が下がる。体当たりのターンは防御 0・溜め 0。
  * 倒すターン・城が落ちるターン。
* **予告**: 攻撃と体当たりの攻撃 3〜5（＋加算×激昂）、防御を取る 4〜6（＋加算）、体当たりの溜めの分に激昂がかからない。ステージ 1・30・100 で、溜めと体当たりの威力が最大どれくらいになるかを RES に書く（試遊の材料）。
* **演出との突き合わせ**: 上の場合で、演出の時間割が作れ、シールドの印・溜めの数字がルール層の量と合う。体の前の印は 10 個で止まる。
* **変わっていないこと**: 同じ乱数の状態から比べて、ほかの10種の予告・乱数の呼び出し・攻防の出来事・時間割が変更の前と同じ（敵の防御がそのターンの終わりに消えることを含む）。★1の並び・各ステージの★が変わらない。最初の★2は巨人。★2の袋に4種が1回ずつ入る。
* **中断データ**: 溜めがあるターン・ないターン・身をかがめるのターンで保存して戻し、同じ操作で同じ結果になる。版 10 の古いデータの扱いが要件5のとおり。

## 【テストプレイで確かめること（実装セッションが発注者に依頼するときに示す）】
1. **出たとき**: `?debug` でゴーレムに切り替えると、ゴーレム（仮の絵。巨人と同じ形で色が石の灰色）が出る。
2. **防御を取る・溜まる**: 2〜3 ターンに1回「防御を取る」を予告し、体の前のシールドの印と数字が増えていく。剣を出さなければ、次のターンも溜めが残る。
3. **削る**: 剣を放つと、当たった分だけ溜めが減る（印が剥がれ、数字が減る）。溜めより多い剣は、残りが本体に当たる。
4. **身をかがめる → 体当たり**: 防御を2〜3回取った後に「身をかがめる」を予告し、次のターンに体当たりが来る。体当たりの予告の数字は赤い札で、攻撃＋溜めの量。身をかがめるのターンに削った分だけ、体当たりの数字が小さくなる。
5. **隙**: 体当たりのターンは防御 0 で、溜めも 0 に戻る。その後また防御を取り始める。
6. **印の上限**: 溜めが 11 以上になっても印は 10 個で、数字が溜めの量を正しく出す。
7. **狙いどおりか**: 「溜めさせるな、削り続けろ」と感じるか。体当たりが痛すぎないか・弱すぎないか。強敵として楽しいか。
8. **倒したとき**: 「〜を倒した！」で★2の強敵の点が付く。3択の次の敵・結果の画面の倒した敵の絵に、ゴーレムの絵が出る。
9. **激昂**: 16 ターン目からの激昂で、攻撃と体当たりの攻撃の分に倍率がかかる（溜めの分はそのまま）。
10. **DEBUG**: ルールの値のスライダーと「元に戻す」、次の行動の指定（防御を取る・攻撃・身をかがめる・体当たり）、溜めの操作が効く。先の並びの一覧で、★2の袋に巨人・毒キノコ・ネクロマンサー・ゴーレムが1回ずつ入る。
11. **中断と再開**: 溜めがある途中・身をかがめるのターンで閉じて「再開」しても、溜めと次の行動が同じように残り、続きから遊べる。
12. **ほかの敵と通しのプレイ**:
    * ほかの敵の見た目と動き・シールドの出方は前と変わらない（防御はそのターンで消える）。最初の★2は巨人のまま。
    * 強敵のステージで、4種がくじ袋の決まりで出る。
    * タイトルから負けまで、PC とスマホで通しで遊べる。

## 【計画書に必ず含めるべき固定タスク】
AIが作成する計画書（RES）のタスクリストには、全実装タスクの後に、以下のタスクを必ず含めること。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **タスクの分け方**: 各タスクの終わりで、起動とプレイが壊れない順・大きさに分ける。
    *   順の例: ルール層（溜めた防御の持ち越しと減り方・行動の決まり・予告・攻防の結果。まだゴーレムは設定にない）→ 画面の溜めの印と数字・予告の札と文字 → スプライトのコピーと見た目・攻撃の見せ方 → 中断データ → ゴーレムの設定（★2の袋に入り始める）→ DEBUG タブ。
    *   ゴーレムを設定に足すのは、見せる表と中断データがそろってからにする（途中で Error にならないように。設定に足すと★2のステージに出始める）。
    *   やむを得ず途中で壊れる区切りがあれば、計画に明記する。
*   **ルールと画面の分離**:
    *   溜めた防御の量・体当たりの威力・予告の量・攻防の結果は、ルール層で決める。演出・画面は結果と状態を読むだけにし、数え直さない。
    *   ルール層は `oz` も画面のモジュールも import せず、`Math.random`・日付を読まない。
*   **アーキテクチャの維持**:
    *   敵の種類の識別子で分岐する if を足さない（設定・表で分ける）。防御を持ち越すか・印の上限と数字を出すかは、設定・決まり・敵の種類ごとの表で決まる。
    *   1つのモジュールに責務を足しすぎない（憲法 3章。合わない処理は新しいファイルに分ける）。`battle.js`・`Game.js`・`enemyBehaviors.js`・`battleTimeline.js` は大きいので、足す処理は分けて置けないか先に検討する。
    *   ほかの敵の攻防の計算は、今の `computeBattle` の結果と同じになるようにする。
*   **動きの時間**:
    *   動きの時間は `dt`・演出の時計だけで決め、状態は時計から求められる形にする（今の演出と同じ）。
    *   演出の速さ（普通・速い）とヒットストップが、新しい動きにも同じように効く。
*   **描画**:
    *   `draw` の中では状態を変えない。`ctx` の状態は `save`・`restore` で囲む。
    *   `js/` に `requestAnimationFrame`・`addEventListener`・`getContext` を書かない。
    *   描く体の数は、敵と兵を合わせて 500 体を目安とする。
*   **エンジンの使い方**:
    *   エンジンは `import { … } from 'oz'` でだけ使い、`oz/` は編集しない。`oz/src/` は読まない。
    *   必要な機能が `oz/ENGINE_API.md` にない、または書かれたとおりに動かないときは、ゲーム側に回避策を書かず、作業を止めて RES に記録する（憲法 3章「エンジンの不足への対応」）。
*   **今回やらないこと**:
    *   ほかの★2の敵（侵略軍）と★3の敵の追加。
    *   ほかの10種の敵の数値と見せ方の変更（シールドの印の出方・防御がそのターンで消える扱いを含む）。
    *   くじ袋・★の抽選・★1の並びの決まりの変更。
    *   新しい音・曲・予告の絵のスプライト。ゴーレムの本番の絵（発注者が後で描く）。
    *   予告の札の並び方（攻撃と防御が1枚にまとまる作り）の作り直し。
    *   遊び方の4ページ目に敵を足すこと。メニューの「敵情報」タブ。
    *   スコアの項目・強化・精鋭の仕組みの変更。
    *   `README.md`・`_doc/` の資料の書き換え。
