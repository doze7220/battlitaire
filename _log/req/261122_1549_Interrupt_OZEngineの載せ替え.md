* エンジンの資料: `./oz/ENGINE_API.md`

## 【作業手順（厳守事項）】
本プロンプトは、載せ替えた OZ Engine に合わせてゲーム側を確かめ・直す Interrupt（作業レポート `Interrupt_OZEngineの載せ替え`）である。必ず以下の順序で作業を行うこと。

1. ルール（`PROJECT_CONSTITUTION.md`）を熟読・把握すること。特に3章のエンジンの決まり（`oz/` の編集禁止・`oz/src/` を読むことの禁止・エンジンの不足への対応・入口の一本化・基礎処理の直書き禁止）。
2. 本REQの【関連する責務】を把握すること。作業に必要な責務情報はすべてここに記載されている。開発資料（`PROJECT_ARCHITECTURE.md`）は、記載外の責務を確認する必要が生じた場合と、要件3の確認でだけ参照すること。
3. 実装対象のコードを読み、【関連する責務】に**記述されている内容と実コードが矛盾する**場合は、修正に着手せず、相違点を報告して指示を待つこと。記述にない事項の存在は相違とみなさない。
4. 相違がなければ、【実装要件】に従って確認と修正を行うこと。直す所が無ければ、コードは変えない（それも正しい結果である）。
5. 作業が完了したら、Interrupt作業レポートテンプレート（`./_log/TEMPLATE_RES_Interrupt.md`）を元に、作業レポート（`./_log/res/YYMMDD_HHMM_RES_Interrupt_OZEngineの載せ替え.md`）を新規作成して出力すること。RES冒頭の参照元REQには本ファイル `./_log/req/261122_1549_Interrupt_OZEngineの載せ替え.md` を記載すること。
   * テンプレートの項目に従い、「原因と修正方針」「対象ファイル」「詳細作業内容」を正確に記述すること。要件1の照らし合わせの結果（変わった章ごとに、ゲーム側への影響の有無と理由）を必ず書くこと。
6. 開発資料（`PROJECT_ARCHITECTURE.md`）の内容に影響がある場合は、資料本体は修正せず、その旨と書き換えの文案を作業レポートの『開発資料の更新予定』欄に明記すること（要件3）。
7. すべての作業が完了したら、チャットにて「実装が完了しました。ビルド・動作確認をお願いします」と報告すること。

## 【実装要件】
発注者が `oz/` を OZ Engine の新しい版で丸ごと置き換えた（版の表示 `oz/VERSION` は 0.1.0 のまま）。新しい版には、キャンバスキャッシュ（`ENGINE_API.md` 25章）、FPS の表示の実行中の出し入れと位置・FPS の値の読み取り（14章）、窓と UI 部品（26章）が入り、エンジンの内部（`Engine.js` など）も変わっている。`oz/` の置き換えのコミットは発注者が行う（本作業の前に済んでいる）。

**ゲームのルール・設定の値・見た目・音・画面の流れは変えない。新しい機能（`CanvasCache`・`Ui`・`Engine.fpsVisible`・`Engine.fps`・`Engine.fpsPosition`）はまだ使わない**（使うのは次の Phase で、別の REQ で指示する）。

*   **要件1: エンジンの資料の変わった点とゲーム側の照らし合わせ**
    *  `oz/ENGINE_API.md` を読み直すこと。変わった点は `git diff HEAD~1 -- oz/ENGINE_API.md`（発注者の置き換えのコミットが直前にある場合。無ければ `git log -- oz/ENGINE_API.md` で置き換えのコミットを探し、その1つ前と比べる）で見られる。
    *  現場設計の確認では、変わった点は次のとおり（漏れがないか自分でも差分で確かめること）。
        *  1章: 使えるものが5つから7つになった（`CanvasCache`・`Ui` が増えた）。`Engine` の説明に FPS の表示の出し入れ・位置・値の読み取りが増えた。
        *  3章: 起動設定 `debug` の意味が「真なら FPS を表示する」から「真なら FPS を表示した状態で始める（`Engine.fpsVisible` の起動時の値）。`Boolean(...)` で解釈する」に変わった。
        *  9章: 「`debug` の FPS 表示は続く」が「FPS の表示（14章）は続く」に変わった。
        *  14章: 「`debug`」の章が「FPS の表示」の章に書き換わった（実行中に切り替えられる・四隅に置ける・値を読める。`draw` の中では読むだけ）。
        *  15章: `CanvasCache` のエラーでループが止まる旨が増えた。
        *  18章: 窓の中の部品のボタン（26章）への案内が1行増えた（18章のボタンの仕様は変わらない）。
        *  23章: スプライトの書き出しの `bounds` を、キャンバスキャッシュの範囲として読んでよくなった（それ以外のキーは今までどおり読まない）。キャンバスキャッシュへの案内が1段落増えた。
        *  25章・26章: 新しい章（キャンバスキャッシュ、UI 部品）。
    *  `index.html`・`js/` がエンジンを使っている所（`import … from 'oz'`、`Engine.start` の設定、`Engine.pushScene`・`changeScene`・`popScene`・`addButton`・`addVirtualPad`・`virtualPadEnabled`・`virtualPadState`、`Assets`・`Sound`、`Scene` のメソッドの名前と引数、`index.html` の import map と canvas）を洗い出し、上の変わった点と照らして、書き方を変える必要がある所があるか確かめる。現場設計の見立てでは、ゲームが使っている API は変わっておらず、直す所は無いか、ごく少ない（例: `js/main.js` の起動設定の型の注釈・説明の文が古い言い回しになっていないか）。
    *  直す必要がある所が見つかったら、その所だけを直す。直してよいのは `index.html` と `js/` の中で、変わった章を理由に挙げられる所だけ。理由を挙げられない「ついでの直し」はしない。
    *  資料のとおりに動かない、または資料に無い機能が要ると分かったときは、ゲーム側に回避策を書かず、作業を止めて報告する（憲法3章「エンジンの不足への対応」）。
*   **要件2: 今と同じく動くことの確認**
    *  変更した .js ファイルがあれば、憲法1章の検証コマンド（`node --input-type=module --check < <ファイル>`）で構文を確かめる。
    *  エンジンの内部が変わっているため、コードを変えなかった場合も、発注者のテストプレイで次が今と同じく動くことを確かめる（テストプレイの依頼は実装統括が行う。RES の「懸念事項・要確認ポイント」に、この確認の一覧を書いておくこと）。
        *  起動: 画面が出て、開発者ツールのコンソールにエラーが出ない。FPS の表示は出ない（起動設定に `debug` を書いていないため）。
        *  BOOT（「TAP SCREEN」）→ タップでタイトル画面。タイトルの曲が流れる。
        *  タイトル → 「遊び方」→ 8ページを「まえへ」「つぎへ」（← →）でめくれる → 「タイトルへ」・Escape で戻る。タイトルの曲は途切れない。
        *  「はじめる」（Enter・Space も）→ タイトルの曲が止まりスタートの音 → STAGE と敵の名前 → TURN とターンの番号・敵の予告 → ステージの曲。
        *  段取り: めくる・置く・捨てる・手札・束の移し替え・放つ（光の玉・式・兵に変わる・金貨のゲージ）が今のとおり動き、効果音が鳴る。
        *  行動を使い切ると「準備終了」→ タップで「BATTLE!」→ 攻防の演出（兵の動き・ヒットストップ・揺れ・HP の減り・当たりの音）→ 次のターン。
        *  途中の敵（ゴブリン・巨人）を倒すと案内 → タップで次の敵のステージ（巨人のステージで曲が頭から流れ直す）。ドラゴンのブレスで札が燃える。
        *  決着（クリアまたは負け）で結果の板 → タップでタイトルへ戻り、タイトルの曲が頭から流れる。
*   **要件3: 開発資料のエンジンの記述の確認**
    *  `PROJECT_ARCHITECTURE.md` のうち、エンジンで使えるもの・エンジンの使い方に触れている記述（例: 冒頭の「エンジンの資料は `oz/ENGINE_API.md` だけ」の段落、1章のフォルダ構造の `oz/` の行、スプライトの決まりの「`bounds` は実行時に読まない」、`Engine.addButton` は使わない旨、`js/main.js` の起動設定、`js/ui/` のバーチャルパッド）を読み、新しい版と食い違う所・古い言い回しの所を挙げる。
    *  新しい版でエンジンに `CanvasCache`・`Ui`・FPS の出し入れが入り、ゲームはまだ使っていない（次の Phase で使う）ことが資料から分かるように、どこに何を書くかの文案を作る。**`ENGINE_API.md` の中身（API の一覧・引数・挙動）は資料に書き写さない**（資料冒頭の決まり。章の番号と機能の名前を挙げる程度にとどめる）。
    *  スプライトの `bounds` を読まない決まりは、ゲーム側の決まりとして今は変えない（キャッシュで `bounds` を使うかは次の Phase で決める）。食い違いではないが、エンジン側で読んでよくなった旨を添えるかは文案で提案してよい。
    *  資料本体は書き換えず、文案を RES の『開発資料の更新予定』欄に書く（反映は実装統括が行う）。

## 【関連する責務】
* `oz/` : エンジン本体（OZ Engine）。外から届き、編集しない。使い方の唯一の資料は `oz/ENGINE_API.md`。`oz/src/` は読まない（`oz/VERSION`・`oz/FINGERPRINTS.txt` は読んでよい）。
* `index.html` : import map（`oz` は `./oz/index.js`、`assets/` は `./assets/`）、canvas、`js/main.js` の読み込み、ページの CSS。ゲームの処理は書かない。
* `js/main.js` : `Engine.start` の設定（解像度、レイヤー `['main']`、最初のシーンは BOOT、`virtualPad: false`、`debug` と `tickRate` は書かない）、起動の前の音の読み込み（`Assets.load`）と SE・BGM の音量の設定。ルール・描画・シーンの中身は書かない。
* `js/scenes/` : シーン（`Scene` の継承）。画面の流れは `Engine.changeScene`・`pushScene`・`popScene` で行う。ポインタの当たり判定は `js/view/layout.js` の `hitTest` で行い、盤面では `Engine.addButton` は使わない（`MenuScene.js` は土台から残した、まだ使っていないメニューで、`Engine.addButton` を使う）。BGM・効果音の呼び出しは `js/scenes/bgmCues.js`・`js/scenes/soundCues.js` の中だけ。
* `js/view/spriteView.js` : スプライトJSを import して `draw(ctx)` を呼ぶ。絵の範囲は凍結した表に持ち、スプライトの `bounds` は実行時に読まない。
* `js/ui/virtualPadConfig.js`・`js/ui/virtualPadView.js` : 土台から残したバーチャルパッド（`Engine.virtualPadEnabled`・`Engine.virtualPadState` を読む）。このゲームでは使わない（`virtualPad: false`）。
* `js/rules/` : ルール層。`oz` を import しない（本作業では触れない）。

## 【絶対遵守ルール (Constraints)】
* **エンジンに触れない** : `oz/` の中のファイルを編集・追加・削除しない。`oz/src/` を読まない（ツールでもシェルでも）。`oz/` の指紋の照合はしない（発注者が行う）。
* **新しい機能を使わない** : `CanvasCache`・`Ui`・`Engine.fpsVisible`・`Engine.fps`・`Engine.fpsPosition` を `js/` から使わない。起動設定に `debug` を足さない。
* **見た目・挙動を変えない** : ルール・設定の値・描き方・音・画面の流れは変えない。変更は、要件1で変わった章を理由に挙げられる所だけ。
* **変更してよいファイル** : `index.html` と `js/` の中の、要件1で直す必要があると分かったファイルだけ。`PROJECT_ARCHITECTURE.md` は書き換えない（文案を RES に書く）。
