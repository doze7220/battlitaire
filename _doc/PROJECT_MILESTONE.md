# マイルストーン・バックログメモ（バトリティア）

本ファイルは発注者（人間）の作業メモであり、DIR/REQ/RESのような確定記録ではない。`Phase XX-00`（DIR策定）の材料として使う。

* **フェイズ管理**：Phase大番号の並びと大まかなテーマのみを書く。サブフェイズ分解（`Phase XX-01`〜）はDIRが正本であり、本ファイルには書かない。DIRを発行したら該当行に `[DIR発行済み: YYMMDD_HHMM]` を付記する。
* **機能バックログ**：DIR策定時に、そのPhaseで扱う項目を拾う。実装が完了した項目は本ファイルから物理的に削除する（完了記録として残す必要はない。完了の記録はRES側が担う）。

企画の中身（ルールの確定事項と案）は `_doc/バトリティア_アイデアメモ.md` にある。

---

## フェイズ管理

P1：コアの試作（ルール層と最小の盤面。段取りのパズルが楽しいかを確かめる）
P2：攻防の演出と手触り（兵の群れ、城、早送り・スキップ、カードの動き、音）
P3：敵の種類と進行（ゴブリン→巨人→ドラゴン、撃退数のスコア）
P4：アウトゲーム成長（ステータス、スキル、保存）

## 機能バックログ

### コアの試作（P1 の候補）
* ルール層: 山札4つ・捨て札・列4本・めくって置く・放つ・ゲージ・行動回数（力こぶ込み）・攻防の計算・決着
* 最小の盤面: 四角いカードに絵文字、山札・列・ゲージ・城・敵の HP と予告の表示、放つボタン
* 敵1体（数値は DIR で仮決め）
* 城と敵の数値、攻防の計算の順番を決める
* 確かめること（アイデアメモ11章）: 見えている4枚から5行動を組むのが楽しいか／倍率が強すぎ・弱すぎないか／置けずに捨てる場面が多すぎないか
* `js/main.js` の `virtualPad` を `false` にする（タップとドラッグだけで遊ぶため）

### ルールの調整（試作の結果しだい）
* 同じスートの束ができなさすぎるとき: 見える枚数を2枚にする
* 置けなくて詰まるとき: 手札1〜2枚／「下なら置ける」（ちょうど1つ下ならボーナス）／捨てるとき少し得をする
* 使いきれなかった攻撃・防御の扱い（捨てる、一部を力こぶに回す）
* 倍率の強さ（「連続の枚数」倍のままでよいか）
* 薬が盾と役割で被る件（敵の設計で補う）

### 演出と手触り（P2 の候補）
* カードがパタパタめくれる・移動する
* 攻防: 守備兵が並ぶ → 敵兵と相殺 → 城へのダメージ → 自軍の突撃 → 敵へのダメージ → 大工の修理
* 数が多いときは大きなユニット1体を10人分として描く
* 早送り・スキップのボタン（必須）
* SE。連鎖で音程が上がる SE は、エンジンに音程の指定がないため、音程違いのファイルを用意するか、エンジンへ連絡票を出すかを判断する

### 敵と進行（P3 の候補）
* ゴブリンの軍勢・巨人・ドラゴン（神に等しい老竜）
* 特殊行動: 大振り／毒／硬い殻／妨害（呪いカードを混ぜる、山札を封じる、山札をシャッフルし直す）
* 何波しのいだか（撃退数）のスコア
* 敵と敵の間に山札を育てる仕組み（カードを足す・抜く・数字を上げる）と特殊カード（残り物、作り置き）。コアが楽しいと確認できてから足すか決める

### アウトゲーム成長（P4 の候補）
* HP を中心にしたステータスの伸び（攻撃・防御の伸びは控えめ）
* ソリティアのルールを曲げるスキル（覗き見、底送り、入れ替え、ずらし、片付け、同じ穴、延長）。装備は2〜3個
* 経験値（またはお金）とその使い道
* `Storage` での保存

### 画面
* タイトル画面、結果の画面
* プレイ中のメニュー（土台の `js/scenes/MenuScene.js` を使う）
