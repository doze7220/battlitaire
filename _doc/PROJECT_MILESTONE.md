# マイルストーン・バックログメモ（バトリティア）

本ファイルは発注者（人間）の作業メモであり、DIR/REQ/RESのような確定記録ではない。`Phase XX-00`（DIR策定）の材料として使う。

* **フェイズ管理**：Phase大番号の並びと大まかなテーマのみを書く。サブフェイズ分解（`Phase XX-01`〜）はDIRが正本であり、本ファイルには書かない。DIRを発行したら該当行に `[DIR発行済み: YYMMDD_HHMM]` を付記する。
* **機能バックログ**：DIR策定時に、そのPhaseで扱う項目を拾う。実装が完了した項目は本ファイルから物理的に削除する（完了記録として残す必要はない。完了の記録はRES側が担う）。

企画の中身（ルールの確定事項と案）は `_doc/バトリティア_アイデアメモ.md` にある。

## 機能バックログ

### ルールの調整（P1 の試作で入れなかったもの。必要になったら拾う）
* 同じスートの束ができなさすぎるとき: 見える枚数を2枚にする
* 置けなくて詰まるとき: 「下なら置ける」（ちょうど1つ下ならボーナス）／捨てるとき少し得をする
* 使いきれなかった攻撃・防御の扱い（いまはフェーズの終わりに消える。一部を力こぶに回す案など）
* 倍率の強さ（「連続の枚数」倍のままでよいか）
* 薬が盾と役割で被る件（敵の設計で補う）

### 演出と手触り（P2・P3 で作ったものの磨き込みの候補。いずれもテストプレイでは OK。P4 の DIR 策定で拾うか決める）
* カードの動き: 長い列の詰め直しで、もとからあるカードは一瞬で移る（滑らかには動かない）／めくれはカードが山札を離れるのと同時に始まる／カードの裏の色・模様は仮
* 攻防の演出: 相殺で当たった印（光・揺れなど）がない／演出中の最下段の色（`js/view/hudView.js` の `BATTLE_PANEL_FILL`）が盤面の背景とわずかに違って見えうる／小さな兵が多いと重なる／兵の絵は図形の仮
* 効果音: 音は仮の合成音（`tools/makeSounds.mjs`）、音量 `SE_VOLUME` 0.7 は仮／起動時に音のロードの間だけページが空になる／途中の敵を倒したときの効果音がない（P3 では鳴らさないことにした）
* 敵の演出（P3）: ドラゴンのブレスで札が燃える段が長い（1枚 0.65 秒、6枚で約4秒。`js/anim/battleAnimConfig.js` で縮められる）

### 敵と進行（P3 で入れないもの。必要になったら拾う）
* 敵の行動の追加: 力溜め（回復は P3 の巨人で入れる）
* 特殊行動: 大振り／毒／硬い殻／妨害（呪いカードを混ぜる、山札を封じる、山札をシャッフルし直す）
* 敵と敵の間に山札を育てる仕組み（カードを足す・抜く・数字を上げる）と特殊カード（残り物、作り置き）。コアが楽しいと確認できてから足すか決める

### 敵の絵（P5 の候補）
* 敵にも、兵と同じ「丸い体と浮いた手」の作りを使う案。大きな玉に手が付くだけで、予告が絵で読める（巨人の振りかぶりで両手を頭の上に上げる、ドラゴンの吸い込みで体がふくらむ、など）。P4 で兵の体を作るときに、敵にどこまで使うかを決める
* 敵の絵も、P4 で決めるクオータービューの角度と描き方の決まり（基準点・大きさ・向き）に合わせて描く

### 4体目以降の敵の候補
* 硬い殻（一定の攻撃に届かないと通らない）。大きな数字が作りやすいこのゲームと相性がよい。同じスートの長い束を作る理由になる

### エンジンへの要望（ブラッシュアップの後にまとめる）
* スプライトの Canvas キャッシュ（スプライトを一度画像に焼き、以後は画像として速く描く）。ゲーム側は `getContext` を書けないので、エンジンの機能として OZ Engine へ連絡票で頼む。最初は JS のスプライトのまま動かし、実際に遅い所・必要な倍率・色ちがいの要否が分かってから要望をまとめる
* 連絡票で詰める論点: 焼く範囲（エディタの書き出しの `bounds` を使うなら、ENGINE_API 23章の「`draw` 以外のキーは読まない」を変えることになる）／焼いた画像のどこがスプライトの原点か／解像度（画素密度と、画面で描く最大の大きさを掛けた大きさで焼かないとぼやける。兵は数によって大きさが変わる）／焼くときに色を差し替えられるか（あれば役割ごとの色ちがいのファイルが要らない）／ウィンドウの大きさが変わったときに焼き直しが要るか

### アウトゲーム成長（P6 の候補）
* HP を中心にしたステータスの伸び（攻撃・防御の伸びは控えめ）
* ソリティアのルールを曲げるスキル（覗き見、底送り、入れ替え、ずらし、片付け、同じ穴、延長）。装備は2〜3個
* 経験値（またはお金）とその使い道
* `Storage` での保存（最高記録を含む）
* 手札の枠を増やすスキル。枠を5以上にすると枠は縮むが文字は縮まず、はみ出して見えるおそれがある（P1 の 01-03 の懸念）
* スキルやステータスで数値が伸び、兵が理論上の最大（ゲージ1つあたり 128 体）を超えたときの描き方（さらに詰めて描く、「+12」のように書き添える、など）。P4 では兵を1人＝1体で描く

### 画面
* プレイ中のメニュー（土台の `js/scenes/MenuScene.js` を使う）
