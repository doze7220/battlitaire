# マイルストーン・バックログメモ（バトリティア）

本ファイルは発注者（人間）の作業メモであり、DIR/REQ/RESのような確定記録ではない。`Phase XX-00`（DIR策定）の材料として使う。

* **フェイズ管理**：Phase大番号の並びと大まかなテーマのみを書く。サブフェイズ分解（`Phase XX-01`〜）はDIRが正本であり、本ファイルには書かない。DIRを発行したら該当行に `[DIR発行済み: YYMMDD_HHMM]` を付記する。
* **機能バックログ**：DIR策定時に、そのPhaseで扱う項目を拾う。実装が完了した項目は本ファイルから物理的に削除する（完了記録として残す必要はない。完了の記録はRES側が担う）。

企画の中身（ルールの確定事項と案）は `_doc/バトリティア_アイデアメモ.md` にある。

## 機能バックログ

### ルールの調整（P1 の試作で入れなかったもの。必要になったら拾う）
* 同じスートの束ができなさすぎるとき: 見える枚数を2枚にする
* 置けなくて詰まるとき: 「下なら置ける」（ちょうど1つ下ならボーナス）／捨てるとき少し得をする
* 使いきれなかった攻撃・防御の扱い（いまはフェーズの終わりに消える。一部を力こぶに回す案など）
* 薬が盾と役割で被る件（敵の設計で補う）

### 演出と手触り（P2〜P4 で作ったものの磨き込みの候補。いずれもテストプレイでは OK。P5 の DIR 策定で拾うか決める）
* 攻防の演出: ヒットマークの絵は仮（`assets/sprites/effect_hit.js`。OZ Vector Editor で作り直して同じ名前で差し替える。05-05 で仮のまま閉じた）
* 効果音: 音は仮の合成音（`tools/makeSounds.mjs`）、音量 `SE_VOLUME` 0.7 は仮／起動時に音のロードの間だけページが空になる

### 敵と進行（P3 で入れないもの。必要になったら拾う）
* 敵の行動の追加: 力溜め（回復は P3 の巨人で入れる）
* 特殊行動: 大振り／毒／硬い殻／妨害（呪いカードを混ぜる、山札を封じる、山札をシャッフルし直す）
* 敵と敵の間に山札を育てる仕組み（カードを足す・抜く・数字を上げる）と特殊カード（残り物、作り置き）。コアが楽しいと確認できてから足すか決める

### 演出と UI の磨き込み（P4 の相談で出たもの。P5 の DIR（261119_2147）では、カードのデザインと演出・フェイズ開始とバトル開始の演出を扱い、ほかは未定のまま残した）
* デバッグモード: タイトル画面に「デバッグモードスタート」を置き、リリースのときはそこを OFF にするだけで消す。1つの定数で、そのボタンとエンジンの FPS 表示（`debug: true`）をいっしょに入り切りする。デバッグモードで始めたときだけ、ゲーム中に操作を呼び出す口（隅のボタン、PC ではキーも）が出る。`addButton` は消せないので、操作は専用のシーン（`pushScene`）にまとめる
  * 操作は「見た目だけ」（演出にだけ仮の値を渡す。例: 理論上の最大の兵 128×3 で攻防を見せる）と「ルールに触る」（ルール層にデバッグ用の操作を作って呼ぶ）に分ける
  * 候補: 兵の数を指定して出す／ゲージの値を変える／敵を切り替える（ドラゴンから始める）／敵の次の行動を指定する（ブレス、巨人の攻撃、回復）／城・敵の HP を 1 にする／乱数の種を表示して同じ種でやり直す／スロー（timeScale 0.25）と一時停止／始め方を選べるようにする
* カードのデザインと演出（スートのスプライトを使う）
* フェイズ開始・バトル開始の演出
* タイトル画面（いまの TITLE は仮）
* 遊び方の図: P4 の後の Interrupt で、タイトル画面から開く「遊び方」（数ページをめくる、文字だけ）を作る。カード・スート・兵・敵のスプライトを使った図を足すかは P5 で決める。プレイ中に開く口は、プレイ中のメニューを作るときに考える
* BGM・SE の候補出し（BGM はタイトルから鳴らす想定。BOOT と TITLE は分けてある）
* 兵の手足: 丸い体に手と足が浮いた形（腕と脚は描かず、手のひらと足首から先を丸・楕円で描く）。P4 の兵は丸い体だけ
* 敵にも同じ「丸い体と浮いた手」の作りを使う案。予告が絵で読める（巨人の振りかぶりで両手を頭の上に上げる、ドラゴンの吸い込みで体がふくらむ、など）

### 4体目以降の敵の候補
* 硬い殻（一定の攻撃に届かないと通らない）。大きな数字が作りやすいこのゲームと相性がよい。同じスートの長い束を作る理由になる

### エンジンへの要望（ブラッシュアップの後にまとめる）
* スプライトの Canvas キャッシュ（スプライトを一度画像に焼き、以後は画像として速く描く）。ゲーム側は `getContext` を書けないので、エンジンの機能として OZ Engine へ連絡票で頼む。最初は JS のスプライトのまま動かし、実際に遅い所・必要な倍率・色ちがいの要否が分かってから要望をまとめる
* 連絡票で詰める論点: 焼く範囲（エディタの書き出しの `bounds` を使うなら、ENGINE_API 23章の「`draw` 以外のキーは読まない」を変えることになる）／焼いた画像のどこがスプライトの原点か／解像度（画素密度と、画面で描く最大の大きさを掛けた大きさで焼かないとぼやける。兵は数によって大きさが変わる）／焼くときに色を差し替えられるか（あれば役割ごとの色ちがいのファイルが要らない）／ウィンドウの大きさが変わったときに焼き直しが要るか

### 強化（P6 インゲーム強化・P7 メタ強化の候補）
* （261119 決定）インゲーム強化: 敵を倒すたびに3つの選択肢が出て、1つを選んで強くなる（Vampire Survivors のレベルアップに近い形）。負けたら消える
* （261119 決定）敵が3体だと1回のプレイで選べるのは2回だけなので、敵（波）を増やし、倒すたびに選ぶ。敵の増やし方（ゴブリンを数波にする、中ボスを足す、4体目以降の候補の「硬い殻」など）は P6 で決める。下の「敵と進行」「4体目以降の敵の候補」も材料
* （261119 決定）強化の種類の候補は4つ。中身は P6 の DIR の前に発注者とブレストして決める（発注者もアイデアを貯めておく）
  * 数値の強化（城の最大 HP、毎フェーズの元の攻撃・防御、束の補正の上限、金貨の効率など）
  * 山札を育てる（カードを足す・抜く・数字を上げる、特殊カード「残り物」「作り置き」）
  * ルールを曲げるスキル（下の項目。最下段の左の空きを使う）
  * 常時効果（パッシブ。例:「盾を放つと修理も +1」「余った攻撃の半分を持ち越す」。組み合わせで強くなるもの）
* （261119 決定）メタ強化: プレイをまたいで残る永続の強化。P7 で作る。メタ強化で「インゲーム強化の選択肢を解放する」形にもできる
* メタ強化の通貨の名前は、ゲーム内の「金貨」（スート）と紛らわしくないものにする
* HP を中心にしたステータスの伸び（攻撃・防御の伸びは控えめ）
* ソリティアのルールを曲げるスキル（覗き見、底送り、入れ替え、ずらし、片付け、同じ穴、延長）。装備は2〜3個
* 経験値（またはお金）とその使い道
* `Storage` での保存（最高記録を含む）
* 手札の枠を増やすスキル。枠を5以上にすると枠は縮むが文字は縮まず、はみ出して見えるおそれがある（P1 の 01-03 の懸念）
* スキルやステータスで数値が伸び、兵が理論上の最大（ゲージ1つあたり 128 体）を超えたときの描き方（さらに詰めて描く、「+12」のように書き添える、など）。P4 では兵を1人＝1体で描く
